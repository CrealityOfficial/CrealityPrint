# 工作目录自动迁移

应用与命令行工具共用 `DataDirectoryMigration`，目标数据版本由根 CMake 的 `CREALITYPRINT_DATA_VERSION` 控制，默认 7.3。软件升级为 7.4 而数据版本仍为 7.3 时，不新建目录。

## 行为

- 目标已初始化时不覆盖。首次优先 7.0，再尝试 6.0；来源目录代表数据代际，应用版本只作记录，不限制前缀；支持仍写入 7.0 的 7.3 构建，以及 6.0 的历史内部版本号 `01.09.03.50`。
- 正式版和 Alpha 隔离，Alpha 对应 `7.3 Alpha`，只检查同渠道来源。
- 系统参数和打印机资源使用安装资源，用户 JSON 和 `.info` 原样复制，原生解析和继承链校验不保存文件。
- 失败原件保存在目标 `migration/quarantine/`。源目录不变。
- 缓存不复制，旧同步元数据保存在 `migration/legacy-sync/`，不重放任务。
- 已存在旧目录但主配置和备份均无效时，停止完整配置迁移，原因写入父目录 `.migration-7.3/report.json`；仍原样复制来源的完整 `user/` 及 `Creality.conf`、`deviceInfo.json`、`user_info.json`，应用静默继续初始化。
- 不弹出迁移界面。任何迁移异常（包括路径、权限、锁和资源错误）均不阻断应用后续启动；失败信息尽可能写入父目录 `.migration-7.3/last-error.txt`，旧 staging 保留供诊断。
- 失败兜底覆盖整个迁移入口：优先使用已选定来源，否则按同渠道 7.0、6.0 查找有 `user/` 或三个根文件任意一项的来源，完整保留多账户、嵌套目录、JSON、`.info`、缓存和同步元数据；不覆盖目标已有文件。同时原样保全上述三个根文件，无 user 目录也可保全根文件。兜底不依赖旧配置解析、资源安装或预设校验，单个文件复制异常不阻止其他文件复制；文件系统不可读、不可写或迁移锁被占用时，记录兜底失败并保持静默启动。
- 目标 `migration/user-fallback.json` 以 `files` 记录 user 文件摘要、以 `root_files` 记录三个根文件摘要，并记录复制异常，`preserve-user-presets` 防止正常加载删除或改写兜底预设。保全生成且摘要未变的配置不会阻止完整迁移重试；正常启动改写配置后按已有目标规则处理；独立命令行诊断工具仍以非零退出码报告完整迁移失败，修复原因后可在user 文件清单与保全根文件摘要未变化且目标无冲突时重试。
- Windows 提交时遇到目录临时拒绝访问或共享占用，会静默重试最多约 2 秒；仍失败则复制 user 兜底。
- 迁移提交成功后自动删除本事务的空 `runtime-backup`；非空备份和迁移锁文件保留。重启恢复或读取已提交状态时也会重试该清理，清理失败不影响已完成的迁移。
- 父目录迁移锁防止并发；Windows 迁移期间以禁止写入共享方式持有源文件。检测到其他 Creality Print 进程时等待最多约 5 秒后失败重试，不退回较旧来源。

## 云端预设

迁入目录暂缓用户预设自动上传和下载，由 `migration/cloud-sync-hold.json` 控制。JSON 和 `.info` 的云端身份及待上传标志保持原样，不伪造同步完成。这一状态不禁用账户登录或设备通信，也不改变旧目录的云同步。

恢复云同步前需要确认服务端/客户端多版本预设兼容性与旧待上传状态的处理策略。本变更没有完成该协议验证，不能把删除 hold 文件作为默认发布步骤。

## 构建和测试

```powershell
cmake --build out/weiyusuo-release/build --target data_directory_migrate
python tests/data_migration/test_migration.py out/weiyusuo-release/build/src/libslic3r/data_directory_migrate.exe
```

Windows 独立工具运行时，需要将应用运行库目录（构建目录的 `src`）加入进程 PATH。它只执行本地迁移，不启动 GUI、登录或云端同步。

```text
data_directory_migrate TARGET RESOURCES TARGET_APP_VERSION [alpha]
```

TARGET 文件名必须等于 7.3（Alpha 为 `7.3 Alpha`）。工具当前仅注册 7.3 规则，与应用相同。目标应用版本参数只用于报告，来源实际应用版本从 Creality.conf 读取。

## 来源识别修复（规则修订 2）

此前按 app.version 的 6.x/7.0–7.2 前缀筛选来源，会误拒绝 7.0 目录中由 7.3 写入的数据，以及 6.0 的内部版本号。现以来源目录及配置结构识别，并继续使用原生解析器只读校验预设。

如果旧实现已经写入空白目标的 COMMITTED 标记，新实现仍不覆盖目标。需要先检查目标是否已有用户修改，经确认后备份完整目标目录再重试。没有迁移标记但已有有效配置的目标也保持不覆盖。

## 失败保全根文件扩展

- 迁移失败时，除完整 `user/` 外，也逐字节保全 `Creality.conf`、`deviceInfo.json`、`user_info.json`；文件不存在则跳过，JSON 损坏不阻止原件保留，目标已有普通文件不覆盖。
- 根文件与 user 独立处理；单项失败继续其他文件，根文件摘要记录在 `user-fallback.json` 的 `root_files` 中。
- 保全的配置及其他文件未变化时允许完整迁移重试，避免仅因保全生成 Creality.conf 而误判初始化完成。保全文件变化后沿用已有目标保护规则。

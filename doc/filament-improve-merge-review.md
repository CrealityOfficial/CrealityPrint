## 增量构建启动崩溃修复

用户在 `weiyusuo-release` 增量构建后，启动停在 `Tab::create_preset_tab()` 的 `GetDropDown().SetFont()`。合并增加了 `ComboBox` 成员，改变对象布局，而部分调用方没有重新编译。

- 现场 `Tab.cpp.obj` 为 15:04:07，控件头文件为 15:27:07，`ComboBox.cpp.obj` 为 15:33:05；Ninja 对调用方及 GUI PCH 记录的头文件依赖均为 0。
- 同一中文 MSVC 在终端与隐藏后台进程中分别产生 UTF-8/GBK 的 `/showIncludes` 输出，与 Ninja 依赖前缀不一致，导致头文件依赖丢失。
- 保留 `cmake/MSVCNinjaEncoding.cmake` 和 `cmake/msvc_utf8.cmd`，统一适用的 Windows MSVC/Ninja 配置与编译编码，并保留现有编译启动器。GUI 禁用 ccache 时仍保留编码启动器。
- Windows 调试配置跟随当前 CMake 目标，移除固定旧构建路径。
- 前轮完整重编译后，`Tab.cpp.obj` 记录 1193 项依赖，GUI PCH 记录 2222 项依赖；后台 C/C++/PCH 实测覆盖头文件变更重编译、无变更不重编译、空格路径、已有启动器及失败返回值。测试位于 `tests/cmake/test_msvc_ninja_encoding.py`。

其他开发者使用旧构建目录时，应重新配置和构建使启动器生效，并检查头文件依赖；若仍异常，清理该构建目录重新构建。

# K3 固定多喷嘴接入 CFS 的耗材切换实现说明

## 1. 文档目的

本文说明当前代码中已经实现的 K3 多喷嘴耗材映射、换料规划和 G-code 生成逻辑。

范围到以下链路结束：

```text
项目逻辑耗材
    -> filament_map
    -> 固定物理喷嘴
    -> 换料 topology
    -> 擦拭塔与冲刷规划
    -> K3 G-code
```

本文只描述当前工作区代码的实际行为、已确认契约和仍需验证的边界。

## 2. 已确认的总体方案

K3 参考 H2D 类型的固定喷嘴职责模型：

1. `Tn` 表示项目中的逻辑耗材，不表示物理喷嘴编号。
2. `filament_map[Tn]` 把逻辑耗材映射到固定物理喷嘴。
3. 当前 K3 默认配置为 4 个固定物理喷嘴，每个喷嘴均可连接 CFS 扩展。换料逻辑根据实际喷嘴数量及耗材映射工作，不写死 4 个固定喷嘴，因此后续双喷嘴机型也可复用同一套逻辑。
4. `M8200 P S<n>` 和 `M8200 L I<n>` 中的 `n` 仍是最终逻辑耗材编号。
5. 固件根据机器端耗材映射找到目标固定喷嘴以及对应的 CFS 槽位或直挂料卷。
6. `Tn` 只负责提交最终工具选择。
7. 切片器不在 `M8200` 前输出中间 `Tn` 帮助定位喷嘴，也不额外输出物理喷嘴编号。
8. 跨喷嘴切换保留原 K3 的抬升、避让和固定喷嘴切换逻辑。
9. 同一喷嘴内的耗材替换参考 K2 Plus 的切断、退料、装料、冲刷和擦嘴逻辑。
10. CFS 与直挂使用同一份逻辑 G-code，由固件根据机器端映射兼容实际供料方式。
11. 打印结束仍调用 `END_PRINT`，最终退料由固件完成。

例如：

```text
T0 -> P1
T2 -> P2
T1 -> P2
```

请求顺序：

```text
T0/P1 -> T2/P2 -> T1/P2
```

其中：

- `T0/P1 -> T2/P2` 是跨喷嘴切换，同时 P2 是本次任务首次使用；
- `T2/P2 -> T1/P2` 不跨喷嘴，是 P2 内部的同喷嘴换料。

## 3. 编号与状态语义

### 3.1 编号规则

| 名称                           | 含义                                   | 示例                |
| ----------------------------- | -------------------------------------- | -------------------|
| `Tn`                          | 0-based 逻辑耗材编号                     | `T0`、`T1`、`T2`     |
| `filament_map[Tn]`            | 1-based 物理喷嘴编号                     | 值 `1` 表示 P1      |
| `next_filament_id`            | 本次事件最终目标逻辑耗材                   | `T1`               |
| `target_resident_filament_id` | 目标喷嘴在本次任务中最后成功请求的耗材       | P2 上次请求过 `T2`   |

耗材温度、耗材直径、最大体积流量等材料参数按逻辑耗材编号读取；喷嘴直径、喷嘴偏移和工具切换回抽等硬件参数按映射后的物理喷嘴编号读取。

### 3.2 T 指令与换料指令速查

- `T<n>`：选择编号为 `n` 的最终逻辑耗材，例如 `T1` 表示选择逻辑耗材 1。该命令只负责提交最终工具选择，不负责切断、退料或装料；固件再根据机器端映射找到对应的固定物理喷嘴和供料来源。
- `M8200 P S<n>`：进入换料准备阶段，`S<n>` 表示本次要使用的最终逻辑耗材编号；固件同时记录进入换料前的打印速度百分比，供结束换料时恢复。
- `M220 S100`：把换料过程的打印速度倍率临时设置为 100%。它不是耗材选择命令。
- `M8200 R E-<长度>`：按给定负向 E 长度执行切断前回抽；只在目标喷嘴存在本次任务内已知旧料且启用切断回抽时生成。
- `M8200 C S0`：通知固件执行切断动作，实际切断由固件控制；切片器通过前后的 `G0` 移动把机构依次送到准备切刀位置、安全位置和进退料位置。
- `M8200 R`：执行退料动作，挤出机与 CFS 料盒同时回抽。首次进料流程也执行该命令，由固件处理机器开始前可能存在的残留料。
- `M8200 L I<n>`：执行进料动作，`I<n>` 表示要装入的最终逻辑耗材编号；固件根据该编号以及机器端映射选择对应的 CFS 槽位或直挂料卷。
- `M8200 O`：结束换料阶段，并恢复进入换料前记录的打印速度百分比。

换料流程中常见的辅助指令：

- `M140 S<温度>`：设置热床目标温度，不等待温度到达；`S0` 表示关闭热床加热。
- `M104 S<温度>`：设置喷嘴目标温度，不等待温度到达；`S0` 表示关闭喷嘴加热。
- `START_PRINT EXTRUDER_TEMP=... BED_TEMP=...`：调用固件开始打印宏，并传入首层喷嘴温度和热床温度。
- `M83`：把挤出机设置为相对挤出模式，后续 `G1 E...` 表示相对当前值进料或回抽。
- `G0 X... Y... F...`：移动到指定机构位置，`F` 表示移动速度；在换料流程中用于准备切刀、切断、安全避让、进退料和擦嘴定位。
- `SET_VELOCITY_LIMIT ACCEL=... ACCEL_TO_DECEL=...`：临时设置换料移动的加速度及减速参数。
- `M400`：等待此前规划的移动和挤出动作全部执行完成。
- `M106 S<转速>`：设置模型风扇转速；`S255` 为全速，`S30` 为低速。`M106 P2 S0` 表示关闭编号为 2 的辅助风扇。
- `G4 P5000`：原地等待 5000 ms，也就是 5 秒。
- `G1 E<长度> F<速度>`：相对模式下，正值为挤出，负值为回抽；`F` 表示挤出或回抽速度。

因此，一次需要装退料的完整事件可以简化理解为：

```text
M8200 P  -> 进入换料准备并记录原打印速度
G0        -> 将机构移动到相应的切断或进退料位置
M8200 C  -> 通知固件执行切断
M8200 R  -> 挤出机与 CFS 料盒同时回抽退料
M8200 L  -> 装入最终逻辑耗材
Tn       -> 选择最终逻辑耗材
M8200 O  -> 结束换料并恢复原打印速度
```
本文统一以当前 K3 profile 实际生成的 `M8200 P/R/C/L/O` 为准

### 3.3 状态只覆盖本次 G-code 任务

`PhysicalNozzleStateRecorder` 为每个固定物理喷嘴独立记录本次任务中最后请求的逻辑耗材。

该记录不表示切片器知道打印开始前喷嘴内真实装有什么。状态规则为：

1. 创建记录器时所有喷嘴均为未知状态。
2. 不根据 `[1,2,3,4]` 等一对一映射推断四个喷嘴已经分别装料。
3. 机器开始 G-code 已经请求首个活动耗材，因此规划阶段只显式记录该首个活动喷嘴。
4. 其他喷嘴第一次成为目标时，仍按“本次任务首次使用”处理。
5. 离开某个喷嘴不会清空其记录。
6. 换料事件成功加入规划后才提交目标喷嘴的新状态。
7. 如果机器中存在与目标不符的残留料，由固件在执行首次进料事务时纠正。

`PhysicalNozzleStateRecorder` 的使用流程如下：

1. 按当前机型的物理喷嘴数量创建记录器，各喷嘴初始值为未知。
2. 开始 G-code 请求首个活动耗材后，通过 `seed()` 记录该耗材对应的物理喷嘴。
3. 每次规划换料前，通过 `evaluate()` 读取目标喷嘴的任务内状态，并生成本次换料 topology。
4. topology 用于判断是否需要跨喷嘴切换、首次进料或同喷嘴换料，并为退料和冲刷提供目标喷嘴的任务内旧料编号。
5. 换料事件成功加入规划后，通过 `commit()` 将目标喷嘴状态更新为本次目标耗材。
6. `resident_filament()` 仅用于查询指定物理喷嘴当前保存的任务内耗材编号。

例如，本次任务的映射与使用顺序为：

```text
T0 -> P1
T2 -> P2
T1 -> P2
T3 -> P1
```

记录和判断过程如下：

1. 开始 G-code 已请求 `T0`，记录 `P1 = T0`。
2. `T0/P1 -> T2/P2`：P2 尚无任务内记录，判定为“跨喷嘴切换 + P2 首次进料”；规划成功后记录 `P2 = T2`。
3. `T2/P2 -> T1/P2`：P2 上一次记录为 T2，因此按 `T2 -> T1` 执行同喷嘴换料和冲刷；规划成功后记录 `P2 = T1`。
4. `T1/P2 -> T3/P1`：虽然当前使用的是 T1，但记录器知道目标 P1 里面上次是 T0，因此应按 T0 → T3 计算退料参数和冲刷量，而不是错误地按 T1 → T3。；规划成功后记录 `P1 = T3`。

因此，`PhysicalNozzleStateRecorder` 是本次 G-code 规划期间的临时喷嘴状态记录器。

## 4. 换料关系判定 topology

### 4.1 数据结构

`FilamentChangeTopology` 保存一次换料关系的判定结果：

| 字段                            | 当前作用                                                                 |
| ------------------------------- | ------------------------------------------------------------------------ |
| `next_filament_id`              | 换料成功后，记录目标喷嘴的新耗材                                         |
| `next_physical_nozzle_id`       | 表示目标物理喷嘴，用于状态查询、冲刷矩阵和 G-code                        |
| `target_resident_filament_id`   | 目标喷嘴在本次任务中记录的旧料，用于退料参数和冲刷计算                   |
| `target_residency_known`        | 判断目标喷嘴是首次使用还是已有任务内旧料                                 |
| `requires_initialization_flush` | 判断是否执行首次进料和固定冲刷                                           |
| `actions`                       | 保存本次换料关系包含的动作类型                                           |

动作类型为：

```text
CrossNozzleSwitch
SameNozzleSwitch
InitializeTargetNozzle
```

这些动作是同一个最终换料事件的组成事实，不会扩展成多个中间工具切换。

### 4.2 判定规则

| 目标喷嘴状态       | 是否跨喷嘴 | topology 结果                                | G-code 行为                                |
| ------------------ | ---------- | -------------------------------------------- | ------------------------------------------ |
| 本次任务尚未使用   | 否         | `InitializeTargetNozzle`                     | 首次进料、固定冲刷、一次最终 `Tn`          |
| 本次任务尚未使用   | 是         | `CrossNozzleSwitch + InitializeTargetNozzle` | K3 跨喷嘴准备、首次进料、一次最终 `Tn`     |
| 已记录另一种耗材   | 否         | `SameNozzleSwitch`                           | 完整同喷嘴换料、污染冲刷、一次最终 `Tn`    |
| 已记录另一种耗材   | 是         | `CrossNozzleSwitch + SameNozzleSwitch`       | K3 跨喷嘴准备、目标喷嘴换料、一次最终 `Tn` |
| 已记录最终目标耗材 | 是         | `CrossNozzleSwitch`                          | 只执行原 K3 跨喷嘴切换，不重复装退料       |
一次最终 `Tn` 指：本次换料事件完成装退料处理后，只输出一次目标逻辑耗材选择命令 T[next_extruder]，不输出目标喷嘴旧料或物理喷嘴对应的中间 T 命令。

目标喷嘴未知时：

```text
target_resident_filament_id = -1
target_residency_known = false
requires_initialization_flush = true
```

目标喷嘴已记录其他耗材时：

```text
target_residency_known = true
requires_initialization_flush = false
actions 包含 SameNozzleSwitch
```

## 5. 规划阶段实现

### 5.1 启用条件

`Print::_make_wipe_tower()` 在以下条件同时成立时启用新 topology：

```cpp
support_filament_nozzle_mapping == true
nozzle_diameter.size() > 1
```

状态容器大小直接使用 `nozzle_diameter.size()`，因此逻辑适用于任意固定多喷嘴数量。

### 5.2 规划流程

每个换料事件按以下顺序处理：

1. 用 `get_physical_nozzle_index()` 解析前后逻辑耗材对应的物理喷嘴。
2. 调用 `PhysicalNozzleStateRecorder::evaluate()` 计算 topology。
3. 如果目标喷嘴已有任务内旧料，以 `target_resident_filament_id` 作为污染矩阵来源。
4. 如果目标喷嘴首次使用，不伪造旧料，也不读取不存在的 `flush[unknown][next]`。
5. 将 topology 随擦拭塔工具切换结果传到 G-code 阶段。
6. 规划成功后调用 `commit()` 更新目标喷嘴记录。

### 5.3 冲刷矩阵

已知目标喷嘴旧料时，污染冲刷使用：

```text
flush[target_resident_filament_id][next_filament_id]
```

如果配置提供了按喷嘴展开的多份矩阵，则读取：

```text
flush_matrix[target_physical_nozzle][old][new]
```

如果只有一份矩阵，则兼容使用第一份 `old -> new` 矩阵。

目标喷嘴首次使用时不读取污染矩阵，固定首次冲刷由 G-code 阶段生成。

## 6. topology 传递链路

规划结果不会在导出阶段重新推导，实际传递路径为：

```text
Print::_make_wipe_tower()
    -> WipeTowerCreality::plan_toolchange()
    -> WipeTowerInfo::ToolChange::filament_change_topology
    -> WipeTower::ToolChangeResult::filament_change_topology
    -> append_tcr_creality()
    -> GCode::set_extruder_new()
    -> change_filament_gcode
```

`WipeTowerCreality::merge_tcr()` 在选择工具切换结果时同步复制对应 topology，避免擦拭塔结果合并后丢失状态。

`GCode::set_extruder_new()` 向 K3 模板提供：

```text
target_residency_known
requires_cross_nozzle_switch
requires_same_nozzle_switch
requires_initialization_flush
target_resident_filament_e_feedrate
target_resident_retract_length_toolchange
target_resident_long_retraction_when_cut
target_resident_retraction_distance_when_cut
target_resident_nozzle_temperature_range_high
```

目标喷嘴旧料已知时，`target_resident_*` 参数取该旧料；首次使用时，以最终目标耗材参数作为安全回退，但 `target_residency_known` 仍保持 `false`。

最新多口径链路会在最终 `filament_map` 确定后，把打印机 Pn 默认值和耗材 Tn 覆盖值统一物化为按 Tn 排列的运行时回抽参数。因此，`target_resident_retract_length_toolchange` 按目标喷嘴当前驻留耗材的 Tn 读取，开始 G-code 按 `initial_no_support_extruder` 读取；物理喷嘴编号只用于 topology、喷嘴驻留状态和按喷嘴选择冲刷矩阵。

## 7. G-code 生成规则

### 7.1 首个活动喷嘴

“首个活动喷嘴”是开始 G-code 最先装载的逻辑耗材所映射到的物理喷嘴，不固定为 P1。当前取 `initial_no_support_extruder`：例如首个非支撑耗材为 T2，且 `filament_map[T2] = 3`，则首个活动喷嘴是 P3。

#### 之前的逻辑

原 K3 面向四喷嘴直挂场景，`machine_start_gcode` 只对首个逻辑耗材升温并执行一次 `Tn`：

```gcode
M104 S140
M104 S220 T[initial_no_support_extruder]
T[initial_no_support_extruder]
M104 S[nozzle_temperature_initial_layer]
```

该流程默认对应喷嘴中的直挂料已经可以直接打印，不包含 `M8200` 装退料事务，也不包含首次进料冲刷和擦嘴。随后直接进入 K3 原有首层引线流程。

#### 当前的逻辑

K3 支持每个固定喷嘴连接 CFS 后，`machine_start_gcode` 对首个非支撑逻辑耗材统一执行首次进料流程：

```gcode
M8200 P S[initial_no_support_extruder] ; 进入换料准备，S 为首个逻辑耗材编号
M8200 C S0                              ; 通知固件执行切断，实际切断由固件控制
M8200 R                                 ; 挤出机与 CFS 料盒同时回抽退料，并处理可能存在的残留料
M8200 L I[initial_no_support_extruder]  ; 执行进料，I 为首个逻辑耗材编号
T[initial_no_support_extruder]          ; 选择最终逻辑耗材，不负责装退料
; 三段 90 mm 冲刷和擦嘴
M8200 O                                 ; 结束换料并恢复进入换料前的打印速度百分比
```

具体处理顺序为：

1. `initial_extruder` 是切片器确定的初始逻辑耗材，可能是支撑耗材。
2. 如果 `initial_extruder` 不是支撑耗材，`initial_no_support_extruder` 与它相同；如果它是支撑耗材，则按打印顺序选择首个非支撑逻辑耗材；如果任务只有支撑耗材，仍回退为 `initial_extruder`。
3. 固件根据 `initial_no_support_extruder` 和机器端映射找到目标物理喷嘴及实际供料来源。
4. 开始 G-code 完成装料后只执行一次目标 `Tn`，随后执行三段 90 mm 冲刷和擦嘴。
5. 完成首次进料后，继续执行 K3 原有首层引线流程。

普通模型先打印时，`initial_extruder` 与 `initial_no_support_extruder` 相同；只有工具顺序以支撑耗材开头时二者才不同。该选择与 Bambu H2D 的开始进料规则一致。

每一段 90 mm 冲刷不是一次连续挤出，而是把 `90 mm` 拆成 5 组脉冲；每组依次挤出 `90 * 0.18` 和 `90 * 0.02`，5 组累计仍为 90 mm。随后通过 `M400` 等待动作完成，使用 `M106 S255` 全速风冷、`G4 P5000` 等待 5 秒，再降到 `M106 S30`，最后执行一次工具切换回抽并结束本段冲刷。

离线切片器不判断机器当前使用直挂料还是 CFS，同一份 G-code 使用相同的首次进料流程；实际供料来源和打印前残留料处理由固件负责。

#### 与规划阶段状态的衔接

规划擦拭塔换料时，`PhysicalNozzleStateRecorder` 按以下方式初始化：

1. G-code 占位符计算和擦拭塔规划共同调用 `ToolOrdering::first_non_support_extruder()`，得到同一个 `initial_no_support_extruder`。
2. 规划器将该耗材设置为 `current_extruder_id`，再根据 `filament_map` 找到对应的物理喷嘴。
3. 因为 `machine_start_gcode` 已经请求该耗材，所以通过 `seed()` 记录“首个活动喷嘴 = `initial_no_support_extruder`”。
4. 只记录这个已经由开始 G-code 处理的喷嘴，其他物理喷嘴仍保持未知状态。
5. 后续换料再次使用该喷嘴时，按照记录的耗材判断是否需要同喷嘴换料；其他喷嘴第一次成为目标时，进入 7.2 的“后续喷嘴首次使用”流程。

这里的 `seed()` 只是把开始 G-code 已经规划的结果同步给后续换料规划，不表示切片器知道打印开始前喷嘴内真实装有什么。

### 7.2 后续喷嘴首次使用

除机器开始代码已经处理的首个活动喷嘴外，其他固定喷嘴第一次成为目标时生成：

```gcode
; 如有需要，先执行不包含 Tn 的 K3 跨喷嘴准备
M8200 P S[next_extruder] ; 进入换料准备，S 为最终目标逻辑耗材编号
M8200 C S0              ; 通知固件执行切断，实际切断由固件控制
M8200 R                 ; 挤出机与 CFS 料盒同时回抽退料，并处理目标喷嘴中的残留料
M8200 L I[next_extruder] ; 执行进料，I 为最终目标逻辑耗材编号
T[next_extruder]         ; 选择最终逻辑耗材，不负责装退料
; flush_length_1 = 90
; flush_length_2 = 90
; flush_length_3 = 90
; 擦嘴
M8200 O                  ; 结束换料并恢复进入换料前的打印速度百分比
```

首次进料有以下约束：

- 不执行旧料长退料 `M8200 R E-...`；
- 固定生成三段 90 mm 冲刷；
- 固定首次冲刷不被骨架冲刷抵扣；
- 只在 `M8200 L` 后输出一次最终 `T[next_extruder]`。

对应的实际代码为：

```cpp
cal_length.assign(3, 90.f);
```

### 7.3 后续同喷嘴换料

如果目标喷嘴在本次任务内已记录另一种耗材：

```gcode
M8200 P S[next_extruder]               ; 进入换料准备，S 为最终目标逻辑耗材编号
M8200 R E-[目标喷嘴旧料的切断前回抽] ; 使用目标喷嘴旧料参数执行切断前回抽
M8200 C S0                             ; 通知固件执行切断，实际切断由固件控制
M8200 R                                ; 挤出机与 CFS 料盒同时回抽旧料
M104 S[目标喷嘴旧料的退料温度]       ; 设置目标喷嘴旧料所需的退料温度
M8200 L I[next_extruder]               ; 执行进料，I 为最终目标逻辑耗材编号
T[next_extruder]                       ; 选择最终逻辑耗材，不负责装退料
; flush[target_resident_filament_id][next_extruder]
; 擦嘴
M8200 O                                ; 结束换料并恢复进入换料前的打印速度百分比
```

目标喷嘴旧料只用于退料参数和污染矩阵，不输出中间 `T[target_resident_filament_id]`。

### 7.4 仅跨喷嘴

如果目标喷嘴已经记录最终目标耗材，则不运行 `M8200` 装退料事务：

```gcode
; 原 K3 跨喷嘴抬升和避让
T[next_extruder] ; 只选择最终逻辑耗材，由固件切换到映射后的固定物理喷嘴
```

K3 profile 中存在两个文本形式的 `T[next_extruder]`，但由互斥条件控制：一个属于材料事务，另一个属于仅跨喷嘴事务。单条实际路径只输出一次最终 `Tn`。

送料长度、温度、速度和 `M8200` 参数没有按尺寸比例缩放。

### 8.2 结束流程

`machine_end_gcode` 保留 K3 既有的结束切断动作，并继续调用固件结束宏：

```gcode
G1 Z{max_layer_z+2} F600
G1 X250 Y150 F10000
M8200 C S0
END_PRINT
```

其中 `M8200 C S0` 负责打印结束切断，最终退料仍由固件的 `END_PRINT` 流程负责。切片器不额外增加独立的装退料事务。

## 10. 必须重新切片验证的场景

| 场景           | 映射与请求顺序                 | 必查结果                                                 |
| -------------- | ------------------------------ | -------------------------------------------------------- |
| 首次单色       | `T0 -> P1`                     | 开始代码执行一次首次进料，`M8200 L I0` 后只有一次 `T0`   |
| 首次跨喷嘴     | `T0/P1 -> T2/P2`               | 先做 K3 跨喷嘴准备，再完成 P2 首次进料；不出现旧料长退料 |
| 同喷嘴换料     | `T2/P2 -> T1/P2`               | 使用 T2 的旧料参数和 `flush[T2][T1]`，只输出最终 `T1`    |
| 跨回已使用喷嘴 | `T1/P2 -> T3/P1`，P1 之前为 T0 | 使用 P1 的 T0 作为旧料，执行跨喷嘴加同喷嘴换料           |
| 仅跨喷嘴       | 切回已经记录最终目标耗材的喷嘴 | 只保留 K3 跨喷嘴逻辑，不运行装退料事务                   |
| 四喷嘴一对一   | `[1,2,3,4]`                    | 每个后续首次使用喷嘴仍执行首次进料，不因一对一映射跳过   |
| 双喷嘴扩展     | 两个固定喷嘴、多逻辑耗材       | 状态容器和映射范围随喷嘴数组变化，不依赖四喷嘴常量       |
| 直挂/CFS 映射  | 使用同一份 G-code              | 固件按机器端映射选择实际供料方式，逻辑 `Tn` 不变         |

每份新导出的 G-code 至少检查：

- `M8200 P`、`M8200 L` 与最终 `Tn` 的编号一致；
- 需要材料事务时，`Tn` 位于 `M8200 L` 之后；
- 同一事务没有中间工具和重复最终工具；
- 首次喷嘴固定三段 90 mm 冲刷；
- 已知旧料时才有旧料长退料；
- 同喷嘴污染矩阵来源是目标喷嘴记录的旧料；
- 跨喷嘴运动、喷嘴偏移和物理喷嘴参数未被逻辑耗材下标替代。

### 12 仍需确认
#### 12.1 固件必须满足的约定

1. `Tn` 只提交最终逻辑耗材选择，不负责切断、退料和装料。固件必须根据机器端映射找到该逻辑耗材对应的固定物理喷嘴以及 CFS 槽位或直挂料卷，切片器不额外传递物理喷嘴编号。
2. `M8200 P S<n>` 进入换料准备并记录当前打印速度百分比，`M8200 L I<n>` 执行目标耗材装入；其中的 `n` 都是最终逻辑耗材编号，固件必须使用同一份机器端映射解析目标喷嘴和供料来源。
3. `M8200 C S0` 负责触发切断；`M8200 R` 负责退料并处理喷嘴中可能存在的残留料；`M8200 O` 负责结束换料并恢复进入换料前的打印速度状态。
4. 首次进料请求的耗材与喷嘴当前残留料不一致时，固件必须完成残留料退出和目标耗材装入，切片器不根据机器打印前的真实驻留状态生成额外分支。
5. 同一份 G-code 用于 CFS 和直挂供料。机器端把目标逻辑耗材映射为直挂料时，固件必须安全兼容对应的 `M8200` 流程。
6. `END_PRINT` 内的最终退料仍由固件负责，切片器不追加独立的打印结束退料序列。

#### 12.2 后续切片与样机验证

1. 当前切断、退料、装料和擦嘴坐标只是按比例预设，必须经过固件和样机安全确认。
2. 首个工具为支撑耗材时，需要使用该特殊场景切片一次，确认开始 G-code 先装载首个非支撑耗材，随后第一次换料从该耗材切换到实际目标耗材。

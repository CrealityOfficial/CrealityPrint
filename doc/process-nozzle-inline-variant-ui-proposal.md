# K3 工艺参数取消喷嘴页签及内联多喷嘴控件方案

## 1. 文档目的

本文用于确定 K3 多喷嘴工艺参数的最终展示和数据处理方式，并记录当前源码已经落地的实现、仍未实现的扩展项和后续验证范围。

方案需要同时解决：

1. 速度页顶部喷嘴页签会让共享参数产生归属歧义；
2. 非速度页面也可能存在喷嘴独立参数；
3. 最新 K3 配置文件已经包含单值和数组混合数据；
4. 界面、预设、对象覆盖和切片必须使用同一套喷嘴身份。

分析与实施以 `feature/f039_group` 分支 `f251164d3` 为基线，并参考提交 `26279471c` 更新后的 K3 参数包。本文内容已按 2026-09-08 当前工作区的实际源码改动重新核对；K3 参数包的具体数值由配置同事另行更新，不纳入本次源码改动。

## 2. 最终结论

推荐采用以下方案：

```text
取消工艺页面顶部的 0.2/0.4/0.6/0.8 喷嘴页签

共享参数
  → 保持一个原生控件

喷嘴独立参数
  → 在参数自身位置同时显示当前全部喷嘴组合

切片
  → 继续按实际物理喷嘴选择对应值
```

最容易记忆的规则是：

> 一个框是共用，多个框是独立，框上标签说明属于哪个喷嘴。

这个方案同时满足两个目标：

- 用户不用切换页签，就能看懂参数作用范围；
- 不需要为了界面统一，把本来共享的参数强制复制成多份。

## 3. 最终界面示例

### 3.1 喷嘴独立数值

```text
顶部表面流量比例
  0.4-标准：1.00
  0.6-标准：1.00
```

这表示：

- 参数有多份数据；
- 0.4 和 0.6 可以分别修改；
- 切片使用哪个物理喷嘴，就读取哪一份。

### 3.2 共享数值

```text
慢速层数        1
```

这表示该工艺只有一份值，所有喷嘴共同使用。

### 3.3 喷嘴独立开关

不能把所有参数都强制做成文本输入框。开关应保持原生复选框：

```text
启用悬垂降速
  0.4-标准：☑
  0.6-标准：☐
```

### 3.4 下拉框支持与工艺参数范围

当前 41 个喷嘴独立业务参数只需要数值/百分比输入框和复选框，没有枚举型独立参数。耗材内联改动已经为通用 `MultiVariantField` 补齐 `coEnum/coEnums → Choice` 支持；这不表示工艺白名单已经新增枚举参数。

如果以后确实新增工艺枚举型独立参数，应复用已有 `Choice`，并验证工艺身份、继承、恢复和 Dirty 链路，保持原生下拉框展示：

```text
喷嘴运动模式
  0.4-标准：[标准模式 ▼]
  0.6-标准：[稳定模式 ▼]
```

因此产品中的“多输入框”概念实际含义是：

> 一个参数拥有多个带喷嘴身份的原生子控件。

## 4. 为什么这个方案优于顶部页签

### 4.1 顶部页签的问题

顶部选择 `0.4-标准` 后，用户会自然理解为：

```text
当前页面中看到的所有参数都属于 0.4 喷嘴
```

但当前速度页同时存在喷嘴独立参数和共享参数。用户无法直接判断修改一个参数会影响当前喷嘴还是全部喷嘴。

### 4.2 内联控件直接表达数据范围

取消页签后，参数的数据范围直接体现在控件数量上：

| 展示形式             | 用户理解         | 数据含义     |
| -------------------- | ---------------- | ------------ |
| 一个控件             | 所有喷嘴共用     | 标量参数     |
| 多个带喷嘴标签的控件 | 每个喷嘴可以不同 | 喷嘴变体参数 |

用户不需要切换页面、观察数值是否变化，也不需要理解底层数组。

### 4.3 不再受页面分类限制

喷嘴独立参数不一定只在速度页。例如：

- 质量页的顶部表面流量比例；
- 质量页的首层、外墙、内墙等线宽；
- 强度页的稀疏填充、内部实心填充等线宽。

采用参数内联展示后，无论参数位于哪个页面，都可以使用同一套规则。页面不再因为包含一个独立参数而整体显示喷嘴页签。

## 5. 与 BambuStudio 的关系

BambuStudio 开发模式中的 L/R 多输入框可以作为控件结构参考：

```text
Bambu：L/R + Standard/High Flow
K3：0.2/0.4/0.6/0.8 + 标准/高流量
```

可复用的思想包括：

- 一个参数生成多个子控件；
- 子控件绑定具体变体索引；
- 每个子控件独立编辑、恢复和显示修改状态。

K3 不能直接照搬的部分包括：

- K3 的用户身份是“喷嘴口径 + 流量类型”，不是固定 L/R；
- 一个可见喷嘴组合可能同时对应多个物理挤出机源行；
- 当前 41 项白名单需要支持数值/百分比文本框和复选框，代码也预留了整数微调框；
- 通用控件现已支持下拉框，但当前工艺白名单没有枚举型独立参数；
- K3 使用纵向排列展示当前有效的不同喷嘴组合，布局密度高于普通 L/R 场景。

因此实施原则是：

> 参考 Bambu 的多变体控件思想，使用 K3 自己的喷嘴身份和通用控件模型。

最新版 BambuStudio 02.08.02.61 的做法也不是“速度页全部独立”，而是使用明确白名单：

- `PrintConfig.cpp` 的 `print_options_with_variant` 定义喷嘴独立参数；
- `Tab.cpp` 中速度、悬垂和主要加速度参数按变体索引创建控件；
- `accel_to_decel_enable`、`accel_to_decel_factor`、Jerk 等参数仍按共享控件创建；
- G-code 阶段使用当前实际喷嘴对应的 `NOZZLE_CONFIG(...)` 值。

K3 与 Bambu 的关键差异是：Bambu 当前源码仍把线宽保留为共享参数，并通过不同口径的独立工艺文件保存线宽差异；K3 则需要在同一工艺中同时表达 0.2/0.4/0.6/0.8 混合口径。因此 K3 除了继承 Bambu 已验证的运动参数白名单，还必须把绝对线宽纳入喷嘴独立范围。

## 6. 最新配置文件现状

### 6.1 K3 工艺预设保存 16 个源行

当前 K3 工艺预设中，下面三个身份数组长度均为 16：

```text
print_extruder_id
print_extruder_variant
print_nozzle_variant
```

它们表达：

```text
4 个物理挤出机 × 4 种喷嘴变体 = 16 个源行
```

完整源行身份是：

```text
print_extruder_id
+ print_extruder_variant
+ print_nozzle_variant
```

界面不应直接显示 16 个输入框，而应把相同“喷嘴口径 + 流量类型”的源行合并为一个可见组合。

例如同一个 `0.4-标准` 可能在 E1、E2、E3、E4 中各有一行：

```text
配置保存：4 个源行
界面显示：1 个 0.4-标准控件
用户编辑：同步写入该组合对应的全部源行
```

### 6.2 不能用数组位置猜喷嘴

当前配置中的 `print_nozzle_variant` 使用 `0/1/2/3` 等身份值，但这些数字不是直接给用户显示的喷嘴直径。

界面标签必须通过机器配置中的喷嘴变体身份解析出：

```text
0.2-标准
0.4-标准
0.6-标准
0.8-标准
```

不能写死：

```text
数组第 0 项一定是 0.2
数组第 1 项一定是 0.4
```

也不能只根据排序后的位置绑定输入框。

### 6.3 最新 K3 配置文件的数据形状

当前配置文件同时出现单值和数组并不一定是问题，应先看源码是否已经把参数声明为喷嘴独立：

- `bridge_speed` 是喷嘴独立参数，使用 16 项数组保存不同喷嘴值，合法；
- `top_solid_infill_flow_ratio` 是喷嘴独立参数；源码允许单值 `1` 广播，当前 K3 参数包已显式写成 16 个 `1`，避免被误解为共享；
- 共享参数必须使用单值；如果共享参数写入不同值数组，才是直接冲突。

按照这个标准，当前配置中暴露出的三个源码类型冲突已有明确结论。

### 6.4 三个已有冲突的最终分类

下面三个参数不能继续由现有配置形状决定语义，应按照实际作用对象修正：

| 参数                         | 最终分类            | 原因                                                                           | 配置要求                           |
| ---------------------------- | ------------------- | ------------------------------------------------------------------------------ | ---------------------------------- |
| `accel_to_decel_factor`      | `Shared`            | Klipper 整机运动规划比例；它作用于当时采用的加速度，不是某个喷嘴的出料能力     | 改为一个单值                       |
| `bottom_shell_layers`        | `Shared`            | 决定对象底壳拓扑和厚度；同一对象可能由多个喷嘴打印，不能用“主喷嘴”猜一个层数 | 改为一个经测试确认的单值           |
| `initial_layer_line_width`   | `NozzleVariant`     | 直接决定当前出料喷嘴的首层线宽，不同口径需要保存不同绝对值                     | 参数包显式保存完整的 16 项身份数组 |

对应处理结论为：

```text
accel_to_decel_factor、bottom_shell_layers
  → 配置恢复单值，源码保持共享

initial_layer_line_width
  → 配置保留喷嘴差异，并补齐源码类型、变体清单、内联控件、对象继承和切片读取
```

不能继续保持“配置存四份、源码只认一份”的状态。

### 6.5 喷嘴独立参数的合法单值广播

源码已经声明为喷嘴独立的参数，可以使用单值表示当前全部喷嘴默认相同。这不属于配置冲突。

例如：

```text
outer_wall_speed = 200
```

表示：

```text
0.2-标准 = 200
0.4-标准 = 200
0.6-标准 = 200
0.8-标准 = 200
```

参数仍然具备喷嘴独立能力。单值广播是源码兼容能力；K3 随包配置为便于阅读，即使所有喷嘴值相同，也显式写成完整数组。

推荐配置规范为：

```text
参数在子预设中不设置
  → 允许缺失，表示继承父预设

参数声明为 Shared 且在子预设中设置
  → 必须写一个单值

参数声明为 NozzleVariant 且在子预设中设置
  → K3 随包配置统一写成与身份数组等长的 16 项数组
  → 各项允许相同；源码继续接受旧配置的单值广播
```

因此，单值、数组和缺失分别表示：

```text
单值：所有喷嘴使用相同默认值
数组：不同喷嘴可以使用不同值
缺失：继承父预设
```

### 6.6 2026-09-10 随包配置复核与整理

本次处理全部 6 份 K3 工艺预设：原有 21 项完整数组保持不变，16 项单值分别广播为 16 项数组，另外补齐以下 4 项。每份预设最终均显式保存 41 个独立业务参数，每项 16 行，三个身份数组保持原样。

| 原缺失参数 | 每行采用的源码默认值 |
| ---------- | -------------------- |
| `initial_layer_travel_acceleration` | `0` |
| `travel_short_distance_acceleration` | `0` |
| `skin_infill_line_width` | `100%` |
| `skeleton_infill_line_width` | `100%` |

修改前已逐级检查继承链，父预设也未提供上述四项，因此按源码默认值展开。显式保存后，未来若调整程序默认值，需要同步检查这些随包参数。

复核发现 `0.08mm`、`0.24mm` 两份工艺中的 `accel_to_decel_factor`、`bottom_shell_layers` 曾使用多值数组，与共享类型不一致。经用户确认，两份工艺均按 `0.24mm` 当前实际生效值恢复为共享单值：`accel_to_decel_factor = "100%"`、`bottom_shell_layers = "7"`。原加载链路将数组拼接为字符串，标量解析只读取首个数值，因此本次恢复单值保持当前生效值不变；数组中其他值不代表曾经生效的喷嘴差异。其余共享参数保持原样。

界面展示与文件形状分别判断：工艺和机器运动能力只有一个有效喷嘴组合时，当前通用控件不显示喷嘴标签；耗材即使只有一个组合仍显示标签。因此，本文“一个控件表示共享”的表述仅适用于多组合对比示例，不能作为判断参数作用范围的通用规则。

验证：JSON 解析、独立参数数组长度、身份对齐及修改前后逐行有效值等价检查通过；独立参数已有数组保持不变，两项共享参数按上述确认值检查，其余共享参数保持不变。未编译，未执行 GUI、保存重开、3MF 往返或重新切片验证。

## 7. 配置文件必须遵守的数据契约

不能简单使用下面的判断：

```text
JSON 是数组
  → 界面就显示多个喷嘴输入框
```

原因是数组可能来自参数包提前更新、格式错误或其他维度的数据。最终应由正式参数声明决定作用范围。

推荐建立一份唯一的“工艺参数作用范围清单”：

```text
Shared          所有喷嘴共用
NozzleVariant   按喷嘴组合独立
```

配置加载按下面规则处理：

| 参数声明            | 配置文件数据       | 处理规则                                                       |
| ------------------- | ------------------ | -------------------------------------------------------------- |
| `Shared`            | 单值               | 正常读取，界面显示一个控件                                     |
| `NozzleVariant`     | 完整数组           | 按完整源行身份读取，界面显示去重后的喷嘴组合                   |
| `NozzleVariant`     | 单值               | 将单值广播到当前全部源行，界面仍显示多个控件                   |
| `Shared`            | 所有元素相同的数组 | 可兼容折叠为单值，同时记录参数包格式问题                       |
| `Shared`            | 元素不同的数组     | 不能静默取第 0 项；必须升级为独立参数或修正参数包              |

最重要的原则是：

> 单值可以安全广播，多份不同值不能安全丢弃。

判断不再参考当前 K3 参数包“碰巧写成单值还是数组”，而是参考 Bambu 已验证链路和 K3 混合口径的实际语义。

| `skeleton_infill_line_width`                 | 骨架填充线宽     |

Bambu 的单口径工艺文件本身已经按喷嘴口径保存不同线宽，例如 0.2 喷嘴常用 0.22/0.25 mm，0.6 喷嘴常用 0.62 mm，0.8 喷嘴常用 0.82 mm。其当前多变体白名单不包含线宽，线宽差异仍由不同口径工艺文件承担。由此可以判断：直接移植 Bambu 的 L/R 白名单不能解决 K3 在同一工艺中混合多种口径的问题；K3 如果继续使用共享绝对线宽，就会把某一口径的值错误套给其他口径。

完成上述线宽独立改造后，`automatic_extrusion_widths` 不再作为正式工艺参数显示，也不加入 `Shared` 或 `NozzleVariant` 清单。这个结论不区分 K3 和其他机型：该参数原本只是把八个常规线宽批量改成 `0`，让切片器按当前喷嘴直径自动计算；现在每个喷嘴已经能够直接保存自己的线宽，继续显示该开关只会形成第二套表达方式。

最终处理规则为：

```text
全部 FFF 工艺参数界面
  → 屏蔽 automatic_extrusion_widths

后续新参数包
  → 不再写入 automatic_extrusion_widths
  → 直接提供各喷嘴经过测试的独立线宽

底层参数定义
  → automatic_extrusion_widths 默认 false
  → 各线宽字段仍保留 0 = 当前喷嘴自动计算
```

不增加旧工艺迁移逻辑：旧版本没有该参数，配置缺失时直接使用源码默认值 `false`；加载工艺时不批量改写八项线宽，也不额外转换该布尔值。线宽自身的 `nil`、`0` 和具体值仍需区分：`nil` 表示继承，`0` 表示当前喷嘴自动计算，具体毫米值或百分比表示当前喷嘴显式设置。

因此最终规则是：

```text
当前工艺参数只有上述 41 个属于 NozzleVariant
不在白名单中的工艺参数全部属于 Shared
```

### 7.2 速度页中明确保持共享的参数

速度页允许同时出现独立参数和共享参数。取消顶部页签并采用内联控件后，两者通过“一行一个控件”或“一行多个喷嘴控件”直接区分。

- 相对规则：`initial_layer_travel_speed`、`internal_bridge_speed`、`bridge_acceleration`、`internal_solid_infill_acceleration`；
- 层级和算法开关：`slow_down_layers`、`overhang_speed_classic`、`slowdown_for_curled_perimeters`、`smooth_speed_discontinuity_area`、`smooth_coefficient`；
- 整机运动规划：`accel_to_decel_enable`、`accel_to_decel_factor`、`travel_short_distance_threshold`；
- Jerk：`default_jerk`、`outer_wall_jerk`、`inner_wall_jerk`、`infill_jerk`、`top_surface_jerk`、`initial_layer_jerk`、`travel_jerk`；
- 全局高级限制：`max_volumetric_extrusion_rate_slope`、`max_volumetric_extrusion_rate_slope_segment_length`、`msao_recovery_enable`、`msao_safe_accel`、`msao_safe_velocity`、`acceleration_limit_mess_enable`、`acceleration_limit_mess`、`speed_limit_to_height_enable`、`speed_limit_to_height`。

其中四个相对规则应在系统工艺中优先写成百分比：

```text
initial_layer_travel_speed            → 相对 travel_speed
internal_bridge_speed                 → 相对 bridge_speed
bridge_acceleration                   → 相对 outer_wall_acceleration
internal_solid_infill_acceleration    → 相对 default_acceleration
```

这样共享的是一条比例规则，计算后的实际值仍会随各喷嘴的独立基准值变化，不需要再保存四份重复比例。

`accel_to_decel_factor` 同样保持共享：它是在各喷嘴已经选出的加速度之上应用统一的整机规划比例，不能因为速度页存在独立加速度，就把该比例也机械地复制成喷嘴数组。

### 7.3 其他页面中明确保持共享的代表参数

以下参数即使不同单口径工艺包曾经取值不同，也不代表它们应在同一次混合喷嘴切片中保存多份：

| 共享类别       | 代表参数                                                    | 原因                                          |
| -------------- | ----------------------------------------------------------- | --------------------------------------------- |
| 层高           | `layer_height`、`initial_layer_print_height`                | 同一层必须使用统一 Z 高度                     |
| 对象拓扑       | `wall_loops`、`top_shell_layers`、`bottom_shell_layers`     | 决定对象结构，不能按当前路径喷嘴切换          |
| 图案和顺序     | 填充图案、墙顺序、接缝模式、支撑样式                        | 属于对象或算法策略                            |
| 相对流量规则   | `bridge_flow`、`internal_bridge_flow`、`ironing_flow`       | 共享比例可作用于实际喷嘴生成的基础流量        |
| 机器或整塔规则 | Jerk、运动限制曲线、擦拭塔几何和全局上限                    | 作用对象不是单条喷嘴工艺路径                  |

`ironing_speed`、`ironing_spacing`、`skirt_speed`、`wipe_speed`、`wipe_tower_max_purge_speed` 在本版契约中也保持 `Shared`。它们不属于最新版 Bambu 的多变体白名单，当前先避免把所有带“速度”字样的参数无边界扩展为喷嘴数组。以后只有在物理测试证明同一工艺中必须并存不同值，并且切片阶段能够明确绑定实际喷嘴时，才单独升级白名单。

### 7.4 配置同事的修改清单

1. 上述 41 个 `NozzleVariant` 参数：值相同可写一个单值；值不同写与三个身份数组等长的完整数组。
2. `accel_to_decel_factor`、`bottom_shell_layers`：删除不同值数组，改为测试确认后的一个共享单值。
3. 四个共享相对规则优先使用百分比，不要为了表达喷嘴差异写成数组；喷嘴差异由其独立基准参数承担。
4. 其他所有工艺参数保持单值或继承父预设，不得新增喷嘴数组。
5. 同一“口径 + 流量类型”对应多个物理挤出机源行时，各源行值必须一致。
6. K3 新参数包不再设置 `automatic_extrusion_widths`；后续其他新参数包也遵守同一规则。各线宽字段仍可独立使用 `0` 表示当前喷嘴自动计算。

配置修改完成后，应验证所有已明确独立的参数能够同时支持两种合法形式：单值正确广播，数组按照完整身份正确选择。不能为了形式统一而强制把相同值展开成 16 项重复数据。

最终确认表应由代码和参数生成工具共同使用：

| 参数     | 最终作用范围      | 配置类型     | 配置形状                 | UI 控件      | 切片选择规则     |
| -------- | ----------------- | ------------ | ------------------------ | ------------ | ---------------- |
| 白名单内 | `NozzleVariant`   | 对应向量类型 | 单值广播或完整身份数组   | 内联多控件   | 按实际物理喷嘴   |
| 白名单外 | `Shared`          | 对应标量类型 | 单值或继承               | 单个原生控件 | 按全局或对象范围 |

## 8. 产品模型与当前代码映射

产品语义仍然只有两类，但当前代码没有新增独立的 `ProcessOptionScope` 枚举，而是沿用现有清单并增加一种 GUI 类型：

| 产品作用范围      | 当前代码判定                                                                 | 当前 UI                                          | 状态   |
| ----------------- | ---------------------------------------------------------------------------- | ------------------------------------------------ | ------ |
| `Shared`          | 不属于 41 项业务白名单                                                       | 沿用原有单个原生控件                             | 已实现 |
| `NozzleVariant`   | 位于 `print_options_with_variant`，且不是三个身份字段                        | 设置为 `ConfigOptionDef::GUIType::multi_variant` | 已实现 |
| 喷嘴源行身份      | `print_extruder_id`、`print_extruder_variant`、`print_nozzle_variant`        | 只参与映射，不生成用户输入框                     | 已实现 |

实际链路是：

```text
print_options_with_variant
  → 排除三个身份字段
  → ConfigOptionsGroup 将字段标记为 multi_variant
  → MultiVariantField 按当前有效喷嘴组合创建子控件
```

顶部喷嘴切换控件仍保留内部状态和兼容调用，但 `update_process_extruder_switch_visibility()` 始终将其隐藏；用户不再通过顶部页签决定当前编辑哪一行。

## 9. 当前通用多变体控件实现

### 9.1 已支持的原生子控件

当前 `MultiVariantField` 根据参数底层类型创建原生子控件：

| 参数类型                                                                 | 子控件     | 当前用途                         |
| ------------------------------------------------------------------------ | ---------- | -------------------------------- |
| `coFloatOrPercent`、`coFloatsOrPercents`、浮点、百分比、字符串及其数组   | `TextCtrl` | 速度、加速度、阈值、流量和线宽   |
| `coBool`、`coBools`                                                      | `CheckBox` | `enable_overhang_speed`          |
| `coInt`、`coInts`                                                        | `SpinCtrl` | 通用能力预留，当前白名单暂未使用 |
| `coEnum`、`coEnums`                                                      | 未支持     | 当前白名单没有此类参数           |

容器当前已经负责：

- 获取当前有效喷嘴组合；
- 把可见组合映射到完整源行；
- 创建带喷嘴标签的原生子控件；
- 动态计算行高；
- 处理编辑、恢复、Dirty、禁用和主题缩放；
- 机器喷嘴组合变化后安全销毁并重建子控件。

具体子控件继续负责原生输入、格式校验和规范化。遇到尚未支持的字段类型时，当前代码会直接抛出逻辑错误，因此后续扩展白名单时必须同时检查控件类型。

### 9.2 子控件身份

每个子控件不能只保存显示顺序，应绑定稳定身份：

```text
参数 key
+ 喷嘴口径
+ 流量类型
+ 对应源行集合
```

当前内部事件使用 `key#source_index`。这里的 `source_index` 来自喷嘴组合对应的配置源行，不是界面的第几行；恢复时还会通过身份比较，把编辑预设中的源行映射到初始/系统预设中的对应源行。

### 9.3 同组多源行的编辑和恢复

同一个 `0.2-标准` 可能对应多个物理喷嘴位置，但产品界面无法、也不需要区分它们。当前实现将“口径 + 流量类型”相同的源行合并为一个可见组合：

```text
界面显示
  → 只显示一个 0.2-标准子控件

用户编辑或恢复
  → 先定位该可见组合的代表源行
  → 从子控件读取校验和规范化后的值
  → 同步写入该组合对应的全部源行
```

恢复不是简单把原始 `boost::any` 直接写回配置，而是先设置子输入框，再读取子输入框规范化后的值，最后走与普通编辑相同的同步链路。这样百分号、空值和布尔值都使用原生控件的解析结果。

本方案的数据契约要求同组默认值保持一致，因此当前界面不提供“同一个 0.2-标准按物理位置分别编辑”的入口。

### 9.4 多对象混合值

对象、零件或高度范围同时选中且同一参数值不一致时，聚合层会传入空 `boost::any`。当前显示规则为：

| 子控件     | 混合值显示 | 用户编辑后的行为                   |
| ---------- | ---------- | ---------------------------------- |
| `TextCtrl` | 空白       | 将新值写入当前选中对象对应喷嘴行   |
| `CheckBox` | 半选状态   | 用户明确勾选或取消后写入统一值     |

`TextCtrl::set_value()` 和 `CheckBox::set_value()` 已在任何 `any_cast` 之前处理空值，避免多对象混合状态触发 `boost::bad_any_cast`。

## 10. 布局方案

### 10.1 当前纵向布局

当前有效组合只有一种时隐藏喷嘴前缀，外观接近普通单行控件，但数据仍保持喷嘴变体语义。

存在两种及以上有效组合时采用纵向形式：

```text
外墙速度    0.4-标准：200
            0.6-标准：160
```

参数名称区域在多变体行中限制为较紧凑的宽度，喷嘴标签使用固定最小宽度，剩余空间留给原生输入框，避免参数名称、喷嘴标签和参数值相互挤压。

### 10.2 悬垂速度等原复合行

当前代码没有实现矩阵型 `CustomVariants`。为了避免原复合行中的多个字段与多喷嘴子控件互相挤占，悬垂各档速度已经拆成独立参数行：

```text
轻微悬垂速度
  0.4-标准：20
  0.6-标准：18

中等悬垂速度
  0.4-标准：30
  0.6-标准：28
```

`overhang_1_4_speed` 至 `overhang_totally_speed`、`bridge_speed` 和共享的 `internal_bridge_speed` 都按单参数行创建。这样完全复用原生字段能力，不引入新的矩阵编辑协议。

### 10.3 行高和滚动

当前行高由 `MultiVariantField` 的子控件布局和 `OG_CustomCtrl::update_multi_variant_height()` 动态计算，不再假设每个参数只有一个固定高度的窗口。

喷嘴组合变化时，当前实现会遍历已经构建的工艺/对象页面并请求刷新多变体字段：

- 新旧布局的源行索引和标签完全相同时直接返回，复用现有控件；
- 组合发生变化时先释放旧子控件，再按新组合重建；
- 重建后重新加载字段值并计算面板、参数行和滚动区域尺寸。

## 11. 编辑、恢复和继承规则

### 11.1 全局工艺

- 每个喷嘴子控件可以独立修改；
- 每个可见喷嘴组合拥有自己的恢复图标和 Dirty 状态；
- 点击恢复只恢复当前可见喷嘴组合，并同步恢复该组合对应的全部物理源行；
- 其他口径/流量组合不受影响；
- 当前没有额外增加“参数标题一键恢复全部喷嘴”的入口。

### 11.2 对象、零件和高度范围

覆盖优先级保持：

```text
全局工艺
  → 对象
  → 零件/修改器
  → 高度范围
```

局部喷嘴值使用稀疏数据：

```text
有值：覆盖当前喷嘴
nil：继承上一级同一喷嘴的值
```

不能因为界面同时显示多个输入框，就自动把继承值复制成局部实值，否则全局参数更新后局部对象不会继续跟随。

同时选择多个对象且值不一致时，界面先显示第 9.4 节所述的混合状态，不会在刷新页面时自动选择某一个对象的值并回写。只有用户主动输入后，才把明确的新值写入所选对象。

### 11.3 搜索和参数说明

当前搜索索引仍以参数基础 key 注册。搜索定位到喷嘴独立参数时，展示的是该参数完整一行以及当前全部喷嘴子控件，不为每个 `key#source_index` 单独增加搜索结果。

本次没有修改参数说明文案，也没有增加“此参数按喷嘴独立保存/此参数为所有喷嘴共用”的固定提示；作用范围主要通过“一行一个控件或多个带喷嘴标签的控件”表达。

## 12. 当前切片数据链路

取消页签不改变最终按物理喷嘴取值的原则。当前工艺源表会在切片前按现有 `process_variant_source_indices` 映射物化为有效物理喷嘴顺序：

```text
工艺预设完整源表
  → 根据机器保留当前有效变体
  → Tn 通过 filament_map 找到物理喷嘴 Pn
  → 找到 Pn 当前喷嘴组合
  → 读取该组合对应的工艺值
```

原有 31 个 `print_options_with_variant` 业务参数继续沿用这条运行时链路。

新增的 10 个线宽参数已经从标量类型改成可空向量类型，并同步修改线宽计算、校验、占位符、填充、墙、支撑、树状支撑、校准和 G-code 等读取点，不能只让界面显示多份值。

新增的 10 个线宽不能在切片前按“对象主喷嘴”统一物化成一份值，而要按照实际路径角色选择喷嘴：

```text
外墙线宽
  → 外墙路径所用耗材
  → filament_map
  → 实际物理喷嘴
  → 该喷嘴的 outer_wall_line_width

支撑线宽
  → 支撑路径所用耗材
  → filament_map
  → 实际物理喷嘴
  → 该喷嘴的 support_line_width
```

首层、内墙、顶面、稀疏填充、内部实心填充、表皮和骨架线宽均使用同一原则。百分比线宽也必须先选择当前喷嘴对应的百分比，再以当前物理喷嘴直径计算绝对值；专用线宽为 0 时，回退到同一喷嘴行的 `line_width`，不能回退到数组第 0 项。

- 百分比线宽以对应物理喷嘴直径换算，专用线宽为 `0` 时回退同一喷嘴行的默认线宽。

### 13.4 受类型迁移影响的入口

- 自定义打印机向导仍生成其原有 8 项线宽，但现在使用单元素 `ConfigOptionFloatsOrPercentsNullable`，由后续流程按需广播；`skin_infill_line_width` 和 `skeleton_infill_line_width` 原本不由该向导写入；
- `Plater`、校准工具、Brim Ears 等直接创建或读取线宽的入口已同步适配新向量类型；
- 本次没有修改 K3 配置 JSON，也没有替配置同事确定具体工艺数值。

## 14. 验收清单

### 14.1 页面展示

- 所有工艺页面不再显示顶部喷嘴页签；
- 共享参数只显示一个原生控件；
- 独立参数显示当前全部有效喷嘴组合；
- 非速度独立参数也能在原页面正确显示；
- 当前喷嘴子控件采用单列纵向排列，并且不重叠；
- 悬垂分级速度、桥接速度等原复合行拆开后，标签和值均能完整显示；
- 当前 41 项白名单中没有喷嘴独立下拉框，不把未支持的枚举参数加入白名单。

### 14.2 配置文件

- 三个身份数组长度一致；
- 独立参数完整数组长度与身份数组一致；
- 独立参数单值能够安全广播；
- 共享参数出现不同数组值时不能静默取值；
- 同一可见组合的多个物理源行值保持一致；
- 保存后不会改变源行身份顺序或丢失不同喷嘴值。

### 14.3 编辑行为

- 修改一个喷嘴不会覆盖其他喷嘴组合；
- 修改一个可见组合会同步其对应的全部物理源行；
- 每个子控件可以独立恢复和显示 Dirty，恢复当前组合时其他组合不变；
- 恢复值经过子控件规范化后再写入，同组全部源行均能正确恢复；
- 对象、零件和高度范围中的 `nil` 继续表示继承；
- 多对象数值不同时文本框显示空白，开关不同时显示半选；用户未编辑前不自动回写；
- 切换机器或喷嘴组合后没有残留旧控件和旧索引；
- 自定义打印机向导创建并保存工艺时，不再向线宽向量字段写入旧标量类型。

### 14.4 切片结果

- 自动和手动 `filament_map` 都能选择正确物理喷嘴参数；
- 不同喷嘴设置明显不同速度后，导出 G-code 的实际速度正确；
- 新确认的非速度独立参数也按物理喷嘴生效；
- 旧单值预设切片结果与升级前一致；
- 保存并重新打开 3MF 后参数语义不变。

## 16. 最终建议

本方案建议正式采用，核心原则可以概括为：

```text
页面没有喷嘴页签
参数自己说明范围

一个控件就是共享
多个控件就是独立

配置按完整身份保存
切片按物理喷嘴取值
```

最新配置文件已经开始表达更多喷嘴差异，这进一步证明“独立能力不应绑定速度页面”。

源码已经按上述契约完成改造；配置参数包更新时仍不能把 JSON 数组直接等同于喷嘴独立，也不能把不同数组值静默压成单值。确认后的独立参数，无论位于质量、速度还是强度页面，都统一使用内联多喷嘴控件；确认后的共享参数始终保持一个原生控件。

这样既能让用户一眼理解参数范围，也能保证配置文件、对象覆盖和最终切片结果保持一致。

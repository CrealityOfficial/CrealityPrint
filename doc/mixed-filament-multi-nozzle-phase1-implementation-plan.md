# 混色耗材多喷嘴口径兼容——阶段 1 实施方案

> 适用分支：`feature/f039_group`
>
> 参考实现：`F:\gerrit\_code\bambu-260506\BambuStudio-02.06.00.51`
>
> 文档状态：阶段 1 代码已实施，待编译和场景验证

## 1. 文档定位

本文只说明混色耗材接入多物理喷嘴、不同喷嘴口径后的第一阶段实施方案。

阶段 1 解决两个问题：

1. 当前打印盘使用混色时，判断实际参与打印的喷嘴口径是否一致。
2. 混色虚拟耗材没有真实喷嘴时，保证前期依赖喷嘴直径的几何计算读取正确口径。

本文不实现新的混色模式，不修改当前整层混色算法，也不实现 Bambu 的子层混色。

为了便于记忆，阶段 1 的主流程统一概括为：

> **先展开、再映射、后比较；当前盘使用混色且实际口径不止一种，就停止切片。**

## 2. 最终结论

阶段 1 可以独立实施和交付，产品规则与切片链路已经闭环。

判断条件不是“机型存在多个喷嘴口径就禁止混色”，而是：

```text
当前 Plate 实际使用了混色耗材
并且
当前 Plate 实际使用的物理喷嘴包含多个不同口径
    -> 提示不支持混色并停止切片
```

其余情况保持原有行为：

- 机型安装了 `0.2/0.4` 喷嘴，但当前盘实际全部使用 `0.4`：允许。
- 混色组分分别落到 `0.2/0.4`：禁止。
- 混色组分全部落到 `0.4`，但同盘普通耗材落到 `0.2`：禁止。
- 当前盘没有使用混色：不增加新的限制。
- 不同 Plate 分别使用不同口径：逐盘判断，不把所有盘合并。
- 同一口径的多个物理喷嘴：允许，判断的是口径种类，不是喷嘴数量。

### 2.1 本轮职责边界

| 分类 | 本轮处理 |
| --- | --- |
| 必须完成 | 有效混色配方展开、基础耗材映射、按 Plate 比较实际口径、GUI 提示、后端兜底、同口径时补齐几何口径查询 |
| 直接复用 | 混色配方创建、编辑、删除、禁用、物理耗材删除后的配方调整、模型引用重映射、现有整层混色和 G-code 生成 |

## 3. 四个基本概念

### 3.1 逻辑耗材

项目和模型选择的耗材编号，例如 `F1`、`F2`、`F3`。

逻辑耗材需要经过 `filament_map`，才能确定最终使用哪个物理喷嘴。

### 3.2 物理基础耗材

真实存在的耗材，例如混色配方中的黑色、橙色、蓝色耗材。

这些耗材可以映射到具体物理喷嘴。

### 3.3 混色虚拟耗材

混色虚拟耗材只是一个配方，不是真实耗材，也没有自己的物理喷嘴。

例如：

```text
F5 = F1 33% + F2 33% + F3 34%
```

切片时，F5 会按照当前整层混色规则，在不同层解析成 F1、F2 或 F3。

### 3.4 物理喷嘴与喷嘴口径

`filament_map` 决定基础耗材最终落到哪个物理喷嘴，物理喷嘴再提供真实的喷嘴口径。

完整关系是：

```text
基础耗材 Fn
  -> filament_map
  -> 物理喷嘴 Pn
  -> nozzle_diameter[Pn]
```

阶段 1 必须比较这条链路最终得到的喷嘴口径，不能直接比较逻辑耗材编号。

## 4. 为什么不能只增加一个提示

只增加界面提示，只能回答“是否允许切片”，不能保证“切片按哪个喷嘴口径计算”。

例如：

| 耗材 | 用途 | 映射结果 |
| --- | --- | --- |
| F1 | 当前盘未使用的普通耗材 | 0.2 mm 喷嘴 |
| F2 | 混色组分 A | 0.4 mm 喷嘴 |
| F3 | 混色组分 B | 0.4 mm 喷嘴 |
| F5 | 虚拟混色 F2 + F3 | 没有真实喷嘴 |

阶段 1 的口径检查会发现 F2、F3 都使用 `0.4 mm`，因此应当允许切片。

但是在自动线宽、层高约束和挤出截面等前期几何计算中，混色还没有按具体层解析，代码可能直接查询“F5 使用多大喷嘴”。F5 没有真实喷嘴，如果直接把 F5 当成物理耗材下标，可能越界并回退到第一项，错误读取 F1 的 `0.2 mm`。

最终会形成不一致：

```text
模型路径按 0.2 mm 计算
实际 G-code 按 F2/F3 对应的 0.4 mm 喷嘴打印
```

因此阶段 1 必须同时解决：

1. 混色使用不同口径时禁止切片。
2. 混色使用同一口径时，前期几何计算读取该口径。

## 5. 阶段 1 完整流程

### 5.1 第一步：按 Plate 收集实际使用的逻辑耗材

收集当前打印盘真正参与打印的耗材，包括：

- 模型、零件和区域使用的耗材。
- 高度范围修改器使用的耗材。
- 外墙、填充等角色耗材。
- 支撑和支撑界面耗材。
- 其他已经进入当前盘切片输入的耗材引用。

只创建了混色配方但当前盘没有使用，不算“使用了混色”。

“切片当前盘”只检查当前盘；“切片所有盘”依次检查每个 Plate，不能把不同盘的耗材和口径合并成一个集合。

### 5.2 第二步：展开混色虚拟耗材

普通耗材保持原编号。

混色虚拟耗材展开成它真正可能使用的物理基础耗材。例如：

```text
当前盘使用：F4、F5
F5 配方：F1 33% + F2 33% + F3 34%

展开结果：F1、F2、F3、F4
并记录：当前盘使用了混色
```

混色展开规则由一个公共接口统一提供。本阶段新增的 GUI 检查、映射服务和切片后端校验必须使用同一结果；现有预览和统计代码只有在直接影响本阶段映射结果时才调整，不为统一形式做额外重构。

### 5.3 第三步：应用最终耗材映射

把展开后的物理基础耗材通过最终 `filament_map` 映射到物理喷嘴：

```text
F1 -> P2
F2 -> P2
F3 -> P4
F4 -> P4
```

自动映射使用自动计算完成后的最终结果；手动映射使用用户确认的完整结果。

用户可编辑和项目持久化的映射只描述真实基础耗材，不给混色虚拟耗材增加独立的映射行。

### 5.4 第四步：得到实际喷嘴口径集合

读取映射后物理喷嘴的真实口径并去重：

```text
P2 = 0.4 mm
P4 = 0.4 mm

实际口径集合 = {0.4}
```

如果结果是 `{0.4}`，说明虽然使用了多个物理喷嘴，但口径一致。

如果结果是 `{0.2, 0.4}`，说明当前盘实际使用了不同口径。

### 5.5 第五步：执行产品限制

统一判断规则：

```text
没有使用混色
    -> 不增加新的限制

使用了混色，实际口径集合只有一种
    -> 允许切片

使用了混色，实际口径集合超过一种
    -> 提示不支持混色并停止切片
```

提示应直接说明原因，例如：

> 当前打印盘使用了混色耗材，且实际使用了不同口径的喷嘴，暂不支持切片。请将本盘所有耗材映射到相同口径的喷嘴后重试。

### 5.6 第六步：建立运行时几何喷嘴代理

对于已经通过口径检查的混色虚拟耗材，在切片运行时为它提供一个仅用于喷嘴几何查询的代表口径。

例如 F5 的有效组分 F2、F3 都使用 `0.4 mm`，则前期查询 F5 的喷嘴口径时返回 `0.4 mm`。

代理必须满足以下限制：

- 只在本次切片运行时存在。
- 不显示为用户可编辑的混色映射行。
- 不写入项目持久化的物理耗材映射。
- 不把虚拟耗材输出为最终 G-code 工具号。
- 不代替每层真实的 F2/F3 解析结果。
- 不使用代理读取最终温度、颜色、材料类型、回抽或换刀参数。

由于进入该步骤前已经确认当前盘实际口径只有一种，所以选取任一有效混色组分作为几何口径代表，得到的喷嘴直径都相同。

“运行时几何喷嘴代理”描述的是结果要求，不限定必须新增某个配置项。实现时可以使用专用查询函数或等价的运行时派生数据，但不能把代理写成用户可编辑、可持久化的虚拟 `filament_map`。

#### 5.6.1 推荐的最小实现

结合当前 `get_physical_nozzle_diameter()` 通过 `filament_map` 查询喷嘴的结构，推荐在 `Print::resolve_filament_mapping()` 中同时维护两份含义明确的数据：

```text
physical_effective_map
    = 用户确认或自动生成的基础耗材映射
    = 用于项目保存、G-code 映射信息和用户再次编辑

runtime_effective_map
    = physical_effective_map
    + 本次切片实际使用的混色虚拟耗材代理项
    = 只供切片运行时的喷嘴查询
```

具体步骤：

1. 展开当前 Plate 使用的混色虚拟耗材，得到每个虚拟耗材的有效基础组分。
2. 使用 `physical_effective_map` 把所有实际基础耗材映射到物理喷嘴。
3. 比较实际喷嘴口径；存在多个口径时直接报错，不生成代理。
4. 口径只有一种时，为每个实际使用的虚拟耗材选择一个有效组分，把该组分的物理喷嘴编号写入 `runtime_effective_map` 对应的虚拟位置。
5. 切片期 `get_physical_nozzle_diameter(config, F5)` 通过运行时映射返回共同口径，不再越界回退到第一喷嘴。
6. `ToolOrdering` 按层把 F5 解析为 F2/F3 后，换刀和 G-code 继续使用基础耗材的真实映射。

例如：

```text
physical_effective_map：F1 -> P1，F2 -> P2，F3 -> P3，F4 -> P4
F5 = F2 + F3
P2、P3 都是 0.4 mm

runtime_effective_map：
F1 -> P1
F2 -> P2
F3 -> P3
F4 -> P4
F5 -> P2    # 也可以选择 P3，几何口径都是 0.4 mm
```

实现约束：

- 虚拟代理只补在运行时映射中，不能出现在耗材分组窗口。
- 项目配置、手动映射和自动映射的有效输入仍然只使用 `physical_effective_map`。
- 保存项目或输出供恢复使用的映射信息时，只写基础耗材部分，不能把运行时虚拟尾项当成用户映射。
- `filament_map_2`、`filament_volume_map` 等派生数据必须区分运行时用途和持久化用途，不能因为补充虚拟尾项改变原有对外语义。
- 本次实际实现只有 `m_config.filament_map` 增加运行时虚拟尾项；`filament_map_2` 和 `filament_volume_map` 继续保持物理基础耗材长度，因为现有喷嘴几何查询不需要它们的虚拟代理。
- 最终材料温度、颜色、流量比例、最大体积流量、回抽和换刀参数仍由逐层解析后的 F2/F3 决定，不能直接读取 F5 的代理项。
- 如果代码审计发现某个非喷嘴直径参数在逐层解析前直接使用虚拟编号，不得借用几何代理扩展其语义；记录为既有混色链路问题，按本阶段实际阻塞程度决定最小修正或留待后续。

### 5.7 第七步：继续使用原整层混色

完成映射和口径处理后，现有整层混色流程保持不变：

```text
F5
  -> 根据当前层号和配方选择一个基础耗材
  -> F1/F2/F3
  -> 对应物理喷嘴
  -> 生成正常换刀和 G-code
```

阶段 1 不向最终 G-code 输出虚拟 `Tn`，也不在同一层内拆分多个子层。

## 6. 统一混色展开规则

公共展开接口需要覆盖以下情况：

1. 普通耗材：直接保留。
2. 双色比例混色：展开实际可能使用的 A、B 组分。
3. 三色及以上混色：展开权重大于零的组分。
4. 手动序列：只展开序列实际引用的组分。
5. 权重为零的组分：不计入当前盘实际使用耗材。
6. 重复引用：去重后返回。
7. 混色配方的删除、禁用、组分删除和模型引用重映射：复用现有混色模块的处理，本阶段不重新实现。
8. 如果旧项目或异常数据绕过现有处理进入统一展开接口：返回“无法解析混色配方”，不得把虚拟编号当成物理耗材，也不得回退到第一种耗材或第一喷嘴。
9. 超出物理耗材范围的组分编号：按异常输入终止本次映射，不在本阶段修复或重建混色配方。

公共结果至少需要表达三类信息：

```text
是否使用了混色
展开后的物理基础耗材集合
无效的混色虚拟耗材集合或错误原因
```

这样 GUI 与后端才能使用完全相同的判断标准。

这里的职责边界是：

- 混色模块负责配方的创建、编辑、删除、禁用、物理耗材删除后的组分调整，以及模型引用重映射。
- 阶段 1 不修改上述产品行为，也不负责修复损坏的混色项目。
- 阶段 1 只保证异常虚拟编号不会进入新的喷嘴映射和口径判断，更不能被误认为第一喷嘴。

## 7. GUI 与后端的双重保护

### 7.1 GUI 提前提示

GUI 的作用是让用户尽早发现问题并调整映射。

自动映射流程：

```text
完成当前 Plate 的自动映射
  -> 展开实际耗材
  -> 检查最终喷嘴口径
  -> 通过后进入切片
```

手动映射流程：

```text
用户确认映射
  -> 检查当前选择是否完整
  -> 检查混色实际喷嘴口径
  -> 不通过时保留映射窗口，允许用户继续调整
```

不同口径的混色错误应优先于普通层高不兼容错误显示，避免用户只看到间接的层高提示。

### 7.2 切片后端兜底

不能只依赖 GUI，因为以下入口可能绕过界面检查：

- 打开旧 3MF 后直接切片。
- 导入 Bambu 3MF。
- 命令行切片。
- 后续增加的其他切片入口。
- GUI 状态与切片配置不同步。

因此 `Print::resolve_filament_mapping()` 或等价切片入口必须执行同一套展开、映射和口径检查。

建议错误顺序为：

1. 统一展开接口无法解析混色虚拟编号；这里只做异常兜底，不负责修复配方。
2. 耗材映射缺失、不完整或越界。
3. 混色任务实际使用了不同喷嘴口径。
4. 普通喷嘴层高或工艺兼容性错误。

## 8. 可变层高行为

阶段 1 不禁止可变层高，也不改变当前混色比例算法。

当前界面使用的整层混色按照层号分配耗材，而不是按照实际打印高度或挤出体积累计比例。

例如 50% A + 50% B，实际层高依次为：

```text
0.10、0.30、0.10、0.30 mm
```

现有混色仍可能按照以下顺序打印：

```text
A、B、A、B
```

按层数是 50:50，但按打印厚度约为：

```text
A = 0.20 mm
B = 0.60 mm
```

因此阶段 1 上线后的定义是：

- 可变层高可以正常切片和使用整层混色。
- 喷嘴口径判断仍按当前 Plate 的实际映射执行。
- 混色比例继续保持原有的按层数近似。
- 不承诺可变层高下材料厚度或体积比例精确等于配置比例。

按实际层高累计配方误差属于后续优化，不属于阶段 1。

## 9. 数据与兼容规则

### 9.1 保留现有混色数据格式

继续使用当前项目的 `mixed_filament_definitions`，不替换成 Bambu 的混色数组格式。

Bambu 3MF 导入后，仍然先转换为当前混色定义，再进入统一展开流程。

### 9.2 保留物理映射语义

- `filament_map` 继续表示逻辑基础耗材到物理喷嘴的一基映射。
- `filament_map_2` 继续是 `filament_map` 的零基派生结果。
- 混色虚拟耗材不作为独立物理耗材要求用户映射。
- 旧项目中如果映射尾部包含虚拟耗材项，只使用和规范化有效的物理基础耗材部分。

### 9.3 保留当前 G-code 语义

- 最终 G-code 只使用已经解析后的基础耗材工具号。
- 不输出混色虚拟工具号。
- 不修改现有换刀、冲刷和擦拭塔协议。
- 阶段 1 只保证混色任务进入这些流程前，物理耗材和喷嘴口径已经正确解析。

## 10. 参考 Bambu 的范围

本阶段参考 Bambu 的核心思路是：

- 混色虚拟耗材先统一展开为基础耗材。
- 本阶段的 GUI 口径检查、映射服务和切片后端使用同一份展开结果。
- 默认整层混色仍然是一层选择一种基础耗材。

本阶段不移植：

- `MixedSubLayerGroup`。
- 同一模型层拆分多个 Z 子层。
- 子层流量、路径和 G-code 重放。
- Bambu 的完整子层混色 UI。
- 按实际层高累计比例的算法。

### 11.1 本次采用的优化方案

复用已有的映射查询链路：

```text
m_full_print_config.filament_map
    = 仅包含物理基础耗材
    = 用于保存、G-code 配置块和外部消费

m_config.filament_map
    = 物理基础耗材映射 + 本次使用的混色虚拟代理
    = 仅用于当前 Print 的切片运行时查询
```

用户和 G-code 看不到虚拟映射，切片前期仍能通过现有 `get_physical_nozzle_diameter()` 取得正确口径。再次应用同一项目配置时，只比较运行时映射的物理前缀，不把虚拟尾项误判成用户修改。

## 12. 实际实施顺序

### 第一步：建立统一展开接口

已完成普通耗材、双色、三色及以上、手动序列和零权重组分的统一展开。异常配方只返回无法解析，不在本阶段修复，也不会把已经解析出的部分组分带入后续映射。

### 第二步：修正映射输入

GUI 和后端映射只接收展开后的物理基础耗材，不再把混色虚拟耗材当成独立可映射耗材。普通物理耗材仍沿用原有映射行为。

### 第三步：实现按 Plate 的 GUI 检查

已接入自动映射、手动映射、切片当前盘和切片所有盘入口。切片所有盘复用同一最终映射，但对每个 Plate 单独收集口径集合。手动映射确认时先检查混色异径，再检查普通层高兼容性，优先显示本需求的直接原因。

### 第四步：实现后端硬校验

`Print::resolve_filament_mapping()` 已按同一规则增加后端硬校验，保证绕过 GUI 的切片入口仍会停止；旧 3MF、Bambu 3MF 和命令行场景仍需实际验证。

### 第五步：补齐运行时几何喷嘴代理

`m_config` 已补充仅限本次 Print 的虚拟代理，允许切片的混色虚拟耗材可通过现有映射查询读取共同口径；建立代理后立即刷新对象 `SlicingParameters`，再进入实际切片，避免首轮参数仍沿用代理建立前的喷嘴口径。`m_full_print_config` 继续只保留物理基础映射。

### 第六步：检查本阶段直接依赖

已把 `Print`、`PrintApply` 和映射服务中直接影响本阶段的重复解析替换为统一接口，并修正显式混色支撑编号的可接受范围；未重构预览和其他混色功能。

## 14. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| GUI 与后端分别解析混色，结果不一致 | 统一使用 `MixedFilamentManager` 的公共展开接口 |
| 把未使用的混色定义当成当前盘已使用 | 只从当前 Plate 的实际耗材引用触发 `has_mixed` |
| 把不同 Plate 的口径合并后误报 | 每个 Plate 独立收集、映射和检查 |
| 零权重组分造成误拦截 | 展开时忽略权重为零且序列未引用的组分 |
| 虚拟耗材被当成独立映射项 | 用户映射只处理物理基础耗材 |
| 虚拟耗材查询喷嘴时回退到第一喷嘴 | 增加仅用于几何查询的运行时代理 |
| 代理污染最终工具号或材料参数 | 限定代理只服务喷嘴几何查询，最终 G-code 仍使用逐层解析后的基础耗材 |
| 只依赖 GUI，旧项目或命令行绕过检查 | 在切片后端增加同一规则的硬校验 |
| 修改混色比例算法扩大需求 | 阶段 1 保持当前整层、按层数混色行为 |

## 15. 回退原则

阶段 1 应保持模块化，出现问题时可以分别回退：

1. GUI 提前提示。
2. 后端不同口径硬校验。
3. 混色统一展开接口的调用替换。
4. 运行时几何喷嘴代理。

回退时不得改变已有 `mixed_filament_definitions`，不得清除用户项目中的混色配方，也不得覆盖工作区其他多喷嘴改动。

## 16. 阶段 1 完成标准

同时满足以下条件后，才认为阶段 1 真正闭环：

1. 是否使用混色由当前 Plate 的实际耗材引用决定。
2. 混色虚拟耗材能够稳定展开为真实基础耗材。
3. 自动和手动映射都使用展开后的基础耗材。
4. 实际喷嘴口径在最终映射之后判断。
5. 当前盘使用混色且实际口径超过一种时，GUI 和后端都能阻止切片。
6. 当前盘实际口径只有一种时，混色虚拟耗材的前期几何计算读取该正确口径。
7. 最终 G-code 只使用逐层解析后的基础耗材，不输出虚拟工具号。
8. 可变层高继续沿用当前按层数比例的整层混色，不增加新的禁用条件。
9. 普通非混色多口径项目保持原有行为。
10. 当前盘、所有盘、旧 3MF 和 Bambu 3MF 的结果一致。

阶段 1 完成后的数据链可以概括为：

```text
当前 Plate 的逻辑耗材
  -> 展开混色虚拟耗材
  -> 物理基础耗材
  -> filament_map
  -> 物理喷嘴及口径
  -> 混色异径校验
  -> 同口径时建立几何代理
  -> 现有整层混色解析
  -> 擦拭塔、换刀和 G-code
```

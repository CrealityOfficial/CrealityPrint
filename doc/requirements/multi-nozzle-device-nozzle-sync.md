# 多喷嘴设备喷嘴信息同步需求说明

## 1. 基本信息

- 需求名称：多喷嘴设备喷嘴信息同步
- 适用模块：打印机选择模块
- 适用范围：具有多个物理喷嘴的打印机
- 文档版本：V1.0
- 最终口径：以本文为准

## 2. 背景与目标

多喷嘴打印机在设备端已经保存各物理喷嘴的直径和流量类型，但切片端仍需要用户逐个选择喷嘴配置。

本需求在“喷嘴口径”区域增加“同步信息”入口。用户点击后，从当前实际绑定的设备请求最新 `nozzleList`，读取各喷嘴的 `diameter` 和 `flow`，并一次性同步到切片端的喷嘴选项。

## 3. 界面要求

### 3.1 显示范围

- 仅多喷嘴打印机显示“同步信息”按钮。
- 单喷嘴打印机保持原有喷嘴口径交互，不显示该同步入口。
- “同步信息”位于“喷嘴口径”标题右侧。

### 3.2 布局与视觉

- “热床类型”和“喷嘴口径”区域之间需要保留明显的纵向间隔。
- “喷嘴口径”标题行和下面的喷嘴选项之间需要保留纵向间隔。
- 同步图标应小于普通工具栏图标，当前视觉尺寸按约 `14 × scale` 设计。
- 图标与“同步信息”文字之间保留适当间距。
- 按钮实际响应区域必须覆盖图标、文字及四周留白，不能只以图标大小作为点击或悬停区域。
- 鼠标移入按钮响应区域时，整个响应区域显示悬停高亮边框。
- 悬停效果不作为设备已绑定的判断依据。

### 3.3 绑定状态

只有同时满足以下条件，才认定当前打印机已实际绑定设备：

1. 当前打印机预设能够解析出绑定设备的 MAC；
2. 设备数据中心存在有效的当前设备；
3. 当前设备地址非空；
4. 当前设备 MAC 与预设绑定的 MAC 完全一致。

状态表现：

- 已实际绑定：“同步信息”文字显示为绿色。
- 未绑定或绑定设备与当前设备不一致：文字使用普通灰色，不得显示为绿色。
- 预设缓存中存在机型关联，但当前设备无效、未连接或 MAC 不一致时，不得仅凭缓存将按钮显示为绿色。

系统预设和用户预设仍按现有规则解析绑定 MAC：

- 系统预设：从 `system_preset_bundle_deivce` 中按机型及喷嘴配置键读取。
- 用户预设：从 `printer_select_mac` 读取。

以上信息只用于找到候选绑定 MAC，最终仍须通过当前设备有效性和 MAC 一致性校验。

## 4. 点击与请求行为

### 4.1 已绑定设备

点击“同步信息”后：

1. 生成本次请求的唯一 `request_id`；
2. 记录发起请求时的设备 MAC；
3. 向设备管理社区页面发送 `request_nozzle_list` 命令；
4. 等待设备列表数据更新；
5. 只处理设备 MAC 和 `request_id` 均与本次请求一致的结果。

请求示例：

```json
{
  "command": "request_nozzle_list",
  "data": {
    "device_id": "设备 MAC",
    "request_id": 1
  }
}
```

### 4.2 未绑定设备

- 点击不得发送喷嘴信息请求。
- 不得改变当前喷嘴选项。
- 不需要弹出提示。

### 4.3 交互反馈

- 同步成功不弹出明确提示。
- 请求失败、返回数据不完整或无法匹配本地喷嘴选项时，不弹出失败原因。
- 失败时保持同步前的喷嘴配置，不允许只更新其中一部分喷嘴。

## 5. 社区端数据获取

社区端接收 `request_nozzle_list` 后，应先定位命令指定的设备，再按设备类型请求喷嘴列表：

- 云设备：调用 `getNozzleList(printer.tbId)`，读取 `response.result.nozzleList`。
- 局域网设备：调用 `DeviceInterface.ReqMultiNozzle(printer.address)`。

为避免旧缓存被误认为新响应，发起新请求时应：

1. 清除该设备原有的 `nozzleList`；
2. 写入本次 `nozzleSyncRequestId`；
3. 将状态回传给 C++ 端；
4. 获取新数据后再次回传设备状态。

社区端源代码归属：

```text
D:\CrealityCommunity\CrealityCommunity\DMgr\src\App.vue
```

该逻辑应在社区仓库提交。C3Slicer 中 `resources/web/deviceMgr/assets/*.js` 属于社区项目构建产物，不应作为社区源代码的替代品手工长期维护；是否随 C3Slicer 提交构建产物，按项目现有打包流程执行。

## 6. 返回数据与解析规则

设备返回数据结构示例：

```json
{
  "nozzleList": {
    "nozzles": [
      { "id": 1, "flow": 0, "texture": 0, "diameter": 0.4 },
      { "id": 2, "flow": 0, "texture": 0, "diameter": 0.2 },
      { "id": 3, "flow": 0, "texture": 0, "diameter": 0.6 },
      { "id": 4, "flow": 0, "texture": 0, "diameter": 0.8 }
    ]
  }
}
```

本需求只读取以下字段：

- `diameter`：喷嘴直径；
- `flow`：喷嘴流量类型。

`id` 和 `texture` 不参与本次本地喷嘴选项匹配。`nozzles` 数组顺序与物理喷嘴顺序一一对应。

流量类型映射：

| 设备 `flow` | 本地喷嘴类型 |
| --- | --- |
| `1` | `High Flow` |
| 其他值 | `Standard` |

每个物理喷嘴使用“直径 + 流量类型”共同匹配本地 `NozzleVariantInfo`。设备返回的喷嘴数量必须至少覆盖当前打印机的物理喷嘴数量，并且所有物理喷嘴都必须找到对应的本地选项，才允许执行同步。

## 7. 同步后的处理

同步采用批量、全量更新：

1. 先完成所有物理喷嘴的本地选项匹配；
2. 任一喷嘴无法匹配时，全部保持原值；
3. 全部匹配后，一次性更新项目配置中的 `variant_index` 和 `variant_id`；
4. 刷新工艺、耗材和打印机喷嘴相关界面；
5. 将当前切片结果标记为需要重新切片，并调度后台处理。

如果设备返回值与当前选择完全一致，则不需要重复刷新和重切片。

## 8. 共同层高范围限制

- 同步喷嘴配置时，不再执行“所选喷嘴组合不存在共同层高范围”的限制。
- 不再弹出“共同层高范围限制”警告框，也不因此恢复之前的喷嘴配置。
- 该弹窗判断和相关格式化辅助函数不得删除，应使用 `#if 0 ... #endif` 整体注释保留。
- 后续若重新启用该限制，只需移除条件编译，不需要重新编写弹窗逻辑。

## 9. 异常处理

以下情况均静默结束，并保持同步前的喷嘴配置：

- 当前未实际绑定设备；
- 请求设备与当前绑定设备不一致；
- 响应 `request_id` 与当前请求不一致；
- 缺少 `nozzleList.nozzles`；
- 喷嘴数量不足；
- `diameter` 或 `flow` 缺失、类型错误；
- 任一“直径 + 流量类型”无法匹配本地喷嘴选项；
- 页面、设备数据中心或打印机侧请求接口不可用。

异常可以写入内部日志，但不得向用户弹出成功提示、失败提示或失败原因。

## 10. 验收标准

| 场景 | 预期结果 |
| --- | --- |
| 单喷嘴打印机 | 不显示“同步信息”按钮 |
| 多喷嘴打印机，当前设备真实绑定且 MAC 一致 | “同步信息”文字为绿色 |
| 多喷嘴打印机，只有预设缓存关联但当前设备无效 | 文字为灰色，点击不发请求 |
| 多喷嘴打印机，当前设备 MAC 与预设绑定 MAC 不一致 | 文字为灰色，点击不发请求 |
| 鼠标悬停按钮 | 图标、文字及留白组成的完整响应区域显示高亮边框 |
| 已绑定设备点击同步 | 请求当前绑定设备的最新 `nozzleList` |
| 返回 4 个有效喷嘴数据 | 按顺序及“直径 + 流量类型”同步 4 个喷嘴选项 |
| 任一喷嘴数据无效或无匹配项 | 所有喷嘴保持同步前状态，无弹窗 |
| 返回旧请求的数据 | 不处理，不覆盖当前喷嘴配置 |
| 同步结果与当前配置一致 | 配置不变，不重复触发刷新和重切片 |
| 同步后的组合没有共同层高范围 | 不显示共同层高限制弹窗，仍允许同步 |

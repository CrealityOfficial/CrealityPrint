# AI Chat 交互规范

本文档定义 AI 助手在切片流程中的动作分级与文案模板，目标是统一前后端在“自动执行 / 确认执行 / 仅提示”上的行为，减少越权感与打断感。

## 设计原则

1. 目标优先  
当用户表达明确目标，如“开始打印”“开始切片”“发送到打印机”，系统可以自动补齐必要步骤。

2. 副作用分级  
会直接修改场景、配置、设备状态的动作，按风险分级决定是自动执行、确认执行，还是仅提示。

3. 用户意图可解释  
每次自动执行都要说明“为什么做”和“下一步是什么”。

4. 状态与对话分层  
聊天区负责解释、建议、任务进展。场景告警/修复入口尽量由通知区或操作卡片承载。

## 动作分级表

| 动作 | 默认级别 | 触发条件 | 说明 | UI 表现 |
|---|---|---|---|---|
| `get_slicer_state` | `AUTO` | 任意 | 纯读取，无副作用 | 不出确认按钮 |
| `get_presets` / `get_edited_config` / `get_config_options` | `AUTO` | 任意 | 纯读取 | 直接返回结果 |
| `import_model(path)` | `AUTO` | 用户提供明确文件路径 | 用户意图明确，副作用可预期 | 显示“正在导入” |
| `open_model_library` | `CONFIRM` | 无本地模型且需用户选模型 | 需要用户参与选择 | 按钮触发 |
| `auto_arrange` | `AUTO` | 为完成“切片 / 打印 / 发送到打印机”的阻塞补救 | 属于主目标前置修复 | 直接执行并提示 |
| `auto_arrange` | `CONFIRM` | 用户手动操作导致越界 / 重叠 | 不应替用户擅自改布局 | 显示“自动摆放”按钮 |
| `auto_arrange` | `CONFIRM` | 用户单独提出“重新摆放 / 自动摆放” | 独立编辑动作 | 显示按钮 |
| `open_filament_mapping` | `CONFIRM` | 缺少映射且阻塞主流程 | 需要用户完成选择 / 确认 | 按钮触发 |
| `apply_preset` | `CONFIRM` | 修改当前打印 / 耗材 / 打印机预设 | 会改配置 | 按钮触发 |
| `apply_param_patch` / `apply_config` | `CONFIRM` | 改打印参数 | 会改配置 | 按钮触发 |
| `auto_orient_model` | `CONFIRM` | 独立编辑请求或推荐优化 | 会改模型姿态 | 按钮触发 |
| `move_model` / `rotate_model` / `scale_model` | `CONFIRM` | 任意 | 明显场景编辑 | 按钮触发 |
| `delete_model` | `CONFIRM` | 任意 | 破坏性操作 | 强确认 |
| `clone_model` / `fill_bed` | `CONFIRM` | 任意 | 会显著改场景 | 按钮触发 |
| `run_slice` | `CONFIRM` | 用户请求切片 | 高成本动作 | 按钮触发 |
| `send_to_printer` | `CONFIRM` | 用户请求打印 | 设备侧动作，高风险 | 按钮触发 |
| `export_gcode` | `CONFIRM` | 用户请求导出 | 产出文件 | 按钮触发 |
| 支撑 / 擦拭塔 / 参数建议 | `INFORM` | 非阻塞优化建议 | 只提醒，不直接做 | 纯提示卡片 |

## 补充判定规则

- `AUTO`：为完成明确主目标的必要低风险补救。
- `CONFIRM`：独立编辑动作、明显改场景 / 配置 / 设备状态的动作。
- `INFORM`：非阻塞建议，只提示。

## 文案模板表

### 1. AUTO：系统自动执行

适用：阻塞主任务的补救动作。

模板：

- `检测到{问题}，我先为你{动作}，再继续{目标}。`
- `为了继续{目标}，我已先执行{动作}。`
- `当前{问题}会阻塞{目标}，我先帮你处理。`

示例：

- `检测到模型超出打印区域，我先为你自动摆放，再继续切片。`
- `为了继续打印，我已先修正模型布局。`
- `当前缺少可打印布局，我先帮你自动摆放。`

按钮区：

- 不显示确认按钮
- 可显示状态：`执行中` / `已完成`

### 2. CONFIRM：需要用户确认

适用：独立编辑动作，或用户手动造成的异常修复。

模板：

- `检测到{问题}，建议执行{动作}。`
- `当前可以通过{动作}来解决{问题}。`
- `这会修改当前{对象}，点击后执行。`

示例：

- `检测到模型超出打印区域，建议自动摆放。`
- `当前模型布局异常，可以通过自动摆放来修复。`
- `这会修改当前布局，点击后执行自动摆放。`

按钮文案建议：

- `自动摆放`
- `完成耗材映射`
- `应用推荐参数`
- `开始切片`
- `发送到打印机`

### 3. INFORM：仅提示

适用：非阻塞建议。

模板：

- `检测到{现象}，建议{动作}。`
- `当前{现象}可能影响{结果}，建议{动作}。`
- `可以考虑{动作}来优化{结果}。`

示例：

- `检测到悬空区域较多，建议开启支撑。`
- `当前模型间距较近，建议重新排布以降低碰撞风险。`
- `当前参数可继续切片，但建议开启擦拭塔以提升多色打印稳定性。`

## 卡片字段文案建议

- 标题
  - `AUTO`：`正在处理`
  - `CONFIRM`：`建议操作`
  - `INFORM`：`优化建议`

- 原因标题
  - 统一用 `原因`

- 动作标题
  - 统一用 `下一步`

- 状态文案
  - `正在自动摆放模型，请等待结果。`
  - `正在准备切片，请稍候。`
  - `等待你确认后执行。`

## 推荐的具体按钮映射

- `auto_arrange` -> `自动摆放`
- `open_filament_mapping` -> `完成耗材映射`
- `apply_preset` -> `应用预设`
- `apply_param_patch` -> `应用参数`
- `run_slice` -> `开始切片`
- `send_to_printer` -> `发送到打印机`
- `open_model_library` -> `去模型库查找`

## 典型场景

1. 用户说“我想打印”  
检测到模型越界，`auto_arrange` 作为主目标补救动作，按 `AUTO` 处理，自动摆放后继续推进流程。

2. 用户说“帮我自动摆放一下”  
这是独立编辑请求，建议按 `CONFIRM` 处理，展示卡片与按钮。

3. 用户手动把模型拖到盘外  
系统发现异常，`auto_arrange` 按 `CONFIRM` 处理，不直接修改场景，只提示修复。

4. 用户给出路径“导入 C:\models\a.stl”  
`import_model(path)` 按 `AUTO` 处理。

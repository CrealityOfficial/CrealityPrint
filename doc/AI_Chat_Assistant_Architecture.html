1. 系统概述

AI切片助手是一个基于CxAgent的智能对话系统，采用MCP (Model Context Protocol) 架构，将大语言模型(LLM)的能力与3D切片软件深度集成。

核心特点：
  • 🔗 通过WebSocket与CxAgent服务端保持长连接
  • 🧠 CxAgent服务端运行LLM，理解用户意图并规划执行步骤
  • 🛠️ 支持多种工具调用：切片、排列、导入模型、参数调整等
  • 📊 实时同步切片器状态作为LLM上下文
  • 💬 SSE流式输出，逐字渲染AI回复

2. 整体架构

🔑 关键发现：双后端架构

代码中存在两套AI后端：

  • 主要 CxAgent - WebSocket长连接，服务端规划+工具调用
  • 备用 Dify - HTTP SSE流式，直接LLM对话（已禁用）

当前版本优先使用CxAgent，Dify作为历史遗留/备用方案。

3. 回应决策流程

当用户发送消息时，系统按以下优先级决策如何回应：

flowchart TB A[用户输入消息] --> B{本地命令匹配?} B -->|是| C[tryHandleLocalCommand] C --> C1{查看配置?} C1 -->|是| C2[直接调用get_edited_config] C1 -->|否| C3{设置颜色?} C3 -->|是| C4[直接调用set_object_color] C3 -->|否| D B -->|否| D{CxAgent已连接?} D -->|是| E[sendToCxAgentChat] E --> E1[WebSocket发送到CxAgent服务端] E1 --> E2[LLM分析意图] E2 --> E3[返回planner_update或tool_call] D -->|否| F{Dify配置可用?} F -->|是| G[sendToDify - SSE流式] G --> G1[HTTP POST到Dify API] G1 --> G2[解析ACTION块] F -->|否| H[显示错误: 未配置AI服务]

3.1 本地命令处理（无需AI）

某些简单命令直接在本地处理，不经过AI：

// chat.js - 本地命令匹配
function tryHandleLocalCommand(userMessage) {
    // 1. 查看配置类查询 - 直接调用C++获取
    if (isCurrentPrintConfigQuery(text)) {
        sendToSlicer('get_edited_config', {});
        return true;
    }
    
    // 2. 设置颜色 - 解析颜色值后直接执行
    if (shouldAutoSetColorAction(text)) {
        const color = inferColorValue(text); // 如"蓝色"->"blue"
        sendToSlicer('set_object_color', { color });
        return true;
    }
    
    return false; // 交给AI处理
}

3.2 CxAgent处理（主要路径）

大多数消息走CxAgent路径，由服务端LLM决策：

// chat.js - 发送到CxAgent
function sendMessage() {
    // 1. 先尝试本地处理
    if (tryHandleLocalCommand(text)) return;
    
    // 2. 主路径：发送到CxAgent
    sendToCxAgentChat(text)
        .catch((error) => {
            // CxAgent失败时显示错误
        });
}

// chat.dify-stream.js - Dify SSE流式处理
async function sendToDify(ctx, userMessage, files, extraInputs, opts) {
    // 判断后端类型
    const backend = resolveChatBackend(state.difyApiBase);
    // gateway模式 或 dify直连模式
    
    const response = await fetch(url, {
        method: 'POST',
        headers: { 'Authorization': 'Bearer ' + token },
        body: JSON.stringify({
            query: userMessage,
            response_mode: 'streaming',
            user: userId
        })
    });
    
    // 读取SSE流
    const reader = response.body.getReader();
    while (true) {
        const { done, value } = await reader.read();
        // 解析事件: message, agent_message, tool_call, message_end等
        switch (event.event) {
            case 'message':
            case 'agent_message':
                fullText += event.answer;
                renderMarkdown(fullText); // 逐字渲染
                break;
            case 'tool_call':
                dispatchToolCallAction(event.tool, event.tool_input);
                break;
            case 'message_end':
                dispatchParsedActionsFromText(fullText); // 解析[ACTION]块
                break;
        }
    }
}

8. 智能回应机制

智能回应的核心在于CxAgent服务端的LLM引擎，它基于以下信息做出智能决策：

8.1 上下文信息收集

客户端自动收集的上下文：
  • 📦 项目状态：是否有模型、当前预设、打印参数等
  • 📸 模型视图：自动截取ISO、正面、底面视图
  • ⚠️ 警告/错误：切片警告、模型越界等
  • 🖨️ 打印机状态：是否连接、是否空闲

8.2 LLM规划决策

当用户说"我要打印一个拉布拉"时，LLM的决策过程：

1
意图识别：用户想要打印一个拉布拉多犬模型
2
状态检查：检查Facts → project.has_model = false
3
规划输出：需要先获取模型 → 调用 open_model_library 工具
4
发送planner_update：
tool: open_model_library
reason_code: MODEL_LIBRARY_REQUESTED

8.3 工具调用执行

// MCPChatPanel.cpp - 执行工具调用
void MCPChatPanel::HandleCxAgentToolCall(const json& msg)
{
    const std::string tool = msg.value("tool", "");
    
    if (tool == "open_model_library") {
        // 打开模型库对话框
        auto* plater = wxGetApp().plater();
        plater->open_model_library(query);
        
        // 返回执行结果
        m_cxagent_bridge->SendToolResult(request_id, true, result);
    }
    
    if (tool == "run_slice") {
        // 开始切片
        Bridge::SlicerBridge::Instance().Execute(
            Bridge::ActionID::START_SLICE, args);
    }
}

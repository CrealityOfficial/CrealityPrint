# 创想云多喷头参数录入方案

## 1. 目标

在现有“编辑机型参数默认值”弹窗上做增量改造，使后台能够维护多挤出机机型的喷嘴变体，同时保持单挤出机机型和原有参数录入流程不变。

本方案覆盖：

- `0.2-Standard`、`0.4-Standard`、`0.6-Standard`、`0.8-Standard` 等现有变体。
- 后续追加 `0.2-HighFlow` 等同口径、不同流量类型的变体。
- 同一打印任务中，不同物理挤出机选择不同喷嘴变体。
- 新增变体后不迁移历史参数包和历史 3MF。

## 2. 核心结论

变体内的参数采用“受控的灵活配置”，不采用完全固定字段，也不允许录入任意未知 key。

参数分为三层：

1. 变体身份字段：固定，不作为普通参数增删。
2. 必填参数：由参数模板定义，必须全部存在，不能在机型页面移除。
3. 可选参数：可以按变体灵活添加，但只能从切片引擎支持的参数库中选择。

这样既能保证参数包完整，又能让未来新增喷嘴相关能力时不必重新设计页面。

## 3. 变体身份与稳定索引

每个变体至少包含以下固定信息：

- `variant_id`：稳定业务 ID，例如 `N02-STANDARD`、`N02-HIGH_FLOW`。
- `variant_index`：参数包内稳定索引，例如 `V0`、`V1`、`V4`。
- `nozzle_diameter`：喷嘴口径。
- `nozzle_volume_type`：流量类型，取值使用切片端已支持的标准枚举。
- `display_order`：只控制后台和客户端显示顺序，不参与数据定位。
- `status`：草稿、使用中或已停用。

约束如下：

- `variant_index` 只追加，不插入、不重排、不复用。
- 发布后的变体不物理删除；不再使用时只标记为停用。
- 修改 `display_order` 不得改变 `variant_index`。
- `variant_id` 和 `variant_index` 发布后均不可修改。
- 同一个 `variant_index` 只能对应一个“口径 + 流量类型”身份。

例如已有 `V0` 至 `V3` 时，新增 `0.2-HighFlow` 必须分配 `V4`，不能插入到 `0.2-Standard` 后面并重排旧索引。

## 4. 前端交互

### 4.1 保留现有弹窗

不新增独立的整页管理入口，继续使用现有“编辑机型参数默认值”弹窗。多挤出机机型额外显示“参数范围”区域：

- 机型通用参数：沿用原有录入方式。
- 喷头变体参数：显示变体选择、映射范围和变体参数。

单挤出机机型不显示这些扩展控件。

### 4.2 挤出机应用范围

默认选择“全部挤出机”。此时不要求用户选择物理挤出机，保存后将当前变体参数同步到 E1 至 E4，并明确显示映射：

```text
E1/V1、E2/V1、E3/V1、E4/V1
```

只有需要维护单个挤出机差异值时，才切换到“指定挤出机”。这样可以满足差异化能力，又不会让常规录入重复四次。

### 4.3 参数模板和参数库

变体参数区顶部显示：

- 当前参数模板。
- 必填参数完整度，例如“必填 3/3”。
- 已添加的可选参数数量。
- “从参数库添加”按钮。

参数行显示“必填”或“可选”：

- 必填参数不能移除。
- 可选参数可以移除。
- 新增可选参数时只展示与当前参数域匹配且切片引擎已支持的参数定义。
- 参数库支持按参数名称、key 或类型实时搜索，搜索只过滤候选列表，不改变已选状态。
- 页面不提供手工输入参数 key 的入口。

### 4.4 机型、工艺和耗材共用对话框

保留现有机型参数包列表作为统一入口。用户从同一参数包记录的“机型参数”“工艺参数”或“耗材参数”列点击“编辑”，分别打开对应的参数编辑弹窗；不在编辑弹窗内部增加机型、工艺、耗材切换器。

三个列表入口复用同一个参数编辑框架和“添加可选变体参数”组件。入口打开组件时传入 `preset_type`、当前预设、当前变体、引擎版本和已添加参数，对话框据此切换标题并过滤参数库：

- 机型只显示 `printer_variant` 参数。
- 工艺只显示 `process_variant` 参数。
- 耗材只显示 `filament_variant` 参数。

三类入口共用搜索、勾选、已添加状态和确认交互，但参数选择结果分别保存到各自的预设域，不能跨域混写。耗材变体在 E1 至 E4 之间共享，因此耗材入口不显示“指定物理挤出机”；机型和工艺入口保留“全部挤出机 / 指定挤出机”。关闭弹窗后返回原列表位置，用户需要编辑其他参数域时再从相应列表列进入。

### 4.5 变体管理

“管理变体”继续在当前编辑弹窗内打开二级界面。列表展示：

- 显示顺序。
- 变体名称。
- 稳定索引。
- 适用挤出机。
- 必填参数完整度和可选参数数量。
- 默认状态、发布状态和操作。

新增变体时录入喷嘴口径、流量类型和初始化来源。后台自动生成稳定 ID 和下一个稳定索引，并执行：

1. 从来源变体复制已有值。
2. 按当前模板补齐必填参数。
3. 保留来源变体已经选择的可选参数。
4. 将新变体保存为草稿。
5. 校验通过后才允许发布参数包。

## 5. 参数定义模型

后台需要维护统一的参数定义，机型页面只维护变体值。建议逻辑模型如下：

```text
参数定义
  key
  value_type
  scope                 # machine / nozzle_variant / filament_variant / process_variant
  required
  default_value
  supported_engine_version
  enabled

变体参数值
  machine_package_id
  variant_id
  physical_extruder_id  # 全部挤出机同步时由后台展开
  parameter_key
  value
```

参数定义是前端可选项的唯一来源。若要支持全新的参数 key，应先完成以下工作：

1. 切片引擎增加该参数的 `ConfigDef` 和序列化定义。
2. 将该参数加入正确的变体作用域集合。
3. 后台参数库登记 key、类型、作用域和默认值。
4. 生成脚本支持该参数的数组展开和长度校验。

仅在后台输入未知 key 不会让 C++ 自动支持该参数。

## 6. 参数包生成规则

机型元数据是变体定义的唯一来源。生成脚本按显式映射生成 printer、process 和 filament 数据，不能通过“挤出机数量 × 当前变体数量”的位置公式推导旧数据。

新增 `V4` 时采用尾部追加：

- machine 元数据追加 E1/V4、E2/V4、E3/V4、E4/V4。
- machine/extruder 的变体参数数组追加 4 行。
- 每个 process 的变体参数数组追加 4 行。
- 每个 filament 的变体参数数组追加 1 行。
- 对应 selector 数组和参数值数组必须同步追加，长度保持一致。

禁止重新生成成以下顺序：

```text
E1/V0...V4、E2/V0...V4、E3/V0...V4、E4/V0...V4
```

该顺序会移动历史数据的物理位置。正确做法是在现有所有行的末尾追加新映射。

`scripts/generate_creality_presets.py` 已按机型 `nozzle_variant_*` 元数据动态识别变体，不再把 K3 的变体数量固定为 4；显式元数据缺失时才使用旧 K3 兼容逻辑。

## 7. 发布、历史数据和迁移

- 已发布参数包不可原地修改，新增变体生成新的参数包版本。
- 历史参数包、历史 3MF 和旧客户端继续使用旧版本中的 V0 至 V3。
- 新版本追加 V4，不要求批量更新历史数据。
- 客户端优先按稳定 `variant_id` 定位，旧数据可回退到 `variant_index`。
- 停用变体保留原索引和数据，只是不再提供给新任务选择。

当前 `F039-0.4-0.4-0.4-0.4` 数据已经使用显式 selector 和稳定变体索引，若暂时不新增变体，不需要修改现有数据。未来新增 V4 时按本方案生成新版本即可。

## 8. C++ 影响

当前 C++ 已通过 selector 扫描匹配物理挤出机和变体，而不是使用动态变体数量计算扁平数组位置，因此采用只追加策略时不要求额外修改核心选择逻辑。

以下情况仍需要修改 C++：

- 新增一个当前 `ConfigDef` 不认识的参数 key。
- 已有参数原本不是变体作用域，需要改为按变体选择。
- 新增客户端尚不支持的 `nozzle_volume_type` 枚举。

建议补充数据加载校验：重复稳定 ID、重复索引、selector/value 长度不一致、引用不存在的变体时阻止加载或发布。

## 9. 验收标准

- 单挤出机机型的原有弹窗和生成结果不变。
- 多挤出机机型可在同一弹窗切换机型通用参数和喷头变体参数。
- 默认一次编辑可同步 E1 至 E4；指定挤出机模式可保存差异值。
- 必填参数不能移除，缺失时不能发布。
- 可选参数只能从受支持参数库添加，并可从当前变体移除。
- 新增 `0.2-HighFlow` 得到 V4，V0 至 V3 不变。
- 变体排序、停用不会改变历史索引。
- 生成后的所有 selector 数组与对应 value 数组长度一致。
- 旧参数包和旧 3MF 无需迁移即可继续打开。

# Windows 混合分辨率多屏下最大化窗口恢复尺寸错误

## 问题现象

在 Windows 多显示器环境中，软件窗口最大化后执行最小化，再从任务栏恢复时，窗口仍被系统标记为“最大化”，但实际只占据当前显示器左上角的一块区域。

本次定位时使用的显示器布局为：

- 主屏：2560 × 1440，工作区为 2560 × 1390，窗口 DPI 为 120。
- 副屏：1920 × 1080，工作区为 1920 × 1040，位于主屏左侧。

观测到的窗口矩形：

- 最小化前：`0,0,2560,1390`，与主屏工作区一致。
- 恢复后：`0,0,1920,1040`，错误地使用了较小显示器的工作区尺寸。
- 此时 `IsZoomed()` 仍为 `true`，所以再次调用普通的 `Maximize()` 不会重新计算窗口大小。

因此，问题不是“最大化状态丢失”，而是“最大化状态仍在，但实际物理窗口矩形错误”。

## 根因

软件在 Windows 上使用自绘标题栏和自定义非客户区。混合分辨率、混合 DPI 或不同任务栏工作区的多屏环境下，Windows 在最小化窗口恢复时可能保留最大化状态，却用另一块显示器的工作区尺寸恢复窗口。

此前只修补 `WINDOWPLACEMENT` / `WPF_RESTORETOMAXIMIZED` 或再次调用 `Maximize()`，处理的都是窗口状态。由于出错时最大化状态本来就是正确的，这些处理无法修正实际的窗口矩形。

`Plater::priv::bring_instance_forward()` 中的单实例唤醒逻辑也不是本问题的触发路径；本次复现是已有进程从任务栏恢复，并且测试配置未启用单实例唤醒。因此该尝试已删除。

## 最终修复

修复不依赖固定的 1080p、2K 或 4K 分辨率，而是使用 Windows 返回的显示器工作区：

1. 收到最大化窗口的最小化命令时，记录窗口所在显示器的 `MONITORINFO.rcWork`。
2. 窗口恢复并收到 `WM_SIZE` 后，仅在窗口仍为最大化状态时执行检查。
3. 根据记录的位置重新找到目标显示器，并重新读取其当前 `rcWork`。
4. 比较 `GetWindowRect()` 与目标工作区；只有不一致时才调用 `SetWindowPos()` 修正。
5. 修正标记为一次性，普通非最大化窗口最小化不受影响。

顶部自绘最小化按钮通过同步发送 `WM_SYSCOMMAND / SC_MINIMIZE`，确保主窗口能够在真正最小化前记录显示器工作区。

## 对其他显示器组合的适用性

该问题并非由“1080p + 2K”这组固定分辨率触发，而是与不同显示器的工作区尺寸、缩放比例和虚拟桌面坐标有关。因此以下组合理论上都可能遇到原问题：

- 1080p + 4K。
- 2K + 4K。
- 相同分辨率但缩放比例不同。
- 任务栏尺寸或位置不同。
- 副屏位于主屏左侧或上方，使用负虚拟桌面坐标。

修复始终动态读取目标显示器的 `rcWork`，没有写死分辨率或缩放比例，所以设计上覆盖这些组合。但本次实机确认范围仅为 1080p + 2K；其余组合仍应纳入回归测试，不能视为已经实机验证。

## 建议回归矩阵

| 显示器组合 | 缩放组合 | 最大化所在屏幕 | 状态 |
| --- | --- | --- | --- |
| 1080p + 2K | 当前测试配置 | 两块屏分别测试 | 已验证 |
| 1080p + 4K | 100% / 150% / 200% 的实际组合 | 两块屏分别测试 | 待验证 |
| 2K + 4K | 100% / 125% / 150% / 200% 的实际组合 | 两块屏分别测试 | 待验证 |
| 任意双屏 | 相同缩放 | 两块屏分别测试 | 待验证 |
| 任意双屏 | 不同缩放 | 两块屏分别测试 | 待验证 |

每组至少覆盖：

- 自绘最小化按钮最小化，再从任务栏恢复。
- 任务栏操作最小化和恢复。
- 连续重复最小化和恢复多次。
- 最大化窗口在两块屏幕间分别测试。
- 副屏放在主屏左、右两侧分别测试。
- 恢复后确认窗口矩形等于当前显示器工作区，窗口仍为最大化状态。
- 取消最大化后确认原来的普通窗口尺寸没有被破坏。

## 代码收敛说明

最终只保留两处必要改动：

- `BBLTopbar::OnIconize()`：让自绘最小化按钮进入可捕获的 Windows 最小化消息路径。
- `MainFrame::MSWWindowProc()`：记录目标工作区，并在恢复时校正错误的真实窗口矩形。

已删除定位过程中证明无效或与实际触发路径无关的代码：

- 删除 `WINDOWPLACEMENT` 和 `WPF_RESTORETOMAXIMIZED` 修补。
- 删除 `Plater::priv::bring_instance_forward()` 的单实例恢复改动。

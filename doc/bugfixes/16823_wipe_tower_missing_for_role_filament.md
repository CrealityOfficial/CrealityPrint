# 16823 【擦拭塔】存在多色没有擦拭塔

## 1. 基本信息

- Bug ID：16823
- 标题：【擦拭塔】存在多色没有擦拭塔
- 反馈人：康美樱
- 处理人：wangwenbin
- 影响模块/影响文件：
  - `src/libslic3r/ModelInstance.cpp`
  - `src/libslic3r/PrintApply.cpp`
  - `src/slic3r/GUI/PartPlate.cpp`
  - `src/slic3r/GUI/GLCanvas3D.cpp`
  - `src/slic3r/GUI/Jobs/ArrangeJob.cpp`
  - `src/slic3r/GUI/Plater.cpp`

## 2. 现象与复现

- 复现场景：
  - 单个模型。
  - 开启擦拭塔。
  - 在“耗材丝类型选项”中，将墙、填充或实心填充等角色耗材设置为其他耗材，例如填充选择耗材 3、实心填充选择耗材 4。
- 实际结果：
  - 问题一：部分链路没有把角色耗材识别为实际使用的多耗材，导致本应生成擦拭塔的多色场景没有擦拭塔。
  - 问题二：即使切片后预览界面已经能出现擦拭塔，准备界面也不会在修改“耗材丝类型选项”后立即显示擦拭塔，需要切片后进入预览，再切回准备界面才显示。
- 期望结果：
  - 只要开启擦拭塔，并且“耗材丝类型选项”使当前盘实际使用了多个耗材，就应按多色处理并生成擦拭塔。
  - 修改角色耗材后，准备界面应立即刷新并显示擦拭塔。

## 4. 根因分析

- 触发条件：
  - “耗材丝类型选项”原先未开放，部分多耗材判断仍沿用旧逻辑。
  - 用户通过墙、填充、实心填充等角色耗材选择其他耗材时，实际已经产生多耗材打印路径，但部分代码仍只统计对象主耗材、支撑耗材或全局耗材数量。
- 问题一：存在多色但没有擦拭塔
  - `ModelInstance`、`PrintApply`、`PartPlate` 等链路没有完整收集 `wall_filament`、`sparse_infill_filament`、`solid_infill_filament` 等角色耗材。
  - 当模型主耗材只有一个，但角色耗材指定为其他耗材时，旧逻辑可能仍认为当前对象或当前盘是单耗材。
  - 擦拭塔生成、摆放空间预估、盘内挤出机统计依赖这些挤出机集合，集合不完整就会导致本应生成擦拭塔的场景被漏判。
- 问题二：准备界面没有立即刷新擦拭塔
  - 准备界面依赖 `PartPlate`、`ArrangeJob`、`GLCanvas3D` 等 GUI 侧逻辑提前判断是否需要显示擦拭塔。
  - 原准备界面的显示判断优先依赖全局耗材数量或旧的盘内耗材统计，没有直接使用包含角色耗材后的当前盘实际挤出机数量。
  - `Plater::on_config_change()` 没有把角色耗材及其生效条件纳入场景更新触发项，导致用户修改“耗材丝类型选项”后，准备界面不会立即重新计算擦拭塔。
- 为什么会出现该现象：
  - 角色耗材开放后，它已经成为多色来源之一，但切片、摆放、准备界面刷新使用的多耗材判断口径没有同步更新。
  - 因此会同时出现两类问题：一类是生成链路漏判导致擦拭塔没有出现，另一类是刷新链路漏判导致擦拭塔不能立即显示。

## 5. 修复方案

- 修复思路：
  - 将角色耗材选项纳入“当前对象/当前盘实际使用挤出机”的统计。
  - 根据墙、填充、实心填充的实际启用条件决定对应角色耗材是否参与统计，避免无打印区域时误判多色。
  - 准备界面擦拭塔显示使用当前盘实际挤出机数量判断。
  - 角色耗材及其生效条件变化时，触发准备界面更新。
- 修改点：
  - `ModelInstance.cpp`：摆放多边形和擦拭塔空间预估时，补充收集对象、零件、修改器和层范围中的角色耗材，修复空间预估阶段漏判多耗材的问题。
  - `PrintApply.cpp`：打印应用阶段的使用挤出机统计补充角色耗材，并按墙、填充、实心填充的实际启用条件过滤，修复切片生成链路可能漏判擦拭塔的问题。
  - `PartPlate.cpp`：盘内挤出机统计补充角色耗材，供 GUI、摆放和准备界面统一使用。
  - `GLCanvas3D.cpp`：准备界面擦拭塔显示逻辑改为基于当前盘实际使用挤出机数量，而不是只看全局耗材数量。
  - `ArrangeJob.cpp`：准备界面虚拟擦拭塔判断补充当前盘实际多耗材场景。
  - `Plater.cpp`：角色耗材和相关生效条件变化时触发场景更新，修复修改选项后准备界面不立即显示的问题。
- 为什么这样改：
  - “耗材丝类型选项”选择其他耗材本质上会让当前盘产生多耗材打印路径，擦拭塔判断应与实际使用挤出机保持一致。
  - 统一切片生成、摆放预估、盘内统计和准备界面刷新口径，可以同时解决“没有擦拭塔”和“准备界面不立即刷新擦拭塔”两个问题。

## 6. 影响范围与风险

- 正向影响：
  - 单模型通过角色耗材实现多色时，可以正确生成擦拭塔。
  - 修改角色耗材后，准备界面可以立即显示擦拭塔。
  - 摆放、准备界面和切片预览对多耗材的判断更一致。
- 可能风险：
  - 角色耗材统计范围扩大后，部分过去被误判为单耗材的配置现在会按真实多耗材场景显示或生成擦拭塔。
  - 若角色耗材设置为其他耗材但对应打印区域实际不存在，需要依赖墙、填充、实心填充等启用条件过滤，避免误判。
- 是否改变旧行为：
  - 单耗材且未通过角色耗材选择其他耗材的场景不应改变。
  - 通过角色耗材实际使用多个耗材的场景会改变为正确生成并立即显示擦拭塔，这是预期行为。

## 7. 回归建议

- 必测场景：
  - 单模型开启擦拭塔，填充选择耗材 3，切片后应生成擦拭塔。
  - 单模型开启擦拭塔，实心填充选择耗材 4，切片后应生成擦拭塔。
  - 单模型开启擦拭塔，墙选择其他耗材，切片后应生成擦拭塔。
  - 修改角色耗材后不切片，直接观察准备界面擦拭塔是否立即刷新。
- 边界场景：
  - 稀疏填充密度为 0 时，`sparse_infill_filament` 不应单独导致误判。
  - 墙圈数为 0 且无 brim 时，`wall_filament` 不应单独导致误判。
  - 顶层和底层层数均为 0 时，`solid_infill_filament` 不应单独导致误判。
  - 对象级、零件级、修改器和层范围中设置角色耗材时，准备界面与切片预览保持一致。
- 反向场景：
  - 关闭擦拭塔时，不应生成或显示擦拭塔。
  - 所有角色耗材均为默认或与主耗材一致时，不应因本次改动额外生成擦拭塔。
  - 多盘场景中，仅实际多耗材的盘显示擦拭塔占位。

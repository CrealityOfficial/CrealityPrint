# BUG 17503 V7.2.1 Beta 打开、克隆及切片初始阶段整体性能下降

## 1. 基本信息

- Bug ID：`17503`
- 标题：`V7.2.1.5443 Beta版本效率整体呈现下降：打开、切片、克隆、等待跳转到切片进度条的耗时整体变长`
- 日期：`2026-08-03`
- 产品 / 模块：`Creality Print / 模型导入、克隆、多色预览、切片交互`
- 类型：`性能回归`
- 复现版本：`7.2.1.5443 Beta`
- 同类慢问题版本：`7.2.0.5226`、`release-260630` 及修复前的 `release-260731`
- 对比正常版本：`7.1.1.4472`（`release-260430`）
- 修复分支：`release-260731`
- 主要触发模型：三角面较多、包含多色涂色数据、对象或实例数量较多的 3MF

## 2. 问题现象

- 与 `7.1.1.4472` 相比，新版本打开部分 3MF 的等待时间明显增加。
- 克隆同一批模型时，`7.1.1.4472` 约十秒出头，`7.2.0.5226` 和修复前最新代码约 `45～47 秒`。
- 点击切片后，后台任务虽然已经启动，但界面长时间没有显示切片进度条，用户感知为“点击切片没有反应”。
- 问题在大三角面、多对象、多色涂色模型上被明显放大；小模型或未涂色模型不一定明显。
- 克隆、打开和切片初始阶段表面上是三个功能，实际共同经过了多色三角面状态统计或分色网格重建代码，因此会同时受到同一底层低效实现影响。

## 3. 影响范围

- 模型耗材统计：`ModelVolume::get_extruders()`。
- 多色网格重建：`FacetsAnnotation::get_facets(..., std::vector<indexed_triangle_set>&)`。
- 3D / Preview 多色模型显示：`GLVolume::simple_render(...)`。
- 克隆后的模型和界面状态刷新。
- 导入后对象树警告图标初始化。
- 点击切片到首次可见进度之间的预览外壳加载和界面消息处理。
- 本次修改不改变：
  - 多色涂色数据的文件编码；
  - 耗材 ID、混色配方及耗材删除 / 重映射规则；
  - 切片几何、路径生成和 G-code 导出算法；
  - `FacetsAnnotation::get_facets(...)` 返回向量按状态 ID 索引的接口约定。

## 4. 修复前复现步骤

### 4.1 克隆

1. 使用包含多色涂色数据和较多三角面的 3MF。
2. 选中模型，连续克隆 10 个实例或对象。
3. 记录操作开始到界面恢复可操作的时间。
4. 对比 `7.1.1.4472`、`7.2.0.5226` 和修复前最新版本。

### 4.2 点击切片到进度条出现

1. 重新启动软件并重新导入相同问题模型，避免第二次操作命中进程内缓存。
2. 点击“切片单盘”。
3. 从点击时刻计时，直到界面第一次显示切片进度。
4. 修复前实测约 `32.070 秒`，期间后台切片实际上已经运行，但主界面未能及时刷新进度。

### 4.3 打开模型

1. 重启软件，确保每次测试均为首次加载。
2. 打开相同 3MF，记录从确认文件到模型、对象树和预览稳定显示的时间。
3. 对比 `7.1.1.4472` 与问题版本，重点关注多色模型和大三角面模型。

## 5. 根因分析

直接放大该问题的提交为：

- 提交：`9ad272ed384526fc97016cdb48e3002043986e5f`
- 作者：`wangwenbin <wangwenbin@creality.com>`
- 日期：`2026-05-08 16:08:22 +0800`
- 标题：`混色耗材-合入FullSpectrum功能`
- Change-Id：`I022916eb77340066c4d8af093b7cd380fe4d043c`
- 已进入：`release-260530`、`release-260630`、`release-260731` 等分支

该提交为支持更多混色状态，将 `EnforcerBlockerType` 从 `int8_t` 扩为 `int16_t`，并将 `ExtruderMax` 从 `Extruder16` 提高到 `255`。扩展本身有业务必要性，问题在于原有调用仍按“最大可能状态数”工作：

```text
for state = NONE ... ExtruderMax
    为当前 state 创建顶点映射
    遍历模型全部三角面
    提取属于当前 state 的三角面
```

状态上限扩大前，最多扫描约 `17` 个状态；扩大后固定扫描 `256` 个状态，理论状态扫描次数增加约 `15 倍`。即使模型实际只用了 1～3 种耗材，也会为其余两百多个未使用状态重复分配临时数据并遍历完整三角面。

该低效逻辑通过两条路径影响三个功能：

1. 克隆和耗材统计：旧版 `ModelVolume::get_extruders()` 为了知道模型使用了哪些耗材，先为全部状态生成完整分色网格，再检查哪些网格非空。
2. 打开和切片预览：`GLVolume::simple_render()` 调用批量 `get_facets()` 重建多色显示网格。切换到 Preview 时主界面线程执行该工作，期间后台虽然发送了切片进度事件，界面线程却无法及时处理，所以进度条迟迟不出现。

问题的本质不是“新增多色功能本身不该存在”，而是业务状态上限扩大后，旧的全量遍历算法没有同步改成按实际使用状态处理。

此前排查过的 `Change-Id: Ib132f476ee8c8d49bf4f248246fce9230ac7c87c` 在本次克隆日志中没有进入关键慢路径，不能作为本问题的直接原因。

## 6. 修复策略

- 复用 `TriangleSplittingData::used_states`。该统计表在涂色数据序列化、3MF 三角面字符串反序列化及状态修改时维护，现有 `Print::apply()` 也已经使用同一数据判断涂色耗材。
- `ModelVolume::get_extruders()` 不再生成 256 份分色网格，直接读取 `used_states` 中实际为真的状态 ID。
- 批量 `FacetsAnnotation::get_facets()` 保持返回向量为 256 个状态槽位，保证调用接口和颜色 ID 索引不变，但只为 `NONE` 和实际使用的状态生成网格。
- 对旧数据或统计表缺失场景，从原始 bitstream 恢复 `used_states`；无法恢复的异常数据保留原有全量扫描作为兼容兜底。
- `FacetsAnnotation::reset()` 同步清空 `used_states`，避免删除涂色后继续使用旧统计结果。
- 将 `ModelVolume::mmuseg_ts` 初始化为 `0`，确保首次查询必定与有效涂色时间戳不一致并建立缓存，消除未初始化值带来的不确定行为。
- 对象树警告图标直接复用各体积已有的 STL 统计，不再为读取警告状态组装包含全部实例的临时大网格。
- 保留导入和切片初始阶段分层耗时日志，便于后续版本持续定位性能回归。

## 10. 回滚与风险

- 风险等级：中低。
- 主要风险：
  - `used_states` 若与 bitstream 不一致，可能遗漏某个多色状态；当前通过写入路径维护、旧数据恢复和异常数据全量扫描降低风险。
  - 对象树警告图标改用汇总体积统计后，修改器体积的修复错误也可能影响对象级警告图标；该行为与现有删除、修复后的图标刷新路径一致。
  - warning 级性能日志会增加一定日志量和少量磁盘 I/O，但不改变业务返回值和线程同步逻辑。
- 回滚方式：
  - 恢复 `ModelVolume::get_extruders()` 和批量 `FacetsAnnotation::get_facets()` 的全状态网格生成；
  - 移除 `reset_used_states()` 和 `mmuseg_ts` 初始化改动；
  - 恢复对象列表通过 `model_object->mesh().stats()` 计算警告图标。
- 不建议回滚 FullSpectrum 的状态范围扩展，因为该扩展承载已有混色业务；如需回滚本性能修复，应仅回滚查询和网格生成优化。

## 11. 后续建议

- 将大三角面多色 3MF 加入打开、克隆和点击切片到首次进度的性能回归集，测试时必须重启软件并首次加载，避免缓存掩盖问题。
- 建立分阶段阈值：归档解析、对象树构建、Preview 外壳重建、克隆、切片同步前置和首次可见进度分别记录。
- 继续优化 `check_filament_vendor_for_models()`。当前该步骤约 `3.6 秒`，仍会对每个多色体积逐个检查 64 个候选耗材，可直接复用 `used_states` 避免重复扫描。
- 继续拆分 `Preview::reload_print()` 内部耗时。修复后该阶段仍约 `12.9 秒`，需要区分外壳加载、实际使用颜色网格构建、GPU 模型初始化和界面刷新。
- 对 FullSpectrum 等扩大状态范围的需求增加复杂度评审，避免代码仍按“最大可能状态数 × 全模型数据量”执行。

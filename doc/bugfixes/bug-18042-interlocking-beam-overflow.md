## 4. 根因分析

### 触发条件与代码链路

开启联锁梁且存在满足条件的不同墙耗材区域时，调用链为：

`PrintObject::slice()` → `generate_interlocking_structure()` → `generateInterlockingStructure()` → `applyMicrostructureToOutlines()` → `generateMicrostructure()`。

微结构生成后，通过多边形差集、并集修改各材料区域的切片轮廓，再生成墙和填充路径。

### 问题原因

`generateMicrostructure()` 原代码：

```cpp
const coord_t beam_w_sum = beam_width + beam_width;
const coord_t middle     = cell_size.x() * beam_width / beam_w_sum;
```

当前 `Point.hpp` 中 `coord_t` 为 `int32_t`，坐标比例为 `0.00001 mm`。本模型对应计算为：

| 项目 | 数值 |
| --- | ---: |
| 梁宽 0.8 mm 对应整数 | 80,000 |
| 单元宽 1.6 mm 对应整数 | 160,000 |
| 乘法中间结果 | 12,800,000,000 |
| int32 最大值 | 2,147,483,647 |
| 正确分割位置 | 80,000，即 0.8 mm |

乘法在除法前已经溢出。按常见的 32 位回绕方式模拟，乘积变为 -84,901,888，截断除法得到 -530，对应约 -0.0053 mm；另一侧宽度约为 1.6053 mm，破坏了两侧各占一半的设计。

有符号整数溢出属于 C++ 未定义行为，上述负值是数值模拟结果，不保证所有构建表现相同。当前源码中的溢出可以明确确认，且其影响与提供的新文件形态吻合；尚需修复后重新切片，最终闭环确认样本异常的因果关系。

## 5. 修复方案

- 修复思路：当前两侧梁宽相同，单元宽度为两倍梁宽，直接平分单元，避免不必要的乘法中间结果。
- 修改点：`src/libslic3r/Feature/Interlocking/InterlockingGenerator.cpp` 的 `generateMicrostructure()`。
- 实际改动：删除 `beam_w_sum`，将分割位置改为：

```cpp
const coord_t middle     = cell_size.x() / 2;
const coord_t width[2]   = {middle, cell_size.x() - middle};
```

- 源码差异为 1 个文件、1 行新增、2 行删除。
- 保留联锁材料资格判断、无墙区域过滤和角色耗材变化后的切片失效逻辑。

## 7. 风险与回退

- 可能风险：当前等宽梁设计下直接平分与原公式的数学意义一致；若未来支持两侧不同梁宽，需要重新设计比例计算并保证中间结果不溢出。
- 风险影响范围：联锁梁微结构的分区几何，以及由其生成的墙和填充路径。
- 回退方案：仅逆向撤销本次 `generateMicrostructure()` 的最小改动，不回退其他历史修复。回退会重新引入本次溢出缺陷。

# Bug 17982：T 指令换料后恢复加速度和抖动速度

## 1. 基本信息
- Bug ID：17982
- 标题：【首层换料后的空驶加速度、抖动速度错误】T 指令模式下，首层层间换色后未重新获取工艺参数中的加速度和抖动速度
- 禅道链接：https://zentao.creality.com/zentao/bug-view-17982.html
- 反馈人：郭锋兴
- 处理人：wangwenbin
- 分支：release-260930
- 影响模块：G-code 生成、T 指令换料、运动参数缓存

## 2. 问题现象
- 用户反馈：首层换料后空驶加速度、抖动速度错误。
- 样例：`擦拭塔测试-5色立方体.3mf`、`组合体_PLA_1d15h20m.gcode`，位于用户提供的 `F:\result\2026bug修复\9月\17982 ...` 目录。
- 实际结果：原 G-code 第 288、289 行正确设置首层加速度 2001、抖动速度 5，但第 552 行 T3、第 1013 行 T2、第 1348 行 T1 换料后均未重新下发；直到第二层才重新设置。
- 首层空驶加速度为 0，按现有逻辑回退首层加速度 2001，该取值本身正确。
- 期望结果：换料宏及耗材起始脚本结束后，显式恢复当前层应使用的运动参数。
- 静态文件仅证实缺少恢复指令；机器实际值是否错误，取决于 T 宏是否修改这些参数，尚未实机确认。

## 3. 复现步骤
- 前置条件：样例机型 Creality K2 Plus，Klipper，PLA，多色 T 指令模式（multicolor_method=0）。首层加速度 2001、首层抖动速度 5、首层空驶加速度 0，普通空驶加速度 12011、抖动速度 13。
1. 打开样例 3MF，切片并导出 G-code。
2. 定位首层 T3、T2、T1 及耗材起始 G-code。
3. 检查其后前往擦拭塔、返回模型的运动前是否重新设置运动参数。
4. 若要验证实际错误，在测试机确认 T 宏会修改参数，并观察换料后的运行值。
- 复现结果：旧文件首层换料后缺少恢复指令。
- 复现概率：未提供；实机结果待验证。

## 4. 根因分析
- 触发条件：换料自定义 G-code 或 T 指令调用的固件宏改变运动参数，Writer 缓存仍保留换料前的值。
- 代码链路：`append_tcr_creality()` → `set_extruder_new()` → 换料与 `filament_start_gcode`；无塔等常规路径使用 `set_extruder()`。
- `GCodeWriter::set_accel_and_jerk()` 原先只比较请求值和缓存值；两者相同时省略输出，无法获知固件宏内部变化。
- 首层通常持续使用同一组参数，因此漏恢复会持续到后续重新输出参数时。

## 5. 修复方案
- `src/libslic3r/GCodeWriter.hpp/.cpp`：为 `set_accel_and_jerk()` 增加默认关闭的 `force` 参数。强制模式下重新输出有效加速度和抖动速度，继续执行机器上限限制并同步缓存；不输出禁用的零值加速度。
- `src/libslic3r/GCode.hpp/.cpp`：增加 `restore_motion_limits_after_toolchange()`，在 `set_extruder_new()`、`set_extruder()` 完成换料及耗材起始脚本后调用。
- 范围限定为打印层内的 Klipper T 模式；非 T 模式、其他 G-code 方言及无打印层的初始化不新增恢复指令，无需换料的早返回保持不变。
- 首层优先使用当前物理喷嘴的首层空驶加速度，未设置正值时回退首层加速度；抖动速度使用首层值。非首层使用普通空驶参数。
- 保留默认加速度、默认抖动速度的启用条件；恢复空驶参数后，正常挤出逻辑继续切换到对应打印参数。
- 当前样例预期在每次首层换料脚本之后输出：
  ```gcode
  SET_VELOCITY_LIMIT ACCEL=2001 ACCEL_TO_DECEL=2001 SQUARE_CORNER_VELOCITY=5
  ```

## 7. 风险与回退
- 风险：自定义换料脚本有意保留的运动参数将被工艺值覆盖；这是本次恢复行为的预期效果。
- 影响范围：打印层内、实际进入换料主流程的 Klipper T 模式；每次换料增加一条有效参数恢复指令。
- 回退方案：撤销本次四个源码文件中的恢复调用、辅助函数及 Writer 强制输出参数，保留其他改动。

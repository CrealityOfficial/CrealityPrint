# 15685 小区域填充流量补偿模型格式校验

## 1. 基本信息
- Bug ID：15685
- 标题：打开附件 3MF 后点击切片出现非法访问提示
- 反馈人：用户反馈
- 处理人：wangwenbin
- 影响模块/影响文件：
  - `src/libslic3r/PrintConfig.hpp`
  - `src/libslic3r/PrintConfig.cpp`
  - `src/libslic3r/Config.cpp`
  - `src/slic3r/GUI/Field.cpp`
  - `src/slic3r/GUI/GUI.cpp`

## 2. 现象与复现
- 复现场景：导入用户附件 `立方体_177510044300015.3mf`，点击切片。
- 实际结果：切片过程中触发非法访问，调用栈停在 `tk::spline::set_points()`，最终在空矩阵访问处崩溃。
- 期望结果：非法或旧 3MF 中的错误 `small_area_infill_flow_compensation_model` 配置不应导致切片崩溃；界面输入错误格式时应阻止写入。

## 4. 根因分析
- 触发条件：3MF 的 `Metadata/project_settings.config` 中保存了非法的 `small_area_infill_flow_compensation_model`，例如不是 `长度,系数;` 成对格式。
- 代码链路：
  - 3MF 加载时 `ConfigBase::load_from_json()` 将该字段反序列化到配置对象。
  - 用户界面编辑该字段时，原逻辑只按 `;` 分割字符串，没有验证每一项是否为合法的 `length,flow`。
  - 后续切片导出 G-code 时，小区域填充流量补偿逻辑会按模型点构造 spline。
- 为什么会出现该现象：
  - 非法字段可能被旧 3MF 或界面输入保存下来。
  - 原加载和输入链路缺少格式校验，错误值进入配置对象。
  - 错误格式导致模型点为空或不满足 spline 输入要求，最终触发非法访问。

## 5. 修复方案
- 修复思路：
  - 统一 `small_area_infill_flow_compensation_model` 的格式校验，只接受 `长度,系数;` 成对格式。
  - 界面输入阶段发现非法格式时提示并阻止写入配置。
  - 加载 3MF 时发现旧文件中该字段非法则忽略该参数，不加载错误值。
- 修改点：
  - `PrintConfig.hpp/cpp`：新增小区域填充流量补偿模型解析与校验函数。
  - `Config.cpp`：3MF JSON 加载时校验 `small_area_infill_flow_compensation_model`，非法则跳过。
  - `Field.cpp`：界面文本输入时校验该字段，非法时提示并恢复旧值。
  - `GUI.cpp`：配置回写时再次校验并规范化有效值。
- 为什么这样改：
  - 校验前置到输入和加载阶段，可以避免错误配置继续传播。
  - 对旧 3MF 采用忽略非法字段的兼容策略，不阻断项目打开。
  - 规则集中在公共解析函数中，减少 UI 与加载逻辑规则不一致的风险。

## 6. 影响范围与风险
- 正向影响：
  - 避免非法模型配置导致切片崩溃。
  - 避免界面继续写入错误格式。
  - 旧 3MF 中错误参数不会被加载到当前配置。
- 可能风险：
  - 旧 3MF 中非标准但曾被保存的该字段会被忽略。
  - 用户输入不满足递增、首项为 0、末项系数为 1.0 等规则时会被拒绝。
- 是否改变旧行为：
  - 是。旧行为会接受并保存非法字段；新行为在输入和加载阶段拒绝或忽略非法字段。

## 7. 回归建议
- 必测场景：
  - 输入合法模型：
    `0,0;0.2,0.4444;0.4,0.6145;0.6,0.7059;0.8,0.7619;1.5,0.8571;2,0.8889;3,0.9231;5,0.9520;10,1;`
  - 加载包含合法模型的 3MF，确认参数正常显示并可切片。
  - 加载包含非法模型的旧 3MF，确认项目可打开，非法字段被忽略，切片不崩溃。
- 边界场景：
  - 少于 3 个点。
  - 第一项长度不是 0。
  - 长度未严格递增。
  - 最后一项流量系数不是 1 或 1.0。
- 反向场景：
  - 其他 `coStrings` 参数加载和界面编辑不受影响。
  - 关闭“小区域填充流量补偿”时，导入旧项目和切片流程保持稳定。

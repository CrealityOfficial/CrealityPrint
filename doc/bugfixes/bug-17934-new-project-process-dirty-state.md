# Bug #17934：新建项目后工艺栏仍显示编辑状态

- 禅道链接：[Bug #17934](https://zentao.creality.com/zentao/bug-view-17934.html)
- 标题：点击新建项目，工艺栏仍显示编辑状态
- 修复日期：2026-09-14
- 提交人：杨艳虹；指派给：贺淼
- 读取时状态：激活、未确认；严重程度：严重；优先级：高
- 影响版本：`CrealityPrint_7.3.0.5903_Alpha`
- 所属计划：`CP 7.3.0 Beta`

## 2. 问题现象

打开第三方保存的 3MF 后新建项目，模型已经清空，但工艺栏仍显示“已修改”标记。禅道期望工艺栏自动选择系统配置。

本次定位到的情况是：当前选中的工艺已经是系统预设，实际工艺参数没有需要保留的修改，但缓存的编辑标记未清除。

## 3. 影响范围

- 模块：准备页面、第三方 3MF 导入、项目重置。
- 场景：导入的差异仅涉及混色耗材等项目级参数，却被强制标为工艺预设修改。
- 修复涉及 `Check3mfVendor.cpp` 和 `PresetBundle.cpp`，并补充预设状态回归测试。

## 4. 修复前复现

1. 打开附件 `U1_snak_多色多盘.3mf`，完成第三方项目的机型选择。
2. 点击“新建项目”。
3. 查看工艺栏，仍显示编辑标记。

用户已确认复现。分析本地同一附件的 `Metadata/project_settings.config`，其 `different_settings_to_system` 记录的差异为：

```text
mixed_filament_definitions
mixed_filament_height_lower_bound
mixed_filament_height_upper_bound
```

## 5. 根因分析

以下结论来自代码检查、附件配置和回归测试，禅道页面本身只描述了现象与期望。

1. `Check3mfVendor::doSelectPrinterPreset()` 使用原始配置 `diff()` 判断差异，应用第三方工艺配置后，直接对选中预设和编辑副本调用 `set_dirty()`。
2. `PresetCollection::current_is_dirty()` 的统一比较规则会排除上述混色项目级参数。这导致实际比较结果为 `false`，但两个预设的 `is_dirty` 标记为 `true`。
3. 新建项目调用 `PresetBundle::reset_project_embedded_presets()`。原实现清理内嵌预设并按需重选，当前系统工艺没有被移除时，不重新计算其编辑标记。
4. 后续界面刷新继续读取残留的标记，因此空项目仍显示工艺已修改。

## 6. 修复方案

- 导入阶段：将直接设置编辑标记改为 `prints.update_dirty()`，按预设编辑器的统一规则比较实际参数。
- 项目重置阶段：清理内嵌预设后，再调用 `prints.update_dirty()`，即使没有移除工艺预设，也同步选中预设和编辑副本的状态。
- 保留原有修改处理语义：真实工艺参数发生变化且用户选择保留时，修改值和编辑标记继续存在；选择放弃时恢复原预设值。

这次修复不通过强制清空所有参数或切换到其他系统工艺来消除标记，也不调整混色参数的现有持久化规则。

## 2. 涂色是怎么存的

要理解这个方案，必须先理解一件反直觉的事：**涂色不是贴在模型表面的一张图片。**

### 2.1 一个选择题

假设模型表面有个三角面，用户在它左下角涂了蓝色。软件要记下这件事，有两种办法：

| | 办法 A：记坐标 | 办法 B：记折纸步骤 |
|---|---|---|
| 内容 | "在 (12.3, 45.6, 78.9) 有蓝色" | "把这个面沿三边中点切成 4 小块 → 左下角那块涂蓝" |
| 是否含坐标 | 是 | **否** |

切片器（从 PrusaSlicer 继承至今）用的是 **办法 B**。这个选择决定了后面的一切。

### 2.2 位流：折纸步骤的二进制写法

把办法 B 那句话翻译成机器格式，每条指令占 4 个二进制位（代码里叫 nibble）：

```
切成 4 块        → 0011
第 1 块不涂       → 0000
第 2 块不涂       → 0000
第 3 块不涂       → 0000
第 4 块涂 2 号色  → 1100 0001
```

拼起来就是：

```
0011 0000 0000 0000 1100 0001
```

**这一长串 0 和 1 就是「位流」（bitstream）。** 完整的数据结构是：

```cpp
struct TriangleSplittingData {
    // 每个被细分的原始面：(面索引, 它的位流从第几位开始)
    std::vector<TriangleBitStreamMapping> triangles_to_split;
    // 所有面的位流首尾相接
    std::vector<bool> bitstream;
};
```

### 2.3 关键性质：位流不含坐标，靠顶点编号定位

重建位流时，子面的顶点是这么算出来的：

```cpp
// TriangleSelector::perform_split()
for (int j = 0, idx = tr.special_side(); j < 3; ++j, idx = next_idx_modulo(idx, 3))
    verts_idxs.push_back(tr.verts_idxs[idx]);
tr.children[0] = push_triangle(verts_idxs[0], verts_idxs[1], verts_idxs[5], ...);
```

**纯拓扑推导**——从父面的三个顶点编号（v0/v1/v2）出发做模 3 轮转，几何信息一个字节都没参与。

这就像折纸说明书写着"对折后取左下角"：说明书本身没有尺寸，它假定你手里那张纸的三个角有固定编号。

由此推出两条性质，一好一坏：

- ✅ **可以整段搬运**：交给任何「三顶点位置和顺序都相同」的三角面，重建结果**逐位相同**。这不是近似，是恒等变换。
- ⚠️ **对顶点顺序敏感**：一旦 v1、v2 编号被对调，同一段位流会解码出**镜像**的结果。

## 3. 我们当前版本的做法：切之前全部清零

```cpp
// CutUtils.cpp :: Cut::perform_with_plane()   —— 改动前
for (ModelVolume* volume : mo->volumes) {
    volume->reset_extra_facets();   // 支撑、接缝、换色、绒毛，全部清零
    ...
}
```

拆分和网格修复两条路径同样清空。

### 3.1 为什么当初必须清

不是疏漏，是**不清更糟**。

涂色挂载方式是「第几号三角面 → 位流」。切割会彻底重建网格：

- 面的**数量**变了（刀口处的面被切碎，还新增了截面盖板）
- 面的**顺序**变了（上下两半各自重新编号）
- 上半边的 0 号面和原来的 0 号面**毫无关系**

所以如果只是把 `reset_extra_facets()` 删掉，原来 500 号面的涂色会跑到新网格的 500 号面上——那可能是模型另一侧的某个面。**结果是涂色乱飞，而不是涂色保留。**

### 3.2 业务影响

| 影响面 | 说明 |
|---|---|
| 返工成本 | 复杂换色模型的涂色是分钟级甚至更久的手工投入，一次切割全部作废 |
| 操作顺序被迫倒置 | 用户必须"先切割、再分别涂色"，而切开后的两半更难对准涂色边界 |
| 竞品差距 | 用户可直接感知的功能完整性缺失 |

## 4. BambuStudio 方案：99% 直接搬，1% 重新算

### 4.1 核心洞察

**一次切割只真正改动了刀口附近极小一圈面。** 一个 10 万面的模型切一刀，通常只有几百个面被重新三角化，其余 99% 是原样搬过去的。

结合 2.3 节的"可整段搬运"性质，方案成立：对这 99% 完全没必要做任何几何近似。

> 注意：位流格式本身早于这个方案很多年（从 PrusaSlicer 继承）。这次的贡献是**发现了它的可搬运性并据此做分解**，不是发明位流。

### 4.2 三分法

让切割在生成新面时顺手记录来源（`cut_mesh()` 新增两个输出参数），据此把新网格分成三类：

| 类别 | 判据 | 处理 | 精度 | 典型占比 |
|---|---|---|---|---|
| **全等面** | 有来源面且三顶点**有序**吻合 | 直接搬位流 | **逐位精确，零几何计算** | 99%+ |
| **刀口碎片** | 有来源面但顶点已改变 | 按面积重叠重新绘制 | 几何近似（误差 < 0.2mm） | ~1% |
| **截面盖板** | 无来源面（标记 `-1`） | 不处理 | 保持未涂色 | 极少 |

这个分解**同时解决了精度和性能**，而不是在两者间折中：99% 的面不参与近似，所以精度问题在它们身上不存在；所有昂贵的几何计算只作用在 1% 上。

### 4.3 全等面：改索引，搬位流

判据必须是**有序**比较（因为 2.3 节的性质）：

```cpp
// classify_cut_faces()
for (int i = 0; i < 3 && congruent; ++i)
    congruent = (dst_triangle[i] - src_mesh.its.vertices[src_face[i]]).squaredNorm()
                <= tolerance_sq;
```

比的是 `dst[0]↔src[0]`、`dst[1]↔src[1]`、`dst[2]↔src[2]`，不是"是不是同一个三角形"。

通过的面直接剪切位流、换个索引贴上：

```cpp
// splice_congruent_paint()
spliced.triangles_to_split.emplace_back(int(dst_face), int(spliced.bitstream.size()));
spliced.bitstream.insert(spliced.bitstream.end(),
                         src_bits.begin() + first, src_bits.begin() + last);
```

容差取源包围盒对角线 × `1e-5`——顶点经过两次 float 变换往返，精确比较不可用；而这个量级比用户能画出的最细笔触小三个数量级，不可能误判。

## 5. 重点：剩下 1% 怎么算

这 1% 的面，位流已经没法用了——刀口把源面切成了碎片，碎片顶点里有新生成的交点，"取左下角那块"失去了参照物。只能改用几何方法。

### 5.1 思路转向：从「拉」改为「推」

直觉做法是「问每个碎片：你什么颜色？」——这条路走不通。

| | 拉取式（旧路径，现为兜底） | 推送式（本方案主路径） |
|---|---|---|
| 做法 | 取碎片 3 顶点 + 1 重心，找源网格最近点读色，取众数 | 把每种颜色当笔刷，按**实测重叠面积**推到新网格上 |
| 细化驱动 | 来自 4 个采样点之间的分歧 | 来自测量出的重叠面积 |
| 致命缺陷 | 比碎片更细的特征可能 4 点全部错过 → 误差报 0 → **不细化 → 永久丢失** | 无此问题 |

拉取式的问题是个死循环：**要发现细特征得先细化，要触发细化得先发现它。** 代码注释原话：

> a feature that misses all 4 is invisible to the refinement and gets lost

推送式把因果反过来，**可见性与细化驱动就此解耦**——只要有可测量的重叠就一定被发现，与新网格三角化多粗无关。

### 5.2 五个步骤

**第 1 步：只取刀口那一小片源数据**

重建整个模型的涂色树是最贵的一步，而这里只需要碎片对应的那几个源面：

```cpp
const AnnotationData fragment_paint = extract_source_roots(
    layer.src, classification.fragment_source_roots, src_ranges);
```

根面编号保持不变，下游无需重映射。

**第 2 步：把源涂色摊平成"叶三角面"**

`PaintRegionSource` 构造时做四件事：

1. **摊平**——递归展开细分树，只留最末端的小三角面（叶子）及其颜色
2. **算法线和面积**——法线用于排除朝向不对的表面
3. **按颜色分组，按面积降序排列**
4. **建 AABB 树**——空间索引，快速找候选叶子

排序有讲究：

```cpp
// 按涂色面积降序。嵌套的小色块面积小、排在后面，所以后画后赢，
// 正好复现用户"先铺大面积、再点小细节"的手感。
std::sort(m_states.begin(), m_states.end(),
          [](const StateInfo &a, const StateInfo &b) { return a.area > b.area; });
```

**`NONE`（未涂色）永远不画**——目标网格本来就是空白的，而"只擦到边"的颜色不会扩散进洞里，所以镂空区域天然存活，不需要专门刷底色。

**第 3 步：给每种颜色找起点**

```cpp
PaintRegionSource::Box3f state_box = info.bbox;   // 这种颜色的整体包围盒
state_box.min().array() -= seed_inflate;          // 按容差放大
state_box.max().array() += seed_inflate;
seed_index.seeds(state_box, start_facets);
```

只要粗略覆盖——下一步的走面过程会自己蔓延。

**第 4 步：走面 + 递归细分**

`paint_region()` 从种子面广度优先遍历，每个面交给 `paint_region_recursive()`，逻辑就三档：

```cpp
const RegionCoverage region_coverage = ctx.coverage(this->facet_vertices(facet_idx));

if (region_coverage == RegionCoverage::None)
    return false;                                      // 没关系，跳过

if (region_coverage == RegionCoverage::Full) {
    undivide_triangle(facet_idx);                      // 完全覆盖 → 丢弃细分
    m_triangles[facet_idx].set_state(ctx.new_state);   // 整面上色
    return true;
}

// Partial：颜色边界穿过这个面 → 切成 4 块，每块再问一次
split_triangle(facet_idx, neighbors, ctx.trafo);
for (每个子面) paint_region_recursive(子面, ..., depth + 1, ctx);
```

**只有 `Partial` 才继续细分**，所以计算量全花在颜色边界上，区域内部一步到位。

走完之后回收：

```cpp
remove_useless_children(facet);   // 四个子面同色 → 合并回父面
```

区域内部因此只占一个节点，无论中途细分多深。

**第 5 步：三个终止条件**

| 条件 | 阈值 | 处理 |
|---|---|---|
| 边长到底 | `0.2mm` | 整面上色，停 |
| 深度到顶 | 20 层 | 整面上色，停 |
| 节点预算耗尽 | 最多 400 万 | 整面上色，打 warning |

三种情况都是**"整面上色"而非"放弃"**：

```cpp
// 保守规则：接触即命中，让比叶子更细的特征被保留而非被侵蚀
if (depth >= ctx.max_depth || !budget_left) {
    tr->set_state(ctx.new_state);
    return true;
}
```

宁可涂多一点，也不要把细特征抹掉。

### 5.3 核心裁决：`coverage()` 怎么判三档

**① 空间查询——先缩小候选范围**

```cpp
if (m_band > 0.0) {
    const float widening = float(m_band) * Sqrt3;
    query_box.min()[dropped_axis] -= widening;   // 只沿投影轴加厚
    query_box.max()[dropped_axis] += widening;
}
```

**只沿一个轴加厚**不是小优化。band 是毫米级（源包围盒对角线/100），而叶子深处只有零点几毫米。各向同性加厚会把整个共面邻域上千片叶子全拉进来逐一裁剪——注释里写明这正是不做限制时的运行时瓶颈。

**② 逐个候选叶子过滤**

```cpp
// 朝向差超过 60° → 不是同一个特征
if (m_leaf_normals[leaf].dot(unit_normal) < NormalAgreementLimit) return true;
// 离本面所在平面太远 → 是另一层表面
if (std::abs((centroid - triangle_in_source[0]).dot(unit_normal)) > m_band) return true;
```

法线这一条是**防薄壁涂色穿透到背面**的关键——背面的叶子距离一样近，但朝向相反。

**③ 真正算重叠面积**

```cpp
const double overlap = triangle_overlap_area(leaf_triangle, triangle_in_source, dropped_axis);
area_matched += overlap;
if (m_leaf_states[leaf] == state) area_in_state += overlap;
```

内部是 Sutherland-Hodgman 多边形裁剪——投影到 2D、求交集多边形、算面积。**精确计算，不是采样估算。**

**④ 三档结论**

```cpp
if (area_matched <= eps || area_in_state <= area_matched * 1e-3)
    return None;
if (area_in_state >= area_matched * (1 - 1e-3) &&      // 这颜色几乎独占
    area_matched  >= target_area * 0.75)                // 且匹配到自身 75% 面积
    return Full;
return Partial;
```

两个分母的选择都有理由：

- **用"已匹配源面积"而非"三角面自身面积"做分母**——弯曲的源表面投影过来有前缩（foreshortening），用自身面积会让判定随曲率漂移
- **`Full` 额外要求匹配到自身 75%**——跨在锐边上的面只有共面那部分能匹配上，这条让它留在 `Partial` 继续细分，直到每块各自落到锐边一侧

### 5.4 精度指标：0.2mm 的三条依据

1. **等于笔刷自身极限**——`select_patch()` 把笔刷夹到 `min(半径/5, 0.2mm)`，**用户画不出更细的笔触**
2. **低于喷嘴直径和层高**——残留误差**传不到切片结果**，即不影响最终打印件
3. **两半取值一致**——上下两半分别处理，用绝对值保证两边停在同一分辨率，涂色边界在刀口处才能严丝合缝

大件模型另有模型相对下限（对角线 / 4096）接管，防止节点数膨胀。

代码注释记录了两次踩坑：全局优先队列会让预算被少数大面吃光；按半边推导下限会让两半阶梯相位错开，看起来就是沿刀口整体偏移。

### 5.5 两道防护栏

**掩码——绝不碰那 99%**

```cpp
stats = reproject_one_annotation_by_region(..., &classification.fragment_faces, ...);
```

走面永远不会踏进全等面，逐位精确搬来的结果不会被几何近似污染。

### 5.6 一个具体例子

刀口穿过一个画了蓝色的面，切成 3 个碎片：

1. 只抽出这个源面的涂色 → 摊平成 8 片叶子（6 蓝 2 空）
2. 蓝色面积 > 空白，蓝色排前面（空白根本不画）
3. 蓝色包围盒相交到 3 个碎片，作为种子
4. 碎片 A：完全在蓝色区内 → `Full` → 整面涂蓝，**1 个节点搞定**
5. 碎片 B：边界穿过 → `Partial` → 切 4 块 → 2 块 `Full`、1 块 `None`、1 块仍 `Partial` → 继续…… 直到边长 < 0.2mm
6. 碎片 C：完全在蓝色外 → `None` → 跳过
7. 收尾 `remove_useless_children()`，把碎片 B 里同色子面合并

## 6. 截面颜色的取色逻辑

这一节回答两个实测中出现的疑问。

### 6.1 渲染：未涂色部分用 volume 自己的挤出机色

**MMU 涂色里没有"白色"这个状态——白色就是"没画过"。**

```cpp
// 3DScene.cpp  —— idx == 0 即未涂色部分
else if (idx == 0) {
    int extruder_id = model_volume->extruder_id();     // ← volume 自己的挤出机
    ColorRGBA new_color = adjust_color_for_rendering(extruder_colors[extruder_id - 1]);
    m.set_color(new_color);
}
```

**注意它取的是 `model_volume->extruder_id()`，不是固定的 1 号耗材。** 这解释了一个实测现象：把 1 号耗材改成蓝色后，截面**仍然是白色**——因为它用的是这个 volume 指定的挤出机（恰好配的是白色耗材）。

所以"上半红、下半白"的圆柱，数据上是这样：

| 部位 | 数据状态 | 显示 |
|---|---|---|
| 上半红色 | 用红色耗材**画上去的**（有涂色数据） | 红 |
| 下半白色 | **未涂色**，走 `extruder_id()` | 白 |
| 截面 | **未涂色**（`Invented`，无从继承） | 白 |

截面和下半段同色，是因为它们在数据上**都是 `NONE`，走同一条取色路径**。

### 6.2 截面保持未涂色是设计意图

```cpp
enum class CutFaceOrigin : unsigned char {
    // Surface the cut invented (the cross-section cap): no source paint applies.
    Invented,
    ...
};
```

截面盖板是刀口新生成的表面，源模型上根本不存在，没有任何涂色数据可继承。类比：把一根红白双色棒子锯断，锯出来的断面本来在棒子内部，**它从来没有颜色**。切片器如果给它猜个颜色反而是错的——用户接下来可能想给这个新表面单独上色。**保持未涂色 = 交还给用户决定。**

### 6.3 G-code 走线：为什么截面上出现红白交替的环

实测观察：截面那一层的走线是「内圈白 → 一圈红 → 更大一圈白 → 再套一圈红 → 最后一整层白」。

**这不是涂色重投影的产物，而是顶/底壳层的颜色投影机制。** 相关代码：

```cpp
// MultiMaterialSegmentation.cpp
static inline std::vector<std::vector<ExPolygons>> segmentation_top_and_bottom_layers(...)
{
    for (size_t i = 0; i < print_object.num_printing_regions(); ++i) {
        max_top_layers    = std::max(max_top_layers, config.top_shell_layers.value);
        max_bottom_layers = std::max(max_bottom_layers, config.bottom_shell_layers.value);
    }
    ...
    slice_mesh_slabs(painted, zs, volume_trafo, &top, &bottom, ...);
}
```

机制是：**侧面的涂色会被"拉伸"投影到顶/底若干层壳上**（层数由 `top_shell_layers` / `bottom_shell_layers` 决定）。目的是让侧面的颜色在顶面边缘也可见，否则从上方看会露出底色。

所以截面那层的走线包含两部分叠加：

1. **侧面颜色投影**：外圈红色来自侧壁的红色涂色，被投影到顶壳层
2. **截面本身**：未涂色，走 volume 挤出机色（白）

交替出现的环，是 `merge_segmented_layers()` 里 `diff_ex` 逐层裁剪后的边界。

### 6.4 关于"最终会不会显示成白色"

你的推断是对的：**如果最外层是一整层白色，那么从外部看到的就是白色。** 但要分清两件事：

- **截面朝上**（切完平放）：最上面几层是顶壳层，会有侧面红色的投影环 → 边缘一圈红、中间白
- **截面朝下或朝内**：投影发生在底壳层，外观取决于观察方向

至于"连起来会有一条线"——**这是顶/底壳投影的固有表现，不是缺陷**。它在未切割的模型上同样存在（任何有侧面涂色的模型，其顶面边缘都会有这么一圈）。切割只是让这个现象出现在了新截面上，因而更引人注意。

> 待确认：如果实测发现这圈投影的**宽度或层数异常**（明显超过 `top_shell_layers` 配置），那才是需要排查的问题。当前观察到的形态符合机制预期。

## 7. 其他场景

同一个目标，四种场景按"新旧面之间有多少已知信息"选择成本不同的手段：

| 场景 | 新旧关系 | 手段 | 精度 |
|---|---|---|---|
| 按连通体拆分 | 只重排索引，几何完全相同 | 逐面搬运 | 完全精确 |
| 碎片合并回收 | 面顺序即拼接顺序，可推算 | 逐面搬运 | 完全精确 |
| 切割 | 有显式面映射，逐面共面 | 位流搬运 + 刀口带重绘 | 99% 精确 + 1% 近似 |
| 网格修复 | 完全重新三角化，**无任何映射** | 全网格区域重绘 | 几何近似 |

**附带修复**：轮廓切和凹槽切原先把所有碎片不分来源合并成一个 volume，导致逐部件耗材配置丢失（部件会变色）。本次改为按来源部件分组合并并继承配置。

**修复路径的两个额外处理**：

- **新增几何剔除**：修复会补洞、加面，这些面在原表面上不存在。设了模型相对阈值（源包围盒对角线 1/100），超出则保持未涂色，避免补出来的洞莫名带色。
- **操作原子性**：先重投影到临时变量，成功后才提交。中途取消时网格和涂色都保持原样。

## 11. 结论与建议

### 11.1 方案评价

**架构方向正确。**「99% 零误差搬运 + 1% 局部近似」的分解是这个问题的合理解法：它同时解决精度和性能，而不是折中。0.2mm 精度目标有明确物理依据（低于喷嘴直径与层高），可以论证"不影响打印结果"。

在不改动 3MF 格式、不改动四个绘制工具、不改动切片管线的前提下，这已接近能拿到的最好结果。

**移植质量良好。** 我方 8 行净增改动全部是数据结构适配（上游用匿名 `std::pair`，我方是具名 `TriangleSplittingData` 且多了 `used_states` 字段）。其中 4+4 行维护 `used_states` 是**必需的**——两处手工拼接位流的函数绕过了 `serialize()`，不补会导致换色校验和 3MF 导出 ID 映射出错。移植者识别出了这个陷阱并额外写了兼容回退。

**但核心洞察有个推论没被贯彻**：「位流对顶点顺序敏感」这一点，切割路径专门防守了，拆分路径漏了（9.1）。

# 最佳对象位置 X/Y 输入框首次打开时消失

## 1. 基本信息

- Bug ID：未提供。
- 日期：2026-09-21。
- 用户反馈：新版本打印机设置中，“最佳对象位置”只显示标签，原有 X/Y 输入框消失。
- 触发时机：用户确认首次打开设置页面即出现，无须切换机型、移动窗口或更改缩放。
- 模块：打印机参数界面、坐标输入控件、高 DPI 缩放。
- 引入提交：`4b604f3ee`，`fix[#18046]:【分辨率】高分屏显示异常`。
- 修复基线：`eef917f02`。

这是独立的控件布局问题；与 bug 18082 的 3MF 参数导入修复无关。这里的 `18046` 是引入提交关联的编号，不作为本次反馈的 Bug ID。

## 2. 问题现象

正常情况下，“最佳对象位置”显示 X、Y 两个输入框，默认值均为 0.50。异常版本仍显示参数标签，但两个输入框及其边框都不可见。

参数 `best_object_pos` 的定义和默认值没有改变，问题发生在控件布局阶段。

## 3. 影响范围

- 参数定义：`src/libslic3r/PrintConfig.cpp` 中的 `best_object_pos`，类型为 `coPoint`。
- 页面入口：`src/slic3r/GUI/Tab.cpp` 中打印机基本信息页面。
- 控件：`src/slic3r/GUI/Field.cpp` 中的 `PointCtrl`。
- 布局容器：`OG_CustomCtrl` 自定义参数面板。
- 同类风险：其他使用 `PointCtrl` 且由自定义参数面板管理布局的坐标参数。

## 4. 复现步骤

1. 使用包含引入提交的新版本打开打印机设置。
2. 进入基本信息中的可打印空间区域，使用能显示“最佳对象位置”的参数模式。
3. 查看“支持多种打印床类型”下方的“最佳对象位置”。
4. 实际结果：只有标签，X/Y 输入框消失。
5. 期望结果：显示 X/Y 输入框及当前参数值，并可正常编辑。

## 5. 根因分析

以下结论来自代码调用链、提交历史和本地 wxWidgets 布局复现。

`PointCtrl::BUILD()` 创建两个 `TextInput`，加入一个水平 sizer。在自定义参数面板中，该 sizer 仅用于组织两个子控件，没有加入页面的常规 sizer 布局，也没有获得布局尺寸。控件位置由 `OG_CustomCtrl::correct_widgets_position()` 直接设置。

提交 `4b604f3ee` 在 `PointCtrl::msw_rescale()` 更新控件尺寸后增加了无条件 `sizer->Layout()`。未分配尺寸的 sizer 当前尺寸为 `0×0`，调用布局后把两个输入框均压缩为 `0×0`。随后自定义布局只更新位置，没有恢复宽高，因而只剩标签可见。

这也解释了为何首次打开即触发：`Tab::activate_selected_page()` 在激活页面后主动调用 `m_active_page->msw_rescale()`，最终进入 `PointCtrl::msw_rescale()`，不需要实际发生跨屏或 DPI 变化。

## 6. 修复策略

在 `PointCtrl::msw_rescale()` 中，仅当 `parent_is_custom_ctrl` 为 false 时执行内部 sizer 的 `Layout()`。

- 自定义参数面板继续直接定位 X/Y 控件，保留刚更新的有效尺寸。
- 普通布局容器继续使用原有 sizer 布局。
- 保留字体、图标、控件最小尺寸、当前尺寸和父窗口布局更新。
- 不修改参数值、默认值及 3MF 读写逻辑。

## 7. 代码变更摘要

文件：`src/slic3r/GUI/Field.cpp`。

为 `PointCtrl::msw_rescale()` 中的 `sizer->Layout()` 添加 `!parent_is_custom_ctrl` 条件，并补充未分配尺寸的 sizer 会使控件变为零尺寸的说明。

## 9. 风险与回滚

- 修改限于自定义参数面板内的坐标控件缩放布局。
- 普通布局路径保留原调用；后续应覆盖其他使用 `PointCtrl` 的页面，确认没有依赖零尺寸内部 sizer 的隐式布局。
- 回滚方式：撤销本次 `PointCtrl::msw_rescale()` 的条件判断；回滚会重新引入首次打开时输入框消失的问题。

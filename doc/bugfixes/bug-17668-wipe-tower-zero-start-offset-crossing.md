# Bug 17668：擦拭塔起始点距离为 0 时冲刷轨迹交叉

## 1. 基本信息

- Bug ID：`17668`
- 标题：`【擦拭塔】当擦拭塔起始点距离设置为 0 时，擦拭塔冲刷线间距超过 100% 后会出现轨迹交叉重叠问题`
- 禅道链接：https://zentao.creality.com/zentao/bug-view-17668.html
- 反馈人：郭锋兴
- 处理人：`wangwenbin`
- 分支：`release-260930`
- 影响模块：Creality K3 擦拭塔、`WipeTowerCreality` 换料冲刷路径
- 处理日期：`2026-09-03`

## 2. 问题现象

### 用户反馈现象

擦拭塔起始点距离设置为 `0 mm`、冲刷线间距设置为大于 `100%` 时，预览中可以看到斜向冲刷轨迹穿过多条正常的水平冲刷线，形成交叉重叠。

### 实际结果

对用户提供的两份 G-code 进行配置和路径对比：

- `正常.gcode`：`prime_tower_start_offset = 2`，`wipe_tower_extra_spacing = 150%`；
- `异常.gcode`：`prime_tower_start_offset = 0`，`wipe_tower_extra_spacing = 150%`；
- 两份文件均为 Creality K3、`0.4 mm` 喷嘴、`0.2 mm` 层高，并关闭起始熨烫；
- 除输出统计外，切片输入配置的关键差异只有 `prime_tower_start_offset`。

第二次换料时，正常文件先空移到首条冲刷线起点，再水平挤出：

```gcode
G1 X128.000 Y235.000
G1 Y241.500 F1782
G1 X110.500 E0.6651 F2025
```

异常文件跳过起点对齐空移，从当前点直接斜向挤出到首条冲刷线终点：

```gcode
G1 X130.000 Y235.000
G1 X110.500 Y241.500 E0.7812 F2025
```

全文件扫描结果：两份文件均有 130 个 `CP TOOLCHANGE WIPE` 冲刷块；正常文件的首段斜向挤出为 0 个，异常文件为 65 个，与路径方向轮换相符。

### 期望结果

- 起始点距离为 `0 mm` 时，冲刷线从擦拭区域边界开始，不进行 X 方向内缩；
- 喷嘴仍应先空移到首条冲刷线起点，然后沿冲刷方向挤出；
- 不应生成连接当前位置与首条冲刷线终点的斜向挤出路径。

## 3. 复现步骤

### 前置条件

- 机型：Creality K3；
- 喷嘴：`0.4 mm`；
- 层高：`0.2 mm`；
- 启用擦拭塔和多耗材换料；
- 起始熨烫：关闭；
- 擦拭塔冲刷线间距：`150%`；
- 擦拭塔起始点距离：`0 mm`。

### 操作步骤

1. 导入包含换料的多耗材模型。
2. 启用擦拭塔。
3. 将冲刷线间距设置为 `150%`。
4. 将擦拭塔起始点距离设置为 `0 mm`。
5. 执行切片并查看擦拭塔换料冲刷路径。
6. 导出 G-code，检查 `CP TOOLCHANGE WIPE` 后的第一条带 E 移动。

### 复现结果

部分路径方向下，第一条带 E 移动同时改变 X、Y 坐标，形成贯穿冲刷区域的斜向挤出，并与后续水平冲刷线相交。

### 复现概率

用户提供的异常 G-code 中 130 个换料冲刷块有 65 个出现首段斜向挤出，即在当前四层方向轮换路径下每隔一个方向稳定出现。

## 4. 根因分析

### 触发条件

- `prime_tower_start_ironing` 为关闭；
- `prime_tower_start_offset` 为 `0`；
- 换料后的当前位置与计算出的首条冲刷线起点不一致；
- 间距大于 `100%` 后冲刷线之间出现可见空隙，使错误斜线更加明显。

### 代码链路

1. `WipeTowerCreality::tool_change()` 创建换料冲刷区域，并调用 `toolchange_Change()` 和 `toolchange_Wipe()`。
2. `toolchange_Change()` 将 Writer 的当前位置设置为换料后返回擦拭塔的位置。
3. `toolchange_Wipe()` 根据当前层方向计算首条冲刷线的 `first_y`，并通过 `purge_start_pos()` 计算实际起点。
4. 原逻辑只有在 `purge_start_offset > WT_EPSILON` 时才调用 `writer.travel()` 对齐到实际起点。
5. 当起始点距离为 `0` 时，对齐空移被跳过，随后 `writer.extrude()` 直接从换料后当前位置挤出到首条冲刷线终点。
6. `writer.extrude()` 按当前位置与目标位置的二维距离计算挤出量，因此生成同时改变 X、Y 的斜向挤出路径。

### 问题原因

代码错误地把两个独立语义绑定在同一个判断上：

- 起始点距离只应决定“冲刷起点在 X 方向内缩多少”；
- 是否需要空移应由“当前位置是否等于实际冲刷起点”决定。

原判断将“起始点不内缩”错误理解为“无需移动到起点”。最容易记忆的结论是：

> 距离决定起点在哪里，位置差决定是否要走过去。

`150%` 间距不是根因。本例线宽为 `0.5 mm`、线中心间距为 `0.75 mm`，线间空隙使斜向路径更容易被观察到。

## 5. 修复方案

### 修复思路

将冲刷起点坐标计算与起点对齐判断解耦：

1. 无论起始点距离是否为 0，都先计算 `first_wipe_start`；
2. 起始熨烫关闭时，比较 Writer 当前位置与 `first_wipe_start`；
3. 两点不一致时，通过不带 E 的 `writer.travel()` 移动到实际起点；
4. 两点已经一致时，不生成无意义的零距离移动；
5. 起始点距离仍只参与 X 坐标计算，不改变冲刷量、线间距和擦拭塔规划深度。

### 修改点

- 文件：`src/libslic3r/FDM/WipeTowerCreality.cpp`
- 函数：`WipeTowerCreality::toolchange_Wipe()`
- 多行冲刷分支：删除 `purge_start_offset > WT_EPSILON` 对起点空移的控制，改为比较当前位置与 `first_wipe_start`。
- 单行冲刷分支：采用相同判断，避免退化场景再次出现斜向挤出。

修复后的核心逻辑：

```cpp
const Vec2f first_wipe_start = purge_start_pos(left_to_right, y);
if ((writer.pos() - first_wipe_start).squaredNorm() > WT_EPSILON * WT_EPSILON)
    writer.travel(first_wipe_start, wipe_speed);
```

## 7. 风险与回退

### 可能风险

- 起始点距离为 0 且当前位置不在首条冲刷线起点时，会新增一段无 E 空移；需要确认该移动不会与特殊擦拭塔外墙或自定义换料路径冲突。
- 单行冲刷区域同样增加位置差判断，需要覆盖极小冲刷量场景。

### 风险影响范围

- 仅影响 `WipeTowerCreality::toolchange_Wipe()` 中关闭起始熨烫后的冲刷入口定位。
- 不改变起始熨烫路径、冲刷线间距公式、冲刷量、塔深规划及其他擦拭塔实现。

### 回退方案

- 回退 `src/libslic3r/FDM/WipeTowerCreality.cpp` 中两个 `first_wipe_start` 位置差判断，恢复原有 `purge_start_offset > WT_EPSILON` 条件。
- 若已提交，可回退对应修复提交，不需要迁移配置或用户数据。

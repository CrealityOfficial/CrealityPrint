# Bug 17685：【F039】左上角喷嘴口径显示异常

## 结论

2026-09-10 补齐另存为场景：单喷嘴旧预设以正式预设的 `printer_variant` 为规格身份，候选列表、当前选中项、显示和点击切换使用同一规格字符串。`nozzle_diameter` 保留为可编辑的实际参数。规格为 `0.4` 时，将参数改成 `0.99` 并另存为，主界面仍显示 `0.4-标准`，设置页保留 `0.99`。多喷嘴及结构化喷嘴变体沿用现有路径。

## 2. 问题现象

### 用户反馈现象

- 补充场景：将 K2 Plus 的喷嘴口径改为 `0.99` 后另存为，选中新用户预设，主界面原来的 `0.4-标准` 变成 `1.0-标准`，设置页仍为 `0.99`。

选择 `Creality K2 Plus 0.4 nozzle` 后进入打印机设置，将喷嘴口径由 `0.4` 临时修改为 `0.66`，主界面左上角喷嘴口径随即显示为 `0.7-标准`。

### 实际结果

- 打印机设置左侧仍选中 `Creality K2 Plus 0.4 nozzle`，但主界面喷嘴口径显示成 `0.7-标准`。
- `0.66` 还会被临时加入喷嘴候选集合；它没有对应的正式系统喷嘴预设，点击后可能无法完成预设切换。
- 显示的 `0.7` 来自 `0.66` 按一位小数格式化，并不是配置被自动改成了 `0.7`。

### 期望结果

- 尚未保存的参数编辑只影响编辑副本和脏状态，不改变主界面当前打印机/喷嘴预设身份。
- 当前正式选中 `Creality K2 Plus 0.4 nozzle` 时，左上角仍显示 `0.4-标准`。
- 只有用户正式切换到其他喷嘴预设后，左上角口径才随正式预设变化。

## 4. 根因分析

### 触发条件

问题只发生在“单喷嘴、无结构化 `nozzle_variant_*` 元数据”的旧预设兼容路径。K2 Plus 当前四个系统预设均属于该路径。

### 代码链路

```text
打印机设置修改 nozzle_diameter=0.66
  -> 值写入 PresetCollection::get_edited_preset()
  -> ObjectList::render_printer_preset_by_ImGui()
  -> SidebarPrinter::nozzle_items(0)
  -> PresetBundle::get_nozzle_variants(0)
  -> 从 get_edited_preset() 读取 0.66，并与系统兄弟预设口径一起生成候选项
  -> SidebarPrinter::get_selection_nozzle_variant(0) 再次读取编辑值 0.66
  -> GUI 按 %.1f 格式化
  -> 左上角显示 0.7-标准
```

涉及的关键逻辑：

- `PresetBundle::get_nozzle_variants()` 从 `printers.get_edited_preset()` 读取基础喷嘴口径。
- 旧预设兼容分支会先把该编辑口径加入候选集合，再扫描同机型系统喷嘴预设。
- `SidebarPrinter::get_selection_nozzle_variant()` 修复前也使用编辑副本确定当前选中项。
- `GUI_ObjectList.cpp` 使用 `boost::format("%.1f")` 生成显示标签，因此 `0.66` 显示为 `0.7`。

### 问题原因

2026-09-10 补充：`88b913d99` 只把读取来源从编辑副本改成正式预设，仍然用 `nozzle_diameter` 生成规格映射并匹配当前项。另存为会把 0.99 保存到正式预设并选中它，因此仍会进入候选，随后被 `%.1f` 显示为 1.0。根因是规格身份与实际参数混用，不能只修改显示精度。

新版 Bambu 2.08.02.61 的 `Plater.cpp` 口径下拉框读取 `printer_variant`；`PresetCollection::diameters_of_selected_printer()` 收集同机型的该字段；`switch_diameter()` 按规格查找并切换整机预设。这段界面读取编辑副本，但读取的是规格字段，不是 `nozzle_diameter`。双喷嘴左右口径不同时，该切换路径要求选一个口径，不能照搬到 K3 独立物理喷嘴变体。以上为本地源码对照，未运行 Bambu GUI。

以下为首次修复的原因记录：

左上角单喷嘴选择器实际承担的是“正式喷嘴预设选择”职责，但旧逻辑把“预设身份”和“编辑中的参数值”混在了一起：

| 状态 | 正确职责 | 修复前错误用途 |
| --- | --- | --- |
| `get_selected_preset()` | 当前正式选中的打印机预设身份 | 未用于旧单喷嘴当前项判断 |
| `get_edited_preset()` | 设置页正在编辑、可能尚未保存的参数副本 | 被用来生成并选中左上角喷嘴项 |
| `PrinterMachineItem::nozzle_presets` | 当前逻辑机型下可实际切换的正式喷嘴预设映射 | 修复前未作为喷嘴列表的唯一来源 |

Bambu 的对应预设选择逻辑以正式选中预设为准：列表项取 `preset.name`，从预设集合刷新时使用 `get_selected_preset().name`，不会用未保存的喷嘴编辑值重写当前预设身份。

## 5. 修复方案

### 修复思路

- 单喷嘴且无结构化喷嘴元数据：正式预设的规格身份驱动选择器，实际直径参数独立保存。
- 规格优先取自身非空 `printer_variant`；缺失时沿正式父预设查找，防止父链循环，也避免父预设查询返回编辑副本。整条父链均无规格时，回退到当前正式预设口径的配置序列化文本，不解析预设名称、不固定成 0.4。
- 无规格且无可用父规格的独立旧配置无法恢复原始规格身份，此时覆盖保存实际口径后，兼容显示也会随正式保存值变化；这是缺失身份元数据时的兼容边界。
- 用户/项目预设保持独立机型身份，不按相同 `printer_model` 合并。
- 多物理喷嘴或结构化变体继续使用现有 `get_nozzle_variants()` 和项目 `variant_id/index` 路径。

### 修改点

1. `src/slic3r/GUI/SiderBar.h`：`nozzle_presets` 改成“规格字符串 → 预设名称”映射。
2. `src/slic3r/GUI/SiderBar.cpp`：新增统一规格解析入口；单喷嘴旧预设的候选和默认 0.4 规格判断按规格进行；`nozzle_items()` 将规格放入该 UI 路径的 `variant_id`，数值口径仅作为硬件口径比较的投影；当前项按规格字符串匹配，点击按同一键查找真实预设。非数值规格保留原标签，数值投影为 0，不从标签猜实际口径。
3. `src/slic3r/GUI/GUI_ObjectList.cpp`：单喷嘴旧预设直接显示规格字符串，不再用 `%.1f` 重建规格；结构化和多喷嘴标签沿用原逻辑。
4. 不修改保存逻辑和 `nozzle_diameter`，不修改切片参数物化。另存为继续保存编辑配置并选中新预设。

## 7. 风险与回退

### 可能风险

- 单喷嘴旧预设的候选项现在依赖 `printer_selector_model()` 中的正式 `nozzle_presets` 映射；如果参数包没有为当前机型建立有效预设映射，喷嘴列表可能为空。
- 2026-09-10 已补齐另存为场景：单喷嘴旧预设直接显示规格字符串。缺失规格时的回退行为见修复方案；结构化及多喷嘴显示精度不在本次范围内。

### 风险影响范围

仅影响单喷嘴、非结构化旧预设的左上角喷嘴列表生成、当前项判断和点击切换。多喷嘴、结构化喷嘴变体、切片参数物化及 G-code 逻辑未修改。

### 回退方案

本次补充修复可整体回退 `SiderBar.cpp`、`SiderBar.h`、`GUI_ObjectList.cpp` 的本次差异，无配置文件迁移。以下是首次修复的回退点：

- `SidebarPrinter::nozzle_items()` 的正式预设列表分支。
- `SidebarPrinter::get_selection_nozzle_variant()` 的正式选中预设读取。
- `apply_nozzle_variant_change()` 对统一候选列表的复用。

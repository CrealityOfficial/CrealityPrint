2. 问题现象

盘名称输入框（以及 AI 侧的重命名接口）未对输入长度做限制，用户可以输入超过 20 个字符的盘名。Bug 描述中仅给出简略步骤，但实际排查发现该限制在多个盘名修改入口均缺失或失效。

⚠ 关键发现：该 Bug 不是一个"代码忘记写了"的问题，而是部分入口有限制但被覆盖、部分入口完全没有限制、核心数据层无防御的多入口系统性缺陷。

3. 根因分析

3.1 盘名修改的 4 个入口点

系统中存在以下独立路径可以修改盘名，每个路径的状态如下：

入口文件原状态问题
① 右键编辑盘名对话框 PlateSettingsDialog.cpp
PlateNameEditDialog		 部分有限制 wxEVT_TEXT 事件中做了截断，但 SetMaxLength(250) 与之矛盾，输入框允许输入 250 个字符后再被截断
② 板设置面板 PlateSettingsDialog.cpp
PlateSettingsDialog		 无限制 完全没有任何字符数限制
③ AI 桥接重命名 SlicerBridgeActionsObject.cpp
DoRenamePlate()		 无限制 AI / MCP 调用直达 set_plate_name()，无长度校验
④ 核心数据层 PartPlate.cpp
PartPlate::set_plate_name()		 无防御 所有路径的最终汇聚点，直接接受任意长度字符串

3.2 问题本质

原有代码只在 UI 层一个对话框中做了非强制限制（事件截断 + 矛盾的 MaxLength），其他入口完全绕过，且核心数据层没有任何防御性校验。这是典型的"只在表现层做了部分限制，遗漏了其他入口和数据层"的防御缺失问题。

4. 设计思路

4.1 修复策略：纵深防御（Defense in Depth）

采用三层防御架构，确保无论从哪个入口修改盘名，都会被限制在 20 个字符以内：

4.2 为什么需要核心层防御？

💡 设计原则：UI 层限制可能被绕过（粘贴、编程调用、外部 Agent），只有在数据写入的最终汇聚点做校验，才能保证 任何 代码路径都不会产生超长盘名。

核心层使用 wxString::Length() + wxString::Left(20) 进行 Unicode 安全截断，而非简单的字节截断，确保中英文混合名称不会出现乱码。

4.3 为什么不只在核心层做？

UI 层限制提供即时反馈——用户在输入时就能感知到限制（输入框无法继续输入），而非提交后才被静默截断。三层各司其职：

层职责用户体验
UI 层输入即限制，提供即时反馈打第 21 个字时输不进去
Bridge 层AI 调用时截断并返回实际名称AI 收到的响应中包含截断后的名称
核心层最后一道安全网，防御所有绕过透明，无感知

5. 修复方案

5.1 核心层：PartPlate::set_plate_name()

📄 C3DSlicer/src/slic3r/GUI/PartPlate.cpp — 行 2028~2047

void PartPlate::set_plate_name(const std::string& name) 
{ 
    // fix:[16411] Limit plate name to 20 characters
    std::string truncated_name = name;
    wxString wx_name = from_u8(name);
    if (wx_name.Length() > 20) {
        wx_name = wx_name.Left(20);
        truncated_name = wx_name.ToUTF8().data();
    }

    // compare if name equal to m_name, case sensitive
    if (boost::equals(m_name, truncated_name))
        return;

    m_name = truncated_name;
    if (m_print != nullptr)
        m_print->set_plate_name(truncated_name);

    generate_plate_name_texture();
}

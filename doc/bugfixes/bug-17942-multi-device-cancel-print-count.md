# Bug 修复记录

## 1. 基本信息
- Bug ID: `17942`
- 禅道链接: `https://zentao.creality.com/zentao/bug-view-17942.html`
- 标题: `多机发送打印时，取消发送也会统计为成功打印次数`
- 处理日期: `2026-09-16`
- 所属产品: `Creality Print`
- 所属模块: `用户满意度调查 / 多设备发送打印`
- Bug 类型: `代码错误`

## 2. 问题现象
- 在“发送到多设备”页面选择设备并点击“开始打印”。
- 软件先进入设备页面并打开“任务传输”窗口。
- 在文件传输完成前点击“取消发送”，设备没有开始打印，但满意度调查使用的成功打印次数仍然增加 `1`。
- 普通单设备发送页面在传输完成后才进入设备详情页，因此取消传输时不会出现同样的提前计数。

## 3. 重现信息
- `[前置条件]` 使用可参与满意度调查打印次数统计的创想设备。
- `[步骤]` 从多设备发送页面选择一台或多台设备，点击“开始打印”，在任务传输窗口中取消发送。
- `[结果]` 文件传输被取消，打印机没有开始打印，但成功打印次数增加。
- `[期望]` 取消或传输失败的任务不计入成功打印次数；同一次多设备操作只要至少一台创想设备成功进入打印阶段，整次操作只计 `1` 次。

## 4. 影响范围
- 模块:
  - `多设备发送打印`
  - `用户满意度调查打印次数统计`
- 关键文件:
  - `src/slic3r/GUI/SatisfactionSurveyIntegration.cpp`
  - `src/slic3r/GUI/SatisfactionSurveyIntegration.hpp`
  - `src/slic3r/GUI/print_manage/App/PrinterMgrView.cpp`
- 不受影响的计数入口:
  - 普通单设备发送打印
  - 设备详情页发起打印
  - AI 发起打印
  - 多设备“仅发送”

## 5. 根因分析
- 多设备页面点击“开始打印”后，会立即发送 `forward_device_detail` 消息，其中携带 `action=print` 和设备地址列表。
- 该消息的实际含义是“进入设备页面并创建批量上传任务”，此时文件尚未传输完成，打印命令也尚未下发。
- 满意度调查原实现将这个页面跳转消息直接视为成功打印事件，立即调用 `record_successful_print()` 保存计数。
- 任务传输窗口后续执行的取消操作只会终止上传并更新上传状态，没有回滚已经保存的满意度打印次数。
- 因此，表面现象与“先进入设备页面、再显示任务传输窗口”的流程有关，底层原因是统计触发点错误地位于传输开始之前。

## 6. 修复策略
- 多设备 `forward_device_detail(action=print)` 不再立即增加成功打印次数，只登记一次待处理的批量打印操作。
- 为每次多设备打印操作生成进程内唯一指纹，并保存尚未结束的设备地址集合。
- 复用现有多设备上传终态回调:
  - 上传取消或失败时，从待处理操作中移除对应设备。
  - 上传完成消息成功交给设备页面后，首台符合条件的创想设备触发一次成功打印计数。
- 首次成功计数后删除整次待处理操作，确保其他设备、延迟批次和后续完成回调不会重复计数。
- 没有匹配待处理操作的上传回调直接忽略，因此不改变普通上传和其他打印入口的既有统计逻辑。

## 7. 代码改动摘要
- 文件: `src/slic3r/GUI/SatisfactionSurveyIntegration.cpp`
  - 新增多设备待处理操作状态，记录剩余设备和操作指纹。
  - 将多设备页面跳转消息从“立即计数”改为“登记待处理操作”。
  - 根据设备上传成功、失败或取消结果维护操作状态。
  - 首台有效创想设备上传完成后计数一次，并清除整次操作。

- 文件: `src/slic3r/GUI/print_manage/App/PrinterMgrView.cpp`
  - 上传失败或取消时通知满意度集成层清理对应设备。
  - 上传完成消息成功交给页面后通知满意度集成层处理成功结果。

## 8. 计数规则
| 多设备操作结果 | 成功打印次数 |
| --- | ---: |
| 所有设备取消 | `+0` |
| 所有设备传输失败 | `+0` |
| 部分设备成功、部分取消或失败 | `+1` |
| 所有设备成功 | `+1` |
| 同一次操作包含延迟批次 | 合计 `+1` |
| 多设备仅发送文件 | `+0` |

## 10. 风险与回滚
- 风险等级: `低`
- 主要风险:
  - 当前成功触发点与现有多设备业务一致，位于上传完成消息交给页面之后；它表示即将进入打印命令阶段，并非打印机状态上报已经明确进入打印中。
  - 待处理状态保存在当前进程内；软件退出后状态自动清除，不会把未完成操作带到下一次启动。
  - 若设备页面忙碌而未接收上传完成消息，本次不会计数，与实际未继续执行打印的结果一致。
- 回滚方案:
  - 回滚 `SatisfactionSurveyIntegration` 中多设备待处理操作及上传结果处理逻辑。
  - 回滚 `PrinterMgrView` 中上传终态通知调用，恢复多设备页面跳转时直接计数的旧行为。

## 11. 业务场景（大白话）
- 用户正在做什么：在多设备页面选择若干打印机，点击开始打印，然后在任务传输窗口取消其中或全部发送任务。
- 程序后台正在做什么：先进入设备页面、创建批量上传任务，再逐台上传文件；上传完成后才继续准备打印。
- 哪个对象或状态出了问题：满意度统计把最开始的“准备批量打印”页面消息误当成了“已经成功打印”。
- 为什么会出现这种行为：统计发生得太早，而后续取消上传没有对应的计数回滚机制。
- 用户最终看到什么：修复前即使取消发送，成功打印次数也会增加；修复后全部取消或失败不计数，只要至少一台创想设备成功进入后续打印阶段，整次多设备操作计一次。

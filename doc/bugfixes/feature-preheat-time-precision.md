# 预热时间插入精度优化说明

## 1. 基本信息
- Bug ID: 无
- 标题: `预热时间插入精度优化`
- 反馈人: 李佳沁
- 处理人: `wangwenbin`
- 影响模块/影响文件:
  - `src/libslic3r/GCode/GCodeProcessor.cpp`
  - G-code 后处理预热插入逻辑

## 2. 现象与复现
- 复现场景:
  - 开启“喷嘴预热/防滴漏”相关功能。
  - 多喷嘴打印中发生 `Tn` 换刀。
  - 设置 `preheat_time`，例如 `12s` 或 `30s`。
- 实际结果:
  - 预热 `M104` 有时没有尽量插入到用户设置的提前时间附近。
  - 部分兜底路径会将注释中的 `preheat Tn time:` 钳制到目标值，导致注释看起来接近用户设置，但不一定反映真实提前量。
  - 连续换刀或当前段可用时间不足时，不容易从 G-code 判断偏差原因。
- 期望结果:
  - 尽量在下一次 `Tn` 换刀前 `preheat_time` 秒插入 `M104`。
  - 优先按用户设置的提前时间查找插入点，允许跨越早前 `Tn`，但不跨越归零/开头类安全边界。
  - 注释显示真实提前量、用户设置值、当前段可用总时间，便于排查。

## 4. 根因分析
- 触发条件:
  - 启用 `ooze_prevention` 且 `preheat_time > 0`。
  - 多喷嘴或 XL 相关场景中，G-code 后处理遇到 `Tn` 换刀行后向前回溯插入预热命令。
- 代码链路:
  - `GCodeProcessor::run_post_process()`
  - `process_line_T()`
  - `ExportLines::insert_lines()`
- 为什么会出现该现象:
  - 原逻辑以回溯阈值和容差判断插入点，并在不满足容差时优先使用 `M104 ... ;cooldown` 或 `Tn` 前位置兜底。
  - 兜底位置不一定最接近用户设置的 `preheat_time`。
  - 兜底时对注释时间做 `clamp`，可能隐藏真实提前量。
  - 对连续换刀场景，如果把 `Tn` 作为硬边界，当前段时间不足时只能插到段首，无法严格贴近用户设置值。

## 5. 修复方案
- 修复思路:
  - 将 `preheat_time` 语义收敛为：尽量在下一次 `Tn` 换刀前指定秒数插入 `M104`。
  - 从当前 `Tn` 向前回溯到最近安全边界，允许跨越早前 `Tn`，收集候选插入点并选择与用户设置值误差最小的位置。
  - 注释输出真实数据，不再用钳制值掩盖偏差。
- 修改点:
  - 在 `ExportLines` 中新增 `InsertionTiming`，传递实际提前时间、目标时间、当前段可用时间、安全搜索窗口和插入模式。
  - 将安全搜索边界限制为 `G28/G29`、`PRINT_START/START_PRINT`；`Tn` 只用于标记当前换刀段和判断是否跨段。
  - `append_line()` 记录最近 `Tn` 或安全边界时间，用于判断插入点是否跨越早前换刀。
  - `insert_lines()` 改为扫描到最近安全边界，并选择最接近 `preheat_time` 的候选点。确定插入点后，只清理插入点之后、目标换刀之前、与预热喷嘴相同的 `cooldown`；其他喷嘴的 `cooldown` 保持不变。
  - 非 XL 预热注释格式调整为:
```gcode
M104 S220 T1 ; preheat T1 time: 11s target:12s available:50s search:132s mode:closest
```
- 字段含义:
  - `time`: 实际提前量，也就是插入点到下一次 `Tn` 的预计时间。
  - `target`: 用户设置的 `preheat_time`。
  - `available`: 当前 `Tn` 到上一个 `Tn` 或安全边界之间的可用总时间。
  - `search`: 允许跨越早前 `Tn` 后，到最近安全边界或缓存限制之间的可搜索时间；它用于排查搜索窗口，不代表当前段长度。
  - `mode`: 插入策略结果。
- 为什么这样改:
  - 用户设置值仍作为唯一目标，不引入物理升温模型。
  - 搜索窗口内最近点选择比旧兜底策略更贴近用户设置。
  - `time/target/available/search/mode` 能直接说明本次预热是否准确，以及是否跨越早前 `Tn` 或受搜索窗口不足影响。

## 6. 影响范围与风险
- 正向影响:
  - `M104` 更优先贴近用户设置的提前时间，当前段不足时可跨早前 `Tn` 查找。
  - 连续换刀场景下，预热可跨早前 `Tn` 追求目标时间，但不会越过归零/开头类安全边界。
  - G-code 注释能反映真实提前量、当前换刀段长度和安全搜索窗口，便于测试和问题定位。
- 可能风险:
  - 旧逻辑优先在 `cooldown` 前插入预热；新逻辑改为优先选择时间最接近的点，部分模型的预热位置可能变化。
  - `preheat_steps > 1` 时，仍按分步目标时间插入，每一步都限制在安全搜索窗口内。
- 是否改变旧行为:
  - 改变预热 `M104` 插入点选择策略。
  - 改变非 XL 预热注释内容，保留原有 `preheat Tn time:` 前缀并追加 `target/available/search/mode`。

## 7. 回归建议
- 必测场景:
  - 当前换刀段约 `50s`，`preheat_time=12s`，检查 `time` 是否接近 `12s`。
  - 当前换刀段约 `8s`，`preheat_time=12s`，但早前 `Tn` 之前仍有可用时间时，检查是否可跨段找到接近 `12s` 的点，且 `mode:crossed_toolchange`。
  - 连续换刀 `T1 -> T2 -> T0`，确认可按用户设置时间跨早前 `Tn` 查找，但不跨越 `G28/G29/PRINT_START/START_PRINT`。
- 边界场景:
  - 当前段内无普通运动候选，确认 `mode:before_toolchange` 可兜底插到 `Tn` 前。
  - 安全搜索窗口可用时间小于目标时间，确认 `mode:search_start`。
  - XL 机型 `M104.1` 路径，确认 `P/Q` 时间仍按实际候选点输出。
- 反向场景:
  - 未开启 `ooze_prevention` 或 `preheat_time=0`，不应插入预热 `M104`。
  - 单喷嘴非 XL 场景，不应启用预热回溯。

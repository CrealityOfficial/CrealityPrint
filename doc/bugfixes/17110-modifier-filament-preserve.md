# 17110 修改组合体颜色时保留修改器耗材选择

## 1. 基本信息
- Bug ID: 17110
- 标题: 修改组合体的颜色时不应该重置修改器的颜色选择
- 反馈人: 未提供
- 处理人: wangwenbin
- 影响模块/影响文件: 左侧对象列表耗材选择，`src/slic3r/GUI/GUI_ObjectList.cpp`

## 2. 现象与复现
- 复现场景: 导入立方体模型，添加参数修改器圆柱体，修改器选择耗材 2；切片正常后，在对象列表将立方体默认耗材从 1 改为 3。
- 实际结果: 修改器界面仍可能显示耗材 2，但底层配置丢失修改器耗材，重新切片后 G-code 只使用耗材 3。
- 期望结果: 修改组合体/对象耗材时，只更新对象及普通模型零件继承关系，不应清除修改器已有的独立耗材选择。

## 4. 根因分析
- 触发条件: 对象节点通过左侧对象列表的耗材下拉切换耗材。
- 代码链路: 下拉选择后调用 `ObjectList::update_filament_in_config()`，对象节点更新 `extruder` 后遍历对象全部 `ModelVolume`，删除子 volume 的 `extruder`。
- 为什么会出现该现象: 该逻辑未区分普通模型零件与 `PARAMETER_MODIFIER`。普通模型零件可以清除 `extruder` 以继承对象耗材，但参数修改器的显式耗材也被删除后，会变成继承对象耗材，导致切片使用耗材统计变为单色。

## 5. 修复方案
- 修复思路: 对象耗材变更时，只清理普通模型零件 `MODEL_PART` 的 `extruder`，保留参数修改器的独立配置。
- 修改点: `src/slic3r/GUI/GUI_ObjectList.cpp` 中 `ObjectList::update_filament_in_config()` 的子 volume 清理条件增加 `mv->type() == ModelVolumeType::MODEL_PART`。
- 为什么这样改: 与 `set_extruder_for_selected_items()` 已有逻辑保持一致，避免两个对象耗材修改入口行为不一致。

## 6. 影响范围与风险
- 正向影响: 对象改色不再破坏修改器的独立耗材选择，G-code 会继续包含修改器耗材。
- 可能风险: 普通模型零件仍会继承对象耗材，修改器不再被对象改色隐式重置。
- 是否改变旧行为: 仅改变参数修改器在对象改色时被清空耗材的旧行为。

## 7. 回归建议
- 必测场景: 立方体 + 圆柱参数修改器，修改器耗材 2，对象耗材改为 3 后重新切片，确认 G-code 同时使用耗材 2 和 3。
- 边界场景: 普通多零件组合体对象改耗材，确认普通零件仍继承对象耗材。
- 反向场景: 修改器选择 default 后对象改耗材，确认修改器按 default 继承对象耗材。

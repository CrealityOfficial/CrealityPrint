## 2. 问题现象

- 用户反馈：选择延时摄影“平滑模式”后，仍可以选择“花瓶模式”和勾选“无稀疏层”，需要参考 Bambu 优化冲突处理。
- 实际结果：平滑模式与无稀疏层缺少双向联动；花瓶模式虽已有参数约束，但全局与盘级配置处理存在缺口，可能保留冲突组合或出现界面与配置不一致。
- 期望结果：平滑模式分别与花瓶模式、无稀疏层互斥；修改时提示并调整关联参数，切片前拦截残留冲突配置。
- 本次处理的是上述两组冲突，不代表花瓶模式与无稀疏层本身互斥。

## 4. 根因分析

### 4.1 平滑模式与无稀疏层缺少双向处理

`Tab::on_value_change()` 原来的 `timelapse_type` 分支只处理是否开启擦拭塔，没有处理 `wipe_tower_no_sparse_layers`；勾选无稀疏层也没有反向调整摄影模式。

平滑摄影需要每层都有擦拭塔用于停靠，而无稀疏层会跳过没有实际换料的塔层，两者的塔层需求冲突。当前工程多条擦拭塔和 G-code 路径直接读取该选项，不能仅依赖某个界面控件的显示状态避免冲突。

### 4.2 花瓶模式的配置层级处理不完整

- `ConfigManipulation::update_print_fff_config()` 原有规则要求花瓶模式使用传统摄影，但主要检查当前配置，未覆盖全局修改时的盘级花瓶开关，也未完整处理局部花瓶配置与全局摄影配置的联动。
- `PartPlate::set_vase_mode_related_object_config()` 原来将 `timelapse_type=tlTraditional` 放进对象配置调整集合，没有直接修改全局摄影设置，导致全局选项可能仍保留平滑模式。
- `TabPrintPlate::on_value_change()` 原来先写入盘级 `spiral_mode`，再调用 `PartPlate::set_spiral_vase_mode()`。启用函数检查到已经开启后提前返回，跳过确认和关联参数调整。

### 4.3 切片前缺少这两组冲突的统一校验

`Print::validate()` 原来没有显式拦截“平滑模式 + 花瓶模式”和“平滑模式 + 无稀疏层”。导入项目等未经过交互联动的配置仍可能进入后续切片流程。

## 5. 修复方案

### 修复思路

参考用户指定的本地 Bambu 源码，补齐双向交互及跨配置层级联动。结合当前工程擦拭塔实现，在 `Print::validate()` 统一拒绝残留冲突配置，明确提示用户调整参数。

| 操作或状态 | 修复后的处理 |
| --- | --- |
| 已勾选无稀疏层，再选择平滑模式 | 提示不兼容，自动取消无稀疏层 |
| 已选择平滑模式，再勾选无稀疏层 | 提示不兼容，自动切换为传统摄影 |
| 全局参数检查发现花瓶与平滑模式冲突 | 沿用花瓶确认对话框；同意则切为传统摄影，拒绝则关闭相关花瓶开关，包括显式启用花瓶的盘 |
| 从盘级入口启用花瓶模式 | 先检查原状态并确认；接受后调整对象参数，同时将全局摄影改为传统模式；拒绝时不启用，并回读实际配置刷新参数页 |
| 导入等入口带入上述冲突组合 | 切片前返回明确错误，要求修改参数后再切片 |

对象配置入口继续沿用原有花瓶提示形式，不额外增加新的确认方式。

### 修改点

| 文件 | 关键修改 |
| --- | --- |
| `src/slic3r/GUI/Tab.cpp` | 增加平滑模式与无稀疏层的双向提示、写回与场景刷新；是否提示开启擦拭塔改为读取联动后的实际摄影配置；盘级花瓶交由 setter 处理，随后回读配置 |
| `src/slic3r/GUI/ConfigManipulation.cpp` | 全局检查遍历盘级花瓶开关，局部检查关联全局摄影值；确认后同步全局摄影、脏标记和参数显示；拒绝时处理相关盘级花瓶开关 |
| `src/slic3r/GUI/PartPlate.cpp` | 将传统摄影写入全局工艺配置，并刷新全局工艺显示与脏标记 |
| `src/libslic3r/Print.cpp` | 在 `Print::validate()` 增加两组冲突校验，分别关联 `timelapse_type` 和 `wipe_tower_no_sparse_layers` |
| `localization/i18n/zh_CN/CrealityPrint_zh_CN.po` | 增加两条交互提示和两条切片校验提示的简体中文翻译 |

与参考实现的区别：本地 Bambu 在擦拭塔跳层判定中使平滑模式不执行跳层；本次采用切片前报错的统一兜底，避免当前工程不同塔路径对同一冲突配置产生不同解释。

# Bug 17857：切片所有盘完成后再显示总览统计

## 2. 问题现象

多盘工程首次切片完成后，移动盘 2 的模型，再执行“切片所有盘”，进度仍为 95% 时已经出现统计表。

禅道期望为“进度 100% 完成后，统计表才显示”。本次修复进一步明确界面顺序：先显示 100% 进度，保留约 200 毫秒，再隐藏进度并显示总览统计表。总览模式不加载单盘刀路渲染数据。

## 3. 影响范围

- 模块：切片预览、所有盘统计、切片进度通知。
- 主要流程：多个非空盘的“切片所有盘”、复用已有切片结果、总览切换到单盘预览。
- 总览统计继续使用各盘的 CPU 切片结果；模型外壳仍可刷新。
- 只有一个非空盘时不走新增的总览加载跳过分支。
- 不修改切片算法、G-code 内容或统计计算公式。

## 4. 修复前复现步骤

1. 打开包含多个盘的工程。禅道附件为 `16拉布布 (3).3mf`。
2. 执行“切片所有盘”，等待首次切片成功。
3. 返回准备界面，移动盘 2 的任意模型。
4. 再执行“切片所有盘”。
5. 观察进度与统计表：进度显示 95% 时，统计表已经显示。

## 5. 根因分析

以下调用链与时序结论来自代码分析；禅道页面提供的是复现现象与期望。

1. `Plater::priv::on_process_completed()` 在最后一盘完成时，通过场景更新和 `reload_print(false)` 进入完整预览加载。
2. `Preview::load_print_as_fff()` 原本未区分总览与单盘刀路预览，结果有效时仍调用 `load_gcode_preview()`，最终进入 `BaseRenderer::load()`。
3. `BaseRenderer::load()` 会设置 95% 的 `Loading display data` 进度并处理消息循环，此时统计表可以被绘制。
4. 总览统计的显示条件原本只检查各盘结果有效、可打印且包含移动数据，未等待切片流程的 UI 收尾。
5. 单纯设置 100% 后立即隐藏进度，不能保证用户看到 100%。此外，`SlicingProgressNotification` 原本只在 `SP_PROGRESS` 状态绘制底部进度条，进入 `SP_COMPLETED` 后也不会绘制该进度条。

## 6. 修复策略

### 6.1 总览跳过刀路渲染加载

`Preview::load_print_as_fff()` 在多个非空盘且处于总览选择状态，或正在执行所有盘切片时，刷新外壳后直接返回，跳过刀路缓冲区构建。

此分支清空 `m_loaded_print`，避免把未加载刀路的盘误认为已经完成预览加载。执行单盘切片或选择具体盘时，先清除总览选择，再走原有的单盘加载流程。

### 6.2 全部切片收尾后进入完成过渡

`on_process_completed()` 在最终预览刷新之后才清除 `m_is_slicing`。成功且仍选中总览时，由 `finish_slicing_progress_before_overview()` 设置 100% 并开启完成过渡，不再依赖刀路加载器隐藏进度。

统计表在原有结果有效性判断之外，还要求：

- 所有盘切片流程已经退出切片状态。
- 后台切片进程不再运行。
- 100% 完成过渡已经结束。

等待期间，总览不绘制此前加载过的单盘刀路。

### 6.3 先绘制 100%，再显示统计表

完成过渡由切片进度通知持有，不使用阻塞休眠：

1. 进入完成状态后仍绘制进度条，数值为 100%，不显示取消按钮。
2. 首次绘制完成进度条时记录时间，并请求后续帧。
3. 在后续绘制中，经过至少 200 毫秒后隐藏进度并清除过渡标志。
4. 请求下一帧；统计表在下一帧才满足显示条件。

未绘制完成进度前，不使用通知原有的自动过期逻辑，以免界面繁忙时跳过 100%。新一轮切片、取消、主动隐藏进度都会清除过渡标志和计时。该过渡仅由总览成功收尾路径开启。

## 9. 风险与回滚

- 改动涉及预览加载与通知显示时序，需要重点验证多盘纯 G-code 工程、复用已有结果，以及切换单盘后的首次加载。
- 200 毫秒从完成进度首次绘制时开始计时；实际切换还取决于后续帧调度，界面繁忙时可能更晚。
- 回滚时应一起撤销本次总览加载判断、统计表显示门槛和通知完成过渡，避免只撤销其中一部分导致进度残留或预览缺失。

# Bug #18004：切换机型后的冲刷系数与矩阵处理

## 1. 基本信息

- Bug：[18004](https://zentao.creality.com/zentao/bug-view-18004.html)
- 标题：【急】【项目反馈】切换机型后，要使用机型默认的冲刷系数，目前切换机型后冲刷系数还是不变

- 提交人：李佳沁；指派给：贺淼
- 页面状态：激活、未确认；严重程度：致命；优先级：高

- 执行：`CP7.3.0 260930`
- 修复分支：`pick/makenow-release-260930`

## 2. 问题现象

禅道记录：从 K2Plus 切换到 i7，冲刷系数仍为 `0.3`；再切换到 i8，仍为 `0.3`。期望 i7 使用 `0.8`，i8 使用 `0.15`。

本次沟通补充的范围：系数按打印机预设保存；真正切换机型时重新计算矩阵；同一机型派生的用户预设不算切换机型；修改系数后立即显示重置按钮；原生 3MF 恢复项目值；第三方 3MF 忽略文件内的冲刷系数和矩阵并重新计算矩阵。

## 3. 影响范围

- 打印机预设切换、应用启动时的配置恢复。
- 冲刷弹窗确认、重置按钮和配置桥接入口。
- Creality Print 原生 3MF、第三方带配置 3MF、第三方纯几何 3MF 的项目打开流程。
- 应用配置中的用户偏好与项目配置中的冲刷系数、矩阵。

## 4. 修复前复现

1. 选择 K2Plus，当前冲刷系数为 `0.3`。
2. 切换到没有单独保存过系数的 i7，打开冲刷弹窗，仍显示 `0.3`。
3. 切换到没有单独保存过系数的 i8，仍显示 `0.3`。
4. 与目标机型默认值 `0.8`、`0.15` 不符。

补充回归场景：将 i7 系数改为 `1.1`，点击“确认”并保存原生 3MF，重新打开后应恢复 `1.1`；打开第三方 3MF 时，应丢弃其中的冲刷参数，按最终选定的打印机和耗材重新计算矩阵。

## 5. 根因分析

以下为代码分析结论，禅道原始页面仅记录了切换机型后的系数现象。

- 系数从全局应用设置读取，弹窗和配置桥接入口也写入全局设置，缺少打印机预设维度，导致前一个机型的值沿用到后一个机型。
- `AppConfig::set_printer_setting()` 的脏标记位于 `return` 之后，无法执行；导出预设选择时会清空当前打印机设置，也需要保留已确认的系数偏好。
- `Plater::on_select_preset()` 中旧的自动重算代码被 `#if 0` 禁用。原注释为 `do not toggle auto calc when change printer`，只能确认当时禁止了切换打印机时的自动计算，不能据此断言历史业务原因。
- 仅以预设名称判断切换无法区分同机型派生预设和真正的机型变化；直接恢复预设缓存矩阵还可能覆盖当前手动矩阵。
- 重置按钮的显隐更新未覆盖即时输入，显隐变化后也缺少布局刷新，导致修改值后按钮仍不可见。
- 3MF 导入包含配置合并、厂商转换、打印机选择与耗材加载等阶段，需要在原始配置中保留文件系数，并在最终配置就绪后明确恢复优先级。第三方矩阵若过早计算，后续配置加载仍可能覆盖结果。

## 6. 修复策略

| 场景 | 系数处理 | 矩阵处理 |
| --- | --- | --- |
| 切换打印机预设 | 读取目标预设已保存的系数；没有有效值时使用该机型默认值 | 只有实际机型变化才重新计算 |
| 同机型系统预设与派生用户预设互切 | 系数仍按预设独立保存和恢复 | 保留当前矩阵，不恢复其他预设的缓存矩阵 |
| 打开原生 3MF，文件包含有效系数 | 优先恢复文件系数 | 保留项目矩阵 |
| 原生 3MF 缺少有效系数 | 同机型保留打开前系数；不同机型读取目标预设偏好或默认值 | 沿用原生项目加载逻辑 |
| 打开第三方 3MF | 忽略文件系数；同机型保留当前系数，不同机型读取目标预设偏好或默认值 | 最终打印机和耗材加载完成后重新计算，并清除手动修改标记 |

- 机型身份优先使用厂商与 `printer_model`，沿继承关系解析；缺少机型标识时使用共同继承根预设，避免将用户预设名称变化误判为机型变化。
- 已保存系数必须完整解析、为有限值且处于 `[0, 3]`；无效值回退机型默认值，默认值无效时回退 `1.0`。
- 忽略无法确定所属打印机的历史全局系数。只有弹窗确认和显式配置修改才更新持久偏好，导入项目本身不覆盖偏好。
- 重置按钮在输入值等于按界面精度格式化的机型默认值时隐藏；输入变化后立即判断并刷新布局，点击后恢复默认值。

## 9. 风险与回滚

- 历史全局系数不迁移到所有机型；无预设偏好的机型首次使用默认值，这是本次修复的预期行为。
- 系数偏好以预设名称为键，矩阵重算以实际机型身份为依据，两者粒度不同；同机型不同预设仍可保存不同系数。
- 第三方 3MF 的手动冲刷矩阵会被有意丢弃，应重点验收多耗材和喷嘴配置加载后的矩阵尺寸与数值。
- 本次未更改基础矩阵乘系数后的整数显示规则。
- 如需回滚，应整体回滚本次代码提交，避免只回滚导入调用方或系数存储入口造成规则不一致。

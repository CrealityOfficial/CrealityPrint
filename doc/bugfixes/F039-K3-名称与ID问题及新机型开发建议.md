# F039 / K3：名称与 ID 问题及新机型开发建议

> 关联 Bug：18126。本文说明优化方向，稳定 ID 与名称的拆分尚未实现。
> 已实施的兼容处理见 [Bug 18126 修复说明](bug-18126-f039-k3-legacy-3mf-compatibility.md)。

## 1. 当前的问题是什么？

**`printer_settings_id` 名字叫 ID，实际保存的是打印机预设名称。程序又用这个名称查找预设，因此它同时承担了“显示名称”和“身份标识”两种作用。**

例如：

| 项目                           | 旧工程                     | 当前系统预设  |
| ------------------------------ | -------------------------- | ------------- |
| 打印机预设名称                 | `Creality F039 0.4 nozzle` | `Creality K3` |
| `printer_settings_id` 名称引用 | `Creality F039 0.4 nozzle` | `Creality K3` |

F039 是内部研发代号，K3 是发布名称，两者在这里指同一款产品。但旧工程按旧名称找预设，新版本使用新名称，没有映射就无法直接关联。

**问题在于：改了名字，也改了程序用来认身份的值。** 目前不能理解为“程序一直用固定的 F039 ID，只把界面名称改成了 K3”。

用户自定义的 `222Creality K3 - 拷贝(1)` 也是预设名称，可以保存在 `printer_settings_id` 中；修改 3MF 文件名不会自动修改它。

## 2. 现在 K3 为什么要做兼容？

旧工程已经保存了名称引用，不能要求用户重新制作工程。因此当前做法是：

```text
读到旧名称 → 通过明确的历史名称映射找到 K3 → 接好关联 → 恢复工程参数
```

历史名称由代码集中注册，不需要在每份配置 JSON 中添加。同步处理继承、兼容列表等关联；用户自定义名称保留，不把其中所有 F039 字样强制替换。

**这是对已有数据的兼容修复，还没有完成名称与 ID 的拆分。** 喷嘴口径等旧参数结构的迁移，详见修复说明。

## 3. 未来具体怎么优化？

**核心就是把 `printer_settings_id` 当前承担的两种职责拆开：稳定 ID 用来关联，显示名称用来展示。**

建议明确使用两个独立字段。以下是设计示例，字段名及 ID 值均不是当前已实现的格式：

| 字段                  | 用途                   | 研发阶段        | 发布之后      |
| --------------------- | ---------------------- | --------------- | ------------- |
| `printer_preset_id`   | 稳定标识这份打印机预设 | `preset-001`    | `preset-001`  |
| `printer_preset_name` | 显示给用户看的名称     | `Creality F039` | `Creality K3` |

打开工程时：

```text
工程保存 preset-001 → 按 ID 找到同一份预设 → 界面显示当前名称 Creality K3
```

用户给自己的预设改名时，同样只改名称，ID 保持不变。

实施时需要一起打通这四处，不能只增加字段：

1. **预设创建与保存：** ID 一次分配并持久保存，不根据名称重新生成；重新生成系统资源也沿用原 ID。
2. **查找与关联：** 预设查找、父预设继承、按打印机预设建立的兼容列表都引用稳定 ID，不靠名称拼接。
3. **3MF 保存与恢复：** 保存预设 ID、名称及必要的参数快照；导入按 ID 关联，同时保留用户自定义名称和工程参数。
4. **界面显示与改名：** 显示名称，内部选择和关联使用 ID；改名不改变身份。

`printer_settings_id` 作为旧格式名称字段保留兼容读取，不能直接把原来的名称替换成新 ID，让旧读取逻辑继续使用。新格式优先读取稳定 ID；旧格式没有 ID 时，才通过已有名称及明确的历史映射完成迁移。无法唯一匹配时保留项目配置，不猜测关联。

这里只聚焦“打印机预设”的身份。`printer_model` 等机型关联如果仍依赖名称，也要接入稳定机型标识，才能保证产品发布改名不影响整条链路；机型 ID 与预设 ID 不混用，一款机型可以有多份预设。

## 4. 新机型开发记住这几条

| 操作                       | 稳定预设 ID      | 显示名称         |
| -------------------------- | ---------------- | ---------------- |
| 首次创建一份预设           | 分配新 ID 并保存 | 可以先用研发名称 |
| F039 发布更名为 K3         | 保持不变         | 修改为发布名称   |
| 用户给同一份预设改名       | 保持不变         | 使用用户的新名称 |
| 修改同一份预设的参数       | 保持不变         | 按需修改         |
| 另存为独立预设             | 分配新 ID        | 使用新预设名称   |
| 保存、重开或导入同一份预设 | 恢复原 ID        | 按名称规则显示   |

验收重点：**先用研发名称保存工程，再修改发布名称，重开工程仍能找到同一份预设，继承、兼容关系及用户参数均正确。** 另存为的独立预设也不能覆盖原预设。

## 5. 以后是不是就不需要兼容了？

**拆分并打通所有关联后，单纯改名不再需要专门增加名称兼容补丁。**

但仍有两类数据要处理：

- 已有旧工程没有稳定 ID：继续保留当前的旧名称迁移入口。
- 参数结构发生变化：例如旧口径数组改为新版喷嘴变体表，仍需参数迁移，与改名无关。

记忆规则：**改名不换 ID，独立副本新建 ID；旧名称要兼容，旧参数按结构迁移。**

# Bug 修复记录：发送取消后重新切片时 GCode 文件被占用

## 1. 基本信息
- Bug ID：`17431`
- 标题：`文件切片后发送打印，移动一下模型后再次切片，报错`
- 禅道地址：https://zentao.creality.com/zentao/bug-view-17431.html
- 日期：`2026-07-25`
- 产品：`Creality Print`
- 模块：`设备管理`
- 计划：`CP7.2.1 20260730`
- Bug 类型：`代码错误`
- 严重程度：`严重`
- 优先级：`高`
- 状态：`激活`
- 影响版本：`CrealityPrint_7.2.1.5419_Beta`
- 关联 Bug：`15494`

## 2. 问题现象
1. 完成文件切片并进入发送打印页面。
2. 上传过程中关闭或取消发送。
3. 返回主界面移动模型并重新切片。
4. 重新切片需要覆盖当前盘临时 GCode，但后台上传仍持有文件句柄，导致切片报错。

## 3. 根因分析
- 发送流程将 `plate->get_tmp_gcode_path()` 直接交给上传协议，没有创建文件副本。
- Klipper4408 和 Moonraker/Klipper 的 multipart 请求、FTP 局域网上传以及 CX 云端压缩都会打开该源文件。
- 历史修复允许发送窗口先关闭、后台任务继续取消；用户因此可以在文件句柄释放前返回主界面重新切片。
- 任务状态回调可能早于协议异步函数返回，收到 `601` 不等于请求对象和文件句柄已经析构。
- CX 云端路径还存在三个延迟点：
  - GCode MD5 计算不可取消。
  - gzip 压缩一次性执行，只在压缩结束后检查取消。
  - OSS `UploadPart()` 是同步请求，原来只在单个分片请求返回后检查取消。
  - `OssClient::DisableRequest()` 仅依赖 libcurl 进度回调；完全断流时同步请求仍会等待低速超时。
  - DNS 阶段尚未创建上传 socket，但此时也尚未打开上传文件；将该阶段与文件上传阶段统一等待，会无谓拖慢窗口取消。

## 4. 修复方案
- 不创建 GCode 副本，避免大文件产生额外磁盘空间和完整复制 I/O。
- 取消令牌增加文件资源阶段：
  - MD5、gzip、HTTP multipart、FTP 和 OSS 上传在打开文件前进入 `FileInUse`。
  - 使用 RAII 保证请求对象及文件流析构后进入 `FileReleased`。
- 发送窗口按阶段处理：
  - 获取凭证、获取 OSS 信息和云端登记等无文件阶段立即逻辑取消，窗口可以关闭。
  - 已进入 `FileInUse` 时保持模态并显示取消中，重复关闭不会绕过等待。
  - 只有协议 `future` 结束并确认 `FileReleased` 后，才发布 `601` 并关闭窗口。
- `RemotePrinterManager` 分阶段发布终态：
  - 协议状态回调只记录结果。
  - 无文件取消立即进入逻辑终态，旧任务后续回调全部丢弃。
  - 文件占用取消等异步协议函数返回、局部请求对象析构后再投递 `601`。
  - 旧准备请求仍在网络超时时，后续发送通过有界工作池启动，不再等待旧任务。
- CX 云端快速取消：
  - MD5 和 gzip 改为分块读取，并在每个数据块检查任务取消令牌。
  - gzip 完成后立即关闭原始 GCode。
  - 获取 Aliyun 凭证、获取 OSS 信息和云端登记三个 HTTP 请求继续尽力主动取消，但不再阻塞无文件阶段的 UI 关闭。
  - OSS 同步请求通过 `OssClient::DisableRequest()` 中断，并在 SDK 内接管、关闭当前 socket。
  - 已关闭 socket 会从活动集合移除，libcurl 关闭回调检测所有权后跳过，避免重复关闭。
  - 取消路径不再同步等待弱网下的 `AbortMultipartUpload`。
- 撤销 cURL quick-exit/multi 私有修改，恢复标准 easy 请求，降低通用网络层风险。
- FTP 局域网上传增加 cURL 进度取消回调，退出传输后由 RAII 关闭 `FILE*`。
- Klipper4408 / Moonraker 阻塞传输主动取消：
  - 限速工具复现时，首次取消到 `601` 返回约 `75` 秒，确认阻塞阶段没有触发 libcurl 进度回调。
  - 上传请求显式开启 active cancel，独立观察取消令牌。
  - 取消后对当前上传 socket 执行 `shutdown`，主动唤醒阻塞的 `curl_easy_perform()`。
  - socket 仍由 libcurl 的关闭回调统一释放，避免跨线程重复关闭或句柄复用风险。

## 5. 影响范围

## 7. 风险与回滚
- 风险等级：`中高`，涉及 WAN/LAN 上传取消、发送窗口生命周期和 OSS 请求控制。
- 无文件阶段的请求可能短暂后台清理，但不会阻止关闭或再次发送；若文件占用阶段协议层无法响应取消，窗口会继续保持模态，不会在文件仍被占用时返回切片页。
- 取消时不再同步等待 OSS multipart 中止，未完成分片由云端生命周期策略清理。
- 回滚时需整体回退发送页关闭状态机、任务终态延迟投递、CX 快速取消及 FTP 取消令牌，避免只回退其中一层重新产生生命周期竞态。

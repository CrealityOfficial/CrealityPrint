## 2. 问题现象

- 用户反馈现象：截图中的“耗材丝类型选项”只有墙、填充、实心填充，之前存在的“擦拭塔”选项被屏蔽，希望恢复并让选择实际生效。
- 实际结果：修复前 `TabPrint::build()` 中创建 `wipe_tower_filament` 控件的语句被注释；参数定义、预设保存和动态列表注册仍存在，但切片端缺少读取该参数并指定塔壁耗材的实现。仅取消界面注释不能补齐功能。
- 期望结果：在支持的创想擦拭塔分支中，用户能选择“缺省”或一个实际耗材；缺省继续自动选料，指定实际耗材后，相关塔壁路径使用该耗材，必要的换料和耗材统计同步完成。

该参数指定的是擦拭塔外墙耗材，不表示整座塔及所有冲刷路径只能使用一种耗材。内部材料分区、接触层和换料冲刷仍遵循各自的生成逻辑。

## 4. 根因分析

### 触发条件

用户需要用一个指定耗材打印擦拭塔外墙，尤其是该耗材未用于模型、或未出现在某些需要塔壁的层中。

### 代码链路

`TabPrint::build()` → `wipe_tower_filament` 配置 → `Print::extruders()` → `ToolOrdering` → `Print::_make_wipe_tower()` → `WipeTowerCreality::generate()`。

### 问题原因

1. **界面入口被屏蔽**：`Tab.cpp` 保留了创建控件的语句，但处于注释状态。
2. **耗材集合未补齐**：`Print::extruders()` 未根据该参数加入仅用于塔壁的耗材。
3. **逐层换料未补齐**：`ToolOrdering` 未确保需要塔壁的层包含指定耗材，单独修改生成器可能遇到该层没有对应换料的问题。
4. **塔壁仍自动选料**：`WipeTowerCreality::get_wall_filament_for_all_layer()` 及逐层选料逻辑按现有耗材和材料类别选择，未读取用户的指定值。
5. **边界约束不完整**：配置合并缺少该参数的实际耗材编号校验，无法保证旧配置或虚拟耗材编号按本次功能范围处理。

本次对比的是用户提供的本地源码：OrcaSlicer 2.4.2 包含指定耗材补入、换料规划和塔壁选料实现；BambuStudio 02.08.02.61 未发现对应选择参数。该结论仅针对这两份本地源码，不推断其与官方发行版本完全一致。

## 5. 修复方案

### 修复思路

保留现有配置键和缺省值，补齐从界面到创想塔壁生成的链路。用户明确限定：只开放“缺省＋实际耗材”，只接入 `WipeTowerCreality`，不开放虚拟混色耗材作为塔壁指定值。

| 场景 | 本次实现行为 |
| --- | --- |
| `wipe_tower_filament = 0` | 显示“缺省”，沿用现有自动选料逻辑。 |
| 值为有效实际耗材编号 | 配置使用从 1 开始的编号；进入引擎耗材索引时减 1。 |
| 关闭擦拭塔 | 选项置灰，保留有效设置值；引擎不启用指定逻辑。 |
| 使用其他擦拭塔生成分支 | 界面隐藏该选项，公共耗材规划不应用该设置。 |
| 非法或虚拟耗材编号 | 界面校正及配置合并回到 0，引擎也有范围保护。 |
| 原本不需要擦拭塔 | 沿用原有是否生成塔的判断，不因设置一个不同耗材而强制生成塔。 |
| 指定耗材未出现在相关层 | 补入该层耗材列表并更新换料分区数。 |
| 生成时指定耗材不可用 | 抛出切片错误，提示检查耗材选择和喷嘴可打印高度，不静默改用其他材料。 |

### 修改点

| 文件 | 关键逻辑 |
| --- | --- |
| `src/slic3r/GUI/Tab.cpp` | 恢复“实心填充”之后的 `wipe_tower_filament` 下拉框。 |
| `src/slic3r/GUI/ConfigManipulation.cpp` | 校正超出实际耗材范围的编号；依据创想塔分支判定控制选项可见性，依据擦拭塔开关控制可用性。 |
| `src/libslic3r/PresetBundle.cpp` | 在 `full_fff_config()` 中将非法或虚拟编号归零，避免截断为最后一个实际耗材而选错材料。 |
| `src/libslic3r/Print.cpp`、`Print.hpp` | 新增 `creality_wipe_tower_filament()`，统一检查编号、生成器分支及是否启用塔；`extruders()` 纳入有效的塔壁耗材。 |
| `src/libslic3r/GCode/ToolOrdering.cpp`、`ToolOrdering.hpp` | 两个构造路径均接入 `insert_wipe_tower_filament()`；抽取并复用 `count_wipe_tower_partitions()` 更新换料分区数。 |
| `src/libslic3r/FDM/WipeTowerCreality.cpp`、`WipeTowerCreality.hpp` | 保存指定耗材；显式选择该耗材打印外墙；无换料层检查当前耗材；通过 `wall_printed` 避免同层切回指定耗材时重复生成外墙。 |
| `localization/i18n/zh_CN/CrealityPrint_zh_CN.po` | 将对应名称统一为“擦拭塔”，说明外墙实际耗材和缺省含义，补充不可打印时的中文提示。 |

逐层补入发生在现有耗材排序、混色组件顺序处理和塔层规划之后。仅在符合条件且尚未包含指定耗材的层中，将它插入到原最后一个耗材之前，保留模型耗材的相对顺序及层结束耗材。随后只重算分区数，不重新创建塔层或改变已确定的塔层高度。

`WipeTowerCreality` 使用独立的指定耗材判断，不修改材料的 `is_soluble` 属性。内部材料分区及接触层逻辑继续沿用原实现。

本次复用而未修改的已有逻辑包括：`Plater.cpp` 中只含实际耗材的 `DynamicFilamentList`、该参数的动态列表注册、全局角色耗材编号重映射，以及参数变化时触发场景更新的配置项列表。原有切片失效逻辑已包含 `wipe_tower_filament`。

## 7. 风险与回退

- 可能风险：指定模型未使用的耗材会增加必要的换料、冲刷量和打印时间；塔的深度也可能随分区需求变化。这些变化需要通过实际切片结果核对。
- 风险影响范围：指定值有效且走 `WipeTowerCreality` 的打印任务；公共分区计数逻辑经过抽取复用，其他分支也需要做缺省行为回归。
- 重点关注：模型混色、支撑自动选料、多喷嘴、不同材料接触层和逐对象打印的组合场景，尚未进行运行验证。
- 临时恢复原行为：将“擦拭塔”耗材设为“缺省”。
- 完整回退：按本次 diff 成组撤销界面、公共耗材规划、创想生成器、配置校验及翻译修改。若后续已提交，按实际提交执行对应回退；本文不预填提交哈希，以实际提交记录为准。
- 不应只撤销逐层补入逻辑而保留强制塔壁选料，否则可能出现指定耗材未进入当前层而切片报错。
- 回退时保留其他无关修改，避免整工作区覆盖。

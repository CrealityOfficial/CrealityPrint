# 打印机预设另存为后机型显示为空修复说明

## 1. 基本信息

- Bug ID：17692
- 标题：打印机预设另存为后主界面机型显示为空
- 禅道链接：https://zentao.creality.com/zentao/bug-view-17692.html
- 反馈人： 康美樱
- 处理人：`wangwenbin`
- 分支：`feature/f039_group`
- 影响模块：打印机预设保存、主界面机型聚合与选择状态

## 2. 问题现象

### 用户反馈现象

在打印机设置中选择系统预设，点击“另存为”创建用户预设后，设置窗口左侧可以看到并选中新预设，但主界面的机型下拉框变成空白。

### 实际结果

- 用户预设已经创建并写入磁盘，并非保存失败。
- 设置窗口能够显示新用户预设。
- 主界面无法把当前预设匹配到机型列表，选中索引变为 `-1`，因此显示空字符串。

### 期望结果

另存为成功后，新用户预设立即成为当前预设；主界面机型名称正常显示，并且与设置窗口、重新启动后的状态保持一致。

## 3. 复现步骤

### 前置条件

- 机型：Creality K3
- 打印机预设：`Creality K3 0.4 nozzle`
- 入口：打印机设置

### 操作步骤

1. 打开打印机设置，选中 `Creality K3 0.4 nozzle`。
2. 点击“另存为”。
3. 使用默认生成的拷贝名称保存为用户预设。
4. 返回主界面，观察左上角机型下拉框。

### 复现结果

设置窗口选中了新用户预设，但主界面机型下拉框显示为空。

### 复现概率

从带父预设且需要补充 `base_id` 的打印机预设执行“另存为”时可稳定触发。

## 4. 根因分析

### 触发条件

同时满足以下条件时触发：

1. 通过“另存为”创建新的用户打印机预设。
2. 新预设继承父预设，保存过程中需要补充父预设的 `base_id`。
3. 主界面使用机型聚合 ID 匹配当前选中项。

### 代码链路

预设集合中存在三份容易混淆的状态：

```text
正式预设：m_presets[m_idx_selected]，作为持久化和列表数据来源
编辑副本：m_edited_preset，承载当前界面编辑内容
保存副本：m_saved_preset，用于保存后状态和脏检查
```

原保存顺序可以记成“先入座，后发身份证”：

```text
创建正式预设，此时 base_id 为空
  -> 立即选中新预设
  -> 正式预设被复制成编辑副本和保存副本
  -> 只给正式预设补 base_id
  -> 刷新主界面
```

最终同一个预设出现两种机型 ID：

```text
机型列表读取正式预设：user:<base_id>
当前选择读取编辑副本：preset:<新预设名称>
```

两者无法匹配，`get_selection_machine()` 返回 `-1`，主界面因此显示空白。重新切换预设或重启后，编辑副本会从磁盘中的正式预设重新生成，所以现象可能暂时消失。

### 问题原因

根本原因不是下拉框少刷新了一次，而是“保存顺序”和“机型身份的数据来源”同时存在问题。

`base_id` 可以理解成用户预设的“机型身份证号”。主界面不是只按显示名称找机型，而是先根据预设类型和 `base_id` 生成稳定的机型 ID，再用这个 ID 在机型列表中查找当前选中项。因此，同一个预设的不同内存副本只要保存了不同的 `base_id`，即使名称和参数完全相同，也会被主界面当成两个不同机型。

以 `Creality K3 0.4 nozzle` 另存为 `Creality K3 0.4 nozzle - 拷贝(1)` 为例，父预设的 `setting_id` 是 `474840`，新用户预设最终应该继承这个值作为 `base_id`。

原保存流程中的状态变化如下：

```text
步骤 1：创建正式用户预设
正式预设：base_id = 空
编辑副本：仍是保存前的旧状态
保存副本：仍是保存前的旧状态

步骤 2：立即激活新预设
select_preset() 把正式预设复制成编辑副本和保存副本
正式预设：base_id = 空
编辑副本：base_id = 空
保存副本：base_id = 空

步骤 3：根据父预设补充身份
代码只修改预设集合中的正式预设
正式预设：base_id = 474840
编辑副本：base_id = 空
保存副本：base_id = 空

步骤 4：刷新主界面
三份状态代表同一个预设，但身份信息已经不一致
```

主界面随后从两个不同的数据源计算机型 ID：

```text
machine_items() 遍历正式预设：
base_id 不为空 -> machine_id = user:474840

get_selection_machine() 读取编辑副本：
base_id 为空 -> machine_id = preset:Creality K3 0.4 nozzle - 拷贝(1)
```

机型列表中只有 `user:474840`，当前选择却拿着 `preset:Creality K3 0.4 nozzle - 拷贝(1)` 去查找，两者必然无法匹配。查找失败后返回 `-1`，主界面绘制代码在选中索引无效时使用空字符串，所以最终看到的是机型下拉框空白。

设置窗口仍能显示新用户预设，是因为它直接按正式预设的名称和选中索引显示，不经过上述机型 ID 聚合匹配。磁盘文件中的 `base_id` 也是正确的，因为写盘时正式预设已经补上了 `474840`。重新切换预设或重启软件后，编辑副本会重新从正式预设或磁盘文件生成，此时也能得到 `base_id = 474840`，所以显示可能恢复正常。

`m_saved_preset` 不直接参与这次下拉框查找，但它与正式预设不一致，说明保存事务本身没有形成完整快照，后续还可能影响脏状态判断或其他依赖预设身份的逻辑。因此修复不能只在下拉框匹配失败时增加显示兜底，而必须先保证身份信息完整，再统一生成编辑副本和保存副本；同时机型身份应读取正式选中预设，而不是可编辑副本。

## 5. 修复方案

### 修复思路

新顺序记成“先办身份证，再入座”：

```text
创建或更新正式目标预设
  -> 确定 inherits、base_id 等完整身份
  -> 保存正式目标预设
  -> 最后激活一次
  -> 统一生成编辑副本和保存副本
```

机型列表来自正式预设集合，因此当前机型身份也统一从正式选中预设读取，不再使用可能包含临时编辑状态的副本。

### 修改点

- `src/libslic3r/Preset.cpp`
  - 在创建和覆盖保存分支中记录唯一的正式目标预设 `target_preset`。
  - 在激活前解析父预设并补齐目标预设的 `base_id`。
  - 脱离父预设时同步清除 `base_id`，保证“脱离”语义完整。
  - 直接保存正式目标预设，保存完成后再调用 `select_preset_by_name()`。
  - 激活时由现有 `select_preset()` 统一生成身份一致的编辑副本和保存副本。
- `src/slic3r/GUI/SiderBar.cpp`
  - `get_selection_machine()` 改为使用 `get_selected_preset()` 计算机型 ID。
  - 保证机型列表和当前选择使用同一类正式数据源。

## 7. 风险与回退

### 可能风险

- `save_current_preset()` 是打印机、工艺和耗材预设共用入口，保存与激活的先后顺序发生调整，需要关注其他预设类型。
- “脱离”保存现在会同步清除 `base_id`，需要验证依赖脱离预设的云同步场景。
- 项目内嵌预设不写普通用户预设文件，但仍会在身份完成后激活，需要验证项目保存和重新加载。

### 风险影响范围

影响预设的另存为、覆盖保存、脱离保存，以及保存后的当前预设激活状态；不修改切片算法、G-code 生成和设备通信逻辑。

### 回退方案

回退 `src/libslic3r/Preset.cpp` 中目标预设保存顺序，以及 `src/slic3r/GUI/SiderBar.cpp` 中正式选中预设的身份读取修改，即可恢复原行为。

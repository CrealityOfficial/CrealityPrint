## 2. 问题现象

- 用户反馈：导入样本后，出现“加载模型文件失败。”和“此文件不包含任何几何数据。”两个提示。
- 实际结果：工程没有正常加载，无法继续切片。
- 期望结果：映射缺失不阻止模型导入；点击切片时，自动模式使用现有自动分配流程，手动模式弹出分组窗口让用户选择，取消则停止本次切片。
- 样本 ZIP 完整性检查通过，包含一个 8 顶点、12 三角面的 26 mm 立方体网格，三个模型对象共享该网格。因此样本并非没有几何数据。

## 3. 复现步骤

### 前置条件

- 样本机型：`Creality K3`，4 个 0.4 mm 喷嘴。
- 工程有 6 个耗材，三个立方体分别使用耗材 1、3、2。
- `Metadata/project_settings.config` 中：
  - `filament_map_mode = AutoForSaving`。
  - `filament_map = [1]`。
  - `filament_map_2 = [0]`。
- 文件标记的保存程序为 `Creality_Print V7.2.2.5537 Beta`。

### 操作步骤

1. 在修复前版本中，将样本作为工程导入。
2. 等待导入结束并观察提示。
3. 实际出现模型加载失败和没有几何数据的提示，模型未正常导入。

复现概率：用户未提供统计次数；本次完成了文件及源码分析，未运行 GUI 复现。

## 4. 根因分析

1. `bbs_3mf.cpp` 的 `prepare_project_filament_mapping_after_load()` 在加载工程配置后校验映射。
2. 原逻辑仅在映射模式和映射数组都不存在时迁移旧格式；字段存在但映射项不足时，进入完整性校验。
3. `validate_complete_filament_map()` 要求映射项数与工程耗材数相同。样本为 1 项映射、6 个耗材，因此返回失败。
4. 3MF 导入失败后，`Model.cpp` 抛出通用加载失败异常；`Plater.cpp` 捕获后继续收尾，成功导入模型数为零，又提示没有几何数据。

此外，正常工程导入结束时会同步映射模式并保留工程映射。单纯补齐数组会把临时默认值当作完整映射，无法保证切片时按原模式重新分配或请求手动确认。

## 5. 修复方案

### 修复思路

将“缺少映射”和“非法映射”区分处理。缺失数据允许导入，并记录本次工程需要在切片前补全；保留已有手动选择和原分配模式。最终分配使用切片前的实际耗材及喷嘴兼容输入，不在导入处另写分配算法。

### 修改点

| 文件 | 关键逻辑 |
| --- | --- |
| `src/libslic3r/Format/bbs_3mf.cpp` | 缺少模式时初始化为自动模式，缺少主映射时初始化空数组；允许短数组及零值未分配项导入。错误类型、超长数组、负数及超出喷嘴范围的值仍拒绝。由主映射同步派生映射。 |
| `src/libslic3r/PresetBundle.hpp` | 增加工程映射待补全状态及原分配模式，作为内存中的临时状态。 |
| `src/libslic3r/PresetBundle.cpp` | 复制工程时复制状态，重置及初始化时清除状态；待补全期间保持原模式。 |
| `src/slic3r/GUI/Plater.cpp` | 从原始导入配置识别缺失映射，保存已有项及模式；导入结束后设置待补全状态，界面默认值仅用于占位。完整映射沿用原流程。 |
| `src/slic3r/GUI/FilamentPanel.cpp` | 点击切片时优先处理待补全工程。自动模式调用 `make_filament_map_auto_input()` 和 `resolve_effective_filament_map()`；手动模式复用分组窗口。确认后同步两份映射并清除待补全状态，取消保留状态并阻止本次切片。 |

### 行为边界

- `filament_map` 是从 1 开始的喷嘴编号；`filament_map_2` 是对应的从 0 开始的编号。
- 主映射完整、仅派生映射缺失时，可直接根据主映射重建派生映射，不要求用户重复选择。
- 自动模式使用实际切片输入，不能固定承诺样本最终为 `[1,2,3,4,1,2]`。
- 未新增 `AutoForMatch` 设备匹配能力，仍由现有解析器处理。
- 本次没有修改通用错误弹窗逻辑。

## 2. 问题现象

### 用户反馈现象

导入 `222立方体.3mf` 后，3MF 内保存的四个物理喷嘴普通回抽长度为：

```text
printer[P] = [0.7, 0.2, 0.3, 0.9]
```

打印机设置界面实际显示为：

```text
printer[P] = [0.2, 0.7, 0.7, 0.7]
```

### 实际结果

3MF 中仅保存当前四个物理喷嘴对应的四行活动参数；导入后，这个四元素数组被当成系统预设的完整 16 行变体表参与选择。选中的系统行号为 `[1, 4, 9, 12]`，除行号 1 外均越界，旧逻辑随后回退到数组第 0 项，因此形成 `[0.2, 0.7, 0.7, 0.7]`。

### 期望结果

导入时先按稳定的喷嘴身份把 3MF 活动行还原到系统预设完整变体表，再由现有变体选择逻辑提取当前四个物理喷嘴的值，最终界面保持：

```text
printer[P] = [0.7, 0.2, 0.3, 0.9]
```

## 3. 复现步骤

### 前置条件

- 机型：Creality K3
- 打印机预设：`Creality K3 0.4 nozzle`
- 活动物理喷嘴：P1=0.2、P2=0.4、P3=0.2、P4=0.4
- 测试文件：`F:\result\2026bug修复\8月\多口径测试\222\222立方体.3mf`
- 3MF 中的 `retraction_length`：`[0.7, 0.2, 0.3, 0.9]`

### 操作步骤

1. 启动 Creality Print 并导入上述 3MF。
2. 打开打印机设置。
3. 依次查看挤出机 1～4 的“回抽长度”。

### 复现结果

修复前显示 `[0.2, 0.7, 0.7, 0.7]`，与 3MF 保存值不一致。

### 复现概率

当系统预设保存完整变体表、3MF 保存活动行，且被修改参数属于按喷嘴变体组织的数组时稳定复现。

## 4. 根因分析

### 触发条件

同时满足以下条件：

1. 机型存在多个物理喷嘴和多个喷嘴变体；
2. 系统预设使用完整变体表，K3 当前为 4 个物理喷嘴 × 4 个喷嘴口径，共 16 行；
3. 3MF 只保存当前活动组合的紧凑数组；
4. 参数被记录在 `different_settings_to_system` 中，需要保留项目覆盖值。

### 代码链路

```text
3MF project_settings.config
  -> PresetCollection::load_external_preset / SimpleDeviceMgr::check_diff_settings_to_system
  -> 完整预设与项目覆盖值合并
  -> PresetBundle::full_fff_config
  -> DynamicPrintConfig::select_extruder_variant_values
  -> UI / 切片有效配置
```

3MF 中用于标识四行活动数据的组合为：

```text
(printer_extruder_id, printer_extruder_variant, printer_nozzle_variant)
```

本次文件对应系统完整表的行号为：

```text
P1/N02 -> 1
P2/N04 -> 4
P3/N02 -> 9
P4/N04 -> 12
```

### 问题原因

旧的项目参数恢复只处理耗材和工艺参数，而且默认每个变体参数都是步长 1；打印机变体参数没有在导入阶段恢复为完整表。后续选择函数拿完整表行号访问四元素紧凑数组，越界时又静默回退到第 0 项，最终造成参数错位。

这不是 `retraction_length` 单个参数的问题。下列同类参数存在相同风险：

- 打印机步长 1 参数：普通回抽、换料回抽、Z 抬升、擦拭、喷嘴容积、喷嘴类型、热端升降温速率等；
- 打印机步长 2 参数：机器最大加速度、最大速度、最大抖动等成对数组；
- 特殊打印机参数：`min_layer_height`、`max_layer_height`；
- 原有耗材和工艺变体参数也需要保持相同恢复语义。

## 5. 修复方案

### 修复思路

建立一个共享的项目变体参数恢复入口，不再针对某个参数写特例：

1. 保留 3MF 导入时的紧凑活动行快照；
2. 从当前系统/继承预设取得完整变体表；
3. 使用稳定身份元组把每个项目活动行映射到唯一系统行；
4. 以完整系统参数数组为底，只覆盖 3MF 明确标记为修改过的活动行；
5. 对步长 1、步长 2、最小/最大层高统一处理；
6. 非变体参数沿用原来的直接导入逻辑；
7. 映射缺失、重复、类型不一致或数组长度异常时，不做猜测，回退到系统预设并输出包含完整项目值、系统值和选择器数组的 warning 日志。

身份元组按预设类型区分：

```text
打印机：(printer_extruder_id, printer_extruder_variant, printer_nozzle_variant)
工艺：  (print_extruder_id, print_extruder_variant, print_nozzle_variant)
耗材：  (filament_extruder_variant, filament_nozzle_variant)
```

### 修改点

- `src/libslic3r/Preset.hpp`
  - 声明共享恢复函数 `restore_project_variant_overrides`。
- `src/libslic3r/Preset.cpp`
  - 实现紧凑活动行到完整变体表的通用恢复；
  - 普通 3MF/外部预设导入统一调用该函数；
  - 异常时记录参数名、预设类型、行数、步长、完整参数/选择器数组及回退策略。
- `src/slic3r/GUI/simple/DeviceListSimple.cpp`
  - 简易模式的 3MF 配置迁移复用同一恢复逻辑；
  - 已恢复的变体参数不再被紧凑数组二次覆盖。
- `src/libslic3r/PrintConfig.cpp`
  - 为选择阶段的数组越界回退增加 warning 日志，打印参数名、目标变体行、步长、完整源数组和回退下标。

### 示例：修改前为什么没有核对，修改后如何处理

以本次 3MF 的 `retraction_length` 为例，项目保存的是当前四个物理喷嘴的活动值：

```text
项目紧凑数组 = [0.7, 0.2, 0.3, 0.9]
紧凑数组下标：[0, 1, 2, 3]
完整表下标：  [1, 4, 9, 12]

映射关系：
compact[0] -> full[1]  = 0.7
compact[1] -> full[4]  = 0.2
compact[2] -> full[9]  = 0.3
compact[3] -> full[12] = 0.9

项目活动行身份：
P1 = (ID=1, Direct Drive Standard, N02)
P2 = (ID=2, Direct Drive Standard, N04)
P3 = (ID=3, Direct Drive Standard, N02)
P4 = (ID=4, Direct Drive Standard, N04)
```

K3 系统预设不是四行活动数组，而是“4 个物理喷嘴 × 4 个喷嘴口径”的 16 行完整变体表。上述四个活动身份在完整表中对应的下标为：

```text
P1/N02 -> 1
P2/N04 -> 4
P3/N02 -> 9
P4/N04 -> 12
```

#### 修改前

旧逻辑不是完全没有做数组边界判断，而是只做了宽松的越界回退，没有核对“数组属于活动行还是完整变体表”这一层语义：

1. 项目参数恢复只覆盖了耗材和工艺变体，没有恢复打印机变体参数；
2. 因为 `retraction_length` 是项目修改项，导入时直接保留了四元素紧凑数组；
3. 后续选择阶段按完整表下标 `[1,4,9,12]` 取值；
4. 选择函数为了兼容历史短数组和单值默认配置，遇到越界不会阻止导入，而是回退到数组第 0 项；
5. 因此它只能发现“下标越界”，不能判断“当前四元素数组根本不是完整变体表”。

实际取值过程为：

```text
下标 1  -> compact[1] = 0.2
下标 4  -> 越界，回退 compact[0] = 0.7
下标 9  -> 越界，回退 compact[0] = 0.7
下标 12 -> 越界，回退 compact[0] = 0.7

最终错误结果 = [0.2, 0.7, 0.7, 0.7]
```

所以问题的关键不是缺少一个普通的 `index < size` 判断，而是导入阶段没有先确认并转换数组的索引语义。

#### 修改后

新逻辑在进入变体选择前先进行结构核对和完整表恢复：

1. 核对项目选择器的三个数组行数是否一致；
2. 核对每个项目活动身份能否在系统完整表中找到唯一行；
3. 核对项目参数长度是否等于“项目活动行数 × 参数步长”；
4. 核对系统参数是合法单行默认值，或长度等于“系统完整行数 × 参数步长”；
5. 复制系统完整参数表，只把项目四个值写入匹配到的 `[1,4,9,12]` 行；
6. 再由原有选择逻辑从完整表提取当前四个活动喷嘴。

以系统默认回抽表为底，合并过程可简化表示为：

```text
系统完整表 = [0.8,0.5,1.5,3, 0.8,0.5,1.5,3,
              0.8,0.5,1.5,3, 0.8,0.5,1.5,3]

覆盖完整表[1]  = 0.7
覆盖完整表[4]  = 0.2
覆盖完整表[9]  = 0.3
覆盖完整表[12] = 0.9

按 [1,4,9,12] 重新选择
最终正确结果 = [0.7, 0.2, 0.3, 0.9]
```

如果任一核对失败，新逻辑不会猜测数组归属，也不会把紧凑数组写到错误喷嘴行，而是保留系统预设值，并用 warning 日志打印项目完整数组、系统完整数组、选择器数组和失败原因。

## 6. 验证清单

### 必测场景

- 导入本次 `222立方体.3mf`，四个挤出机普通回抽长度显示为 `[0.7, 0.2, 0.3, 0.9]`；
- 普通模式和简易模式分别导入并核对；
- 修改其他步长 1 打印机变体参数后保存 3MF、重新导入，值与保存前一致；
- 修改至少一个步长 2 参数后保存 3MF、重新导入，成对值和喷嘴归属均一致；
- 修改 `min_layer_height`、`max_layer_height` 后保存并重新导入，值不串行。

### 边界场景

- 3MF 只修改部分物理喷嘴：未修改行继续使用当前系统预设值；
- 不同喷嘴口径组合、非顺序组合和重复口径组合均按身份元组匹配；
- 紧凑选择器缺失、长度不一致、找不到唯一系统行时，使用系统值并产生 warning；
- 系统预设只提供一行默认值时，可安全扩展到完整表。

### 反向场景

- K2 Plus 等单喷嘴多耗材机型的非变体参数导入行为保持不变；
- 未列入 `different_settings_to_system` 的参数仍跟随当前系统预设；
- 耗材覆盖参数仍按耗材覆盖优先级生效，本修复不改变覆盖优先级；
- 工艺和耗材变体参数的 3MF 导入需回归，确保共享逻辑未改变其身份语义；
- Tn/Pn 运行时回抽索引修复属于另一条链路，本修复不改变该逻辑；
- 3MF 与既有 G-code 是否来自同一映射快照不在本次处理范围。

## 7. 风险与回退

### 可能风险

- 历史 3MF 的选择器数据本身不完整或存在重复身份时，无法可靠判断活动行归属；
- 以后新增变体参数但未加入对应参数集合时，该参数不会进入通用恢复。

### 风险影响范围

仅影响带变体表的打印机、工艺或耗材预设在导入项目覆盖值时的数组恢复；普通标量参数和非变体数组不经过该逻辑。

### 回退方案

可回退本次四个文件的代码改动。异常输入当前采用“系统预设值 + warning”的保守策略，不会把无法确认归属的项目数组强行写入其他喷嘴行。

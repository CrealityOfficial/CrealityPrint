## 5. 根因分析

以下为代码分析及局部回归结果，需区分已确认的编码缺陷和原始退出原因：

- 程序启动调用 `boost::nowide::nowide_filesystem()`，使 Boost 文件路径按 UTF-8 解释窄字符串。
- `load_gcode()` 原先将 `filename.ToStdString()` 传给 `file_size()`。在 CP936 下，中文路径会被转成本地编码，再被 Boost 当作 UTF-8 解码，产生与附件相同的 `codecvt` 异常。局部程序已复现此行为。
- 该文件大小统计原本位于 `catch (...)` 保护范围内，因此它不能直接解释日志中的未捕获异常和程序退出。
- 预览文件名原先通过默认 `mb_str()` 保存；云下载目录枚举将 UTF-8 窄字符串隐式转为 `wxString`；重命名又经过 `ToStdString()`。这些转换会引入编码不一致或字符丢失。
- `GUI_App::OnExceptionInMainLoop()` 返回 `false`，与附件中未捕获异常后应用退出的行为一致，但不提供首次抛出位置。

目前没有原始文件的完整客户端复现或崩溃调用栈，不能将上述局部复现等同于定位了原 Bug 的最终退出点。

## 6. 修复策略

- 文件系统操作使用 `into_path()`，避免先转为本地编码。
- 存入 `std::string` 或 JSON 的文件名、路径使用 `into_u8()`，显示时用 `from_u8()` 恢复。
- 目录枚举使用 `from_path()`；文件名匹配改用 `wxString::Contains()`。
- 重命名结果保留为 `wxString`，避免无意义的本地编码往返。

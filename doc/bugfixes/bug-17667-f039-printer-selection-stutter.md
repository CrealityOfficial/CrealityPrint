# Bug 17667：F039 添加、切换机型卡顿

## 1. 缺陷信息

- 禅道编号：17667
- 标题：【F039】添加机型变卡死
- 产品：Creality Print
- 模块：准备页面
- 期望：添加和切换机型时界面保持流畅
- 地址：https://zentao.creality.com/zentao/bug-view-17667.html

实际排查发现，“已有机型切换”和“添加新机型”是两个独立流程，卡顿原因也不同，需要分别处理。

## 2. 已有机型切换卡顿

### 2.1 现象

在准备页的机型下拉框中，从 K2、K1C 等已有机型切换到另一个机型时，点击目标项后界面明显停顿；K3 多喷嘴机型的刷新量更大，现象更明显，并曾出现点击 K3 后错误切换到 K1 的问题。

### 2.2 根因

F039 为支持按机型聚合不同喷嘴预设，引入了 `PrinterMachineItem` 分组列表。分组列表原先在 ImGui 绘制调用栈中直接执行：

```cpp
Tab::select_preset(...)
```

该函数会同步刷新打印机、工艺、耗材、参数页和切片状态。把整套刷新直接放进 ImGui 当前绘制帧，会造成点击目标项后的界面停顿，也绕过了原有 wxWidgets 下拉框事件链。

### 2.3 修复

保留 F039 的机型分组展示和 `default_preset` 选择规则，但不再从 ImGui 中直接调用 `Tab::select_preset()`。`SidebarPrinter::select_machine()` 查找对应的真实 wx 下拉框条目，然后调用：

```cpp
SidebarPrinter::select_printer_preset(...)
```

由它投递 `wxEVT_COMBOBOX`，恢复原有处理路径：

```text
ImGui 分组机型项
  -> 查找 default_preset 对应的 wx 条目
  -> wxPostEvent(wxEVT_COMBOBOX)
  -> Plater::priv::on_select_preset()
  -> Tab::select_preset()
```

修改只调整调用入口和执行时序，目标机型、目标预设、未保存配置检查、兼容性计算以及工艺/耗材刷新逻辑均保持原样。

## 3. 添加新机型卡顿

### 3.1 现象

已有机型切换恢复流畅后，通过“添加机型”入口打开机型向导时仍会卡顿。因此不能把已有机型切换的修复视为 Bug 17667 已全部解决。

### 3.2 根因

程序启动时，`ProfileFamilyLoader` 已经异步预加载配置族数据。添加机型仍有两条入口无条件强制重新扫描全部配置族：

1. `GuideFrame::LoadProfile()`：准备页打开添加机型向导时调用；
2. `PrinterPresetConfig::LoadProfile()`：首页添加设备获取机型数据时调用。

两处原调用均为：

```cpp
ProfileFamilyLoader::get_instance()->request_and_wait();
```

`request_and_wait()` 内部执行 `request(true)`，其中 `true` 表示即使数据已经加载完成，也要重新执行完整扫描，并在当前调用线程等待结束。`GuideFrame` 又是在窗口显示前执行该调用，所以卡顿直接发生在点击添加入口之后、向导出现之前。

### 3.3 修复

两处改为：

```cpp
ProfileFamilyLoader::get_instance()->wait_until_loaded();
```

`wait_until_loaded()` 内部执行 `request(false)`：

- 启动预加载仍未完成时，等待正在进行的任务；
- 启动预加载已经完成时，直接复用现有结果；
- 不再因为打开添加页面而强制重复扫描全部配置族。

现有后台添加准备流程本身也使用 `wait_until_loaded()`，本次修改让旧向导和首页数据入口与该流程保持一致。

### 3.4 未改变的原有逻辑

本次没有删除或跳过添加机型后的业务处理，以下流程保持不变：

- 解析选择的机型和喷嘴口径；
- 计算对应的默认耗材；
- `SaveProfile(...)` 保存选择；
- `apply_config(...)` 应用配置；
- `load_current_presets()` 刷新当前预设和参数页；
- 返回准备页并更新界面状态。

因此修改影响的是“读取机型配置数据前是否重复强制扫描”，不改变新机型的添加结果。

### 3.5 创建打印机预设弹窗的显示时序

“Create printer/创建打印机预设”属于另一条管理项流程。原实现从 ImGui 下拉框点击后立即使用 `CallAfter` 投递 wx 事件，wx 回调可能在 ImGui 下一帧显示“下拉框已关闭”之前打开模态弹窗，表现为弹窗已经出现、下拉框却短暂冻结后才消失。

修复后，点击管理项时先执行 `ImGui::CloseCurrentPopup()` 并请求额外绘制帧；下一帧再调用 `select_printer_management()` 投递原 `wxEVT_COMBOBOX`。这样先完成下拉框收起的画面，再打开 `CreatePrinterPresetDialog`，不改变创建预设及保存流程。

## 4. 最小代码改动

- `src/slic3r/GUI/SiderBar.cpp`
  - 已有机型切换恢复 wx 下拉框事件路径。
- `src/slic3r/GUI/WebGuideDialog.cpp`
  - 添加机型向导复用已加载的配置族结果。
- `src/slic3r/GUI/PrinterPresetConfig.cpp`
  - 首页添加设备获取机型数据时复用已加载的配置族结果。
- `src/slic3r/GUI/GUI_ObjectList.cpp`
  - 创建打印机预设时先关闭 ImGui 下拉框，下一帧再投递原 wx 管理项事件。

其他排查期间尝试过、但不属于最终根因的缓存或刷新短路改动不纳入本修复。

## 5. 验证建议

### 已有机型切换

- K2、K1C、K1 等已有机型之间切换无明显停顿；
- K3 能正确选中，不会错误切换到 K1；
- K3 与单喷嘴机型双向切换后，机型、喷嘴、工艺和耗材状态一致。

### 添加新机型

- 点击准备页“添加机型”后，向导能够快速显示；
- 首页添加设备获取机型列表时无同步全量扫描造成的卡顿；
- 确认添加后，新机型及所选喷嘴能正常保存并显示；
- 已有机型和耗材选择不被意外修改。

### 管理项弹窗时序

- 点击“创建打印机”“创建喷嘴”等管理项后，下拉框先正常收起；
- 下拉框收起后的下一帧打开对应弹窗，不出现下拉框冻结后才消失的现象；
- 同一点击只打开一次弹窗，取消或确认后的行为与原流程一致。

## 6. 当前状态

- 已有机型切换卡顿已由用户确认解决；
- 添加机型入口已取消重复强制配置扫描，复用启动阶段的预加载结果；
- 管理项下拉框与弹窗的显示时序已调整为“先关闭下拉框，下一帧投递原 wx 事件”；
- 最终方案不改变机型选择、创建预设、保存配置和刷新预设等原有业务逻辑；
- 本文档记录的方案确定为本缺陷终版；
- 按开发要求，本次修改不执行本地编译。

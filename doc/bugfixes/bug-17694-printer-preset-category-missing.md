# 打印机预设下拉框分类消失问题分析与修复方案

> 一句话结论：多口径功能把主界面的打印机下拉框从“预设名单”改成了“机型名单”，但生成新名单时漏掉了“系统、用户、项目”身份，因此界面只能把所有机型平铺显示。

## 1. 基本信息

- Bug ID：17694
- 标题：打印机预设下拉框不再区分系统配置和用户配置
- 禅道链接：https://zentao.creality.com/zentao/bug-view-17694.html
- 反馈人：康美樱
- 处理人：`wangwenbin`
- 分支：`feature/f039_group`
- 影响模块：准备页左侧打印机选择器、打印机预设聚合、多口径喷嘴选择

## 2. 问题现象

### 用户反馈现象

旧版本的打印机下拉框会明确显示“用户配置”和“系统配置”，用户能够快速判断一个机型来自系统参数包，还是自己创建的预设。

多口径改造后的版本不再显示分类标题，系统机型、用户副本和自定义机型混在同一个列表中。

### 实际结果

当前下拉框类似下面这样平铺显示：

```text
Creality K1C
Creality K2 Plus
Creality K3
Creality K3 0.4 nozzle - 拷贝(1)
My-Creality K1C
SPARKX i7
选择/移除打印机
```

用户只能根据名称猜测哪些是系统配置、哪些是用户配置。

### 期望结果

保留现在“先选机型、再选喷嘴口径”的多口径交互，同时恢复清晰的来源分类：

```text
项目配置
  项目内嵌机型

用户配置
  Creality K3 0.4 nozzle - 拷贝(1)
  My-Creality K1C

系统配置
  Creality K1C
  Creality K2 Plus
  Creality K3
  SPARKX i7

选择/移除打印机
```

分类标题只用于说明，不允许被选中；真正的机型仍按现有逻辑切换。

## 3. 复现步骤

### 前置条件

- 软件中已安装多个系统打印机预设。
- 至少创建一个用户打印机预设，例如系统预设的“拷贝”或自定义机型。
- 使用包含多口径机型聚合功能的版本。

### 操作步骤

1. 打开准备页。
2. 展开左侧“打印机”下拉框。
3. 查看系统机型和用户机型的排列方式。

### 复现结果

- 系统机型和用户机型全部平铺显示。
- “用户配置”“系统配置”分类标题消失。
- 底部“选择/移除打印机”等管理入口仍然存在。

### 复现概率

稳定复现。只要当前版本走新的逻辑机型列表，分类标题就不会显示。

## 4. 根因分析

### 4.1 最容易记住的解释

可以把旧、新逻辑理解成两张名单：

```text
旧名单：姓名 + 身份
新名单：姓名
```

旧名单中的每一项不仅有打印机名称，还带有“系统、用户、项目”身份，所以界面可以按身份分组。

多口径改造重新生成了一张“机型名单”。新名单保留了机型名称和喷嘴信息，却没有保留身份。界面拿到新名单后，只知道要显示哪些机型，不知道它们应该放在哪个分类下。

因此，根本问题不是翻译丢失，也不是系统预设和用户预设真的失去了身份，而是“预设转换为逻辑机型”时漏传了身份字段。

### 4.2 旧版本逻辑

旧版本直接使用打印机预设下拉框生成的完整列表：

```text
读取所有打印机预设
  → 判断项目、用户、系统身份
  → 分别收集到对应分组
  → 插入“项目配置、用户配置、系统配置”标题
  → 显示完整下拉列表
```

不同喷嘴口径会被当作不同预设显示，例如：

```text
Creality K2 Pro 0.2 nozzle
Creality K2 Pro 0.4 nozzle
Creality K2 Pro 0.6 nozzle
Creality K2 Pro 0.8 nozzle
```

分类清楚，但用户需要在主下拉框中直接选择具体口径。

### 4.3 多口径改造后的逻辑

多口径功能希望把“机型”和“喷嘴口径”分开：

```text
多个口径预设
  → 按逻辑机型聚合
  → 主下拉框只显示 Creality K2 Pro
  → 喷嘴下拉框单独选择 0.2、0.4、0.6、0.8
```

这个交互方向是正确的，问题出在新的逻辑机型结构只保存了：

- 机型 ID；
- 显示名称；
- 默认打印机预设；
- 支持的喷嘴口径和对应预设；
- 挤出机数量等机型信息。

它没有保存“系统、用户、项目”来源。

主界面的 ImGui 下拉框随后直接遍历这张扁平机型名单，因此只能逐项显示名称，无法恢复分类标题。

### 4.4 更深层的结构问题

底层只有一份打印机预设数据，但存在两个用途不同的列表适配器：

```text
旧 wx 预设列表
  → 一个条目代表一个真实打印机预设
  → 仍被 3MF 导入、设备自动匹配和测试接口使用

新 ImGui 机型列表
  → 一个条目代表一个逻辑机型
  → 同机型的多个喷嘴预设会被聚合
```

这两个列表表达的不是同一个对象，因此不能简单强制合并：旧列表需要保留 `0.4 nozzle` 等真实预设名，新列表需要向用户隐藏这些实现细节。

原结构真正的问题是“交叉依赖”：主 ImGui 的机型来自新列表，但“选择/移除打印机”“创建打印机”等入口仍从旧 wx 控件中提取。这样新界面并没有一份完整、独立的模型，旧控件调整条目、排序或权限时，主界面就可能再次漏同步。

所以，本问题的根本原因可以概括为两点：

1. 新的逻辑机型模型缺少预设来源字段。
2. 主机型选择器的模型不完整，仍把旧 wx 控件当作部分数据来源。

## 5. 修复方案

### 5.1 修复原则

不恢复旧的“每个喷嘴口径都是一个主下拉项”逻辑，也不在界面中通过名称猜测分类。

正确方向是：保留逻辑机型聚合，在统一的打印机选择器数据模型中明确保存来源、机型族和喷嘴变体。

可以记成一句话：

> 机型负责分组，喷嘴负责切换，来源负责分类。

### 5.2 统一数据模型

每个逻辑机型至少需要明确保存三类信息：

```text
来源：项目 / 用户 / 系统
机型族：哪些喷嘴预设属于同一个逻辑机型
喷嘴变体：每个口径对应哪个真实打印机预设
```

本次在逻辑机型结构中增加明确的来源类型：

```text
Project：项目内嵌预设
User：用户创建或另存为的预设
System：参数包提供的系统预设
```

来源判断只读取预设自身属性：

```text
项目内嵌标记为真
  → 项目配置

系统标记为真
  → 系统配置

其他普通预设
  → 用户配置
```

用户预设即使继承自系统预设，也仍然属于“用户配置”。`base_id` 表示继承或机型族关系，不能代替来源判断。

### 5.3 使用明确的机型键

逻辑机型聚合不能依赖显示名称，因为名称可能被翻译、重命名或另存为。

本次将原来的字符串 `machine_id` 拆为：

```text
MachineKey
  ├─ origin：Project / User / System
  └─ family_id：机型族标识
```

聚合键必须同时包含：

```text
来源 + 机型族 ID
```

当前 `family_id` 按兼容优先级生成：

```text
系统预设且 printer_model 有效：vendor ID + printer_model
用户预设和项目内嵌预设：优先 base_id，其次 setting_id
任何缺少 base_id 和 setting_id 的兼容预设：暂时回退到 preset name
```

这样可以保证：

- 同一系统机型的 0.2、0.4、0.6、0.8 口径合并成一个机型；
- 系统 K1C 和用户 My-K1C 不会因为 `printer_model` 相同而混在一起；
- 来源不同的同名机型不会错误合并；
- 已有 `base_id` 或 `setting_id` 的机型不再依赖显示名称匹配。

这里的“兼容预设”不是按创建时间区分新旧，而是指没有 `base_id` 和 `setting_id` 的数据。新建的本地或项目预设如果没有生成这两个 ID，同样会使用名称兜底。

本次没有贸然新增持久化字段，避免旧用户预设、云同步和旧 3MF 缺少新字段时出现迁移问题。对于既没有 `base_id`、也没有 `setting_id` 的兼容预设，仍保留名称兜底；如果后续确认 `base_id` 不能唯一表达用户机型族，再单独设计并迁移持久化的 `printer_family_id`。

### 5.4 统一生成选择器结构

业务层一次性生成结构化结果：

```text
项目配置
  └─ 项目机型列表

用户配置
  └─ 用户机型列表

系统配置
  └─ 系统机型列表

管理操作
  ├─ 选择/移除打印机
  ├─ 创建喷嘴
  └─ 创建打印机
```

主 ImGui 机型选择器只使用这份结构化结果，不再从旧 wx 控件中反查标题、索引或管理入口。

旧 wx 控件继续承担“真实打印机预设列表”职责，供 3MF 导入、设备自动匹配和测试接口使用。它不再是主 ImGui 机型选择器的数据供应者，两种不同用途之间不再交叉取数据。

分类标题由界面根据来源绘制为不可选择项；管理入口使用明确的动作类型，不再依赖旧下拉框索引和 marker。

### 5.5 选择和切换逻辑

当前选中项不再依赖显示名称或下拉框位置，而是通过稳定机型键匹配：

```text
当前正式打印机预设
  → 计算“来源 + 机型族 ID”
  → 找到对应逻辑机型
  → 在界面中高亮
```

用户选择机型时：

```text
选择逻辑机型
  → 找到该机型的默认预设
  → 默认进入 0.4 mm 预设
  → 调用现有打印机预设切换流程
```

用户选择喷嘴时：

```text
当前逻辑机型 + 目标喷嘴口径或 variant ID
  → 找到真实打印机预设或喷嘴变体
  → 调用统一的喷嘴切换流程
```

这样分类标题的增加、隐藏和排序都不会影响真实选择逻辑。

### 5.6 实际修改点

- `src/slic3r/GUI/SiderBar.h`
  - 为逻辑机型补充 `origin + family_id` 机型键。
  - 增加结构化的打印机选择器分组和管理动作定义。
- `src/slic3r/GUI/SiderBar.cpp`
  - 统一完成来源判断、机型族聚合、喷嘴预设收集和当前选中项计算。
  - 一次生成项目、用户、系统分组以及明确的管理动作。
  - 管理入口直接执行对应行为，不再通过旧控件索引模拟选择。
- `src/slic3r/GUI/GUI_ObjectList.cpp`
  - 按“项目、用户、系统”分组绘制。
  - 分类标题不可选择，机型通过 `MachineKey` 切换。
  - 不再读取旧 wx 控件的管理条目和索引。

本次未修改预设持久化格式。

## 7. 风险与回退

### 可能风险

- 如果错误定义用户机型族 ID，多个用户预设可能被合并，或者同一机型的不同喷嘴无法聚合。
- 如果当前 `base_id` 实际只表示继承父预设，而不是机型族，多个用户预设仍可能被聚合到一起。
- 没有 `base_id` 和 `setting_id` 的旧预设仍依赖名称兜底，重命名后机型键会变化。
- 旧 wx 列表和主 ImGui 列表表达不同对象，后续修改时不能再次互相读取控件条目。

### 风险影响范围

主要影响准备页打印机列表展示、机型选择、喷嘴口径切换、用户预设另存为、项目内嵌预设和管理入口，不涉及切片算法本身。

### 回退方案

- 若结构化选择器出现问题，可回退新选择器模型和 ImGui 分组绘制修改，恢复当前扁平机型列表。
- 不建议回退到旧的逐喷嘴预设列表，因为这会破坏多口径功能“先选机型、再选喷嘴”的交互目标。
- 如果后续新增持久化机型族 ID，应保留现有 `base_id`、`setting_id` 和名称兜底迁移，避免旧用户预设无法加载。

## 8. 备注

### 历史备注摘要

本问题不是翻译缺失，也不是系统、用户预设属性丢失。旧的“用户配置”“系统配置”翻译和分类代码仍然存在，只是主界面已经不再使用旧的完整预设列表显示机型。

多口径改造的目标是正确的：主下拉框选择逻辑机型，喷嘴口径在独立控件中选择。本次补齐新模型的来源分类、机型键和管理动作，同时保留旧 wx 控件的真实预设列表用途，没有恢复旧的逐喷嘴主列表。

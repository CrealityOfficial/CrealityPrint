# Bug 修复记录

## 1. 基本信息
- Bug ID：`15494`
- 标题：`F022-广域网-报错后无法关闭发送页`
- 所属产品：`Creality Print`
- 所属模块：`设备管理`
- 所属计划：`CP 7.2.1`
- Bug 类型：`代码错误`
- 严重程度：`严重`
- 优先级：`高`
- 关联单：
  - https://zentao.creality.com/zentao/bug-view-3283.html
  - https://zentao.creality.com/zentao/bug-view-15321.html
- 分支/提交：`release-260731`

## 2. 现象
- 广域网（WAN）发送场景下，上传报错后发送页无法正常关闭。
- 点击关闭时 webview 进程关不掉，窗口卡住。
- 更严重的情况：对话框关闭/销毁后，后台上传线程的回调仍持有已失效的对话框指针，触发脚本投递或状态回调，导致崩溃或界面异常。
- 影响：用户在发送报错后无法退出发送页，操作被阻断。

## 3. 影响范围
- 模块：`设备管理 / 发送到打印机（SendToPrinter）`
- 关键文件：
  - `src/slic3r/GUI/print_manage/App/SendToPrinter.cpp`
  - `src/slic3r/GUI/print_manage/App/SendToPrinter.hpp`
- 受影响流程：
  - 3MF 发送（`handle_send_3mf`）
  - GCode 发送（`handle_send_gcode`）
  - 广域网上传报错 / 取消 / 完成回调路径
  - 关闭发送页（`OnCloseWindow`）

## 4. 复现步骤（修复前）
1. 打开发送页，选择广域网设备发送打印任务。
2. 上传过程中触发报错（网络失败或服务端返回非 0 状态码）。
3. 点击关闭发送页。
4. 结果：窗口无法关闭 / webview 进程关不掉；或在关闭后上传回调回来时访问已销毁对象，出现崩溃。

## 5. 根因分析
- 旧实现中，上传任务的进度回调、状态回调、完成回调均以裸 `this` 捕获对话框指针，并依赖 `std::atomic<bool> m_isClosed` 标志位判断是否丢弃回调。
- 该方案存在时序缺陷：
  - 后台上传线程与主线程存在竞态，`m_isClosed` 检查与对话框实际销毁之间没有可靠的生命周期保障，回调仍可能访问到已析构对象。
  - 关闭流程被拆成两步（点击关闭仅置标志 + 取消上传，真正的 `Close()` 由上传回调通过 `post_close()` 反向触发）。当上传报错、回调路径异常或未如期返回时，`post_close()` 不被调用，窗口无法关闭。
  - lambda 回调直接跨线程操作 UI（脚本投递、埋点上报），缺乏统一的有效性校验与代次（generation）管理，连续发送时旧任务回调可能污染新任务。

## 6. 修复方案
- 引入 `SendToPrinterUiGate` 生命周期门（`SendToPrinter.cpp`）：
  - 以 `std::shared_ptr<SendToPrinterUiGate>` 持有，回调侧统一以 `std::weak_ptr` 捕获，替代裸 `this` + `m_isClosed`。
  - 门内维护 `dialog` 指针、`accepting_callbacks` 开关、`generation` 代次号和 `active_frontend_data`。
- 新增统一回调投递入口 `post_to_send_dialog(...)`：
  - 通过 `wxGetApp().CallAfter` 把回调 marshalling 回主线程；
  - 执行前做五重校验：`weak_gate.lock()` 成功、`accepting_callbacks` 为真、`dialog != nullptr`、`generation` 匹配、`!IsBeingDeleted()`，任一不满足即安全丢弃。
- 重构关闭流程 `OnCloseWindow`：
  - 新增 `m_closing` 防重入标志。
  - 关闭时若仍在上传，先上报 `"Cancel"` 埋点，随后 `invalidate_ui_gate()` 作废后续回调，再 `cancelUpload(...)`，最后 `event.Skip()` **立即放行关闭**，不再等待上传回调反向关窗。
  - 特意在 `cancelUpload` 之前失效 UI 门，避免其同步回状态时触碰对话框。
- 代次（generation）管理：每次 `handle_send_3mf` / `handle_send_gcode` 发起上传时 `++generation`，旧上传的进度/状态/完成回调因代次不匹配被丢弃。
- 以 `run_script_if_ready(...)` 替代 `post_script(...)`：在主线程内直接校验 `m_browser` 有效且非 busy 后执行脚本；删除 `post_close()`（关闭改由 `OnCloseWindow` 单点驱动）。

## 7. 代码改动摘要
- 文件：`src/slic3r/GUI/print_manage/App/SendToPrinter.hpp`
  - 新增前置声明 `struct SendToPrinterUiGate;`。
  - 成员替换：移除 `std::atomic<bool> m_isClosed`，新增 `std::shared_ptr<SendToPrinterUiGate> m_ui_gate` 与 `bool m_closing`。
  - 方法替换：移除 `post_script(...)`、`post_close()`，新增 `invalidate_ui_gate()`、`run_script_if_ready(const wxString&)`。
  - 头文件包含调整：移除 `<atomic>`，新增 `<cstdint>`、`<memory>`。
- 文件：`src/slic3r/GUI/print_manage/App/SendToPrinter.cpp`
  - 新增 `SendToPrinterUiGate` 结构体与匿名命名空间内的 `post_to_send_dialog(...)` 模板函数。
  - 构造函数创建 `m_ui_gate` 并绑定 `dialog=this`；`receive_color_match_info` 处理器改为 weak_ptr 投递。
  - 析构函数调用 `invalidate_ui_gate()` 并反注册 `receive_color_match_info`。
  - `OnCloseWindow` 重构为 `m_closing` 防重入 + 先失效门再取消上传 + 立即 `event.Skip()`。
  - `handle_send_3mf` / `handle_send_gcode` 的三类上传回调统一改用 `weak_ui_gate` + `upload_generation` + `post_to_send_dialog(...)`。
  - 新增 `run_script_if_ready(...)`、`invalidate_ui_gate(...)` 实现，删除 `post_script(...)`、`post_close(...)`。

## 8. 验证清单
- [ ] 广域网发送成功：正常上报成功并可正常关闭发送页。
- [ ] 广域网发送报错（非 0 状态码）：报错后可立即关闭发送页，webview 进程正常退出。
- [ ] 上传中途点击关闭：窗口立即关闭，上报一次 `Cancel`，无崩溃。
- [ ] 关闭后上传回调回来：回调被安全丢弃，无悬垂指针访问。
- [ ] 连续两次发送：旧任务回调不污染新任务 UI（代次校验生效）。
- [ ] 局域网（LAN）发送路径回归：进度、完成、脚本投递行为正常。

## 9. 回滚 / 风险
- 回滚方式：回退 `SendToPrinter.cpp/.hpp` 中 `SendToPrinterUiGate`、`post_to_send_dialog(...)`、`OnCloseWindow` 重构及回调替换，恢复 `m_isClosed` + `post_script/post_close` 旧实现。
- 风险等级：中（涉及上传回调生命周期与关闭流程的核心重构）。
- 需关注的副作用：
  - 上传成功与关闭窗口竞态时，成功事件可能被 `OnCloseWindow` 的 `Cancel` 埋点覆盖，需确认埋点归类符合预期。
  - 删除 `post_close()` 后不再有"回调反向关窗"路径，需确认无其他流程依赖上传回调自动关闭窗口。

## 2. 问题现象

用户创建一个由三个物理耗材组成的混色耗材，删除其中一个被引用的物理耗材后，右侧混色耗材列表只显示两个组成项。问题截图中的编辑页面同样只显示两个物理耗材选择项。

禅道描述中以拓竹的行为作为参照：三色组成结构应继续保留，被删除的组成位置显示为空，等待用户重新选择物理耗材。

示例：

```text
删除前：物理耗材 1 + 2 + 3
删除物理耗材 2 后：物理耗材 1 + 空槽 + 2

错误显示：1 + 2
期望显示：1 + -- + 2
```

## 3. 影响范围

- 准备页面右侧混色耗材列表的组成项显示。
- 三色混色耗材编辑弹窗的组成项数量与缺失项选择框。
- `gradient_component_ids` 中缺失占位符与 `gradient_component_weights` 的位置对应关系。
- 删除混色耗材所引用物理耗材后的修复入口。

不涉及以下逻辑：

- 正常物理耗材编号的去重和有效 ID 收集。
- 混色比例、渐变曲线及层间轮换算法。
- 混色耗材虚拟编号和稳定身份。
- 未发生物理耗材删除时的正常混色列表显示。

## 4. 修复前复现步骤

1. 在准备页面添加至少三个物理耗材。
2. 创建一个包含三个组成项的混色耗材，例如 `1|2|3`。
3. 删除其中一个被引用的物理耗材，例如物理耗材 2。
4. 查看右侧混色耗材列表。
5. 点击该异常混色耗材，打开编辑弹窗。

修复前结果：

- 被删除位置对应的 `0` 占位符在 GUI 解析时被过滤。
- 右侧列表只显示剩余两个物理耗材。
- 旧版本编辑路径同样只创建两个选择框。
- 三个权重仍保存在数据中，但显示只消费两个组成项，可能出现权重位置错位或末项被忽略。

期望结果：

- 保留原有三个组成位置。
- 被删除位置显示为空槽或 `-- Select --`。
- 其余物理耗材按删除后的编号规则前移。
- 三个权重继续与原有三个槽位一一对应。
- 用户补齐缺失槽位前，该混色耗材保持不可用状态。

## 5. 根因分析

### 5.1 底层数据已经保留缺失占位符

`MixedFilamentManager::remove_physical_filament()` 删除物理耗材时不会移除对应的渐变组成位置，而是将命中的 ID 改为 `0`，并将更大的物理耗材 ID 减 `1`。

```text
gradient_component_ids：1|2|3
删除物理耗材 2：      1|0|2
gradient weights：     保持原有三个位置
```

`normalize_gradient_component_ids()`、序列化和重新加载逻辑也允许保留 `0`。因此问题不在删除或保存阶段，而在 GUI 消费数据的阶段。

### 5.2 有效 ID 解析会主动过滤 `0`

`decode_gradient_ids()` 的用途是收集有效且不重复的物理耗材 ID。该函数只接受大于等于 `1` 的编号，适合切片、颜色计算或映射等不应消费缺失项的场景。

右侧混色列表修复前同样调用该函数：

```text
存储值：1|0|2
解析值：1, 2
显示数：2 个组成项
```

列表虽然已经具备 `comp_id == 0` 时绘制空白徽标的代码，但 `0` 在进入绘制循环前就被过滤，因此空白徽标永远不会出现。

### 5.3 编辑弹窗曾存在相同问题

提交 `a9d61d584`（`fix[#17858]: preserve missing mixed filament slots when editing`）已经为编辑弹窗增加槽位保留解析，使当前分支能够将 `1|0|2` 转换成三个 `MixedFilamentResult::components`，并为 `0` 创建 `-- Select --` 选项。

该提交只将槽位解析用于编辑结果构造，没有同步修改右侧列表，因此当前分支表现为“编辑弹窗已覆盖、列表仍缺一项”的部分修复状态。

## 6. 修复方案

### 6.1 将槽位解析定义为 GUI 通用能力

将 `decode_gradient_slots_for_edit()` 重命名为 `decode_gradient_slots()`，明确它不仅用于编辑，还用于所有需要保持组成位置的 GUI 场景。

该函数的语义为：

- 保留每个组成位置。
- 保留值为 `0` 的缺失占位符。
- 支持旧式紧凑格式，例如 `102`。
- 支持新的 `|` 分隔格式，例如 `1|0|10`。
- 不负责过滤重复或无效物理耗材；需要有效 ID 集合的调用方继续使用 `decode_gradient_ids()`。

### 6.2 列表和编辑弹窗使用同一槽位解析

- `build_result_from_mixed()` 继续调用槽位解析，为编辑弹窗保留完整组成结构。
- `Sidebar::update_mixed_filament_panel()` 改为调用相同的槽位解析。
- 列表绘制循环收到 `0` 后，复用已有空槽徽标绘制逻辑。
- `comp_weights` 按完整槽位数量消费，保持与缺失位置前后的权重对齐。

### 6.3 保留有效 ID 解析的原有用途

不全局替换 `decode_gradient_ids()`。纹理导入、混色预览、有效成员收集等只需要真实物理耗材的路径仍应过滤 `0`，避免缺失占位符被误当作可用工具。

## 7. 代码改动摘要

| 文件 | 实际修改 |
|---|---|
| `src/slic3r/GUI/Plater.cpp` | 将编辑专用槽位解析重命名为 GUI 通用槽位解析；编辑结果构造和右侧列表共同使用；列表保留 `0` 并显示现有空槽徽标 |

本次没有修改：

- `MixedFilamentManager::remove_physical_filament()`。
- 混色耗材序列化和加载格式。
- `MixedFilamentDialog` 的控件创建、确认按钮和缺失项提示逻辑。
- 切片、G-code 或物理工具解析代码。

## 9. 风险与回滚

- 风险等级：`低`。
- 修改仅影响混色耗材 GUI 列表如何解释已经存在的组成槽位，不改变底层数据。
- 主要风险：
  - 列表宽度需要同时容纳空槽、其余组成徽标和警告图标，应在不同 DPI 下检查布局。
  - 旧式紧凑格式中的字符 `0` 与新式多位编号中的数字 `0` 必须继续按不同规则解析；`1|10` 表示耗材 1 和 10，不包含缺失槽位。
  - 权重数量异常的历史数据仍由现有补齐规则处理，本次不改变其归一化策略。
- 回滚方式：
  - 将列表解析恢复为 `decode_gradient_ids()`。
  - 将 `decode_gradient_slots()` 恢复为原名称，并仅供编辑结果构造使用。

回滚不会影响已保存的 `0` 占位数据，但列表会重新隐藏缺失槽位。

## 10. 结论与证据边界

- Bug 17856 的直接原因是右侧列表使用了“有效物理 ID”解析器，导致底层已经正确保存的 `0` 槽位在显示前被过滤。
- 当前修复使列表与编辑弹窗共享保留槽位的解析语义，三色结构、缺失位置及权重对应关系不再丢失。
- 删除、序列化和编辑弹窗的基础能力来自当前分支已有实现；本次改动补齐了列表显示这一遗漏入口。
- 禅道基本信息、现象和期望来自 Bug 17856 页面；根因与修复边界依据当前源代码、提交 `a9d61d584` 和工作区差异分析。

## 4. 根因分析

### 触发条件与代码链路

切换预设后参数更新进入 `ConfigOptionsGroup::refresh_overhang_layout()`。当分组或悬垂速度模式改变、且旧布局已经存在时，会清理旧字段并创建新控件，再替换旧布局。

问题代码位于 `src/slic3r/GUI/OptionsGroup.cpp`：

```cpp
if (parent_sizer != nullptr)
    parent_sizer->Replace(old_sizer, sizer, true);
old_sizer->Clear(true);
delete old_sizer;
```

`wxSizer::Replace(wxSizer*, wxSizer*, bool)` 成功时，内部通过 `wxSizerItem::AssignSizer()` 释放旧 sizer。随后调用 `old_sizer->Clear(true)` 属于释放后访问，再执行 `delete old_sizer` 则会重复释放。

这是明确的对象所有权错误。内存回收、复用状态会影响是否立即崩溃，因此本地未复现不能排除该缺陷。

## 5. 修复方案

### 修复思路

旧布局有效时先清理剩余窗口，再执行布局替换；根据替换结果确定唯一的释放责任方。

### 修改点

文件：`src/slic3r/GUI/OptionsGroup.cpp`，函数：`ConfigOptionsGroup::refresh_overhang_layout()`。

1. 将 `old_sizer->Clear(true)` 放到 `Replace()` 之前，清理旧布局中的剩余窗口。
2. 使用 `replaced` 保存替换结果。成功后由 wxWidgets 释放旧 sizer，本函数不再访问或删除它。
3. 父布局为空或替换未成功时，手动删除仍未被 wxWidgets 释放的旧 sizer；保持原有未挂接布局的处理方式，不新增兜底挂接行为。
4. 保留旧控件停用、字段回收、新控件创建及 `reload_config()` 流程；正常替换沿用父布局中原有的位置、比例和边距。
5. 保留临时诊断，增加 `OLD_SIZER_CLEAR_END` 和 `SIZER_REPLACE_END`（含 `replaced`）记录。修复后的 `OLD_SIZER_DESTROY_BEGIN` 移至清理和替换之前。

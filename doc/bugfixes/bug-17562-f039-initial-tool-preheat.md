# Bug 17562：F039 多色打印首次工具选择重复升降温

结论：首次 `Tn` 仅用于选择初始工具，不应生成提前预热指令；只有后续工具切换才需要提前预热。

## 2. 问题现象

### 用户反馈现象

- 导入提供的 3MF 并切片后，第一耗材对应喷嘴先升至打印温度，随后目标温度下降，之后又重新升温。
- 原始 G-code 第 150～155 行如下：

```gcode
START_PRINT EXTRUDER_TEMP=220 BED_TEMP=40
M104 S140
M104 S220 T0
M104 S190 T0 ; preheat T0 time: 0s target:8s before_t:0s toolchange:0s available:0s search:0s mode:search_start
T0
M104 S220
```

### 实际结果

- 起始 G-code 已经要求 T0 达到 `220℃`。
- G-code 后处理仍把首次 `T0` 当作需要提前预热的工具切换，在其前面插入 `M104 S190 T0`。
- `190℃` 来自 `220℃ + preheat_temperature_delta(-30℃)`。
- 该指令诊断信息为 `time:0s`、`available:0s`，没有提前预热收益，却覆盖了 T0 的 `220℃` 目标，形成 `220℃ → 190℃ → 220℃` 的目标温度变化。

### 期望结果

- 第一条 `Tn` 只选择本次打印的初始工具，不生成提前预热指令。
- 从第二条 `Tn` 开始，后续真实工具切换继续按 `preheat_time` 和 `preheat_temperature_delta` 提前预热。
- 本次不调整 `M109` 的生成或注释逻辑。

## 3. 复现步骤

### 前置条件

- 机型：`Creality K3`（F039 对应机型）
- 喷嘴：`0.4 mm`
- 模式：多耗材、多工具打印
- 关键参数：
  - `ooze_prevention = 1`
  - `preheat_time = 8s`
  - `preheat_temperature_delta = -30℃`
  - 首层喷嘴温度 `220℃`

### 操作步骤

1. 导入提供的 `立方体.3mf`。
2. 执行切片并导出 G-code。
3. 检查 G-code 开头第一条 `T0` 及其前后的 `M104` 指令。
4. 搜索注释 `preheat T0 time: 0s`。

### 复现结果

- 第一条 `T0` 前出现自动插入的 `M104 S190 T0`。
- T0 在已设置为 `220℃` 后又被设置为 `190℃`，工具选择完成后再恢复为 `220℃`。

### 复现概率

- 使用当前 3MF 和配置重新生成同类 G-code 时稳定出现。

## 4. 根因分析

### 触发条件

- 开启防滴漏预热功能，且 `preheat_time > 0`。
- 配置为多工具打印。
- 起始 G-code 中包含用于选择初始工具的第一条 `Tn`。

### 代码链路

1. `GCodeProcessor::run_post_process()` 逐行读取待导出的 G-code。
2. `ExportLines::classify_command()` 将所有 `Tn` 识别为 `Toolchange`。
3. 原逻辑对每一条 `Toolchange` 都调用 `process_line_T()`，没有区分首次工具选择和后续工具切换。
4. `process_line_T()` 调用 `ExportLines::insert_lines()` 回溯预热位置。
5. 非 XL 机型按照“打印温度 + 提前预热温差”生成 `M104`；本例为 `220 - 30 = 190℃`。

### 问题原因

- 预热功能的对象应是后续即将切入的工具，而不是打印开始时选择的初始工具。
- 第一条 `Tn` 前不存在“从当前工具切换到下一个工具”的过程，初始工具温度已经由起始 G-code 管理。
- 原实现按指令类型统一处理所有 `Tn`，导致首次工具选择也被插入预热降温指令。

## 5. 修复方案

### 修复思路

- 使用通用功能语义判断，不绑定 F039、K3 或其他具体机型名称。
- 后处理开始时记录尚未出现工具选择。
- 遇到第一条 `Tn` 时：保留工具选择指令并同步换刀时间缓存，但不调用预热插入逻辑。
- 遇到第二条及后续 `Tn` 时：继续调用原有 `process_line_T()`，保留提前预热功能。

### 修改点

- 文件：`src/libslic3r/GCode/GCodeProcessor.cpp`
- 关键逻辑：
  - 新增局部状态 `tool_selection_seen`。
  - 第一条 `Tn` 仅将状态更新为已完成初始工具选择。
  - 仅当 `tool_selection_seen == true` 时调用 `process_line_T()`。
  - `export_lines.sync_toolchange_time()` 对首次和后续 `Tn` 均继续执行，避免影响后续换刀时间抵扣和跨工具回溯。
- 未修改：
  - `M109` 生成及注释逻辑。
  - 预热温度计算公式。
  - 后续换刀预热时间、换刀耗时抵扣和安全边界逻辑。

## 7. 风险与回退

### 可能风险

- 部分第三方机型起始模板可能曾依赖切片器为第一条 `Tn` 插入预热；修复后初始工具温度应由其起始 G-code 负责。
- 如果后续修改工具指令识别规则，需要确保 `tool_selection_seen` 只由有效的 `Tn` 工具选择推进。

### 风险影响范围

- 仅影响开启预热后处理时的第一条 `Tn`。
- 第二条及后续工具切换、温度计算、换刀耗时同步和 `M109` 不受影响。

### 回退方案

- 回退 `GCodeProcessor::run_post_process()` 中的 `tool_selection_seen` 状态判断，恢复为每条 `Tn` 都调用 `process_line_T()`。

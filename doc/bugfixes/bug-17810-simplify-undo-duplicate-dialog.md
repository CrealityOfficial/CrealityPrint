# Bug #17810：模型简化后撤销重复弹出错误对话框

## 1. 基本信息

- Bug ID：17810
- 标题：模型简化后点击撤销按钮，会错误地弹出两个弹窗
- 所属产品：Creality Print
- 所属模块：准备页面
- 所属计划：CP 7.3.0 Beta
- 严重程度：一般
- 优先级：高
- 影响文件：`src/slic3r/GUI/Gizmos/GLGizmoSimplify.cpp`

## 2. 问题现象

### 2.1 复现步骤

1. 导入包含多个模型的工程，其中至少一个模型带有涂色或自定义支撑数据。
2. 选中单个模型，进入“模型简化”。
3. 等待简化预览完成并点击“应用”。
4. 点击工具栏“撤销”按钮。
5. 在错误对话框中点击“确认”。

### 2.2 实际结果

- 撤销过程中弹出“仅支持对单个零件做简化”的错误对话框。
- 关闭第一次对话框后，同一错误对话框再次出现。
- 从问题附件可以观察到：第一次对话框出现时模型数据尚未完全恢复；关闭后涂色数据恢复，随后又出现第二次对话框。

### 2.3 期望结果

- 撤销操作正常恢复简化前的模型、涂色和自定义支撑数据。
- 撤销过程中不应重新进入模型简化工具，也不应出现选择校验错误对话框。

## 3. 根因分析

### 3.1 撤销快照记录了错误的工具状态

原实现的执行顺序为：

1. Simplify Gizmo 仍处于激活状态。
2. 调用 `Plater::take_snapshot()` 创建简化前快照。
3. 替换模型网格。
4. 调用 `close()` 关闭 Simplify Gizmo。

撤销快照除了保存模型和选择信息，还会序列化 `GLGizmosManager` 的当前工具状态。由于创建快照时 Simplify Gizmo 尚未关闭，快照中的 `m_current` 被记录为 `Simplify`。

### 3.2 撤销时模型与 GL 选择状态存在恢复时序差

撤销加载快照时会依次恢复模型、序列化选择和 Gizmo 状态。序列化选择中的对象 ID 需要在 3D 场景刷新后才能重新绑定为实际的 `GLVolume` 选择，因此 Gizmo 恢复与 GL 选择重建之间存在短暂的中间状态。

快照错误地重新激活 Simplify Gizmo 后，`GLGizmoSimplify::on_render_input_window()` 在该中间状态调用 `get_model_volume()`，得到空指针并进入非法选择处理分支。

### 3.3 在渲染路径中显示模态框放大了问题

非法选择处理分支直接调用 `MessageDialog::ShowModal()`。模态对话框会启动嵌套事件循环，使撤销恢复和界面刷新发生重入。Simplify Gizmo 在恢复前后多次进入相同校验分支，因此用户连续看到两个相同的错误对话框。

该错误信息本应服务于用户主动以非法选择进入简化工具的场景，不应由撤销恢复出的临时 UI 状态触发。

## 4. 修复方案

调整 `GLGizmoSimplify::apply_simplify()` 的状态提交顺序：

1. 在关闭工具前取得并校验当前 `ModelVolume`。
2. 缓存卷名称，并将已计算完成的简化网格移动到局部变量。
3. 调用 `close()`，确保 Simplify Gizmo 已退出。
4. 在模型尚未发生修改的前提下创建撤销快照。
5. 清理与旧网格绑定的涂色、支撑和接缝数据。
6. 将局部保存的简化网格写入模型，并执行后续网格更新。

修复后的关键语义是：

- 快照仍然在任何模型数据变更之前创建，撤销内容保持完整。
- 快照中的 Gizmo 状态为关闭，不会在撤销时重新打开 Simplify Gizmo。
- 简化计算结果在关闭工具前转移到局部变量，不依赖 Gizmo 关闭后的成员状态。
- 保留原有非法选择提示逻辑，用户主动使用错误选择进入工具时的行为不受影响。

## 5. 代码变更

变更文件：`src/slic3r/GUI/Gizmos/GLGizmoSimplify.cpp`

- 新增对 `m_state.result` 的断言，明确“应用”阶段必须已有有效简化结果。
- 在关闭 Gizmo 前缓存 `volume_name` 和 `simplified_mesh`。
- 将 `close()` 移到 `take_snapshot()` 之前。
- 使用局部 `simplified_mesh` 更新模型，移除对关闭后 Gizmo 成员状态的依赖。
- 删除函数末尾重复的 `close()`。

## 6. 方案选择说明

本次没有直接删除或屏蔽 `on_render_input_window()` 中的错误对话框。仅屏蔽弹窗虽然可以隐藏现象，但没有修正撤销快照携带错误 Gizmo 状态的问题，还可能使其他恢复逻辑继续处理不应激活的工具。

通过修正快照边界，使撤销历史同时表达正确的模型状态和 UI 工具状态，能够从源头消除重复弹窗，并保持原有选择校验能力。

## 7. 影响范围与风险

### 7.1 正向影响

- 模型简化后撤销不再重新激活 Simplify Gizmo。
- 不再因撤销过程中的临时选择状态弹出一个或多个错误对话框。
- 涂色、自定义支撑和接缝数据仍由原撤销机制恢复。
- 重做快照记录的是简化完成且工具已关闭的正常状态。

### 7.2 行为变化

- 简化动作对应的撤销快照不再保存“简化工具打开”的 UI 状态。
- 撤销完成后保持普通准备页面状态，而不是重新进入简化工具。这与“应用后工具已经关闭”的用户可见状态一致。

### 7.3 风险评估

- `close()` 只关闭 Gizmo、停止工作线程请求并释放预览渲染资源，不修改 `Model`，因此关闭后创建的快照仍是简化前模型。
- `ModelVolume` 指针在 `close()` 前取得；关闭 Gizmo 不删除或替换模型对象，该指针在后续网格更新阶段仍有效。
- 简化结果使用局部 `unique_ptr` 持有，避免 `on_set_state()` 清理 Gizmo 状态时影响待提交网格。
- 本次变更局限于“应用简化”的提交顺序，不改变简化算法、参数、网格计算或通用撤销实现。

## 8. 回归测试建议

### 8.1 核心用例

1. 单个普通模型执行简化并应用。
2. 点击撤销，确认模型恢复且没有错误对话框。
3. 点击重做，确认简化结果恢复且 Simplify Gizmo 未自动打开。
4. 连续执行多次撤销和重做，确认撤销栈顺序正确。

### 8.2 数据恢复用例

- 带多色涂色的模型：简化后撤销，确认颜色完全恢复。
- 带自定义支撑的模型：简化后撤销，确认支撑标记完全恢复。
- 带接缝涂色的模型：简化后撤销，确认接缝数据完全恢复。
- 同时包含涂色、支撑和接缝数据的模型：确认只出现原有的数据清理通知，不出现简化选择错误框。

### 8.3 选择与生命周期用例

- 简化预览过程中切换到其他模型，确认工具能安全退出或切换。
- 简化预览过程中取消操作，确认原模型不变且不新增撤销记录。
- 选择单个多零件对象、单个 Volume 和多个对象分别尝试进入简化，确认原有可用性与错误提示符合设计。
- 简化应用后立即执行快捷键撤销和工具栏撤销，两条入口结果一致。

### 8.4 稳定性用例

- 对高面数模型连续执行“简化—撤销—重做”。
- 操作期间快速切换选择或视图，确认无崩溃、悬空指针、重复弹窗或后台线程残留。
- 保存并重新打开工程，确认模型网格和涂色数据一致。

## 9. 验收标准

- Bug 附件中的复现流程不再出现“仅支持对单个零件做简化”对话框。
- 撤销一次只回退一次简化操作，重做一次只恢复一次简化操作。
- 简化前的模型几何、涂色、自定义支撑和接缝数据能够正确恢复。
- 撤销和重做完成后 Simplify Gizmo 均不会被异常激活。
- Release 配置编译通过，且未引入新的编译警告或静态检查错误。

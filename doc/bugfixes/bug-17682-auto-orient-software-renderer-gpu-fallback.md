## 2. 问题现象

禁用独立显卡并重启 Creality Print 后，软件启动阶段提示当前显示驱动无法提供所需 OpenGL 支持，程序已降级为软件渲染。

在该环境下执行自动朝向：

- 新版本点击“调整朝向”后直接闪退，没有回退到 CPU。
- 旧版本可以正常调用 CPU 完成自动朝向。
- 调试器捕获到 Windows 异常 `0xC0000005`。
- 异常发生在 `opengl32.dll`，访问了无效地址 `0x0000000000000308`。

## 3. 重现步骤

1. 在 Windows 设备管理器或系统配置中禁用独立显卡。
2. 重启 Creality Print。
3. 确认启动时出现“软件渲染”警告。
4. 导入可打印模型。
5. 打开自动朝向功能并点击“调整朝向”。

修复前结果：

- 程序在 GPU OpenGL 上下文初始化阶段闪退。
- 自动朝向没有进入 CPU 回退路径。

期望结果：

- 软件渲染环境不尝试初始化 GPU 自动朝向。
- 自动朝向沿用既有 CPU 回退逻辑。
- 操作过程中 3D 场景和背景保持正常。

## 4. 根因分析

### 4.1 软件渲染状态未传递给 GPU 自动朝向

启动流程已经通过 `software_renderer_mode()` 判断驱动能力，并显示软件渲染警告。但该状态此前只用于主界面渲染降级，没有作为可查询的运行时状态提供给 `GpuOrient`。

因此，即使程序已经明确进入软件渲染模式，首次执行自动朝向时仍会创建私有 WGL 上下文，并调用 `wglGetProcAddress("wglCreateContextAttribsARB")` 查询扩展函数。

调试器显示访问冲突发生在 `wglGetProcAddress()` 内部。该异常属于显卡驱动/OpenGL ICD 边界的原生访问冲突，不能依赖普通 C++ 异常处理安全回退。因此，已经确认的软件渲染环境必须在进入 WGL 探测前被拦截。

### 4.2 旧版本正常的原因

旧版本没有进入新增的 GPU 自动朝向初始化链路，自动朝向直接运行 CPU 实现，因此不会触发 WGL 扩展函数调用，也不会切换主界面的 OpenGL Context。

## 5. 修复方案

本次采用局部修复，不改变原有自动朝向调用结构和 CPU 回退流程。

### 5.1 保存软件渲染状态

在 `OpenGLManager` 中保存启动阶段的软件渲染判定，并提供只读查询接口。状态采用粘性记录：一旦本进程进入软件渲染模式，后续初始化不会将其重新覆盖为硬件渲染。

### 5.2 软件渲染时禁止初始化 GPU 自动朝向

`GpuOrient::Impl` 初始化时首先查询软件渲染状态：

- 软件渲染：记录 GPU 不可用原因并立即返回。
- 硬件渲染：继续执行原有 GPU OpenGL 初始化。

这样可以保证出现软件渲染警告后，自动朝向不会再进入 `wglGetProcAddress()`，外层原有 `available()` 判断会自然进入 CPU 回退路径。

## 6. 代码修改摘要

### `src/slic3r/GUI/OpenGLManager.hpp`

- 增加进程级软件渲染状态字段。
- 增加 `is_software_renderer()` 查询接口。

### `src/slic3r/GUI/OpenGLManager.cpp`

- 在启动 OpenGL 初始化阶段保存软件渲染判定。
- 使用粘性状态，避免启动环境变量被清除后丢失降级信息。

### `src/slic3r/GUI/simple/gpu/GpuOrient.cpp`

- 软件渲染环境直接禁用 GPU 自动朝向。

未修改以下调用层逻辑：

- `OrientJob.cpp`
- `GLObjectManipulateToolbarSimple.cpp`
- `SlicerBridgeActionsProcess.cpp`

上述位置继续使用项目原有的 GPU 可用性判断和 CPU 回退流程。

## 7. 修复后流程

```text
软件启动
  └─ 检测到软件渲染并保存状态
       └─ 用户执行自动朝向
            └─ GpuOrient 检测到软件渲染
                 ├─ 不创建私有 WGL Context
                 ├─ 不调用 wglGetProcAddress
                 └─ available() 返回 false
                      └─ 原有流程调用 CPU 自动朝向
```

## 9. 风险与回滚

风险等级：低。

主要风险：

- 启动阶段一旦判定为软件渲染，本次进程将始终禁用 GPU 自动朝向；显卡状态改变后需要重启软件重新检测。
- 某些驱动虽然可提供基础界面 OpenGL，但不支持 GPU 自动朝向所需的 OpenGL 4.3 Compute Shader，此时仍会按原有失败路径回退 CPU。

回滚方式：

- 移除 `OpenGLManager` 的软件渲染状态字段及查询接口。
- 移除 `GpuOrient` 中的软件渲染短路。
- 回滚后软件渲染环境会重新面临自动朝向初始化闪退风险。

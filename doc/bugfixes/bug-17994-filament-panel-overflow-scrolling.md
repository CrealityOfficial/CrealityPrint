## 2. 问题现象
- 禅道原始描述：`耗材卡片没有限制个数且没有滚动条，如果个数很多时就什么都看不到了`。
- 耗材数量增加后，耗材卡片区域会持续向下扩展，没有独立且受控的可视窗口。
- 卡片超过侧栏可见范围时，底部卡片不可达或挤压侧栏后续控件，最终导致耗材区域无法正常查看和操作。
- 普通滚轮按多个较小滚动单位移动，会让自绘耗材卡片在一次滚轮操作中重复重绘，卡片较多时滚动不够顺畅。
- 当前工作区同时修正了“添加一个耗材”按钮的禁用图标和光标反馈；该项不是禅道正文明确描述的主现象，按伴随交互修正记录。

## 5. 根因分析
- 原耗材卡片直接挂载在 `FilamentPanel`，`wxWrapSizer` 也直接加入外层布局：
  - 卡片数量增加时，布局高度随行数持续增长；
  - 没有独立 viewport、virtual size 和垂直滚动条；
  - 侧栏只能被动扩展或裁剪内容，无法稳定限制卡片区域高度。
- 耗材卡片是自绘子窗口。若沿用 `wxScrolledWindow` 默认的小步滚动，一次滚轮刻度可能产生多次位移和重绘，卡片较多时会放大绘制开销。
- 行列数同时受卡片尺寸、侧栏宽度和滚动条宽度影响：
  - 仅按无滚动条宽度计算列数时，显示滚动条后可用宽度会减少；
  - 窄侧栏下可能少容纳一列，原行数计算随之失效。
- 添加按钮是 `HoverBorderIcon` 自绘控件：
  - `setEnable(false)` 负责切换控件内部绘制状态；
  - 再调用原生 `Enable(false)` 可能阻止正常的自绘刷新或鼠标状态处理；
  - 如果只保留原生窗口启用，又缺少业务入口检查，则仍可能错误执行添加。因此视觉禁用和业务拦截必须分层处理。

## 6. 修复方案
- 为耗材卡片增加独立滚动容器：
  - 使用 `wxScrolledWindow` 作为受限 viewport；
  - 在其中创建 `m_filament_content` 内容面板；
  - 将 `wxWrapSizer` 和所有 `FilamentItem` 改挂到内容面板。
- 新增 `FilamentPanel::update_scroll_height()` 统一计算布局：
  - 卡片占位宽度为 `FILAMENT_BTN_WIDTH + 8 DIP`；
  - 行高为 `FILAMENT_BTN_HEIGHT + 8 DIP`；
  - 根据当前客户区宽度计算列数和行数，列数最少为 `1`；
  - 行数超过 `5` 时计入系统垂直滚动条宽度，再次计算列数和行数；
  - viewport 高度限制为 `min(rows, 5) * row_height`；
  - virtual height 保留全部行，确保所有卡片均可滚动访问；
  - 回落到 `5` 行以内时隐藏滚动条并将位置恢复到顶部。
- 将滚动单位设置为一整行，并累计滚轮 rotation：
  - 普通垂直滚轮每达到一个 wheel delta 后按行滚动；
  - `Ctrl + 滚轮`、非垂直滚轮或没有垂直滚动条时交还默认事件处理；
  - 减少一次滚轮操作中的中间位移和重复重绘。
- 在所有影响布局的入口调用统一刷新：
  - 窗口尺寸变化；
  - 添加耗材；
  - 删除耗材；
  - 清空耗材；
  - 侧栏宽度重排；
  - Windows DPI 缩放。
- 调整添加按钮的禁用策略：
  - 为亮色和暗色主题分别设置禁用图标；
  - 仅通过 `setEnable(enable)` 切换自绘状态，不再对该自绘按钮调用原生 `Enable(enable)`；
  - `wxEVT_LEFT_DOWN` 处理器继续以 `can_add_filament()` 拦截实际添加；
  - `HoverBorderIcon::OnMouseMove()` 在 busy 或自绘禁用时使用 `wxCURSOR_ARROW`，可用时才使用 `wxCURSOR_HAND`；
  - 混合耗材按钮仍保留原生 `Enable(enable)`，并在打开对话框前后重复检查 `can_add_filament()`。

## 10. 回滚与风险
- 回滚方式：
  - 回退 `FilamentPanel` 的 `wxScrolledWindow`、内容面板、滚轮处理和动态高度计算；
  - 将 `FilamentItem` parent 和 `wxWrapSizer` 恢复到原 `FilamentPanel`；
  - 回退 `Plater` 中的禁用图标与自绘状态策略；
  - 回退 `HoverBorderIcon` 的禁用态光标判断。
- 风险等级：`中`，主要影响准备页耗材侧栏布局和交互，不修改切片数据或 Profile 数据。
- 重点风险：
  - 卡片 parent 改变后，依赖父窗口的事件路由、坐标换算或主题背景可能发生变化。
  - 滚动条出现后可用宽度减少，临界宽度下列数可能变化；当前方案已二次计算，但仍需覆盖多种 DPI 和侧栏宽度。
  - 将原生窗口保持为 enabled 后，业务安全性依赖所有添加入口继续执行 `can_add_filament()`；新增入口也必须遵守该约束。
  - 不同平台的 wheel delta、系统滚动条宽度和 DPI 取整可能造成一行滚动量或布局边界差异。
  - 内容面板位置通过 `CalcScrolledPosition()` 更新，需验证删除、缩放及滚动后不会出现坐标漂移。

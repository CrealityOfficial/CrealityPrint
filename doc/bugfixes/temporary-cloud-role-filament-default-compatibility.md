# 云端角色耗材默认值临时兼容

## 1. 背景

- 云端工艺参数尚未完成更新，三个角色耗材参数仍可能使用值 `1` 表示缺省。
- 新版正式语义使用值 `0` 表示缺省，值 `1` 表示实际耗材 1。
- 当前版本临时使用值 `1` 表示缺省；值 `0` 只作为旧值或异常值兜底归一到 `1`，待云端更新后再恢复正式语义。

涉及参数：

- `wall_filament`
- `sparse_infill_filament`
- `solid_infill_filament`

## 2. 当前临时规则

- 参数定义使用 `min=0`、默认值 `1`。
- 参数值为 `1`：按缺省处理，墙、稀疏填充和实心填充继承对象、模型体或局部区域自身的 `extruder`。
- 参数值为 `2`、`3` 等大于 1 的值：按显式角色耗材处理，覆盖对象自身耗材。
- 参数值为 `0`：不作为正式语义使用，加载/应用时临时归一到 `1`。
- 普通模型体的耗材优先级为：显式 `wall_filament` / `sparse_infill_filament` / `solid_infill_filament` > 模型体 `extruder` > 对象 `extruder` > 工艺默认值。
- 对象 `extruder` 只作为缺省兜底值；如果模型体自身设置了 `extruder`，模型体值必须覆盖对象兜底值。
- 修改器和高度范围的显式 `extruder` 表示局部覆盖，仍高于父区域继承值，但低于自身显式角色耗材。
- 界面暂时隐藏“缺省”选项，只显示耗材 `1`、`2`、`3` 等选项。
- 已保存的值 `0` 在界面上临时映射到第一个可见项，避免出现空选择。
- 暂时关闭旧 3MF 的 `1/1/1 -> 0/0/0` 自动迁移，但保留全部迁移实现代码。

示例：对象自身使用耗材 3：

- 工艺参数为 `1/1/1`：三个角色最终都使用耗材 3。
- 工艺参数为 `0/0/0`：先归一到 `1/1/1`，最终也使用耗材 3。
- 工艺参数为 `2/2/2`：三个角色最终都使用耗材 2。

示例：对象自身使用耗材 3，模型体自身使用耗材 1：

- 工艺参数为 `1/1/1`：三个角色按缺省处理，最终使用模型体自身耗材 1。
- 工艺参数为 `2/2/2`：三个角色按显式角色耗材处理，最终使用耗材 2。

## 3. 优先级演进与问题原因

旧版本逻辑：

- `extruder` 会强覆盖 `wall_filament`、`sparse_infill_filament`、`solid_infill_filament`。
- 合并顺序为对象配置先应用，模型体配置后应用，因此模型体 `extruder` 会覆盖对象 `extruder`。
- Bambu 这类 3MF 中对象配置保存 `extruder=3`，每个模型体保存自己的 `extruder=1/2/3/4/5/6`，旧版本可以保持多色。
- 问题是旧版本不区分角色耗材是否为用户显式设置，后续 `extruder` 也会覆盖用户设置的 `wall/sparse/solid`，导致“墙用 3、填充用 1、实心填充用 2”这类角色耗材配置失效。

修改前的新版本逻辑：

- `extruder` 只在 `wall/sparse/solid` 为缺省时补位，用于保护用户显式设置的角色耗材。
- 问题是代码只判断当前值是否缺省，没有记录这个值的来源。
- 对象 `extruder=3` 先把缺省的 `wall/sparse/solid` 填成 3 后，模型体自身 `extruder=1/2/3/4/5/6` 会认为三个角色字段已经不是缺省，因此无法覆盖。
- 结果是 Bambu 多色模型的所有模型体都继承对象耗材 3，切片后变成单色。

本次修复后的逻辑：

- 普通模型体优先级固定为：显式 `wall/sparse/solid` > 模型体 `extruder` > 对象 `extruder` > 工艺默认值。
- 对象 `extruder` 写入角色字段时只作为 fallback，不能阻止后续模型体 `extruder` 覆盖。
- 只有大于缺省值的角色耗材才被视为显式设置，才可以阻止后续 `extruder` 覆盖。
- 修改器和高度范围仍保留局部覆盖语义：显式角色耗材 > 局部 `extruder` > 父区域继承值。

## 4. 修改位置

- `src/libslic3r/PrintConfig.cpp`
  - 三个参数使用 `min=0`、默认值 `1`。
  - `handle_legacy()` 临时将三个角色耗材参数的值 `0` 归一为 `1`。
- `src/libslic3r/PrintObject.cpp`
  - `is_default_role_filament()` 仅使用 `filament == 1` 判断临时缺省值。
  - 漏进来的值 `0` 会先归一到 `1`，再进入角色耗材应用逻辑。
  - 只有大于 1 的角色值才作为显式覆盖。
  - 合并模型体配置时需要区分“显式角色耗材”和“由上层 `extruder` 继承得到的兜底值”，后者允许被更内层模型体 `extruder` 覆盖。
  - 普通模型体使用 `volume extruder > object extruder`；修改器和高度范围的显式 `extruder` 保持局部覆盖语义。
- `src/libslic3r/Format/bbs_3mf.cpp`
  - `ENABLE_LEGACY_ROLE_FILAMENT_MIGRATION` 暂时设为 `false`。
  - 迁移判断、迁移函数及调用链均保留。
- `src/slic3r/GUI/Plater.cpp`
  - 三个参数注册到 `dynamic_filament_list_1_based`，隐藏“缺省”选项。
  - 值 `0` 临时映射到第一个可见项。
  - 动态列表刷新后如果旧选项越界，临时显示第一个可见项，避免删除耗材后残留失效耗材文本。
  - 删除耗材时，如果三个角色耗材参数引用了被删耗材或越界值，临时回退到值 `1`。
- `src/slic3r/GUI/PartPlate.cpp`
  - 准备页和自动摆盘估算盘内耗材时，只有角色耗材值 `2` 及以上才作为显式已用耗材统计。
  - 避免界面上显示的 `1 PLA` 被误认为实际耗材 1，从而额外生成擦拭塔。
- `src/libslic3r/PrintApply.cpp`
  - `get_used_extruders()` 统计已用耗材时，同样只把角色耗材值 `2` 及以上作为显式耗材。
  - 避免 `normalize_fdm_2()` 因误统计耗材 1 而保留多耗材/擦拭塔逻辑。
- `tests/fff_print/test_printobject.cpp`
  - 覆盖值 `0` 兜底归一、值 `1` 继承模型体耗材、值 `2` 显式覆盖，以及模型体 `extruder` 覆盖对象 `extruder` 兜底值。

## 5. 云端更新后的还原清单

云端数据全部更新为值 `0` 表示缺省后，执行以下还原：

1. 将三个参数的默认值从 `1` 恢复为 `0`，`min` 保持 `0`。
2. 删除 `PrintConfig.cpp` 中三个角色耗材参数值 `0` 归一到 `1` 的临时处理。
3. 将 `is_default_role_filament()` 恢复为仅值 `0` 表示缺省，并删除值 `0` 归一到 `1` 的兜底。
4. 将 `ENABLE_LEGACY_ROLE_FILAMENT_MIGRATION` 改回 `true`，恢复旧 3MF 版本迁移。
5. 将三个参数从 `dynamic_filament_list_1_based` 切回 `dynamic_filament_list`，重新显示“缺省”选项。
6. 删除 `DynamicFilamentList1Based::index_of()` 中值 `0` 和越界值映射到第一项的临时兼容。
7. 删除 `DynamicFilamentList1Based::apply_on()` 中旧选项越界后回到第一项的临时兼容。
8. 将 `Plater.cpp` 中删除耗材后的角色耗材兜底值从 `1` 恢复为正式语义下的 `0`。
9. 将 `PartPlate.cpp` 和 `PrintApply.cpp` 中角色耗材显式统计条件从 `> 1` 恢复为正式语义下的 `> 0`。
10. 调整测试：值 `0` 继承对象/模型体耗材，值 `1`、`2`、`3` 分别明确指定对应耗材，并保留模型体 `extruder` 覆盖对象 `extruder` 兜底值的用例。

## 6. 注意事项

- 当前临时语义下，用户在界面选择第一项耗材 1，切片时仍会被解释为缺省，而不是强制使用耗材 1。
- 本兼容不应长期保留；云端参数更新后必须按还原清单恢复正式语义。
- 还原时不要删除旧 3MF 迁移代码，只恢复迁移开关和参数语义。

## 1. 基本信息

- Bug ID：未提供
- 标题：多口径工艺和耗材参数从单值展开为完整变体数组后误报未保存修改
- 禅道链接：未提供
- 反馈人：未提供
- 处理人：wangwenbin
- 分支：`feature/f039_group`
- 影响模块：工艺预设、耗材预设、多口径参数页、预设 dirty 判定、3MF 差异参数生成、未保存修改弹窗

## 2. 问题现象

### 用户反馈现象

在新建项目中使用 K3 多口径配置，当前参数均为系统值且未进行修改。随后导入 `333` 目录中的两个 3MF 时，程序仍弹出“加载项目：未保存的更改”。

弹窗中可见大量旧值与新值完全相同的项目，例如：

```text
普通打印加速度：12000 -> 12000
首层加速度：2000 -> 2000
内墙加速度：5000 -> 5000
外墙加速度：5000 -> 5000
```

第一阶段语义比较接入后，上述相同值项目已被过滤，但测试中仍出现“列表为空、只有保存/放弃按钮”的弹窗。该现象说明有效参数已经判定为相同，剩余 dirty 项是无法在设置搜索器中展示的变体身份数组。

过滤工艺身份数组后，再次导入 `333-3立方体.3mf` 时，弹窗进一步暴露出耗材“参数覆盖”中的回抽项，旧值和新值均显示为 `N/A`：

```text
切料时回抽（试验）：N/A -> N/A
切料回抽距离：N/A -> N/A
切换材料时的回抽量：N/A -> N/A
Retraction Length：N/A -> N/A
额外回填长度：N/A -> N/A
```

这些项目使用可空值；`N/A` 对应配置中的 `nil`。系统耗材预设保存单个 `nil`，耗材多口径页为独立编辑各喷嘴变体而展开为多行 `nil`，旧 dirty 逻辑仍按数组形状判为不同。

### 实际结果

虽然用户没有修改系统工艺或耗材参数，多口径参数界面初始化后仍将当前预设判定为 dirty，导入其他项目时弹出未保存修改对话框。

### 期望结果

- 工艺或耗材的单值系统默认参数展开为完整变体数组，但各变体的有效值未发生变化时，不判定为修改，不弹窗；
- 只有同一个喷嘴变体的有效值确实改变时才判定为修改；
- 弹窗准确显示发生变化的喷嘴变体及其旧值、新值。

## 3. 复现步骤

### 前置条件

- 机型：Creality K3；
- 存在多个物理喷嘴和多个喷嘴口径变体；
- 工艺预设：`0.12mm Standard @Creality K3 0.4 nozzle`；
- 当前为新建项目，未手工修改预设参数；
- 测试目录：`F:\result\2026bug修复\8月\多口径测试\333\`。

### 操作步骤

1. 新建项目并选择 K3 多口径配置；
2. 打开带有 0.2、0.4 变体切换的工艺参数页和耗材参数页；
3. 不修改任何参数；
4. 导入 `333` 目录中的任意 3MF；
5. 观察是否出现未保存修改弹窗。

### 复现结果

修复前弹出未保存修改对话框，并先后显示旧值、新值相同的工艺参数，以及 `N/A -> N/A` 的耗材回抽覆盖参数。

### 复现概率

系统工艺或耗材参数使用单值默认值，而多口径 UI 将当前编辑配置展开为多行变体数组时稳定触发。

## 4. 根因分析

### 触发条件

系统工艺预设中的部分参数只保存一个公共默认值，例如：

```text
initial_layer_speed = [60]
```

工艺预设同时具有完整的变体身份表：

```text
(print_extruder_id, print_extruder_variant, print_nozzle_variant)
```

打开多口径工艺界面后，为支持不同喷嘴口径独立编辑，当前编辑配置被展开为完整变体数组：

```text
系统物理存储：[60]

当前编辑存储：
[60,60,60,60,
 60,60,60,60,
 60,60,60,60,
 60,60,60,60]
```

耗材可选覆盖参数存在同样的存储语义。例如系统预设没有单独覆盖回抽长度时，逻辑值为单个 `nil`：

```text
系统耗材存储：filament_retraction_length = [nil]
当前编辑存储：filament_retraction_length = [nil, nil, nil, nil]
```

两边都表示“所有喷嘴变体均不覆盖打印机回抽长度”，有效值均为 `N/A`，只是物理数组长度不同。耗材行身份由以下两项组成：

```text
(filament_extruder_variant, filament_nozzle_variant)
```

### 代码链路

```text
Tab::update_process_extruder_switch
  -> ensure_process_nozzle_variant_rows
  -> 当前编辑配置扩展完整变体行

TabFilament::update_filament_nozzle_variant_switch_impl
  -> ensure_filament_nozzle_variant_rows
  -> 当前耗材编辑配置扩展活动喷嘴变体行

  -> GUI_App::has_current_preset_changes
  -> PresetCollection::current_is_dirty
  -> PresetCollection::is_dirty
  -> UnsavedChangesDialog::update_tree
```

### 问题原因

旧逻辑直接比较配置数组的物理结构：

```text
[60] != [60,60,60,...]
[nil] != [nil,nil,nil,nil]
```

因此把“为 UI 编辑而展开数组”误认为“用户修改参数”。第一版共享比较只接入了 `TYPE_PRINT`，耗材 `TYPE_FILAMENT` 仍走原始数组比较，所以工艺误报消失后又显示出耗材 `N/A -> N/A` 的第二层误报。

弹窗显示又按两个数组共同存在的下标范围比较。系统数组只有第 0 项，所以只显示第 0 项的值，最终出现：

```text
旧值 60 -> 新值 60
```

根因不是两个 3MF 内容不同。弹窗在加载目标 3MF 之前检查当前项目，目标文件仅触发了这次检查。

## 5. 修复方案

### 修复思路

保留系统预设和当前编辑配置原有的存储结构，不为了比较而修改或强制展开系统预设。比较时建立逻辑视图：

```text
变体身份 -> 该参数的有效值
```

比较规则：

1. 参数数组只有一个值时，该值是所有未单独配置变体的公共默认值；
2. 参数数组为多行时，数组长度必须与本配置自己的变体选择器行数一致；
3. 工艺使用 `(物理挤出机 ID, 挤出机变体, 喷嘴变体)` 定位对应行；耗材使用 `(挤出机变体, 喷嘴变体)` 定位对应行，耗材不引入物理喷嘴 Pn 语义；
4. 系统的 0.2-标准只和当前的 0.2-标准比较，0.4-标准只和当前的 0.4-标准比较；
5. 数组长度不同本身不代表修改，只有同一身份解析出的有效值不同才代表修改；
6. 工艺的三个选择器、耗材的两个选择器都是参数行的身份索引表，仅用于对齐，不作为独立的用户参数判 dirty；
7. 身份表发生变化时主动复查全部多口径参数，即使参数数组原始文本相同，只要值被重新分配给不同身份，仍将真实参数加入 dirty；
8. 当前配置为 4 行紧凑活动表、系统为 16 行完整表时，以当前活动身份作为比较域，系统中额外的未活动身份不构成修改；
9. 真实参数的选择器缺失、数组长度不合法、身份重复或当前身份在系统中找不到时，不压制该参数的 dirty，继续使用原始差异结果。

### 比较示例

#### 新建项目，没有实际修改

```text
系统存储：[60]
当前存储：[60 × 16行]

系统(P1/0.2-标准) = 60  当前(P1/0.2-标准) = 60
系统(P1/0.4-标准) = 60  当前(P1/0.4-标准) = 60
...

有效值全部相同 -> 非 dirty -> 不弹窗
```

即使两边身份表的物理形状不同，也只把它们当作查找参数行的索引：

```text
系统身份表：16行
当前身份表：4行紧凑活动变体

print_extruder_id / print_extruder_variant / print_nozzle_variant
只负责说明每一行是谁，不单独构成修改。

最终是否 dirty，仍由 initial_layer_speed 等真实参数按身份比较后决定。
系统中另外 12 个未出现在当前紧凑表里的身份不参与本次修改判定。
```

#### 耗材回抽覆盖没有实际修改

```text
系统存储：filament_retraction_length = [nil]
当前存储：filament_retraction_length = [nil, nil, nil, nil]

系统(0.2-标准) = nil  当前(0.2-标准) = nil
系统(0.4-标准) = nil  当前(0.4-标准) = nil
系统(0.6-标准) = nil  当前(0.6-标准) = nil
系统(0.8-标准) = nil  当前(0.8-标准) = nil

每个身份的有效值都表示“不覆盖”，即界面中的 N/A。
结果：非 dirty，不出现 N/A -> N/A 弹窗。
```

如果仅把 0.4-标准的耗材覆盖回抽长度改为 0.8 mm，则只有该身份不同：

```text
系统(0.4-标准) = nil  当前(0.4-标准) = 0.8

结果：filament_retraction_length 为 dirty
弹窗：Retraction Length（0.4-标准） N/A -> 0.8 mm
```

#### 只修改 0.4-标准

```text
系统(0.2-标准) = 60  当前(0.2-标准) = 60  -> 相同
系统(0.4-标准) = 60  当前(0.4-标准) = 88  -> 不同

结果：initial_layer_speed 为 dirty
弹窗：首层速度（0.4-标准） 60 -> 88
```

#### 同时修改 0.2、0.4-标准

```text
系统(0.2-标准) = 60  当前(0.2-标准) = 55
系统(0.4-标准) = 60  当前(0.4-标准) = 88

弹窗：
首层速度（0.2-标准） 60 -> 55
首层速度（0.4-标准） 60 -> 88
```

### 修改点

- `src/libslic3r/PrintConfig.hpp`
  - 声明通用预设变体差异结构、工艺/耗材身份选择器识别函数和共享语义比较接口。
- `src/libslic3r/PrintConfig.cpp`
  - 实现单值公共默认、完整数组和紧凑数组的有效值解析；
  - 使用同一个底层比较器，按工艺三元身份或耗材二元身份匹配对应行；
  - 返回真实变化身份以及两边的实际取值下标；
  - 正常的单值默认回退不再产生 warning，真正异常的短数组只记录一次 warning。
- `src/libslic3r/Preset.cpp`
  - `is_dirty` 对 `TYPE_PRINT` 和 `TYPE_FILAMENT` 使用同一语义规则，过滤仅由数组展开产生的结构差异；
  - `dirty_options` 使用相同规则生成真实 dirty 参数列表；
  - `dirty_options_without_option_list` 使用相同规则生成 3MF 的 `different_settings_to_system`，避免三处语义不一致。
  - 过滤工艺三个、耗材两个纯结构身份选择器的原始数组差异，避免真实参数均相同时仍弹出空列表；
  - 身份选择器变化时复查全部多口径参数，身份换位导致有效值换位时将真实参数补入 dirty；无法安全对齐的多值参数保守保留 dirty。
- `src/slic3r/GUI/UnsavedChangesDialog.cpp`
  - 工艺和耗材弹窗均根据共享比较结果显示真实发生变化的变体；
  - 系统单值使用第 0 项，当前完整数组使用身份对应行，不再显示相同的旧值和新值。

## 6. 验证清单

### 必测场景

- 新建 K3 多口径项目，打开工艺参数页但不修改，导入 3MF 时不弹未保存修改对话框；
- 新建 K3 多口径项目，打开耗材参数页但不修改，`[nil]` 展开为多行 `nil` 后不判 dirty，不显示 `N/A -> N/A`；
- 系统 `[60]`、当前 `[60 × 16行]` 判定为相同；
- 只修改 0.2-标准，弹窗只显示 0.2-标准的真实差异；
- 只修改 0.4-标准，弹窗只显示 0.4-标准的真实差异；
- 同时修改 0.2、0.4-标准，弹窗分别显示两项；
- 保存 3MF 后检查 `different_settings_to_system`，仅数组展开不应新增该参数，真实修改仍应保留该参数。
- 单独修改某个耗材喷嘴变体的覆盖回抽值，弹窗只显示该变体的 `N/A -> 实际值`，其他仍为 `nil` 的变体不显示。

### 边界场景

- 两边都是单值数组：保持原有单值比较；
- 两边都是完整数组但行顺序不同：按身份匹配，不按位置盲目比较；
- 参数原始数组相同但身份行互换：按有效归属识别真实差异，不因原始数组相同而漏报；
- 一边单值、一边紧凑活动行：公共默认值分别与每个活动身份比较；
- 耗材一边 `[nil]`、一边多行 `nil`：按耗材二元身份比较并判定为相同；
- 系统身份表 16 行、当前身份表 4 行，且 4 个活动身份有效值相同：不触发 dirty；
- 选择器数组长度与多值参数不一致、身份重复或参数长度异常：真实参数不被误判为相同；
- 当前紧凑表出现系统表中不存在的身份：无法安全继承，保守保留真实参数 dirty；
- 同口径分布在多个物理挤出机时，底层逐身份比较，弹窗按相同工艺变体合并展示。

### 反向场景

- 普通单喷嘴工艺预设不受影响；
- 普通单喷嘴耗材预设不受影响；
- 打印机参数不经过本次工艺/耗材预设比较器；
- 真实修改、保存预设、放弃修改和跨项目保留修改行为保持原有入口；
- 3MF 导入时紧凑数组恢复为完整表的既有逻辑不变；
- Tn/Pn 运行时映射不在本次修改范围。

### 编译/测试结果

- 已对 `333` 目录中的两个 3MF 进行配置静态检查；
- 已静态回放 `[60]` 对比 `[60 × 16行]`，预期无差异；
- 已静态检查系统 16 行完整身份表与当前 4 行紧凑活动表的对齐规则，系统额外身份不会独立触发 dirty；
- 已静态回放 0.2=55、0.4=88，预期分别得到对应变体差异；
- 第一轮 GUI 测试确认相同值参数已不再列出，同时暴露三个结构身份数组残留 dirty 导致的空弹窗；本次已补充过滤该结构差异；
- 第二轮 GUI 测试曾暴露耗材可空回抽覆盖参数的 `N/A -> N/A`；将耗材变体接入同一语义比较器后，测试人员重新导入 `333-3立方体.3mf`，确认未再误弹“未保存的更改”，测试效果正常；
- 已执行源码编码、乱码和 `git diff --check` 检查；
- 按用户要求本次未执行编译；GUI 实际导入验证已由测试人员完成并通过。

## 7. 风险与回退

### 可能风险

- 历史配置的工艺或耗材变体选择器不完整，可能导致真实多值参数无法建立唯一身份映射；
- 新增变体参数但未加入 `print_options_with_variant` 或 `filament_options_with_variant` 时，不会进入本次语义比较。

### 风险影响范围

仅影响工艺、耗材预设变体参数的 dirty 判定、差异列表和未保存修改展示。打印机运行参数、Tn/Pn 映射和切片取值不变。异常配置仍按原始数组差异判 dirty，采用保守策略，不会静默丢失用户修改。

### 回退方案

回退本次共享比较器以及三个 dirty/弹窗接入点，即可恢复原始数组比较行为。该回退不涉及 3MF 文件格式和系统预设数据。

## 8. 备注

- 两个目标 3MF 的参数内容可以不同，这不会导致当前新建项目被误判为 dirty；它们只触发加载前检查。
- 本次修复不把系统 `[60]` 物理改写成 16 项，而是在比较时构建逻辑有效值视图。
- GUI 实测结果：工艺与耗材参数均未实际修改时，导入 `333-3立方体.3mf` 不再误弹未保存修改对话框。

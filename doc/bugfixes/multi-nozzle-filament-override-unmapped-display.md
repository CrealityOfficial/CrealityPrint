# 多喷嘴耗材参数覆盖未分组显示修复说明

## 1. 基本信息

- Bug ID：未提供
- 标题：耗材未绑定喷嘴时，参数覆盖页面错误显示第一个喷嘴的继承值
- 禅道链接：未提供
- 反馈人：未提供
- 处理人：`wangwenbin`
- 分支：`feature/f039_group`
- 影响模块：多喷嘴耗材设置、耗材参数覆盖页面

## 2. 问题现象

### 用户反馈现象

多喷嘴机型进入“耗材设置 → 参数覆盖”时，耗材与物理喷嘴的分组尚未发生。此时未勾选的覆盖项仍会显示一个具体数值，该数值实际来自某个 Printer 喷嘴参数。

### 实际结果

- 耗材设置页面显示在前，耗材分组和喷嘴绑定发生在点击切片时。
- 映射未确定时，旧 UI 使用当前耗材入口记录的挤出机下标读取 Printer 参数。
- 第一个耗材的下标默认为 `0`，因此页面容易显示 E1/第一个物理喷嘴的参数。
- 该数值会让用户误以为耗材已经绑定 E1，或者误以为该值就是最终切片继承值。

### 期望结果

- 已勾选覆盖项：显示当前耗材 preset 中明确保存的覆盖值。
- 未勾选覆盖项：不显示任何候选物理喷嘴的具体参数，值位置统一显示 `null`；鼠标悬停时提示“未覆盖（分组后继承喷嘴参数）”。
- 切片时仍根据最终 `filament_map` 选择物理喷嘴并生成有效参数，不改变耗材 preset 的存储语义。

## 3. 复现步骤

### 前置条件

- 使用支持耗材到物理喷嘴映射的多喷嘴机型。
- 项目中存在至少一个耗材。
- 尚未在点击切片流程中完成本次耗材分组。
- Printer 各物理喷嘴的回抽参数存在可区分数值时更容易观察。

### 操作步骤

1. 选择多喷嘴机型和耗材 preset。
2. 不执行耗材分组，直接打开对应耗材设置。
3. 进入“参数覆盖”页面。
4. 查看未勾选的回抽长度、速度、抬 Z、擦拭等覆盖项。

### 复现结果

修复前，未勾选项显示由当前挤出机下标选出的 Printer 数值；第一个耗材通常显示 E1 的值。

### 复现概率

满足上述前置条件时稳定出现。

## 4. 根因分析

### 触发条件

耗材覆盖项为 `nil`，表示耗材不覆盖 Printer 参数；同时耗材尚未通过 `filament_map` 绑定物理喷嘴。

### 代码链路

修复前的 UI 链路：

```text
耗材入口下标
  → TabFilament::m_active_extruder
  → TabFilament::add_filament_overrides_page/update_filament_overrides_page
  → printer_option_index
  → 从 Printer 配置读取某个物理喷嘴参数
  → 将该数值显示为耗材未勾选项的灰色继承值
```

最终切片的正确链路仍然是：

```text
逻辑耗材 Tn
  → 点击切片时确定 filament_map
  → 物理喷嘴 Pn
  → Printer 的 Pn 基础参数
  → 耗材 Tn 的 nullable 覆盖
  → 最终有效参数 effective[Tn]
```

### 问题原因

耗材参数页面先于喷嘴映射显示，当前阶段不存在唯一的物理喷嘴。旧代码却使用耗材入口下标代替最终映射下标，提前选择 Printer 参数作为 UI 继承值。该选择没有可靠的数据依据。

## 5. 修复方案

### 修复思路

将“是否覆盖”和“最终继承值”分开：

- 参数覆盖页面只负责编辑耗材是否覆盖，以及覆盖后的明确值。
- 未覆盖时只展示继承语义，不提前选择任何物理喷嘴。
- 最终继承值继续在切片映射确定后计算。

### 修改点

- `src/slic3r/GUI/Tab.cpp`
  - 删除参数覆盖页面用于读取 Printer 物理喷嘴数值的 `printer_option_index` UI 逻辑。
  - 用户取消勾选时，将耗材配置保持为 `nil`。
  - 不再隐藏或替换原字段控件；未勾选时直接让原字段进入 `nil` 显示状态，并提示“未覆盖（分组后继承喷嘴参数）”。
  - 数值输入框和枚举下拉框在原控件中显示 `null`；布尔字段使用原生半选状态表示 `nil`。
  - 已勾选时继续使用原字段控件，恢复并显示耗材 preset 当前喷嘴变体行中的覆盖值。
- `src/slic3r/GUI/Field.cpp`、`src/slic3r/GUI/Field.hpp`
  - 为原生字段的 `set_na_value` 增加可选的事件抑制能力，页面刷新时只更新显示和字段缓存，不产生配置变更或 Dirty 状态。
  - 补齐枚举字段的 `null` 文本显示，以及 nullable 布尔字段的半选显示和恢复逻辑。
- `localization/i18n/CrealityPrint.pot`
  - 增加继承状态文案的翻译源字符串。
- `localization/i18n/zh_CN/CrealityPrint_zh_CN.po`
  - 增加中文文案“未覆盖（分组后继承喷嘴参数）”。

## 7. 风险与回退

### 可能风险

- `Field::set_na_value` 是通用字段接口，本次只扩展其事件控制参数，并保持原有默认行为；仍需回归 nullable 数值、枚举和布尔字段。
- 参数页重建、preset 切换或喷嘴变体切换时，原字段的 `null` 状态和覆盖值必须正确刷新。
- 该修复只改变 UI 预览语义，不应改变切片阶段的有效参数计算。

### 开发回归及处理

初版实现通过 `Line::append_widget` 添加提示文本。参数覆盖页面使用非 `staticbox` 的 `OG_CustomCtrl` 自绘布局，该路径中的普通 `sizer` 为空，激活页面时在 `OptionsGroup::activate_line()` 调用 `sizer->Add()`，导致读取访问权限冲突。

第二版通过额外只读 `TextInput` 覆盖原字段位置，虽然避免了崩溃，但形成两个控件叠加，出现边框、单位区域和宽度不一致的问题。

最终实现不再进入 `append_widget` 路径，也不再创建、移动或覆盖第二个输入框。未覆盖和已覆盖状态始终复用原生 `Field` 控件，仅切换字段的 `nil` 显示、可编辑状态和 Tooltip，从根本上消除空 `sizer`、控件重叠及缩放定位风险。

### 风险影响范围

仅影响耗材设置的参数覆盖页面，不修改 `filament_map`、Printer 参数、耗材覆盖值及 G-code 映射规则。

### 回退方案

回退 `Tab.cpp` 的未覆盖显示逻辑以及 `Field.cpp/Field.hpp` 的原生 `nil` 显示扩展，并删除对应本地化文案即可；不需要迁移项目文件或耗材 preset。

### 1.1 当前整体逻辑速记

```text
System 按机型合并
User / Project 按预设名称独立
普通另存为创建独立用户预设
创建喷嘴只增加当前预设内部的 nozzle variant
3MF 只保存项目当前选择的 variant_id / variant_index
切片前再把变体物化成实际口径、流量类型和参数行
```

最短记忆方式：**系统按机型合，用户按名字分，喷嘴在预设里存，项目只记录当前选哪个。**

## 2. 问题现象

### 2.1 整体方案实施前

打印机选择器直接消费打印机预设列表，没有稳定地区分 System、User、Project，也没有把“打印机条目”和“喷嘴规格”拆成两层。

典型结果：

- 系统预设、用户另存为、项目内嵌预设混在一起；
- 同一个系统机型的不同口径可能显示成多台打印机；
- 用户普通另存为的两个预设又可能因 `base_id` 相同而被错误合并；
- “创建喷嘴”通过复制打印机、工艺和耗材预设制造新的兄弟打印机预设；
- UI 聚合、继承关系和喷嘴切换共用同一套隐含规则，修一处容易破坏另一处。

### 2.2 期望结果

需要同时满足以下四条不变量：

| 对象             | 身份规则                                      | 选择器结果                   |
|------------------|-----------------------------------------------|------------------------------|
| System 系统预设  | `vendor + printer_model`                      | 同机型聚合为一台逻辑机器     |
| User 用户预设    | 单个 `preset.name`                            | 每次普通另存为都独立显示     |
| Project 项目预设 | 单个 `preset.name`                            | 每个项目内嵌预设独立显示     |
| 喷嘴规格         | 预设内 `variant_id + variant_index`           | 在当前机器内部切换，不换身份 |

一句话记忆：**System 按机型合，User/Project 按预设分，喷嘴在预设内部选。**

## 3. 复现步骤

### 3.1 用户预设错误聚合

1. 选择一个系统打印机预设。
2. 普通另存为 `0.4-test1`。
3. 再次普通另存为 `0.4-test2`。
4. 打开打印机选择器。

实施前错误结果：两个用户预设可能因为继承同一 `base_id` 被聚合。

最终结果：`0.4-test1` 和 `0.4-test2` 是两个独立 User 条目；无论口径相同还是不同，都不互相合并。

### 3.2 系统机型多口径重复显示

1. 安装同一 `printer_model` 的 0.2、0.4、0.6、0.8 系统预设。
2. 打开打印机选择器。

实施前错误结果：不同口径可能显示成多台机器。

最终结果：同 vendor、同 `printer_model` 的系统预设只显示一台机器，喷嘴下拉显示可用口径。

### 3.3 创建喷嘴

1. 选择一个用户打印机预设。
2. 执行“创建喷嘴”。
3. 选择一个尚不存在的口径并确认。

实施前错误结果：生成新的打印机预设，并批量复制工艺、耗材预设。

最终结果：当前打印机预设名称不变，只在其内部增加结构化喷嘴变体及对应参数行。

## 4. 根因分析

### 4.1 三种身份被混用

| 字段/概念          | 正确职责                           | 禁止用途                       |
|--------------------|------------------------------------|--------------------------------|
| `base_id`          | 记录预设继承来源                   | 禁止作为 UI 机器聚合键         |
| `setting_id`       | 记录本地/云端预设记录身份          | 禁止作为用户机器聚合键         |
| `printer_model`    | 表示系统产品机型                   | 禁止合并不同用户另存为预设     |
| `preset.name`      | 表示一条用户或项目打印机预设       | 不用于跨预设喷嘴兄弟关系       |
| `variant_id/index` | 表示当前打印机内部的喷嘴变体       | 不用于创建另一台逻辑打印机     |

原逻辑将 `base_id`、`setting_id` 当成 User/Project 的候选聚合键。普通另存为通常继承相同的父预设，因此多个本应独立的用户预设会得到相同机器键。

### 4.2 创建喷嘴仍在制造打印机预设

原“创建喷嘴”流程为：

```text
选择机型和口径
  -> 生成“机型 + 口径”打印机预设名
  -> 克隆打印机预设
  -> 克隆工艺预设
  -> 克隆耗材预设
  -> 通过切换打印机预设实现口径切换
```

这会把“打印机身份”和“喷嘴能力”绑在一起，也是后续需要额外 family ID 才能重新拼回一台机器的根源。

## 5. 修复方案

### 5.1 选择器身份规则

`PrinterMachineKey` 只保存 `origin + machine_id`：

```text
System  -> machine_id = "model:"   + vendor_id + ":" + printer_model
User    -> machine_id = "preset:"  + preset.name
Project -> machine_id = "project:" + preset.name
```

不再读取 `base_id`、`setting_id`，也不引入 `printer_family_id`。

### 5.2 喷嘴变体结构

打印机预设内部使用现有结构化字段：

| 字段                            | 作用                                   |
|---------------------------------|----------------------------------------|
| `nozzle_variant_ids`            | 稳定、可读的喷嘴变体 ID                |
| `nozzle_variant_diameters`      | 变体口径                               |
| `nozzle_variant_volume_types`   | Standard/High Flow 等流量类型          |
| `nozzle_variant_extruder_ids`   | 变体所属物理喷头                       |
| `nozzle_variant_indices`        | 物理喷头内部的变体索引                 |
| `printer_nozzle_variant`        | 打印机参数行对应的喷嘴变体索引         |
| `variant_id` / `variant_index`  | 当前 3MF 项目选择的喷嘴变体            |

单喷头与多喷头都使用同一套结构化选择逻辑。选择喷嘴后只更新项目的 `variant_id/index`；切片前由 `full_fff_config()` 将选中变体物化为实际 `nozzle_diameter`、流量类型和对应参数行。

### 5.3 创建喷嘴的新流程

```text
选择当前打印机预设
  -> 校验目标口径是否已存在
  -> 缺少元数据时，先把当前口径迁移成基础 variant
  -> 给每个物理喷头追加目标口径 variant
  -> 复制同物理喷头的参数行作为新变体起点
  -> 写入用户输入的层高上下限和回抽长度
  -> 保存同一个用户/项目预设
  -> 将项目 variant_id/index 切换到新变体
```

系统预设不可直接覆写。对系统预设执行“创建喷嘴”时，创建或复用一个确定名称的 User 副本，再在该副本内部增加变体；不会生成一组按口径拆分的用户兄弟预设。

### 5.4 旧预设和旧 3MF 兼容

| 输入                         | 处理方式                                                                   |
|------------------------------|----------------------------------------------------------------------------|
| 旧系统预设，无结构化变体     | System 扫描同机型兄弟口径；单喷头切换兄弟预设，多喷头在切片配置中物化选择  |
| 旧用户/项目预设，无变体字段  | 只显示自身当前口径，禁止扫描同机型用户兄弟预设                             |
| 旧 3MF，无 `variant_id`      | 使用打印机预设当前口径或基础变体                                           |
| 新 3MF，含 `variant_id`      | 新版本恢复所选变体                                                         |
| 新 3MF 放到旧版本            | 旧版本只读取基础 `nozzle_diameter`，无法恢复项目所选变体                   |

本方案没有新增 `printer_family_id`，因此不需要本地 `.info`、云端 JSON 或 3MF sidecar 的额外生命周期和迁移逻辑。

## 9. 追加修复：K3 结构化代表预设选择

### 9.1 新发现的问题

在系统打印机下拉框选择 `Creality K3` 时，界面可能没有切换到 K3 的结构化代表预设，或者实际切换到隐藏的旧口径兄弟预设。随后四个物理喷头的口径下拉框都只显示 `0.4-标准`，缺少 0.2、0.6、0.8。

当前 K3 参数数据的关键差异如下：

| 预设                              | `printer_variant` | `nozzle_diameter`       | 结构化喷嘴数据                         |
|-----------------------------------|-------------------|-------------------------|----------------------------------------|
| `Creality K3 0.2 nozzle`          | `0.2`             | `[0.4,0.4,0.4,0.4]`     | 无                                     |
| `Creality K3 0.4 nozzle`          | `0.4`             | `[0.4,0.4,0.4,0.4]`     | 有，4 个物理喷头各 4 种口径，共 16 条 |
| `Creality K3 0.6 nozzle`          | `0.6`             | `[0.4,0.4,0.4,0.4]`     | 无                                     |
| `Creality K3 0.8 nozzle`          | `0.8`             | `[0.4,0.4,0.4,0.4]`     | 无                                     |

新的结构化配置本身完整；问题发生在选择器没有稳定落到 `Creality K3 0.4 nozzle`，从而使后续喷嘴下拉框读取了不带 `nozzle_variant_*` 的预设。

### 9.2 根因

#### 9.2.1 代表预设选择依赖遍历顺序

原逻辑通过 `nozzle_diameter` 是否全为 0.4 判断默认预设。K3 的四个预设运行时该字段均为 `[0.4,0.4,0.4,0.4]`，因此它们都会满足默认条件。后遍历到的隐藏兄弟预设可以覆盖已经找到的结构化 0.4 代表预设。

结果为：

```text
选择逻辑机器 Creality K3
  -> default_preset 被旧兄弟预设覆盖
  -> 旧兄弟预设在可见 wxComboBox 中不存在，或者没有结构化喷嘴表
  -> 机器切换失败，或者喷嘴下拉框只剩 0.4
```

#### 9.2.2 模拟事件与控件状态不一致

ImGui 机器选择器通过代码构造 `wxEVT_COMBOBOX`。原逻辑只给事件设置目标索引和文本，没有先更新原生 `wxComboBox` 的当前选中项。下游同时读取事件值和 `GetSelection()` 时，可能看到“事件指向 K3、控件仍指向原来的第一项”的不一致状态。

### 9.3 本次追加改动

| 修改点                       | 最终规则                                                                                 |
|------------------------------|------------------------------------------------------------------------------------------|
| 结构化代表预设识别           | `nozzle_variant_ids`、`nozzle_variant_diameters`、`nozzle_variant_extruder_ids` 必须存在、非空且长度一致 |
| 代表预设优先级               | 同一 System 逻辑机器中，带有效结构化喷嘴数据的预设优先级最高，不允许普通兄弟预设再次覆盖 |
| 结构化机器的喷嘴来源         | 直接读取代表预设内部的 `nozzle_variant_*`，不再给该机器建立兄弟预设口径映射             |
| 模拟下拉事件                 | 先执行 `SetSelection(idx)`，再发送带控件 ID、目标索引、目标文本和事件对象的 `wxEVT_COMBOBOX` |

修改后的主链路：

```text
点击 Creality K3
  -> 按 vendor + printer_model 找到逻辑机器
  -> 优先选中带 16 条 nozzle_variant_* 数据的结构化代表预设
  -> 原生 wxComboBox 先同步到目标索引
  -> 再发送 wxEVT_COMBOBOX
  -> 下游事件值与 GetSelection() 一致
  -> 四个物理喷头分别显示 0.2/0.4/0.6/0.8
```

### 9.4 本次追加改动的范围

本 Patchset 只保留以下两项：

1. 结构化代表预设优先选择。
2. 模拟 `wxComboBox` 事件前同步实际选中项。

本 Patchset 暂不增加旧系统兄弟预设的口径恢复逻辑。旧的 0.2/0.6/0.8 系统预设后续由参数包更新处理，不作为本次代码交付的兼容输入。

因此，本节对第 5.4 节作以下范围修正：

| 输入场景                                      | 本次处理方式                                                       |
|-----------------------------------------------|--------------------------------------------------------------------|
| 新结构化 K3 代表预设                         | 完整支持，作为 K3 的唯一运行时代表预设                             |
| 同目录残留旧系统兄弟预设                     | 不允许其覆盖结构化代表预设                                         |
| 直接加载并继续使用旧兄弟预设                 | 本次不承诺恢复完整喷嘴选项，由后续参数包更新处理                   |
| User/Project 普通另存为预设                   | 继续逐条独立显示，不通过 `base_id` 或系统兄弟关系聚合              |

# Bug 修复记录：热床温度模式参数逻辑异常

## 1. 基本信息
- Bug ID: `16838`
- 标题: `【新增机型参数】热床温度模式参数逻辑异常`
- 禅道链接: `https://zentao.creality.com/zentao/bug-view-16838.html`
- 反馈人: `康美樱`
- 处理人: `wangwenbin`
- 分支: `release-260731`
- 影响模块: `G-code 热床温度生成`
- 代码文件:
  - `src/libslic3r/GCode.cpp`
  - `doc/bugfixes/bug-16838-bed-temperature-mode.md`

## 2. 问题现象
- 用户导入附件 `3mf` 后，切片并查看热床温度。
- 首层热床温度使用的是耗材 1 的首层设定温度。
- 第二层热床温度使用的是耗材 2 的其他层设定温度。
- 表现为同一次打印中，热床温度模式选择后，不同阶段取值来源不符合预期，容易出现首层和第二层温度来源不一致。

通俗理解：
- `UseMaxTemperature` 应只看本次实际参与打印的耗材。
- `UseFirstMaterial` 不应固定取耗材 1，而应使用当前阶段传入的首打印耗材。
- 如果本次没有使用耗材 1，就不应该因为数组下标或默认参数去读取耗材 1。

## 3. 复现步骤
1. 打开附件 `3mf`。
2. 切片后查看首层热床温度。
3. 查看第二层热床温度。

实际结果：
- 首层温度用的是耗材 1 的首层设定温度。
- 第二层用的是耗材 2 的其他层设定温度。

期望结果：
- `UseMaxTemperature` 模式下，只在本次实际使用的耗材中取最高热床温度。
- `UseFirstMaterial` 模式下，按调用阶段传入的首打印耗材取温度，不固定取耗材 1。

## 4. 根因分析
热床温度模式有两个关键分支：

- `UseMaxTemperature`: 取最高热床温度。
- `UseFirstMaterial`: 取首个耗材对应热床温度。

旧逻辑存在两个问题：

1. `UseMaxTemperature` 的统计范围不够准确。
   - 旧逻辑可能遍历热床温度配置数组。
   - 这样会把未参与本次打印的耗材也算进去。
   - 如果未使用耗材温度最高，最终热床温度会被错误抬高。

2. `UseFirstMaterial` 容易退化成固定耗材 1。
   - 部分调用点直接传 `0`，也就是耗材 1。
   - 后续修复中也曾将非最高温分支固定为数组第 0 项。
   - 但 `first material` 不等于耗材 1，尤其是只使用耗材 3/4/5 时，固定耗材 1 明显错误。

参考 Bambu 的逻辑：
- `by_highest_temp` 只统计实际参与打印的耗材。
- `by_first_filament` 不在公共函数里重新决定第一个耗材，而是由调用点传入当前阶段的首打印耗材。
- 第二层切换普通层温度时，只执行一次，后续层沿用第二层设置后的普通层热床温度。

## 5. 修复方案
本次修复对齐 Bambu 的取值语义：

1. `UseMaxTemperature`
   - 优先使用调用方传入的实际耗材集合。
   - 没有传入时，使用 `m_writer.extruders()` 中的实际打印耗材。
   - 避免未使用耗材参与最高温计算。

2. `UseFirstMaterial`
   - `GCode::get_bed_temperature()` 的非最高温分支恢复为使用调用点传入的 `extruder_id`。
   - 不在函数内部固定取耗材 1。
   - 不在函数内部重新查找全局首耗材。

3. 修正传参
   - BBL 配置块中原先传 `0` 的首层热床温度，改为传实际打印耗材里的首个耗材。
   - 后续配置块中原先传 `0` 的首层热床温度，改为传 `initial_extruder_id`。

## 6. 代码改动摘要
文件: `src/libslic3r/GCode.cpp`

- 修正首层配置注释中的热床温度取值：
  - 原来固定传 `0`。
  - 现在使用 `print.extruders().front()`，空集合时才兜底 `0`。

- 修正后续配置块中的首层热床温度取值：
  - 原来固定传 `0`。
  - 现在传 `initial_extruder_id`。

- 修正 `GCode::get_bed_temperature()` 的 `UseFirstMaterial` 分支：
  - 原来错误固定读取第 0 项。
  - 现在恢复为 `bed_temp_opt->get_at(extruder_id)`。

- 保留 `UseMaxTemperature` 按实际使用耗材集合取最大值的逻辑。

文件: `doc/bugfixes/bug-16838-bed-temperature-mode.md`

## 7. 验证清单
- [ ] `UseMaxTemperature`: 只使用耗材 3/4/5，耗材 1 未使用但热床温度最高，确认 G-code 不取耗材 1 的温度。
- [ ] `UseFirstMaterial`: 只使用耗材 3/4/5，确认启动 G-code、首层热床温度和配置注释不固定取耗材 1。
- [ ] `UseFirstMaterial`: 首层第一个打印耗材与第二层第一个打印耗材不同时，确认第二层普通层热床温度取第二层首打印耗材。
- [ ] 第三层及后续层：确认不会因为当前层首个耗材变化而重复输出新的热床温度，后续层沿用第二层设置后的普通层热床温度。
- [ ] 单耗材打印：确认热床温度仍取当前板型对应温度。
- [ ] 不同板型回归：光滑 PEI、纹理 PEI、自定义面板分别切片，确认热床温度数组选择正确。

## 8. 风险与回退
风险：
- `UseFirstMaterial` 对齐 Bambu 后，不表示整盘打印全程固定同一个耗材温度。
- 第二层切换普通层热床温度时，会按第二层当前首打印耗材取值；后续层不再自动按层更新热床温度。
- 如果产品后续希望“全程固定实际使用耗材集合中的第一个耗材”，需要另行定义规则，这将不同于 Bambu 当前逻辑。

回退方式：
- 回退 `src/libslic3r/GCode.cpp` 中本次对 `get_bed_temperature()` 和首层温度传参的修改。
- 回退后风险是：未使用耗材可能继续影响最高温，或 `UseFirstMaterial` 继续错误固定到耗材 1。

## 2. 问题现象
准备页面右上角耗材卡片的“更多”菜单包含 `Merge with` 操作。候选耗材较多时，合并目标子菜单会一次性展示全部条目，可能超出当前显示器工作区，导致位于下方的耗材无法看到或点击。

同时，原交互还存在以下体验问题：
- 鼠标仅悬停到 `Merge with` 就自动展开子菜单，容易误触。
- 悬停展开路径在 UI 线程中等待 `100 ms`，会造成不必要的阻塞。
- 父菜单与子菜单切换焦点时，Windows 弹窗失活处理可能错误关闭菜单链。
- 主菜单部分按钮宽度不一致，长文本可能显示拥挤。

## 3. 影响范围
- 耗材卡片右上角 `...` 更多菜单。
- `Edit`、`Delete`、`Merge with`、`Decompose Color` 菜单项。
- `Merge with` 下的物理耗材和混合耗材候选列表。
- 多显示器、不同分辨率和不同系统缩放比例下的子菜单布局。

不涉及以下业务逻辑：
- 耗材合并算法和混合比例计算。
- 颜色拆解算法。
- 切片、G-code 生成及打印任务。

## 4. 修复前复现步骤
1. 在准备页面添加较多物理耗材，或创建可用的混合耗材目标。
2. 点击任一耗材卡片右上角的 `...`。
3. 将鼠标移到 `Merge with`。
4. 观察子菜单自动展开。
5. 当候选项数量超过屏幕剩余高度时，观察列表底部超出显示器工作区。
6. 尝试选择位于列表下方的合并目标。

修复前结果：下方候选项不可见或不可点击，且悬停会造成非预期展开。
## 5. 根因分析
以下根因由当前代码和本次修复差异推导得出：

1. `MaterialSubMenu::init()` 原先使用纵向 sizer 并通过 `SetSizerAndFit()` 展示全部候选项，没有视口、滚动偏移和滚动条。
2. 子菜单尺寸没有根据锚点下方的剩余空间和当前显示器工作区收缩，条目多时会向屏幕下方继续延伸。
3. `HoverButton::OnEnter()` 在 `Merge with` 悬停时投递展开事件，并在 UI 线程调用 `sleep_for(100 ms)`；悬停即展开不符合本次交互要求。
4. 父子 `ManagedPopupWindow` 同时存在时，Windows 的失活事件可能发生在父子弹窗切换过程中。旧关闭流程没有区分“菜单链内部切换”和“真正离开菜单链”。
5. `PopupWindowManager` 的注册与关闭逻辑缺少重复注册和空列表保护，父子弹窗的销毁顺序也不够明确。

## 6. 修复方案
### 6.1 点击展开，取消悬停展开
- `Merge with` 仅在鼠标按下后仍于按钮内部释放时切换展开状态。
- 再次点击 `Merge with` 收起子菜单。
- 悬停 `Merge with` 不再自动展开，也不再阻塞 UI 线程。
- 鼠标进入 `Edit`、`Delete` 或 `Decompose Color` 时，仍会收起已打开的合并子菜单，避免遮挡其它操作。

### 6.2 增加可滚动候选列表
- 使用 `m_content_panel` 承载物理耗材和混合耗材条目。
- 当候选项超过当前显示器可用高度时，只展示能够完整容纳的行数。
- 通过移动内容面板实现滚动，偏移量限制在：

  ```text
  0 .. content_height - view_height
  ```

- 增加独立的细滚动条子窗口，支持：
  - 鼠标拖动滑块；
  - 点击轨道跳转；
  - 鼠标捕获及捕获丢失恢复；
  - 在列表项、内容面板和滚动条上使用滚轮。

### 6.3 DPI 与多显示器适配
- 所有条目、间距、滚动条和边距尺寸统一使用 `FromDIP(...)`。
- 根据子菜单屏幕坐标调用 `wxDisplay::GetFromPoint(...)`，获取实际所在显示器。
- 使用该显示器的 `GetClientArea()` 计算工作区，避免菜单被任务栏或屏幕边缘遮挡。
- 子菜单保持锚定在 `Merge with` 下方；空间不足时减少可见行并启用滚动，而不是向上覆盖父菜单。
- 水平方向预留 `8 DIP` 边距并限制在当前显示器工作区内。

### 6.4 父子弹窗生命周期
- `PopupWindowManager::RegisterPopup()` 增加重复注册保护。
- `CloseLast()` 增加空列表保护，并先从管理列表移除，再调用基类关闭和销毁。
- `CloseAll()` 改为按 LIFO 顺序关闭，确保先关闭子菜单，再关闭父菜单。
- Windows 下增加菜单链激活判断：焦点仍在任一已注册菜单或其子窗口内时，不因父子菜单切换而关闭；切换到主窗口或其它应用后关闭整条菜单链。
## 7. 代码改动摘要
### `src/slic3r/GUI/FilamentPanel.cpp`
- `HoverButton::OnLeftDown()`：移除按下时展开逻辑。
- `HoverButton::OnLeftUp()`：在按钮内部释放时切换 `Merge with` 子菜单。
- `HoverButton::OnEnter()`：取消悬停展开和 `100 ms` UI 线程等待。
- 新增 `MaterialSubMenuScrollBar`：负责滑块绘制、轨道点击、拖动和鼠标捕获。
- `MaterialSubMenu::scroll_to()`：限制并应用内容滚动偏移。
- `MaterialSubMenu::on_wheel()`：按系统滚轮行数和 `40 DIP` 行高滚动。
- `MaterialSubMenu::layout_scrollable_list()`：按当前显示器工作区计算可见行数及滚动条状态。
- `MaterialSubMenu::fit_to_display()`：将子菜单水平限制在当前显示器工作区内。
- `MaterialSubMenu::init()`：将候选项放入内容面板，并统一绑定滚轮事件。
- `ManagedPopupWindow::Dismiss()`：Windows 下区分菜单链内部焦点切换与真正失活。
- `Merge with` 和 `Decompose Color` 按钮宽度统一为 `150 DIP`。

### `src/slic3r/GUI/FilamentPanel.h`
- `PopupWindowManager` 增加重复注册、空列表及 LIFO 关闭处理。
- `ManagedPopupWindow` 默认启用 `wxPU_CONTAINS_CONTROLS`。
- `MaterialSubMenu` 增加内容面板、候选项集合、滚动条及滚动状态。
- 增加滚动布局、显示器适配和偏移接口。

### 关键布局参数
- 菜单项：`150 x 32 DIP`。
- 条目四周间距：`4 DIP`。
- 单行步长：`40 DIP`。
- 内容基础宽度：`158 DIP`。
- 滚动条带宽：`10 DIP`。
- 滑块宽度：`4 DIP`。
- 滑块最小高度：`24 DIP`。
- 显示器边缘预留：`8 DIP`。

## 9. 风险与回滚
- 风险等级：`中低`。
- 修改集中在耗材更多菜单、合并子菜单和通用弹窗管理，不影响耗材数据及切片算法。
- 主要风险：
  - Windows、macOS 和 GTK 的瞬态弹窗失活语义存在差异，需要分别验证。
  - 系统“每次滚动行数”设置会影响滚轮移动距离。
  - 触摸板或高精度滚轮可能产生小于标准 detent 的滚轮值，需要关注连续性。
  - 当锚点下方不足一整行时，当前策略仍至少展示一行，应在极低分辨率或高缩放环境重点检查。
  - 打开状态下将窗口跨屏移动不属于本次实时重排承诺；应移动主窗口后重新打开菜单验证目标屏 DPI。
- 回滚方式：回退 `FilamentPanel.cpp` 和 `FilamentPanel.h` 中 `HoverButton`、`MaterialSubMenu`、`ManagedPopupWindow` 与 `PopupWindowManager` 的本组改动。

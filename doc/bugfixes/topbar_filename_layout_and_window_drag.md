# Topbar 文件名布局、控件遮挡与窗口拖动交互修复

## 1. 基本信息
- Bug ID：无（界面布局与交互体验优化）
- 标题：Topbar 在 1080p/最小窗口下文件名偏移或被裁剪，控件区域无法拖动窗口
- 反馈人：用户反馈
- 处理人：
- 影响模块/影响文件：
  - `src/slic3r/GUI/BBLTopbar.cpp`（Topbar 布局、文件名绘制、页面按钮容器尺寸、鼠标交互）
  - `src/slic3r/GUI/BBLTopbar.hpp`（子控件拖动事件与拖动状态）

## 2. 现象与复现
- 复现步骤：
  1. 在 1920×1080 屏幕下启动软件，并将窗口调整到允许的最小宽度。
  2. 观察顶部“在线模型/准备/预览/设备”按钮右侧的文件名，以及右侧客服、最小化、最大化和关闭按钮。
  3. 分别在 Topbar 空白区域、页面按钮、模式切换控件和工具栏按钮上按住鼠标并尝试拖动窗口。
  4. 在文件、下三角、保存、撤销、重做、客服和窗口按钮上按下鼠标但暂不松开。
- 实际结果：
  - 文件名没有位于“设备”按钮和右侧分隔线之间的视觉中心，最小窗口下“未命名”等文本会被裁掉。
  - “设备”按钮右侧存在一块外观与 Topbar 相同、但会参与命中测试的不可见区域，覆盖文件名左侧；1080p/高 DPI 下更明显，2K 屏幕因可用空间较大而不易暴露。
  - 窗口只能从 Topbar 的非控件区域拖动；鼠标位于页面按钮、模式切换或工具栏按钮上时无法拖动窗口。
  - AUI 工具栏按钮在左键按下阶段就触发菜单、保存、撤销、关闭等操作，无法等待拖动意图判定。
  - 窗口缩到最小宽度时，右侧窗口按钮存在被挤出或裁掉的风险。
- 期望结果：
  - 文件名始终在页面按钮实际右边界与右侧分隔线之间水平居中，并在空间不足时安全省略。
  - 不存在覆盖文件名的不可见控件区域，窗口按钮在最小宽度和 DPI 变化后保持可见。
  - Topbar 的空白区、文件名、页面按钮、模式切换和工具栏按钮区域均可用于拖动窗口。
  - 工具栏按钮仅在同一按钮上正常松开时触发；达到系统拖动阈值后改为拖动窗口，不执行按钮动作。

## 3. 责任提交追溯
- 问题由 Topbar 既有布局与事件模型共同造成：
  - `ButtonsCtrl` 作为四个页面按钮的父 `wxControl` 加入 `wxAuiToolBar`，其宿主尺寸可能大于内部可见按钮内容。
  - 文件名绘制区域依赖伸缩占位项，而不是页面按钮和右侧分隔线的真实边界。
  - AUI 工具项统一使用 `wxEVT_AUITOOLBAR_TOOL_DROPDOWN`，该事件在当前实现中于 `LEFT_DOWN` 阶段派发。
- 本次问题包含 DPI、最小窗口布局和鼠标事件协作等多个既有路径，无对应单一责任提交。

## 4. 根因分析
- `ButtonsCtrl` 不是真正的透明按钮，而是“在线模型/准备/预览/设备”四个按钮的父窗口。其背景色与 Topbar 相同，因此多出的客户区视觉上不可见，但仍会拦截鼠标并覆盖后方绘制内容。
- 原 `ButtonsCtrl::reLayout()` 使用 `Layout()`、`Fit()`、`GetBestSize()` 和 `SetMinSize()` 组合更新尺寸。在 AUI 重新布局、DPI 缩放及最小宽度约束下，父控件可能保留大于内部 `wxSizer` 内容的宽度，形成“设备”右侧的不可见区域。
- Topbar 还在页面按钮之后固定增加了 `30 DIP` 间距，进一步压缩了文件名可用空间。
- 文件名区域原先直接取伸缩占位项的矩形，并附加 `4 DIP` 垂直偏移：
  - 水平范围没有以最后一个可见页面按钮的真实右边界为起点。
  - 垂直位置不是 Topbar 的严格居中位置。
  - 当透明宿主区域覆盖到标题绘制区域时，即使省略算法正确，文字左侧仍可能被子窗口裁切。
- Topbar 初始化和 DPI 重布局后沿用已有最小尺寸，未在 `Realize()` 后重新使最佳尺寸失效并计算，导致最小窗口宽度可能没有完整包含右侧操作项。
- 鼠标事件只绑定在 `BBLTopbar` 本身。页面按钮和模式切换属于独立子窗口，会先接收鼠标事件，因此父 Topbar 无法从这些区域启动窗口拖动。
- 对 AUI 工具项采用“先让按钮处理按下、超过阈值后再取消”的方式无效，因为 `wxEVT_AUITOOLBAR_TOOL_DROPDOWN` 已在左键按下时执行，保存、关闭等动作无法事后撤销。

## 5. 修复方案
- 页面按钮容器尺寸：
  - 为 `ButtonsCtrl` 增加 `GetButtonsRight()`，获取最后一个可见按钮的实际右边界。
  - `reLayout()` 改为使用 `m_sizer->GetMinSize()` 计算内容尺寸，并同步设置控件大小、最小尺寸和 `wxSizer` 布局范围，避免父窗口保留多余客户区。
  - 在将 `ButtonsCtrl` 加入 AUI 工具栏前先完成一次 `reLayout()`。
- 文件名布局：
  - 删除页面按钮后的固定 `30 DIP` 留白。
  - 文件名左边界使用最后一个可见页面按钮的实际右边界，右边界使用客服区域前分隔线的位置。
  - 删除 `4 DIP` 垂直偏移，按 Topbar 高度严格垂直居中。
  - 文件名绘制、命中测试和 Tooltip 共用同一个动态矩形；空间不足时继续使用省略号截断。
- Topbar 最小尺寸：
  - 初始化和 DPI 重布局的 `Realize()` 后调用 `InvalidateBestSize()`，再以 `GetBestSize()` 更新最小宽度，确保右侧操作和窗口按钮被计入。
- 子控件区域拖动：
  - 递归为页面按钮容器及其子按钮、模式切换控件绑定左键按下、松开和移动事件。
  - 按下时记录来源窗口和屏幕坐标；移动超过系统 `wxSYS_DRAG_X/Y` 阈值后，向原控件发送控件外松开事件以取消待处理点击，再启动窗口拖动。
  - 模式切换控件增加松开位置检查，控件外松开不再切换 AI/专业模式。
- AUI 工具项区域拖动：
  - 在 `BBLTopbar::OnMouseLeftDown()` 中拦截可操作工具项的按下事件，不再让 AUI 立即派发业务动作。
  - 未达到拖动阈值且在同一工具项上松开时，重新构造并派发原 `wxEVT_AUITOOLBAR_TOOL_DROPDOWN`，保持文件菜单、保存、撤销、重做、客服和窗口按钮原有处理函数不变。
  - 移出原按钮松开或达到拖动阈值时不派发工具事件，避免拖动窗口时误保存、误撤销、误最小化或误关闭。
  - Windows 使用 `WM_NCLBUTTONDOWN/HTCAPTION` 进入原生窗口拖动，保留系统吸附、最大化拖拽还原等行为；GTK 继续使用平台窗口移动接口。

## 6. 影响范围与风险
- 正向影响：
  - 1080p、最小窗口和高 DPI 下，文件名位置稳定，不再被页面按钮父窗口遮挡。
  - 页面按钮右侧不再存在无意义的不可见命中区域，Topbar 可用空间增加。
  - 用户可从 Topbar 大部分区域直接拖动窗口，不必寻找狭小空白位置。
  - 文件、保存、撤销、重做、客服和窗口按钮改为标准的“松开触发”交互，拖动与点击能够区分。
- 是否改变旧行为：
  - 工具按钮的业务处理函数不变，但触发时机由左键按下调整为在同一按钮上左键松开。
  - 鼠标移动距离达到系统拖动阈值后优先解释为窗口拖动，这是本次预期行为。
  - 文件名仍会在空间不足时显示省略号，完整名称继续通过 Tooltip 查看。
- 可能风险：
  - 鼠标捕获、控件外松开和 AUI 工具事件重派发涉及事件顺序，需要重点回归菜单弹出、窗口关闭及模式切换。
  - Windows、GTK 和 macOS 的窗口拖动接口不同，应分别验证；本次主要验证目标为 Windows。
  - 系统拖动阈值受操作系统和 DPI 影响，不同环境下开始拖动的手感可能略有差异。

## 7. 回归建议
- 分辨率与 DPI：
  - 在 1920×1080 的 100%、125%、150% 缩放下，将窗口缩到最小宽度，确认文件名未被裁掉，客服及最小化/最大化/关闭按钮完整可见。
  - 在 2K 屏幕及跨显示器 DPI 切换后重复验证，确认页面按钮容器没有重新出现多余宽度。
- 文件名布局：
  - 分别验证短文件名、长文件名、中文名和未命名项目，确认文字位于“设备”按钮与右侧分隔线之间居中。
  - 长文件名空间不足时应显示省略号，悬停后 Tooltip 显示完整名称。
- 页面按钮与模式切换：
  - 单击“在线模型/准备/预览/设备”，确认页面切换正常。
  - 从上述按钮及 AI/专业模式切换控件上按住并拖动，确认窗口移动且不切换页面/模式。
  - 按下后移出控件再松开，确认不触发控件动作。
- AUI 工具按钮：
  - 文件按钮和下三角按钮应在松开后弹出菜单，按下未松开时不得弹出。
  - 保存、撤销、重做和客服按钮应在松开后各执行一次，按住拖动时不得执行。
  - 最小化、最大化/还原和关闭按钮应在松开后执行，按住未松开时窗口状态不得变化。
  - 在禁用状态下验证保存、撤销和重做按钮，确认松开不执行动作，但仍可从该区域拖动窗口。
- 窗口行为：
  - 普通窗口、最大化窗口下分别从 Topbar 空白区、文件名、页面按钮和工具按钮区域拖动，确认移动、吸附及最大化拖拽还原正常。
  - 快速点击、轻微抖动和超过阈值的拖动分别测试，确认不会出现一次手势同时触发按钮和移动窗口。
- 构建验证：
  - `Release` 配置下构建 `libslic3r_gui`，确认 `BBLTopbar.cpp` 编译及静态库生成成功。

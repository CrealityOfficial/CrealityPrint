## 2. 问题现象

准备页面右侧的混色耗材列表能够将不同类型物理耗材组成的混色条目标记为异常。模型使用该异常混色耗材后，点击切片没有显示对应错误，切片流程仍会继续。

禅道期望：耗材异常时弹出相应提示，并且无法切片。

本次对应的提示文案为：

```text
不支持不同类型的耗材进行混色打印，请到软件右侧的耗材列表处理带！的混色耗材。
```

## 3. 影响范围

- 准备页面右侧混色耗材列表的异常标记。
- 修改物理耗材预设后的混色兼容状态刷新。
- 模型、对象配置、局部层范围和多色涂色数据引用混色虚拟耗材时的切片前校验。
- 混色耗材错误提示的中英文国际化资源。

不涉及以下逻辑：

- 混色比例、渐变曲线和层间轮换算法。
- 混色耗材虚拟编号分配和稳定身份。
- G-code 中的物理工具解析与耗材映射。
- 未被当前模型引用的混色耗材定义。

## 4. 修复前复现步骤

1. 在准备页面添加至少两个不同类型的物理耗材，例如 PLA 与 PETG 或 TPU。
2. 使用上述物理耗材创建混色耗材。
3. 确认右侧混色耗材条目显示异常标记。
4. 将该混色耗材分配给模型、局部层范围或多色涂色区域。
5. 点击切片。

修复前结果：没有显示耗材类型不兼容提示，切片流程仍可继续。

期望结果：显示对应提示并终止本次切片；用户修复混色耗材配置后才可继续。

## 5. 根因分析

### 5.1 GUI 警告与切片校验使用两套逻辑

右侧混色耗材面板会读取组成项对应的 `filament_type`，类型不一致时显示警告图标。该判断只用于 GUI 展示，没有进入 `Print::validate()` 的切片前校验链。

修复前的主要链路为：

```text
右侧混色耗材列表
  → 比较组成耗材类型
  → 显示异常标记

点击切片
  → BackgroundSlicingProcess::validate()
  → Print::validate()
  → 只检查混色耗材是否可用、组成耗材是否缺失
  → 未检查 filament_type 是否一致
  → 继续切片
```

界面显示异常不等于后端拒绝使用，因此同一混色耗材在 GUI 和切片流程中出现了不同状态。

### 5.2 面板自行解析组成编号

面板原有代码独立解析 `gradient_component_ids` 并收集组成耗材类型，没有与切片后端共享判断。旧逻辑直接搜索字符 `0` 时还可能混淆缺失占位符与新格式中的多位编号，例如 `1|10` 中的物理耗材 `10`。

### 5.3 物理耗材预设变化后警告刷新不完整

用户切换物理耗材预设时，物理耗材类型可能从相同变为不同，或从不同恢复为相同。原流程更新物理耗材列表后没有立即重建混色面板，导致异常标记可能滞后。

## 6. 修复方案

### 6.1 统一混色组成项和类型兼容判断

在 `MixedFilament` 中增加：

```cpp
std::vector<unsigned int> referenced_component_ids(size_t num_physical) const;
bool has_type_mismatch(const std::vector<std::string> &physical_types) const;
```

- 优先读取 `gradient_component_ids`，为空或不足两个有效组成项时回退到 `component_a`、`component_b`。
- 同时支持旧式单字符编号和新的 `|` 分隔多位编号。
- 忽略缺失或越界项；缺失状态继续由 `has_missing_component()` 和 `is_available()` 处理。
- GUI 与切片后端共同调用 `has_type_mismatch()`，避免判断标准分叉。

### 6.2 在切片入口校验实际使用的混色耗材

`Print::validate()` 收集物理耗材的 `filament_type`，并在现有混色可用性校验中增加类型检查。

校验范围保持为当前模型实际引用的混色耗材：

- 对象、Volume、局部层范围和自定义换料通过 `object_used_extruders()` 收集。
- 多色涂色通过 `mmu_segmentation_facets.used_states` 收集。
- 未被模型引用的异常混色条目不阻止切片。

类型不一致时返回普通 `StringObjectException`。现有后台切片校验和通知机制负责显示错误并停止切片，无需新增专用异常或通知类型。

### 6.3 刷新列表并补充国际化文案

- 混色列表复用统一的缺失项和类型不兼容判断。
- 物理耗材预设选择完成后调用 `update_mixed_filament_panel(false)`，立即刷新异常标记。
- 在 POT 和简体中文 PO 中增加切片错误文案。

## 9. 风险与回滚

- 风险等级：`中低`。
- 主要风险：
  - 不同耗材预设可能使用语义相同但字符串不同的 `filament_type`，当前规则按项目已有类型字符串直接比较。
  - 混色耗材 ID 使用 1-based，`object_used_extruders()` 使用 0-based；新增代码沿用现有 `+1` 转换，需通过实际对象和涂色场景回归。
  - 新增接口位于 `MixedFilament.hpp`，首次构建会使包含该头文件的目标重新编译；这是一次性依赖重建，不是构建目录失效。
- 回滚方式：
  - 回退 `MixedFilament` 的两个辅助接口及调用点。
  - 回退 `Print::validate()` 中的类型不兼容分支。
  - 回退 `Plater.cpp` 的统一判断与预设变化刷新。
  - 同步删除新增国际化文案和专项测试。

回滚时不应恢复已删除的初始化通知、按钮禁用或 ImGui 空指针补丁。

## 10. 结论与证据边界

- 当前代码将 GUI 警告和切片阻断统一到同一类型兼容判断，并只阻止实际引用异常混色耗材的切片任务。
- 现有 `Print::validate()` 错误链已经能够同时完成提示和停止切片，不需要新增通知生命周期或按钮状态管理。
- 禅道基本信息、现象和期望来自 Bug 17869 页面；根因、调用链和风险依据当前源代码及工作区差异分析。

## 2. 问题现象

切换软件语言为繁体中文后，准备页面的官方耗材颜色弹窗未完整翻译。禅道截图圈出了三类可见问题：颜色名仍显示简体字（如“米黄”），分组标题显示英文 `Official Filament`，按钮显示英文 `+ More Colors`。禅道文字描述仅写明“在繁体下的语言翻译没有”，没有列出更多受影响文案；本文只按截图和现有代码界定范围。

期望：弹窗固定文案显示繁体译文；后台提供繁体中文颜色名称时，颜色名也显示繁体译文。名称缺失时按既定规则回退英文，不显示空白。

## 3. 影响范围

- 官方耗材颜色弹窗中的固定文案与颜色名称。
- 官方颜色接口数据到本地 `filaments_color.json` 的字段提取，以及随包颜色文件的离线显示。
- 不涉及 3MF 工程颜色、切片算法、耗材预设参数和弹窗以外的界面文案。

关键文件：

- `src/slic3r/GUI/OfficialMaterialColorCache.hpp`
- `src/slic3r/GUI/OfficialFilamentColorDialog.cpp`
- `localization/i18n/zh_TW/CrealityPrint_zh_TW.po`
- `resources/profiles/Creality/filament/filaments_color.json`

## 4. 复现步骤

1. 将软件语言切换为繁体中文，并重新进入准备页面。
2. 打开一个有官方颜色列表的 Creality 耗材颜色弹窗。
3. 查看 `Official Filament`、`+ More Colors` 两处固定文案与颜色名称。
4. 对比繁体翻译目录和后台对应颜色的繁体中文字段。

禅道截图中的英文固定文案和简体颜色名是两条不同的翻译链路。若后台颜色字段为空，当前客户端会显示英文颜色名称；英文也为空时，弹窗显示 HEX 值。

## 5. 根因与数据链路

### 5.1 固定文案缺少繁体翻译条目

弹窗中的 `Official Filament` 和 `More Colors` 都通过 `_L(...)` 查询本地翻译。两个 `msgid` 已在 `CrealityPrint.pot` 和简体中文 PO 中出现，但当前 `zh_TW/CrealityPrint_zh_TW.po` 没有对应条目。因此繁体语言下会回退显示英文。仅在后台录入颜色名称不能修复这两个按钮/标题文案。

### 5.2 颜色名称依赖后台或随包数据

当前客户端的语言映射为 `zh_TW → colorZh`、`zh_CN → colorCn`。接口数据转换为本地缓存时会保留非空的 `colorZh`，弹窗按当前语言读取；`colorZh` 为空或不存在时回退 `colorEn`。因此，“客户端认识繁体字段”和“实际有繁体译名可显示”是两个不同条件。禅道截图来自问题发生时的版本，不能据此断言当前代码仍会将 `colorCn` 当作繁体名称。

仓库当前随包的 `resources/profiles/Creality/filament/filaments_color.json` 含有中文、英文字段，但没有 `colorZh`。在首次离线启动或联网更新尚未成功时，它不能提供繁体颜色名称。禅道历史备注也指出后续需要后台录入。**尚未核实目标环境接口当前是否已经补齐 `colorZh`，不能据此宣布 Bug 已解决。**

两条显示链路为：

```text
后台颜色字段 → 下载、校验并写入本地 filaments_color.json
             → 打开官方颜色弹窗时按耗材 ID 读取本地缓存
             → zh_TW 取 colorZh；缺失则取 colorEn；仍缺失则显示 HEX

界面固定文案 → _L("Official Filament") / _L("More Colors")
             → zh_TW 的 CrealityPrint PO 翻译；缺失则显示英文
```

## 6. 修复策略与当前进度

1. 在繁体中文 PO 中补齐 `Official Filament` 和 `More Colors` 的译文，并按项目既有本地化流程生成语言资源。
2. 客户端维持 `zh_TW → colorZh` 的明确映射及英文回退；不依据简体名称自动生成繁体译文。
3. 后台为需要翻译的颜色录入 `colorZh`，并保证接口返回该字段；客户端刷新成功后才会替换旧缓存。
4. 若要求**首次离线启动**也显示繁体名称，还需在发布前同步更新随包的 `filaments_color.json`。仅更新在线接口无法改变离线安装包内的初始数据。
5. 验证语言切换、刷新成功、刷新失败保留旧缓存和离线首次启动四条路径。

截至本文撰写，客户端字段映射已存在；繁体 PO 条目仍缺失。后台录入、随包数据更新和界面实测尚未完成确认。本文件记录修复边界，不将问题标为已修复。

## 9. 风险与回滚

- 仅有客户端映射、没有后台译名时，界面仍显示英文；这属于数据缺失，不是语言映射失效。
- 仅由后台补颜色译名无法解决 `Official Filament` 和 `More Colors` 的英文回退；这两处需要客户端本地化资源。
- 在线缓存刷新是异步的；在刷新完成前打开弹窗可能看到旧缓存，需要在验证时区分时序。
- 回滚后台译名或客户端映射会使繁体名称再次回退英文；不影响 3MF 颜色和切片结果。

## 10. 结论与证据边界

Bug 17898 不能仅凭客户端已支持 `colorZh` 就关闭。截图中的两个英文固定文案对应繁体 PO 缺项，需由客户端补齐；颜色名称还取决于后台 `colorZh` 和随包数据。目标环境接口数据与实际 GUI 效果仍待验证。禅道页面提供问题现象、截图和流转记录，客户端行为与翻译/随包字段现状来自当前仓库代码和数据文件。

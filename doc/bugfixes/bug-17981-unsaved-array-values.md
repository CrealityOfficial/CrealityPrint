## 4. 根因分析

### 触发条件

发生实际预设修改，差异项进入弹窗；参数类型为 `coFloatsOrPercents` 等数组类型。

### 代码链路

1. `src/libslic3r/PrintConfig.cpp` 将 `outer_wall_line_width` 定义为可空的 `coFloatsOrPercents`。
2. `UnsavedChangesDialog.cpp` 从选中预设和编辑中预设读取旧、新配置，收集差异项。
3. 工艺、耗材的喷嘴独立参数沿用身份比较结果，分别构造旧、新配置的 `key#index`；机型参数沿用深度比较产生的索引。
4. `get_string_value()` 将参数转换为显示文本。
5. 弹窗将文本传入旧值、新值控件；预设比较窗口也调用同一格式化函数。

### 问题原因

- 原函数支持单值 `coFloatOrPercent`，遗漏数组 `coFloatsOrPercents`，因此返回空字符串。
- 原有数组分支分散处理，部分类型未提供索引时仅显示第 0 项，可能遗漏后续项的变化。
- 原逻辑主要判断整个参数是否为空，未统一判断所取数组项的 `nil`，也未统一处理缺失参数及索引越界。
- 数组支持 `nullable` 不代表普通参数界面必然显示 `N/A`。耗材覆盖未启用是明确的空值场景；工艺局部覆盖也可能使用 `nil`，但该弹窗比较的是预设配置，不是直接比较对象局部配置。

## 5. 修复方案

### 修复思路

统一在公共显示函数处理数组，复用配置类型自身的序列化接口，避免对外墙线宽或某个预设类别增加特例。

### 修改点

文件：`src/slic3r/GUI/UnsavedChangesDialog.cpp`。

- `get_string_value()` 通过 `ConfigOptionVectorBase` 统一识别数组。
- 有索引时显示指定项；无索引且存在多项时显示完整数组，例如 `[0.42, 0.55]`。
- 数值、整数、百分比、数值或百分比、字符串数组复用 `vserialize()`，保留每项单位。
- 布尔值保留 `true/false`，枚举沿用中文名称转换，坐标保留原有可读格式。
- 枚举直接转换显示名称，不额外执行依赖枚举键映射表的序列化。
- 当前项为 `nil` 时沿用 `N/A`；参数缺失、普通数组为空、索引无效或越界时显示 `Undef`，不擅自回退为第 0 项。
- 兼容预设列表、打印区域、缩略图等整体数据保留原有专用展示逻辑。
- 未保存修改弹窗的旧值、新值增加完整文本提示，便于查看列宽截断的数组内容。
- 保留既有喷嘴身份比较、差异项选择及迁移、放弃、保存行为，不改变配置值和切片计算。

## 2. 问题描述

对模型依次执行“打印时间优化 → 支撑体积优化 → 默认”，新版本的结果相对于模型初始姿态出现额外 Z 轴旋转。

禅道步骤栏记录了上述现象，结果栏和期望栏为空。下述期望与根因根据问题描述及代码分析整理，不是禅道中已有的测试结论。

修复目标：

- 优化可以改变倾角、选择新的底面，但不应因连续执行而累积无关的平面旋转。
- 在几何、缩放、镜像和算法参数相同时，同一策略的求解输入不受前一次优化姿态影响。
- 单个实例独立参与求解，不混入其他实例的网格。
- 保留既有贴床和打印板越界处理。

“默认”对应 `MinArea` 优化策略，并非恢复导入姿态。修复不要求三个策略产生相同倾角，也不把“默认”改成重置操作。

## 3. 根因分析

### 3.1 输入包含已有旋转和全部实例

原 `OrientJob::create_orientation_input()` 使用 `obj->mesh()`。`ModelObject::mesh()` 会将各实例的完整变换应用到原始网格，再合并全部实例。因此输入既包含前一次操作后的旋转，也包含同一对象其他实例的网格。

### 3.2 累积旋转引入额外平面转角

原结果应用方式为：

```cpp
instance->rotate(orientation_input.rotation_matrix);
```

`ModelInstance::rotate()` 将新旋转左乘到当前旋转。不同轴的旋转不可交换；连续采用不同底面进行最短弧旋转时，最终姿态可能附带绕 Z 轴的转角。底面方向约束本身不唯一限定平面转角，因此切换策略时可能积累与优化目标无关的平面旋转。

### 3.3 直接保留欧拉角 Z 分量存在边界问题

同一旋转矩阵可能对应不同的欧拉角表示；接近竖直姿态时还存在奇异位置。直接读取并保留通用欧拉角分解的 Z 分量，可能受到分支选择和浮点误差影响，需要先定义一致的倾角分解，再提取剩余的平面朝向。

## 4. 修复方案

### 4.1 在未旋转的单实例参考系求解

```cpp
om.mesh = obj->raw_mesh();
om.mesh.transform(instance->get_transformation().get_matrix(
    /*dont_translate=*/true, /*dont_rotate=*/true));
```

`raw_mesh()` 保留模型部件自身的变换。随后只应用当前实例的缩放和镜像，排除实例平移、已有旋转及其他实例。三种策略因此使用相同参考系中的模型几何。

### 4.2 分离倾角与平面朝向

新增 `orientation_tilt()`，从旋转矩阵最后一行构造 Z 转角为零的规范倾角：

```text
c = hypot(R(2,1), R(2,2))
x = c < 1e-10 ? 0 : atan2(R(2,1), R(2,2))
y = atan2(-R(2,0), c)
z = 0
```

在竖直奇异位置固定滚转角为零，避免从接近零的矩阵元素推导不稳定的滚转角。令当前旋转为 `R_current`，对应规范倾角矩阵为 `T_current`：

```text
H = R_current × transpose(T_current)
heading = atan2(H(1,0), H(0,0))
```

对求解结果提取规范倾角，将其 Z 分量设置为 `heading`，再通过 `instance->set_rotation()` 设置绝对姿态。这样保留选定底面的朝下方向，避免把新的倾角继续叠加到旧姿态。

这里保留的是规范分解下的平面朝向；在奇异位置不承诺界面欧拉角数值的唯一性，应结合模型朝向和底面方向验证。

### 4.3 继续执行已有位置修正

设置旋转后继续使包围盒缓存失效、调用 `ensure_on_bed()`，并执行已有打印板越界检查和必要的 XY 居中处理。17680 的打印空间约束仍由同一回调执行。

## 5. 代码影响范围

本次实现修改：`src/slic3r/GUI/Jobs/OrientJob.cpp`。

- `orientation_tilt()`：规范倾角分解及竖直奇异位置处理。
- `apply_orientation_transform()`：分离当前平面朝向，应用绝对目标倾角。
- `create_orientation_input()`：构造独立、未旋转的实例网格。

以下现有入口共用该实现，无需重复修改：

- 标准异步 `OrientJob`。
- 简易模式工具栏 `GLObjectManipulateToolbarSimple.cpp`。
- AI Bridge 的 `SlicerBridgeActionsProcess.cpp`。

修复位于求解器输入与结果应用边界，适用于上述入口的 GPU 求解及 CPU 回退，不修改三种策略自身的评分公式。

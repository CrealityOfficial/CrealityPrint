# Bug 修复记录

## 1. 基本信息
- Bug ID: `17610`
- 禅道链接: `https://zentao.creality.com/zentao/bug-view-17610.html`
- 标题: `【int32+10nm提升切片性能-二期】填充减少0.1%~0.2%，桥接轨迹增加0.1%~0.2%`
- 处理日期: `2026-08-21`
- 所属产品: `Creality Print`
- 所属模块: `切片引擎 / 填充路径生成`
- 关联优化: `int32 + 10nm 提升切片性能（二期）`
- Bug 类型: `代码错误`

## 2. 问题现象
- 使用相同模型和切片参数对比优化前后的 G-code，预览界面显示稀疏填充略微减少，桥接轨迹略微增加。
- 预览中的桥接耗材均显示为 `0.55 m`，这是耗材挤出长度按 `0.01 m` 四舍五入后的结果，不能直接反映喷嘴 XY 轨迹差异。
- 静态解析发现，优化后的 `Z=14.2 mm` Internal Bridge 存在同一直线先正向挤出、再立即反向重走约 `5.170 mm` 的局部重复轨迹。
- 总体耗材变化很小，但局部重复挤出可能形成凸起，并增加喷嘴刮蹭风险。

## 3. 禅道重现信息
- 对比文件位于 `int32vsint64/gcode对比/17610-23盘`：
  - 优化前: `优化前_3DBenchy_PLA_34m24s.gcode.txt`，生成器版本 `V7.2.1.5476`。
  - 优化后: `优化后_3DBenchy_PLA_34m26s.gcode.txt`，生成器版本 `V7.2.1461.5493`。
- `[步骤]` 使用第 23 盘的单个 3DBenchy 模型，在优化前后版本中保持相同模型、工艺和打印机配置并分别切片。
- `[步骤]` 在 G-code 预览中对比 Sparse infill、Bridge 和 Internal Bridge 的统计及 `Z=14.2 mm` 附近轨迹。
- `[结果]` Sparse infill 略微减少，Bridge 与 Internal Bridge 总轨迹增加；优化后出现约 `5.170 mm` 的共线反向挤出。
- `[期望]` int32 与 10nm 精度优化不应改变有效交点配对，不应生成桥接反向重复挤出，填充与桥接统计应与基线保持在合理误差范围内。
- 当前提供的 3MF 中 `plate_id=23` 没有 `model_instance`，截图中的活动场景没有完整保存；修改后的精确重切仍需补充或重新保存第 23 盘单 Benchy 复现工程。

## 4. 影响范围
- 模块:
  - `FillRectilinear` 扫描线交点排序
  - 直线类稀疏填充路径生成
  - Bridge 与 Internal Bridge 路径生成
- 关键文件:
  - `src/libslic3r/Fill/FillRectilinear.cpp`
- 受影响流程:
  - 10nm 内部坐标精度下同位置或近位置交点的排序与配对
  - 共享 `slice_region_by_vertical_lines()` 的 Grid、Monotonic 及桥接填充路径
  - 退化交点附近的路径连接方向和局部轨迹长度
- 本次修改不调整桥接面分类、挤出流量、速度或 G-code 统计规则。

## 5. 根因分析
- 以下数据由两份 G-code 和当前代码静态分析得到：
  - 两份 G-code 的 `583` 项有效配置完全一致。
  - 两份 G-code 的外轮廓 footprint 去除平移后一致，且 `240` 层 Z 序列一致；该证据支持模型外形、尺寸和实例变换一致，但不能单独证明源网格逐三角面完全相同。
  - 填充路径在对象局部坐标中生成，因此实例最终平移不能解释局部路径变化。
  - Sparse infill 喷嘴 XY 轨迹由约 `28479.440 mm` 变为 `28478.722 mm`，减少约 `0.718 mm`；对应耗材减少约 `0.02670 mm`。
  - Bridge 喷嘴 XY 轨迹增加约 `56.112 mm`，Internal Bridge 增加约 `19.933 mm`，两类桥接合计增加约 `76.045 mm`；对应耗材合计增加约 `2.22741 mm`。
  - Bridge 耗材由约 `0.55034 m` 变为 `0.55157 m`，所以预览界面四舍五入后均显示 `0.55 m`。
- 提交 `9759f50d9` 移植了 BBL 的 10nm 扫描线交点调整逻辑，包括提前设置交点类型、记录 `prev_idx` 和调用 `adjust_sort_for_segment_intersections()`。
- 该移植遗漏了前置的同位置交点排序规则，仍使用默认的精确有理数 `operator<` 排序；BBL 对应实现会在交点 `pos()` 相同且属于同一轮廓时保证 `LOW` 排在 `HIGH` 前。
- 10nm 量化下，同位置或近位置交点的初始顺序可能因此与后续 LOW/HIGH 嵌套调整的预期不一致，改变扫描线交点配对、路径端点及连接方向，并可能生成局部反向重复挤出。
- 该根因与本次 G-code 异常高度吻合，但由于尚未使用修改后的程序重切有效第 23 盘工程，仍需动态回归完成闭环确认。

## 6. 修复策略
- 当前补齐 BBL 的扫描线交点 comparator：
  - 当两个交点的 `pos()` 相同且 `iContour` 相同时，按 `type` 排序，确保 `LOW` 位于 `HIGH` 前。
  - 其他情况按 `pos()` 排序。
- 保留 `adjust_sort_for_segment_intersections()`，继续修复 10nm 精度下近邻交点的 LOW/HIGH 嵌套顺序。
- 不回退已有的 10nm 扫描线交点调整，避免重新引入无效嵌套、断线或漏填问题。
- 不扩大到 `ClipperSafetyOffset`、桥接面分类或其他坐标精度逻辑，保持本次修改最小化。
- 当前 comparator 是对 BBL 行为的忠实移植，但其严格弱序风险尚未解决；该实现只能作为评审版本，生产合入前必须证明风险输入不可达或进一步修正排序规则。

## 7. 代码改动摘要
- 文件: `src/libslic3r/Fill/FillRectilinear.cpp`
  - 将扫描线交点的默认排序替换为 BBL 同位置交点 comparator。
  - 同一位置、同一轮廓的 LOW/HIGH 交点按类型优先排序。
  - 保持后续近邻交点顺序调整流程不变。
- 文件: `doc/bugfixes/bug-17610-int32-sparse-infill-bridge-path-difference.md`
  - 记录问题数据、根因、修改范围、验证状态及回归风险。

## 9. 风险与回滚
- 风险等级: `高`
- 主要风险:
  - comparator 使用取整后的 `pos()` 排序，可能改变其他直线类填充中近重合交点的顺序，需要回归 Grid、Monotonic 和桥接路径。
  - BBL comparator 对同一 `pos()`、不同轮廓的交点返回等价，但对同一轮廓的 LOW/HIGH 又返回先后关系，可能形成非传递的等价关系，不满足 `std::sort` 的严格弱序前置条件。
  - 如果上述多轮廓同位置组合可以进入排序，排序行为将不受保证；该问题虽然继承自 BBL 实现，仍必须在生产合入前证明输入不可达或修正 comparator，并使用退化模型回归。
  - 当前第 23 盘活动场景未完整保存，静态分析不能替代修改后的同工程重切验证。
- 回滚方案:
  - 回滚 `FillRectilinear.cpp` 中自定义 comparator，恢复默认交点排序。
  - 保留问题 G-code 和最小复现工程，用于对比回滚前后的桥接反向轨迹。

## 10. 后续建议
- 保存一个只包含单个 Benchy、固定实例变换和完整切片配置的最小 3MF 回归文件。
- 增加扫描线交点排序单元用例，覆盖同位置 LOW/HIGH、多个轮廓共享位置及近位置交点。
- 在保持 BBL LOW/HIGH 配对语义的前提下，为多轮廓同位置交点设计满足严格弱序的确定性排序规则。
- 增加 G-code 回归检查，检测同一角色内连续共线反向挤出，并统计各角色喷嘴 XY 长度和耗材长度。
- 后续移植 BBL 修复时按依赖提交整体核对，避免只移植后处理逻辑而遗漏其前置排序规则。

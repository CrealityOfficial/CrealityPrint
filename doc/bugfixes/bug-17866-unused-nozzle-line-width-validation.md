## 4. 根因分析

### 4.1 用附件数值理解错误

立方体使用耗材 1，耗材 1 使用喷嘴 1，因此本例需要的支撑线宽是 `0.62`。

```text
正确检查本例需要的数值：0.62 > 0.2，合法。

当前循环：
喷嘴 1：0.62 > 0.2，通过。
喷嘴 2：0.40 > 0.2，通过。
喷嘴 3：0.20 <= 0.2，立即报错。
喷嘴 4：同样为 0.20，但已经提前返回。
```

**第 3 个喷嘴没有参与本例打印，却使使用第 1 个喷嘴的立方体无法通过校验。**

### 4.2 代码链路

```text
导入后的界面后台更新
  → BackgroundSlicingProcess::validate()
  → Print::validate()
  → 对象开启支撑或筏层
  → validate_extrusion_width(..., "support_line_width", ...)
  → 遍历 m_config.nozzle_diameter 的全部下标
  → extrusion_width <= layer_height
  → 返回 Too small line width，并关联对象与参数名
```

修复前关键位置（行号为分析时快照）：

| 文件 | 位置与作用 |
|---|---|
| `src/slic3r/GUI/Plater.cpp:10456` | 界面调用后台校验 |
| `src/slic3r/GUI/BackgroundSlicingProcess.cpp:762` | 转交给 `Print::validate()` |
| `src/libslic3r/Print.cpp:1980` | 线宽校验函数；循环范围是全部机器喷嘴 |
| `src/libslic3r/Print.cpp:2096` | 开启支撑或筏层时检查支撑线宽 |

### 4.3 Bambu 的实际逻辑与可借鉴部分

核对的本地版本：`F:\gerrit_code\BambuStudio-02.08.02.61\BambuStudio-02.08.02.61`。

在该版本 `src/libslic3r/Print.cpp:1557`、`:1575`：

- 从参与打印的 `extruders` 计算最小、最大喷嘴直径。
- 读取单个线宽值，并未遍历按喷嘴独立存储的线宽数组。
- 线宽为 0 时按自动处理；线宽小于等于层高时报错。
- 过大阈值是最大使用喷嘴直径的 2.5 倍。
- 仅在有支撑或筏层时检查支撑线宽。

该版本 `PrintConfig.cpp:5536` 的 `support_line_width` 为 `coFloat` 单值。C3 当前是可空的线宽数组，并支持相对喷嘴直径的百分比，两者数据结构不同。

可借鉴的是“从参与打印的配置判断合法性”；

### 4.4 统一层高：层高检查和线宽检查要分开理解

本次按用户确认的统一层高使用场景讨论，不以“不同对象使用不同层高”为修复理由。

- A 使用 0.6 喷嘴，B 使用 0.2 喷嘴，统一层高 0.1：几何上限检查 `0.1 <= 0.2` 可以通过。
- 相同喷嘴组合，统一层高 0.3：B 的 0.2 喷嘴不能满足要求，拦截合理。
- 只有 A 使用 0.6 喷嘴，机器另装了未使用的 0.2 喷嘴：不应拿未使用喷嘴的线宽拦截 A。

注意：`层高 <= 喷嘴直径` 只是其中一项检查。`Print::resolve_filament_mapping()` 还检查喷嘴的最小、最大层高范围，因此“通过几何上限检查”不等于“整个工程一定能切片”。

### 4.5 K2 Plus 为什么没有暴露同样的问题

当前 K2 Plus 0.4 机器预设为 `nozzle_diameter = [0.4]`、`single_extruder_multi_material = 1`。对应标准工艺的墙线宽、支撑线宽为单值 `0.42`。

多种耗材轮流通过同一个物理喷嘴，同一个对象/Region 的角色线宽不会因为换耗材而多出一组不同直径喷嘴的值。K3 将线宽扩展为按喷嘴独立的数组后，校验仍然没有按用途选值，才暴露出本次问题。

这不意味着旧代码所有检查都足够精确，只是单喷嘴、单值配置中没有“闲置 0.2 喷嘴的线宽混入当前检查”这个条件。

### 4.6 深查发现的两个边界

**边界一：混色只允许同口径，但仍需展开成员以确定物理喷嘴映射。**

**当前不允许不同口径混色，本次修复不放开这个限制。** `Print::resolve_filament_mapping()` 的现有检查要求：本盘使用混色耗材时，本盘参与打印的真实耗材所映射的喷嘴口径一致。

同口径不等于同一个物理喷嘴。例如，耗材 4 使用喷嘴 1（0.4 mm），耗材 2 使用喷嘴 2（0.4 mm），两者口径相同，但编号与参数取值位置仍需通过映射确定。展开成员是为了找清这个对应关系，不是为了支持不同口径混色。

普通耗材经 `filament_map` 映射到物理喷嘴。混色耗材需要先调用 `MixedFilamentManager::expand_filament_usage()` 展开成实际成员耗材，再逐一映射。

```text
普通：耗材 2 → filament_map[1] → 物理喷嘴
混色：混色耗材 5 → 实际成员耗材 4、2 → 各自的 filament_map → 同口径的物理喷嘴集合
```

展开函数输入、输出的耗材 ID 均从 1 开始；`Print::extruders()` 的下标从 0 开始。展开结果中的 `physical_filament_ids` 是真实耗材 ID，仍需映射，不能直接作为物理喷嘴下标。

`Print::resolve_filament_mapping()` 会为已使用的混色耗材构造代表喷嘴映射，但该处理发生在切片阶段，不能假定导入后早期校验已有完整的代表映射。

这里要区分两个用途：判断混色成员能否一起打印时，仍由现有逻辑检查全部成员；读取当前模型几何 Flow 的线宽时，使用与现有运行时映射一致的代表成员。不能在校验中检查一组独立线宽，路径生成却只读取另一组线宽。

**边界二：自动支撑的“实际打印耗材”和“几何参数取值”目前不是同一件事。**

- 在 `GCode.cpp:7807` 附近，支撑耗材为 0 时，会结合当前层耗材、可溶性和支撑覆盖设置选择打印耗材；不能保证只使用所属对象的模型耗材。
- 修复前，在 `Flow.cpp:218`、`:256`，支撑/界面耗材为 0 时，`0 - 1` 最终使数组读取回退到第 0 项，即物理喷嘴 1 的几何参数。
- `Config.hpp:430` 与 `PrintConfig.hpp:394` 定义了相关越界/空值回退行为。

因此，本次将自动支撑几何参数来源明确为本盘参与模型打印的稳定代表耗材，优先选择非可溶耗材，并使校验、普通支撑、支撑界面及过渡 Flow 共用这个来源。G-code 仍按现有逻辑选择每层打印耗材。

这是对既有“一份支撑几何 Flow”的明确化，不表示每层会按换入耗材重新生成一套支撑路径。即使候选喷嘴直径相同、各自线宽不同，自动支撑几何仍使用代表耗材对应的线宽；显式指定支撑耗材则使用指定耗材的线宽。不同直径下自动支撑的现有限制保持不变。

## 5. 修复方案

### 5.1 最终实现：按用途解析有效参数，校验与 Flow 共用

```text
当前对象 / Region
  → 启用的打印角色：墙、填充、支撑等
  → 该角色的耗材
  → 对应物理喷嘴
  → 解析实际采用的线宽，保留来源参数名
  ├→ 打印前：检查线宽与层高、喷嘴直径
  └→ 生成路径：用同一份输入构造 Flow
```

例如统一层高 0.2，喷嘴 1 打墙、喷嘴 2 打填充：只检查喷嘴 1 的墙线宽和喷嘴 2 的填充线宽；不把喷嘴 2 的墙线宽也拿来检查。

新增 `FlowWidthConfig` 保存角色、有效线宽、喷嘴直径和来源参数名。`resolve_model_flow_width()`、`resolve_support_flow_width()` 等解析入口同时用于校验和实际路径生成。

### 5.2 三步记忆：问用途、取数值、做判断

**第一步：问用途。** 墙使用 `wall_filament`；稀疏填充使用 `sparse_infill_filament`；实心填充和顶面使用 `solid_infill_filament`。按角色启用条件收集检查项，支撑/筏层、特殊填充、裙边及 Brim 也分别使用对应入口。内墙 Flow 还参与墙路径间距等计算，不单以最终内墙圈数判断是否取值。

**第二步：取数值。** 共用物理喷嘴映射、单值广播、空值回退、首层覆盖和缺省线宽回退。混色几何代表成员的解析可在运行时代表映射尚未安装时使用。旧式单喷嘴多耗材机器保留单喷嘴兼容路径。

**第三步：做判断。** 解析后指定的线宽值小于等于层高时报错，大于对应喷嘴直径的 5 倍时报错；最终仍为 0 时继续使用原有算法计算行为。错误保留对象和真正提供数值的参数名，例如支撑线宽为 0、回退到非法缺省值时，跳转到 `line_width`。

“指定的线宽值”不是另一个开关。已屏蔽的 `automatic_extrusion_widths` 不参与这里的报错判断。线宽设为 0 时，先按相应角色规则回退；最终仍为 0 才使用 Flow 的计算值。百分比则按选中喷嘴直径换算。

### 5.3 导入配置校验与打印校验分工

修复前，`PrintConfig.cpp` 的配置校验另有一套“线宽超过喷嘴直径 2.5 倍”的检查，可能遍历未使用的数组项；`Print.cpp` 则采用 5 倍上限。

本次移除配置层依赖实际喷嘴用途的重复判断，保留配置数值范围等基础检查。喷嘴相关线宽限制统一在打印阶段对有效输入执行，采用原有打印阶段的 5 倍上限。

这是明确的行为调整：某个有效线宽在 2.5 倍与 5 倍之间时，不再被导入层提前拒绝；超过 5 倍的实际使用线宽仍在打印前被拦截。闲置预设行不会仅因与本次喷嘴无关的比例关系而阻止导入。

树支撑尖端、分支直径检查继续调用支撑 Flow，因而同步使用新的共用参数来源；它们原有的比较公式不变。层高兼容规则保持不变。模型越界、逐对象碰撞、擦料塔与模式不兼容等独立规则不在本次修改范围。

## 7. 风险与回退

- 普通模型路径保持已有首层、角色及缺省线宽取值顺序；自动支撑原先错误回退到闲置喷嘴 1 时，本次会改变它的几何线宽。这是需要重点重切核对的行为变化。
- 同直径多喷嘴自动支撑仍使用一份代表几何 Flow，未改成按每层换料重新生成路径；G-code 的自动选料调度保持原样。
- 统一空值/0 回退取值后，原先被跳过、但实际会被 Flow 读取的非法值可能开始正确报错。首层与裙边等原先未完整覆盖的有效输入也会被检查。
- 导入层 2.5 倍上限改为打印阶段 5 倍上限，须同时验证区间内合法输入和超过 5 倍的非法输入。
- 回退时应将本次共用解析及其消费端、校验端一起撤销，避免只回退某一端再次造成取值不一致。不要回退用户预设或无关改动。

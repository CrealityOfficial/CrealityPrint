## 2. 问题现象

混色耗材由两个或多个物理耗材组成。修复前，如果用户删除了其中一个被引用的物理耗材，程序不会将该组分标记为空，而是自动寻找相邻编号的其他物理耗材并替换。

例如：

```text
物理耗材：1、2、3
混色耗材：1 50% + 2 50%

删除物理耗材 2 后：
修复前：自动改成 1 50% + 2 50%（新 2 原本是旧 3）
期望：  1 50% + -- 50%
```

修复前的行为会造成以下问题：

- 用户配置被静默改变，新组分并非用户主动选择；
- 混色耗材看起来仍然有效，无法判断原始物理耗材已经缺失；
- 模型、涂色数据和混色虚拟编号可能继续引用语义已经改变的耗材；
- 自动替换后的耗材类型可能与剩余组分不兼容，例如形成 `PLA + TPU`；
- 用户无法在原混色耗材记录中明确补齐缺失组分。

禅道期望为：删除被混色耗材引用的物理耗材后，原位置变为空并显示空状态标记；混色耗材进入异常状态，等待用户重新选择物理耗材。

## 3. 修复前复现步骤

1. 启动 Creality Print，进入准备页面。
2. 添加至少 `3` 个物理耗材。
3. 创建一个混色耗材，例如 `1 50% + 2 50%`。
4. 可选：把该混色耗材分配给模型、局部层范围或多色涂色区域。
5. 删除物理耗材 `2`。
6. 查看混色耗材列表和编辑弹窗中的组分。

修复前的实际结果：

- 被删除的组分被前序或后序物理耗材自动替换；
- 后续物理耗材编号继续前移，界面上无法区分“原组分仍存在”和“已被自动替换”；
- 找不到合法替代项时，混色记录可能被直接删除；
- 三个及以上组分的混色耗材可能移除组分、清空权重或直接删除整行。

期望结果：

- 被删除组分保留原位置和比例，但组分 ID 变为缺失占位；
- 其他编号大于被删除耗材的物理组分正常减 `1`；
- 混色记录保留，显示空状态、红色边框和感叹号；
- 用户补齐缺失组分前，该混色耗材不能参与切片或作为合并目标；
- 补齐组分后恢复正常状态，原混色记录的稳定身份和虚拟槽位不变化。

## 4. 现有数据与编号语义

### 4.1 物理组分编号

`MixedFilament::component_a` 和 `component_b` 使用从 `1` 开始的物理耗材 ID。多组分混色耗材使用 `gradient_component_ids` 保存紧凑编号，例如：

```text
"124" -> 物理耗材 1、2、4
```

删除一个物理耗材时需要分别处理：

- 等于被删除 ID 的组分：原引用已经不存在，应进入缺失状态；
- 大于被删除 ID 的组分：物理列表前移，ID 应减 `1`；
- 小于被删除 ID 的组分：保持不变。

### 4.2 缺失占位符

本次修复使用 `0` 表示“该位置引用的物理耗材已删除”。例如：

```text
简单混色：component_a = 1, component_b = 0
多组分混色：gradient_component_ids = "106"
```

多组分字符串中的 `0` 是位置占位符，不是普通物理耗材 ID。它必须保留，才能使 `gradient_component_weights` 中的比例继续与原组分位置一一对应。

### 4.3 稳定身份与虚拟耗材 ID

混色耗材作为虚拟耗材排在物理耗材之后，并可能被模型、局部配置和涂色数据引用。每条混色记录还具有 `stable_id`，用于在列表重建和物理耗材增删后识别同一条记录。

本次修复区分两个概念：

- 可用：组分完整、编号合法、已启用且未删除，可以参与切片和合并；
- 占用虚拟槽位：记录仍然存在，需要保持虚拟编号稳定，即使当前因缺失组分而不可用。

缺失记录因此是“不可用但仍占槽”，不能简单从启用列表中移除，否则其后的混色虚拟 ID 会整体前移，模型已有分配可能指向错误耗材。

## 5. 根因分析

### 5.1 删除逻辑主动选择替代耗材

原 `MixedFilamentManager::remove_physical_filament()` 在发现混色组分引用了待删除物理耗材时，会执行以下策略：

1. 优先从被删除编号之前查找未被使用的物理耗材；
2. 找不到时再从之后查找；
3. 找到后直接替换原组分；
4. 没有替代项或最终两个组分相同时，删除整条混色记录。

多组分混色耗材也会查找替代组分，找不到时可能删除某个组分或整条记录。这套逻辑本身就与禅道“原位置变为空”的产品期望冲突，是问题的直接根因。

### 5.2 原序列化规则不允许保存空组分

原解析逻辑要求 `component_a`、`component_b` 必须大于 `0`；多组分编号归一化也会过滤 `0`。即使删除阶段临时写入空值，重新同步项目配置或再次打开工程时，缺失记录仍会被判为非法并丢弃。

因此只修改删除函数不足以完成需求，还必须同步修改：

- 定义解析；
- 多组分编号归一化；
- 混色记录序列化和加载；
- 自动重建时对未完成记录的保留规则。

### 5.3 “仅枚举启用项”的虚拟编号会导致后续记录移位

原虚拟耗材 ID 只枚举 `enabled && !deleted` 的混色记录。一旦缺失记录被禁用，它会立即退出编号序列，其后的混色记录全部前移。

如果模型原本引用后续混色耗材，编号前移会使相同数值指向另一条记录。即使界面空状态显示正确，也可能引入模型颜色、涂色状态和切片工具号错配。

### 5.4 切片与合并入口缺少统一可用性判断

修复前，多个入口只检查 `enabled` 或 `deleted`：

- 混色到混色的合并菜单；
- 物理耗材到混色耗材的合并菜单；
- 混色组分解析和周长挤出机解析；
- 使用物理挤出机数量统计；
- 切片前对对象、层范围和涂色状态的校验。

如果缺失记录为了保持编号而继续占槽，仅靠旧判断无法保证它不参与后续业务。

### 5.5 列表和编辑弹窗没有缺失状态表达

原列表只绘制正常的颜色编号徽标，编辑弹窗也默认所有组分均为合法物理耗材。缺失状态没有对应的占位符、红框、感叹号、悬浮提示和确认按钮约束。

## 6. 修复策略

### 6.1 删除引用时写入 `0`，不再自动挪用耗材

`remove_physical_filament()` 改为逐项调整：

```text
component == deleted_id -> component = 0
component >  deleted_id -> component -= 1
component <  deleted_id -> component 保持不变
```

对于多组分混色耗材，同样在原字符位置写入 `0`，保留每个组分的顺序和权重。只要出现缺失组分，该记录就设为不可用，但不会被删除。

### 6.2 增加“可用”和“占槽”两个统一判断

`MixedFilament` 新增：

```cpp
bool has_missing_component() const;
bool is_available(size_t num_physical) const;
bool occupies_virtual_slot() const;
```

语义如下：

- `has_missing_component()`：简单组分或多组分列表中存在 `0`；
- `is_available()`：记录启用、未删除、无缺失、组分不重复且所有 ID 均在物理耗材范围内；
- `occupies_virtual_slot()`：记录未删除，并且正常启用或处于缺失待修复状态。

`MixedFilamentManager` 同时区分：

- `enabled_count()`：当前完整、可供切片使用的混色记录数；
- `virtual_count()`：当前占用虚拟编号的记录数，包括缺失待修复记录；
- `total_filaments()`：物理耗材数加虚拟槽位数。

### 6.3 保留缺失记录的序列化和稳定身份

序列化与加载流程允许 `component_a`、`component_b` 和 `gradient_component_ids` 中出现 `0`。加载缺失记录时：

- 保留 `stable_id`；
- 保留原组分顺序、比例、分布模式和自定义属性；
- 强制设置为不可用；
- 不参与完整自动组合的匹配；
- 项目刷新、保存和重新打开后仍能恢复为空状态。

自动重建混色列表时，缺失记录被单独保留，避免因物理耗材数量变化或配置同步被清理。

### 6.4 使用稳定身份维护物理删除后的虚拟编号映射

`PresetBundle::build_filament_id_remap()` 改为枚举所有占槽记录，并优先通过 `stable_id` 建立旧虚拟 ID 到新虚拟 ID 的映射。

这样可以同时满足：

- 被删除物理耗材之后的物理 ID 正常前移；
- 缺失混色记录继续保留槽位；
- 后续混色记录不会因为前一条记录暂时不可用而错误压缩；
- 找不到对应稳定记录时清除为 `NONE`，不把旧数据误指向其他耗材；
- 用户修复缺失组分后，原记录继续使用同一稳定身份和槽位顺序。

### 6.5 缺失耗材不参与切片和合并

合并菜单统一过滤 `!is_available()` 的混色记录；缺失记录既不能作为物理耗材的合并目标，也不能作为混色耗材的合并来源或目标。

切片链增加两层保护：

1. `Print::validate()` 在几何处理之前检查对象、模型体、层范围、自定义换刀和 MMU 涂色状态是否仍引用不可用混色槽位；
2. `MixedFilamentManager::resolve()` 和 `resolve_perimeter()` 在实际解析组分时再次拒绝不可用记录。

中文切片错误为：

```text
混色耗材引用了不存在的耗材，请重新选择原耗材。完成配置后即可进行切片。
```

英文对应为：

```text
The mixed filament references a filament that no longer exists. Please reselect the original filament. Slicing will be available once the configuration is complete.
```

如果缺失混色耗材没有被任何模型、局部配置或涂色状态引用，其他有效耗材仍可正常切片；缺失记录本身不会被计入已使用物理挤出机，也不会参与组分展开。

### 6.6 列表异常状态按高保真 UI 展示

混色耗材列表对缺失记录显示：

- 组件框使用 `#E84C4C` 红色边框；
- 缺失组分使用 `20 x 20 DIP` 占位框；
- 占位框中绘制两段居中的细横线，不显示错误耗材编号；
- 深色主题使用 `#2D2E31` 背景、`#505052` 边框；
- 浅色主题使用 `#FFFFFF` 背景、`#D0D4DE` 边框；
- `20 DIP` 感叹号图标放在组件框内部右侧；
- 图标资源使用 `resources/images/mixed_filament_missing_warning.svg`；
- 悬浮提示统一为“混色耗材引用了不存在的耗材”；
- 合并按钮禁用，点击组件区域仍可进入编辑弹窗修复。

正常物理耗材编号统一按两位格式显示，例如 `01`、`06`，使正常徽标和缺失占位框尺寸一致。

### 6.7 编辑弹窗允许修复，但禁止未完成配置确认

编辑弹窗将 `0` 显示为缺失占位，而不是普通耗材编号。只要存在未选择组分：

- 显示警告面板；
- 确认按钮禁用；
- 提示用户为每个组分重新选择耗材。

用户选择完整且类型兼容的物理耗材后，记录恢复启用；修复操作不会创建新记录，也不会移动原虚拟槽位。

### 6.8 物理耗材类型变化时实时更新异常状态

这是禅道原始描述之外、同一异常状态链路的补充处理：如果被引用物理耗材的预设发生变化，导致一个混色耗材包含不同耗材类型，例如 `PLA + TPU`，列表会立即重新检查当前物理耗材类型。

类型不兼容时：

- 组件框切换为红色边框；
- 显示感叹号；
- 禁用合并；
- 悬浮提示“无法混合。请选择相同的耗材类型。”；
- 打开编辑弹窗后显示具体槽位和耗材类型，确认按钮保持禁用。

物理耗材预设选择完成和物理耗材列表刷新时都会更新混色面板，避免必须重启、折叠面板或重新打开工程后才出现告警。

### 6.9 清除模态弹窗造成的残留悬停状态

打开混色耗材编辑弹窗时，wxWidgets 模态窗口可能中断原组件框的 `LEAVE_WINDOW` 事件，导致关闭弹窗后绿色悬停边框残留，并与第二行的悬停状态叠加。

点击组件框或其子控件时，现在会在打开弹窗前主动清除当前行的悬停标记。关闭弹窗后，只会有鼠标实际所在行显示绿色悬停边框。

| 模型未引用缺失混色耗材 | 缺失记录仍在列表 | 保留 | 显示异常状态 | 其他有效耗材可切片 |
| 模型或涂色仍引用缺失混色耗材 | 缺失记录仍在列表 | 保留 | 显示异常状态 | 切片前给出错误提示 |
| 打开弹窗并补齐同类型组分 | 更新原记录并重新启用 | 原槽位不变 | 恢复正常 | 可切片、可合并 |
| 补齐后形成 `PLA + TPU` | 记录保留但类型不兼容 | 原槽位不变 | 红框、感叹号 | 禁止确认 / 合并 |
| 打开并关闭编辑弹窗后悬浮第二行 | 两条记录均不改变 | 不变 | 仅第二行显示绿色悬停 | 不受影响 |

## 9. 影响范围与风险

### 正向影响

- 删除物理耗材不再静默改写用户的混色配方；
- 简单混色和多组分混色采用一致的缺失占位语义；
- 缺失记录能够保存、重载和继续编辑；
- 暂时不可用的记录不会造成后续混色虚拟 ID 错位；
- 切片和合并入口共享统一的可用性判断；
- 列表、编辑弹窗和切片错误均能明确说明需要用户修复；
- 物理耗材类型变化后，异常状态可以实时刷新；
- 模态弹窗不会遗留多个绿色悬停框。

### 不受影响的功能

- 完整混色耗材的比例、分布模式和颜色混合算法；
- 未被删除物理耗材引用的正常混色记录；
- 普通物理耗材的颜色和预设编辑；
- 用户主动删除整条混色耗材的操作；
- 未使用混色耗材的普通单色 / 多色切片流程。

### 当前边界与风险

- 风险等级：`中`；
- 缺失记录继续占用虚拟槽位，因此也计入总耗材槽位数量；需要与 Bug `17601` 的“物理 + 混色最多 64”规则联合回归；
- 多组分紧凑编号格式目前仍只直接表达 `0-9`，超过 `9` 个物理槽位的多组分编码属于既有格式边界；
- ID 重映射会影响对象配置、涂色状态和后续虚拟耗材编号，需要覆盖删除首个、中间和末尾物理耗材的场景；
- 类型一致性当前依据耗材预设返回的类型字符串分组，空类型、自定义类型名称和别名需要实机确认；
- 本地 MO 是生成产物且受仓库忽略规则影响，正式打包必须确保由更新后的 PO 重新生成；
- 当前未增加专门的自动化单元测试，主要依赖静态检查、目标编译和 GUI 回归。

## 11. 回归建议

### 必测场景

- 两组分混色分别删除左侧和右侧物理组分；
- 三组分及以上混色分别删除首、中、末组分；
- 删除前序但未被引用的物理耗材，确认编号前移正确；
- 缺失混色耗材已分配给整个对象、模型体、层范围和涂色区域；
- 缺失记录修复前保存 / 重开，修复后再次保存 / 重开；
- 缺失状态下尝试切片、合并和编辑；
- 补齐为相同类型和不同类型物理耗材；
- 打开 / 关闭多个混色编辑弹窗并在各行间移动鼠标。

### 编号与边界场景

- 删除第一个、中间、最后一个物理耗材；
- 同一个物理耗材被多条混色记录引用；
- 一条多组分混色中存在多个缺失占位；
- 缺失记录之前和之后均存在其他正常混色记录；
- 混色记录接近总槽位上限 `64`；
- 模型同时使用物理耗材、正常混色耗材和缺失混色耗材；
- 删除物理耗材后执行撤销 / 重做，检查数据和 UI 是否一致。

### 显示与本地化场景

- 简体中文和英文界面；
- 浅色 / 深色主题；
- 不同 Windows DPI 和侧栏宽度；
- 感叹号、两段横线、红框、绿色悬停框及 tooltip 的位置和层级；
- tooltip 在组件框、编号、百分比和感叹号上的显示一致性。

## 12. 回滚与后续建议

### 回滚方式

该修复跨越数据、编号、切片和 UI 多层，不能只回滚列表样式。完整回滚需要同时恢复：

- `MixedFilament` 的缺失占位、可用性和占槽语义；
- 删除物理耗材时的 `0` 占位逻辑；
- 缺失记录的序列化与加载支持；
- `PresetBundle` 按稳定身份维护虚拟 ID 的重映射；
- `Print` 的缺失混色引用预检；
- 合并菜单的可用性过滤；
- 编辑弹窗和列表的异常状态 UI；
- 新增图标和本地化文案。

只回滚其中一部分可能造成“UI 看似正常但数据被丢弃”或“记录被禁用后后续虚拟 ID 错位”。回滚后，Bug `17585` 的自动挪用耗材行为会再次出现。

### 后续建议

- 为 `MixedFilamentManager::remove_physical_filament()` 增加单元测试，覆盖简单混色、多组分、多个缺失位置和 ID 前移；
- 增加序列化往返测试，断言 `0`、权重、`stable_id`、启用状态和分布模式均不丢失；
- 增加虚拟 ID 重映射测试，覆盖缺失记录位于列表首、中、末的情况；
- 将“混色耗材是否可用”的耗材类型一致性校验逐步下沉到共享数据层，避免 GUI 和切片层分别计算；
- 为缺失记录占用 `64` 个总槽位名额的产品语义补充明确测试和产品说明；
- 正式打包流程增加 PO 到 MO 的一致性检查，避免源码已有中文但运行包仍显示英文；
- 清理混色链路中的临时 `MF_REMAP` / `MIXEDDBG` 日志，保留必要的低频诊断信息。

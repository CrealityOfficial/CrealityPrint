## 4. 根因分析

- 触发条件:
  - 模型在横向壳层传播过程中生成了点数较多、局部退化或存在重复/共线点的多边形。
  - `discover_horizontal_shells()` 进入窄区域过滤逻辑，需要对 `new_internal_solid` 执行 `opening()` 与 `diff()`。
- 代码链路:
  - 25% “正在生成填充区域”阶段会执行 `PrintObject::discover_horizontal_shells()`。
  - 横向壳层逻辑会根据 top/bottom shell 配置，把外表面对应的实体填充区域传播到相邻层。
  - 为避免生成过窄实体填充，代码会通过 `opening(new_internal_solid, ...)` 计算可保留区域，再通过 `diff(new_internal_solid, opening_result)` 找出过窄区域。
- 为什么会出现该现象:
  - 问题工程的局部几何复杂度较高，传入宽度检查的多边形包含大量点或不规整轮廓。
  - `opening()` / `diff()` 对这类输入的几何布尔运算成本明显放大。
  - 该逻辑位于逐层、逐区域、逐壳层传播循环内，单次复杂输入会导致 25% 阶段长时间无进展，表现为切片卡住。

## 5. 修复方案

- 修复思路:
  - 在横向壳层宽度检查前，对参与 `opening()` / `diff()` 的多边形做轻量预处理。
  - 先移除重复点、共线点和退化多边形，降低无效几何带来的布尔运算成本。
  - 当点数超过阈值时，再使用很小的容差做 Douglas-Peucker 简化，控制病态输入的复杂度。
- 修改点:
  - `src/libslic3r/PrintObject.cpp`
    - 新增 `prepare_horizontal_shell_width_check_input()`。
    - 在两处横向壳层窄区域判断前，使用预处理后的 `width_check_solid` 执行 `opening()` 和 `diff()`。
    - 当预处理结果或 opening 结果为空时，直接跳过对应差集计算。
- 为什么这样改:
  - 原始 `new_internal_solid` 仍用于最终实体填充区域更新，预处理结果只参与“过窄区域”判定。
  - 简化容差为 `0.005mm`，只用于降低宽度检查阶段的几何复杂度，避免明显改变切片主体轮廓。
  - 相比直接跳过该逻辑，该方案仍保留窄区域过滤能力，对正常模型行为影响更小。

## 6. 影响范围与风险

- 正向影响:
  - 复杂 3mf 在 25% “正在生成填充区域”阶段的几何布尔运算耗时降低。
  - 重复点、共线点、退化轮廓不再直接进入横向壳层宽度检查。
- 可能风险:
  - 极小细节区域的“过窄实体填充”判定可能与修复前存在轻微差异。
  - 由于预处理仅用于宽度检查，不直接替换最终 `new_internal_solid`，风险范围较小。
- 是否改变旧行为:
  - 普通点数和正常轮廓的模型只会进行清理，不触发简化。
  - 点数超过阈值的复杂轮廓会在宽度检查阶段使用简化后的输入。

## 7. 回归建议

- 必测场景:
  - 使用 17145 附件 3mf 重新切片，确认不再长时间卡在 25%。
  - 确认切片能进入后续阶段并正常完成。
- 边界场景:
  - 大量薄壁、斜面、碎片化面片模型，确认实体填充生成稳定。
  - top shell / bottom shell 层数较高的模型，确认横向壳层传播结果无明显异常。
- 反向场景:
  - 普通单色模型、多色模型、含桥接底面的模型，确认切片结果和预览无明显变化。

# 17289 切片引擎坐标精度优化后盘2模型多了很多回抽和擦拭轨迹

## 1. 基本信息
- Bug ID：17289
- 标题：【切片引擎坐标精度优化】盘2模型切片后多了很多回抽和擦拭轨迹
- 反馈人：测试反馈
- 处理人：
- 影响模块/影响文件：`src/libslic3r/libslic3r.h`

## 2. 现象与复现
- 复现场景：将 SCALING_FACTOR 从 1e-6（1nm精度）降低到 1e-5（10μm精度）后，对盘2模型进行切片。
- 实际结果：模型表面填充层出现大量不必要的回抽和擦拭动作，填充线不再连续挨着打印，而是跳跃式打印。
- 期望结果：表面填充线应连续有序打印，与修改前行为一致，无多余回抽和擦拭。

## 3. 责任提交追溯
- 问题出现在将 SCALING_FACTOR_INTERNAL 从 0.000001 修改为 0.00001 时引入。coord_t 改为 int32 本身不会触发此问题（int32 + 1e-6 验证正常）。

## 4. 根因分析
- 触发条件：SCALING_FACTOR 从 1e-6 变为 1e-5（精度降低 10 倍）。
- 代码链路：精度降低 → 模型坐标转为整数时粒度变粗（同一物理坐标，整数值变小 10 倍）→ Clipper 布尔运算中的 ClipperSafetyOffset（固定值 10.f）相对于坐标值的比例变大 → 填充区域的 union/difference 运算产生微小的多边形拓扑差异 → 表面填充区域被拆分为多个不连续子区域 → 填充线被分割到不同子区域 → 路径排序无法连续排列 → 产生跨区域 travel → 触发回抽和擦拭。
- 为什么 BBL 没有这个问题：BBL 的填充路径生成/连接算法版本较早，与我们从 Orca/PrusaSlicer 合并的新版 monotonic 填充逻辑不同，对精度降低的敏感度不同。
- 验证矩阵：

| 组合 | coord_t | 精度 | 结果 |
|------|---------|------|------|
| 原始 | int64 | 1e-6 | ✅ 正常 |
| 方案A | int32 | 1e-5 | ❌ 回抽多 |
| 方案B | int64 | 1e-5 | ❌ 回抽多 |
| 方案C | int32 | 1e-6 | ✅ 正常 |

结论：问题 100% 由精度降低导致，与 int32/int64 无关。

## 5. 修复方案
- 修复思路：保持 SCALING_FACTOR 不变（1e-6），不降低精度。仅将 coord_t 从 int64 改为 int32 + 启用 CLIPPERLIB_INT32（对齐 PrusaSlicer 方案）。
- 修改点（`src/libslic3r/libslic3r.h`）：将 SCALING_FACTOR_INTERNAL 恢复为 0.000001，SCALING_FACTOR_INTERNAL_LARGE_PRINTER 保持 0.00001。
- 最终方案：int32 + 1e-6 精度（与 PrusaSlicer 完全一致的组合，运行多年无问题）。
- 最大坐标范围限制：int32 + 1e-6 最大支持 2.1 米，当前所有机型均 <1 米，满足需求。

## 6. 影响范围与风险
- 正向影响：恢复精度后表面填充行为与修改前完全一致，无多余回抽和擦拭。
- 可能风险：无。int32 + 1e-6 是 PrusaSlicer 使用多年的成熟组合。
- 是否改变旧行为：切片结果与原始 int64 + 1e-6 方案基本一致（仅因 int32 Clipper 模式差异可能有极微小的坐标差异，不影响打印质量）。
- 性能收益保留：int32 带来的内存减半和 cache 效率提升仍然有效，但因精度未降低，收益略小于 BBL 方案（预估切片提速 3-8%）。

## 7. 回归建议
- 必测场景：盘2模型切片后，表面填充线应连续有序，无多余回抽和擦拭。
- 必测场景：复杂模型（法师、满盘克隆等）切片正确，无崩溃。
- 必测场景：薄壁模型（壁厚 0.4-0.8mm）壁生成完整。
- 必测场景：Arachne 可变壁厚模型（壁厚渐变、尖角）无异常。
- 边界场景：打印机最大范围内模型（如 400mm 盘）切片正常，无溢出。

## 2. 问题背景

禅道原始问题描述为：切换日语、泰语、越南语、印度尼西亚语后，部分界面仍显示中文或未正确翻译，期望各语言均正常显示。

历史记录显示：

1. 登录界面翻译已单独修改。
2. 模型库相关内容需要由云端处理对应语言逻辑。
3. `2026-07-21` 补充确认主界面的新手引导页面仍未处理。

本文档及当前代码改动聚焦第 3 项，即主界面六步蒙层操作导览的本地化与长文本显示问题。登录界面和模型库云端逻辑不在本次修改范围内。

## 3. 问题现象

主界面新手引导存在以下问题：

1. 六个步骤及“跳过、上一步、下一步、完成”等按钮未完整走通用多语言翻译流程。
2. 第 2 步 Wi-Fi 图标、第 4 步 Mapping 图标在部分语言中不显示，或图标两侧只显示单边括号。
3. 翻译文本遇到行内图标时会提前换行，括号与图标可能被拆开。
4. 日语等长文本换行后只显示下一行的首个字符，后续内容被截断。
5. 第 5、6 步括号内的操作名称与页面实际按钮文案不一致。
6. 部分 PO 存在乱码、`<unk>`、错误机器翻译或拼写错误。

## 4. 六步导览结构

| 步骤 | 操作说明 | 文案结构 |
| --- | --- | --- |
| 1 | 选择或添加打印机预设 | 单段文本 |
| 2 | 点击 Wi-Fi 图标选择匹配预设的打印机 | 图标前文本 + Wi-Fi 图标 + 图标后文本 |
| 3 | 导入模型文件 | 单段文本 |
| 4 | 点击 Mapping 图标映射耗材 | 图标前文本 + Mapping 图标 + 图标后文本 |
| 5 | 切片单盘并生成 G-code | 单段文本，操作名称放在 `【】` 内 |
| 6 | 发送打印并开始打印 | 单段文本，操作名称放在 `【】` 内 |

其中第 2、4 步由两个独立的 gettext 条目包围行内图标：

```text
第 2 步：翻译("Click 【") + Wi-Fi 图标 + 翻译("】 to select ...")
第 4 步：翻译("Click the Mapping button【") + Mapping 图标 + 翻译("】to map ...")
```

PO 译文必须保留这一结构，确保最终显示为 `【图标】`。

## 5. 根因分析

### 5.1 使用了受限的本地化接口

六步导览文案及操作按钮原先使用 `_L_ZH()`，不能完整覆盖所有已支持语言。切换到日语、泰语、越南语、印度尼西亚语等语言时，部分内容无法按当前语言正确获取译文。

### 5.2 按固定字符位置拆分翻译

原实现针对特定步骤和语言使用固定的 `SubString()` 下标拆分文本。不同语言的语序、长度和字符宽度不同，固定下标会导致：

- 文案被截断；
- 括号被拆掉或只剩一侧；
- 图标后的文字在错误位置换行；
- 新增语言需要继续增加特殊分支。

### 5.3 图标显示依赖翻译文本结构

原实现通过后半段翻译是否为空决定是否显示图标，使图标状态与 PO 翻译的拆分结果耦合。翻译调整后，图标可能被错误隐藏。

### 5.4 单个 `wxStaticText` 多行绘制不稳定

导览使用单个 `wxStaticText` 承载多行长文本。部分语言在当前布局和动态尺寸计算下只能绘制第二行的首个字符，继续增加换行也不能解决内容截断。

### 5.5 PO 翻译结构不一致

22 种语言的导览翻译存在以下不一致：

- 第 2、4 步部分语言保留 `】`，但缺少 `【`；
- 部分语言同时省略左右括号；
- 第 5、6 步括号内名称与 `Slice plate`、`Send print` 实际按钮译文不同；
- 个别语言包含乱码、`<unk>`、拼写错误或错误机器翻译。

## 6. 修复方案

### 6.1 六步文案启用完整本地化

文件：`src/slic3r/GUI/GUI_App.cpp`

- 六步导览文案由 `_L_ZH()` 改为 `_L()`。
- 第 2、4 步继续保留“图标前文本 + 图标 + 图标后文本”的结构。
- 不在运行时删除、补充或替换 PO 中的括号，显示内容以 PO 译文为准。

### 6.2 导览操作按钮启用完整本地化

文件：`src/slic3r/GUI/UITour.cpp`

以下按钮由 `_L_ZH()` 改为 `_L()`：

- `Skip`
- `Previous`
- `Next`
- `Finish`

### 6.3 图标显示由步骤配置决定

文件：`src/slic3r/GUI/UITour.cpp`

- 使用步骤传入的 `littleImg` 判断是否显示行内图标。
- 图标显示不再依赖翻译后半段是否为空。
- 图标与后半段文字之间保留固定间距。

### 6.4 按实际像素宽度换行

文件：

- `src/slic3r/GUI/UITour.cpp`
- `src/slic3r/GUI/UITour.hpp`

处理方式：

1. 使用当前字体的 `GetTextExtent()` 测量字符串实际宽度。
2. 通过二分查找确定每一行可容纳的最大字符范围。
3. 拉丁语系文本优先在空格边界换行。
4. 第 2、4 步第一行同时计算前半段文字、图标宽度和后半段剩余宽度。
5. 移除基于语言和固定字符下标的 `SubString()` 特殊分支。

### 6.5 每一续行使用独立文本控件

原有单个多行 `wxStaticText` 替换为动态纵向 sizer：

- 每一行创建独立的 `wxStaticText`；
- 更新步骤时通过 `Clear(true)` 清理旧续行；
- 根据测量结果创建任意数量的新行；
- 面板高度根据 sizer 最小尺寸动态扩展。

该方式解决日语及其他长文本在第三行以后只显示首字符的问题，也避免继续为第 4、5、6 步分别增加硬编码补丁。

### 6.6 统一 22 种语言 PO

检查范围：

```text
ca, cs, de, en, es, fr, hu, id, it, ja, ko,
nl, pl, pt_BR, ru, sv, th, tr, uk, vi, zh_CN, zh_TW
```

统一规则：

1. 第 2、4 步的图标必须各有且仅有一对括号，最终显示为 `【图标】`。
2. 第 5 步括号内文案必须与同语言 `msgid "Slice plate"` 的 `msgstr` 完全一致。
3. 第 6 步括号内文案必须与同语言 `msgid "Send print"` 的 `msgstr` 完全一致。
4. 清理已发现的乱码、`<unk>`、拼写错误和错误机器翻译。

例如越南语第 5 步：

```text
修改前：Nhấp 【Cắt lớp khay in】 để tạo tệp G-code cho việc in
实际按钮：Đĩa mỏng
修改后：Nhấp vào 【Đĩa mỏng】 để tạo tệp G-code cho việc in
```

## 10. 影响范围与风险

### 正向影响

- 新手引导完整支持当前 22 种语言。
- 新增或调整翻译时不再依赖固定字符下标。
- 长文本可根据实际字体宽度自动扩展为任意行数。
- 图标显示不再受翻译文本结构影响。
- 第 5、6 步操作名称与实际按钮保持一致。

### 注意事项

- 修改 PO 后必须重新生成 MO；只修改 PO 不会更新已运行程序中的翻译。
- 第 5、6 步当前通过 PO 保持按钮名称一致。未来如果修改 `Slice plate` 或 `Send print` 的按钮译文，需要同步更新对应导览译文。
- 动态新增和销毁续行控件涉及多次前进、后退切换，运行验收时需要关注布局刷新和控件生命周期。
- 不同平台字体度量可能存在差异，Windows 验证通过后仍建议补充 macOS 和 Linux 抽查。

## 11. 回退方案

- C++ 行为异常时，可回退 `GUI_App.cpp`、`UITour.cpp` 和 `UITour.hpp` 的导览本地化及动态换行改动。
- 单个语言译文异常时，只回退对应 `CrealityPrint_<lang>.po` 的六步导览条目。
- 回退 PO 后需要重新生成 MO，确保运行资源与 PO 源文件一致。

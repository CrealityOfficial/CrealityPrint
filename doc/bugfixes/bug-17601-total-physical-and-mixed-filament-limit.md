## 2. 问题现象

准备页右侧耗材区域同时维护两类可用于切片的耗材：

- 物理耗材：由 `FilamentPanel` 和 `PresetBundle` 维护；
- 混色耗材：由 `MixedFilamentManager` 维护，作为物理耗材之后的虚拟耗材参与编号、上色和切片。

修复前，物理耗材自身最多只能添加到 `64` 个，但物理耗材和混色耗材之间没有共享同一个总量上限。例如已有 `63` 个物理耗材时，仍可继续添加多个混色耗材，使切片实际使用的耗材总数超过 `64`。

禅道期望为：

```text
物理耗材数 + 有效混色耗材数 <= 64
```

当两者总数等于 `64` 时：

- “添加物理耗材”按钮置灰；
- “添加混色耗材”按钮置灰；
- 即使通过事件、批量添加或弹窗确认等路径触发，也不能继续写入第 `65` 个耗材。

## 3. 修复前复现步骤

1. 启动 Creality Print，进入准备页面。
2. 在右侧耗材区域添加物理耗材，并添加一个或多个混色耗材。
3. 让“物理耗材数 + 混色耗材数”达到 `64`。
4. 观察“添加物理耗材”和“添加混色耗材”按钮状态。
5. 分别尝试继续添加物理耗材和混色耗材。

修复前的实际结果：

- 物理耗材按钮只依据物理耗材面板自身数量判断是否可用；
- 混色耗材按钮没有总数上限判断；
- 只要物理耗材本身未达到 `64`，即使物理耗材与混色耗材合计已经达到或超过 `64`，仍可能继续添加；
- UI 按钮状态不能表达实际的切片耗材总量约束。

期望结果：两个添加入口共享同一个总量判断；合计达到 `64` 后同时置灰且所有写入路径均拒绝继续添加，删除任一有效耗材释放名额后恢复可用。

## 4. 现有计数语义

### 4.1 物理耗材原有限制

`FilamentPanel` 已存在物理耗材自身的上限：

```cpp
int m_max_count = { 64 };
```

原有 `FilamentPanel::can_add()` 只检查物理耗材控件数量：

```cpp
return m_vt_filament.size() < m_max_count;
```

该判断能够阻止第 `65` 个物理耗材，但不知道混色耗材数量。

### 4.2 混色耗材计数

`MixedFilamentManager::total_filaments(num_physical)` 已提供统一计数语义：

```text
总耗材数 = 物理耗材数 + enabled_count()
```

其中 `enabled_count()` 只统计同时满足以下条件的混色耗材：

- `enabled == true`；
- `deleted == false`。

因此本次限制针对的是当前有效、会占用虚拟耗材编号的混色耗材；已禁用或已删除的混色记录不占用总数名额。

## 5. 根因分析

### 5.1 两套耗材共用编号空间，但添加条件彼此独立

物理耗材与有效混色耗材最终使用同一个连续耗材编号空间。混色耗材的虚拟编号从物理耗材数量之后开始，例如 `4` 个物理耗材时，第一个混色耗材编号为 `5`。

修复前的添加条件却没有采用同一个编号空间：

```text
添加物理耗材
  └─ 只检查 physical_count < 64

添加混色耗材
  └─ 只检查 PresetBundle 是否存在
```

因此，物理耗材上限虽然是 `64`，却不等于“所有可切片耗材上限是 `64`”。当混色耗材存在时，两者合计可以越过切片支持的最大值。

### 5.2 UI 状态与数据状态没有统一刷新

两个添加按钮属于不同控件：

- 物理耗材使用 `HoverBorderIcon`；
- 混色耗材使用 `ScalableButton`。

原有代码没有一个公共方法根据总耗材数同步更新两者。添加、删除、载入混色定义或刷新面板后，按钮无法统一进入或退出禁用状态。

### 5.3 只在按钮点击处判断不足以覆盖批量入口

物理耗材除标题栏按钮外，还可以通过 `Sidebar::add_filament()`、`add_custom_filament()` 和 `add_filaments_batch()` 等路径添加。批量添加如果只在开始时判断“当前总数小于 64”，仍可能一次跨过上限，例如当前总数为 `63` 时批量增加 `2` 个物理耗材。

混色耗材通过模态弹窗创建。若只在打开弹窗前判断，确认写入前缺少防御校验，添加规则仍没有完整封闭在实际写入边界附近。

## 6. 修复策略

### 6.1 建立统一总数判断

在 `Plater.cpp` 中增加当前修复使用的上限常量：

```cpp
constexpr size_t MAX_TOTAL_FILAMENTS = 64;
```

新增 `Sidebar::can_add_filament()`，同时检查：

1. `Sidebar`、物理耗材面板和 `PresetBundle` 均已初始化；
2. 物理耗材自身仍未达到 `FilamentPanel` 上限；
3. `mixed_filaments.total_filaments(num_physical) < 64`。

等价逻辑为：

```text
允许添加 = 物理面板允许添加
        && 物理耗材数 + 有效混色耗材数 < 64
```

空指针或初始化未完成时返回 `false`，避免 UI 构造和切换阶段误开放添加入口。

### 6.2 同步两个添加按钮

新增 `Sidebar::update_filament_add_button_states()`，使用同一个判断结果更新：

- `m_bpButton_add_filament`：同步自定义 `setEnable()` 状态和 wxWidgets 原生 `Enable()` 状态；
- `m_btn_add_mixed`：更新原生 `Enable()` 状态并刷新控件。

这样两个按钮不会再分别依据各自局部状态决定是否可用。

### 6.3 在 UI 与数据入口同时拦截

当前改动不是只做按钮置灰，还在以下添加入口加入统一校验：

- 物理耗材标题栏“添加”按钮；
- `Sidebar::add_filament()`；
- `Sidebar::add_custom_filament()`；
- `Sidebar::add_filaments_batch()`；
- 混色耗材按钮打开弹窗前；
- 混色耗材弹窗确认、写入管理器前。

其中批量添加额外检查：

```cpp
total_count + num_new <= MAX_TOTAL_FILAMENTS
```

从而防止一次批量操作直接从小于 `64` 跳到大于 `64`。

### 6.4 在数量变化后刷新按钮

按钮状态在以下时机重新计算：

- Sidebar 初始化完成；
- `on_filaments_change()` 收到数量变化；
- 物理数量未变但仍需刷新动态耗材列表的提前返回分支；
- `update_mixed_filament_panel()` 载入、添加、删除或清理混色耗材后。

由于新增混色耗材、删除混色耗材、删除物理耗材等操作最终都会刷新混色耗材面板，达到 `64` 时两个按钮会一起置灰，释放名额后会一起恢复。

### 6.5 补齐禁用图标和标题栏事件隔离

物理耗材和混色耗材按钮都增加了明暗主题下的禁用图标，并在 `sys_color_changed()` 中重新设置，避免主题切换后仍使用旧主题资源。

物理耗材标题栏的点击处理新增按钮命中区域判断。鼠标位于自动映射、冲刷体积、添加、删除、设置或折叠按钮区域时，不执行标题栏折叠逻辑。该处理可避免添加按钮禁用后，点击其所在位置意外触发耗材区域折叠或展开。

## 7. 代码修改摘要

### `src/slic3r/GUI/Plater.hpp`

新增两个 `Sidebar` 私有方法：

```cpp
bool can_add_filament() const;
void update_filament_add_button_states();
```

### `src/slic3r/GUI/Plater.cpp`

- 增加 `MAX_TOTAL_FILAMENTS = 64`；
- 使用 `MixedFilamentManager::total_filaments()` 计算物理与有效混色耗材总数；
- 统一维护两个添加按钮的启用状态；
- 为物理单个添加、外部调用和批量添加补充总量保护；
- 为混色耗材弹窗打开前及确认后补充总量保护；
- 在物理 / 混色数量变化和初始化时刷新按钮；
- 增加明暗主题禁用图标；
- 避免点击禁用按钮区域时误触发物理耗材标题栏折叠。

本次候选修复没有修改 `MixedFilamentManager` 的编号和序列化规则，也没有改变单个混色耗材的配比、组分或显示颜色算法。

## 8. 修复后的预期行为

| 物理耗材数 | 有效混色耗材数 | 当前总数 | 添加物理耗材 | 添加混色耗材 |
| ---: | ---: | ---: | --- | --- |
| 1 | 0 | 1 | 可用 | 可用 |
| 63 | 0 | 63 | 可用，添加后总数为 64 | 可用，添加后总数为 64 |
| 63 | 1 | 64 | 置灰并拒绝添加 | 置灰并拒绝添加 |
| 60 | 4 | 64 | 置灰并拒绝添加 | 置灰并拒绝添加 |
| 64 | 0 | 64 | 置灰并拒绝添加 | 置灰并拒绝添加 |
| 62 | 1 | 63 | 单个添加可用；批量增加 2 个时拒绝 | 可用，添加后总数为 64 |

当总数为 `64` 时删除一个物理耗材或有效混色耗材，刷新完成后的总数变为 `63`，两个添加按钮应恢复可用。编辑已有混色耗材的组分和比例不增加条目数量，不应占用新的名额。

## 9. 影响范围与风险

### 正向影响

- 准备页物理耗材和混色耗材共享 `64` 个有效耗材上限；
- 两个添加按钮在达到上限时同步置灰；
- 单个添加、批量添加和混色弹窗确认路径均有防御校验；
- 删除耗材释放名额后可恢复添加；
- 明暗主题均有明确的禁用态图标；
- 禁用按钮不会因为鼠标事件继续传播而误切换物理耗材区域的折叠状态。

### 不受影响的功能

- 已有物理耗材的颜色、预设和打印参数编辑；
- 已有混色耗材的组分、比例和显示颜色计算；
- 混色耗材虚拟 ID 的既有排列规则；
- 删除、合并及耗材 ID 重映射逻辑；
- 模型涂色、切片路径和 G-code 生成算法本身。

### 当前代码范围边界

- 本次上限常量和统一判断位于 `Sidebar`，尚未下沉为 `PresetBundle` 或 `MixedFilamentManager` 的全局数据约束；
- 当前修复覆盖准备页 Sidebar 的添加按钮、`Sidebar` 公共添加方法及其批量路径，但仓库中仍存在设备耗材同步、简易模式、3MF 导入等直接调用 `set_num_filaments()` 的路径；这些入口是否都应采用“物理 + 混色不超过 64”的规则，需要按禅道“所有颜色相关功能”备注继续核对；
- 对已经包含超过 `64` 个有效耗材的历史项目，当前逻辑会禁用继续添加，但不会主动裁剪、删除或重映射已有数据；兼容策略需要产品确认，不能静默丢弃用户配置；
- `FilamentPanel::m_max_count` 与 `Plater.cpp::MAX_TOTAL_FILAMENTS` 当前都为 `64`，后续若修改上限，需要避免两处常量不一致。

### 风险

- 风险等级：中低；
- 按钮状态依赖混色管理器已与项目配置同步，载入、切换项目和设备同步后需确认刷新时序；
- `HoverBorderIcon` 同时维护自定义状态和 wxWidgets 原生状态，需验证 hover、点击与工具提示在禁用状态下表现一致；
- 主题切换会重建禁用图标，需验证深色 / 浅色和高 DPI 下的尺寸与清晰度；
- 如果非 Sidebar 入口仍可增加物理耗材，可能出现数据总数超过 `64`、但两个 Sidebar 按钮仅被动置灰的情况。

## 11. 回归建议

### 必测场景

- 纯物理耗材从 `63 -> 64`；
- 物理与混色组合从 `63 -> 64`；
- 总数 `64` 时分别尝试添加物理耗材和混色耗材；
- 删除物理耗材、删除混色耗材后的按钮恢复；
- 混色耗材弹窗打开、取消、确认后的状态；
- 对象颜色弹窗触发的批量物理耗材添加。

### 边界场景

- `1` 个物理耗材、`63` 个有效混色耗材；
- `63` 个物理耗材、`1` 个有效混色耗材；
- 存在已删除或已禁用混色记录时的有效计数；
- 当前总数 `62`，批量增加 `2` 个和 `3` 个物理耗材；
- 在混色弹窗打开期间触发项目或耗材状态更新；
- 新建、打开、恢复和切换项目时首次绘制按钮状态；
- 浅色 / 深色主题及 `100%`、`125%`、`150%`、`200%` DPI。

### 反向场景

- 总数小于 `64` 时两个添加入口保持正常；
- 添加第 `64` 个耗材成功，不应错误限制为最多 `63` 个；
- 编辑现有物理 / 混色耗材不被添加限制阻断；
- 删除、合并和 ID 重映射后模型耗材分配保持正确；
- 已有 3MF 在不新增耗材时仍可正常打开、保存和切片；
- 切片所见耗材颜色、对象列表耗材编号和预览颜色保持一致。

## 12. 回滚与后续建议

### 回滚方式

回滚时需要同时恢复以下改动：

- 从 `Sidebar` 移除 `can_add_filament()` 和 `update_filament_add_button_states()`；
- 恢复物理耗材添加路径只调用 `FilamentPanel::can_add()` 的旧逻辑；
- 移除混色耗材添加入口的总数校验；
- 移除批量添加的 `total_count + num_new` 校验；
- 移除两个按钮的禁用图标和数量变化刷新；
- 恢复物理耗材标题栏原有点击处理。

回滚后，物理耗材自身仍最多为 `64` 个，但物理耗材与有效混色耗材的合计数量会重新失去上限保护，Bug `17601` 将再次出现。

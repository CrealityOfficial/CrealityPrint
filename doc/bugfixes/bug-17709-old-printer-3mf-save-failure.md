# Bug 17709：【F039】老机型无法保存 3MF

## 2. 问题现象

### 用户反馈现象

在 F039 等支持耗材喷嘴映射的机型中建立项目后，切换到不支持耗材喷嘴映射的老机型，再保存 3MF，软件提示：

> 保存文件失败。请检查目录是否存在，以及是否有其他程序打开了该项目文件。

### 实际结果

- 目标目录有效且项目文件未被其他程序占用，3MF 仍然保存失败。
- 弹窗显示的是通用文件写入错误，不能直接反映内部实际失败原因。
- 切换打印机后，项目仍可能保留上一台多喷嘴打印机的 `filament_map`。例如目标老机型只有 1 个物理喷嘴，但映射中仍存在 `2`、`3`、`4` 等喷嘴编号。
- 3MF 导出阶段执行严格映射校验时，判定映射超出目标打印机的喷嘴范围并终止保存。

### 期望结果

- 打印机发生切换后，项目映射应立即按照目标打印机的映射能力和物理喷嘴拓扑重新整理。
- 切换到不支持映射的单喷嘴老机型时，所有项目耗材均应映射到喷嘴 `1`。
- 用户无需先切片或手动修改耗材映射，即可正常保存 3MF。
- 真正的目录不存在、文件占用等文件系统错误仍保持原有处理逻辑。

## 3. 复现步骤

### 前置条件

- 使用支持耗材喷嘴映射的 F039 多喷嘴打印机预设建立项目。
- 项目中存在多个耗材，当前 `filament_map` 包含大于 `1` 的物理喷嘴编号。
- 准备一个不支持 `support_filament_nozzle_mapping` 的单喷嘴老机型预设，例如问题截图中的 `SPARKX i7`。

### 操作步骤

1. 在 F039 打印机下打开或创建多耗材项目。
2. 确认项目已形成多喷嘴耗材映射。
3. 从打印机预设下拉框切换到单喷嘴老机型。
4. 不重新切片，直接执行“文件 -> 保存项目”或“另存项目”。
5. 观察保存结果。

### 复现结果

- 修复前：弹出“保存文件失败”提示，目标 3MF 未正常生成。
- 内部触发条件：项目映射仍引用旧打印机的喷嘴编号，而目标打印机的 `nozzle_diameter.size()` 为 `1`，严格导出校验返回映射越界错误。

### 复现概率

- 满足“多喷嘴映射项目 -> 不支持映射的单喷嘴老机型 -> 未重新切片直接保存”条件时稳定复现。

## 4. 根因分析

### 触发条件

问题需要同时满足以下条件：

1. 当前项目保存了多喷嘴 `filament_map`。
2. 用户切换到映射能力或喷嘴拓扑不同的目标打印机。
3. 打印机切换流程更新了打印机、工艺及耗材预设，但未同步重建项目映射。
4. 用户在映射被切片流程重新计算之前直接保存 3MF。
5. 导出阶段按照目标打印机的喷嘴数量严格检查旧映射。

### 代码链路

1. `Tab::select_preset()` 完成打印机预设选择和兼容耗材更新。
2. 修复前该流程没有把打印机切换作为项目映射的失效边界，上一台打印机的 `filament_map` 被继续保留。
3. 对不支持 `support_filament_nozzle_mapping` 的老机型，原有 `PresetBundle::initialize_project_filament_mapping()` 和 `sync_project_filament_mapping_mode()` 会提前返回，无法清除多喷嘴遗留状态。
4. 保存项目时，`Plater` 组装完整配置并进入 `bbs_3mf` 导出。
5. `validate_project_filament_mapping()` 使用项目耗材数量和目标打印机 `nozzle_diameter.size()` 校验完整映射。
6. 当单喷嘴目标机型收到含 `2`、`3`、`4` 的旧映射时，校验失败，3MF 导出返回 `false`，上层最终显示通用保存失败弹窗。

### 问题原因

根本原因不是目录不存在或文件占用，而是项目级映射的生命周期没有覆盖打印机切换：

- `filament_map` 表示“项目逻辑耗材 -> 当前打印机物理喷嘴”的关系，本质上依赖当前打印机的映射能力和喷嘴拓扑。
- 切换打印机后，原映射已经失去适用前提，不能作为普通项目数据原样继承。
- 严格导出校验正确地阻止了非法配置落入 3MF，但切机流程没有在校验前恢复合法状态。

BambuStudio 02.06.00.51 的参考逻辑是在 `printer_model` 变化后切回自动映射模式，并在切片阶段根据新打印机拓扑重新计算映射。C3 当前存在保存前严格校验，因此不能只等待切片阶段处理，必须在打印机切换完成时立即将项目映射物化为目标打印机可接受的状态。

## 5. 修复方案

### 修复思路

把打印机切换定义为项目耗材映射的失效边界：目标打印机选择成功且确实发生预设切换后，立即调用统一映射初始化流程，按目标打印机重新生成完整映射。

- 目标打印机支持耗材喷嘴映射：根据目标打印机的物理喷嘴数量、当前耗材数量和工艺喷嘴兼容性重新计算自动映射。
- 目标打印机不支持耗材喷嘴映射：根据目标打印机的实际喷嘴数量生成兼容映射；单喷嘴机型生成全 `1` 映射。
- 同步重建派生字段 `filament_map_2` 和 `filament_volume_map`，将模式恢复为 `fmmAutoForSaving`，并取消旧项目映射保留标记。
- 保存前继续执行映射模式同步，作为非标准入口或中间状态的最后防线；严格导出校验本身不降级、不绕过。

### 修改点

#### `src/slic3r/GUI/Tab.cpp`

- 在打印机预设选择前记录原打印机预设名称。
- 目标预设选择完成、兼容耗材列表更新后，判断打印机预设是否真实发生变化。
- 发生变化时调用 `PresetBundle::initialize_project_filament_mapping()`，使映射在用户再次切片或保存之前完成更新。

#### `src/libslic3r/PresetBundle.cpp`

- `initialize_project_filament_mapping()` 不再对“不支持映射的 FFF 打印机”直接返回，而是进入兼容映射整理流程。
- `sync_project_filament_mapping_mode()` 根据目标打印机的 `support_filament_nozzle_mapping` 和 `nozzle_diameter.size()` 处理能力边界。
- 不支持映射的目标打印机通过 `build_legacy_filament_map()` 重建合法映射，并同步：
  - `filament_map`
  - `filament_map_2`
  - `filament_volume_map`
  - `filament_map_mode`
- 清除 `m_preserve_project_filament_mapping`，避免上一台打印机的映射继续覆盖目标打印机状态。

## 7. 风险与回退

### 可能风险

- 打印机预设发生切换时，原有手动映射会被重新初始化。这是本次修复的预期行为，因为手动映射绑定来源打印机的物理喷嘴拓扑，不能直接迁移到另一台打印机。
- 目标打印机预设的喷嘴数量或能力字段配置错误时，可能无法生成合法映射；该情况应保留明确日志并由严格校验阻止无效 3MF。
- `filament_map_2`、体积类型映射或混合喷嘴模式若未同步，可能造成保存配置与切片配置不一致，因此验证时必须同时检查相关派生字段。

### 风险影响范围

- 仅影响打印机预设实际发生切换后的项目映射初始化，以及不支持映射打印机的保存前映射同步。
- 不修改 3MF 严格校验规则，不改变正常文件写入和文件占用处理。

### 回退方案

- 回退 `src/slic3r/GUI/Tab.cpp` 中打印机切换后的映射初始化调用。
- 回退 `src/libslic3r/PresetBundle.cpp` 中不支持映射打印机的兼容映射整理分支。
- 不建议通过删除或放宽 `bbs_3mf.cpp` 的严格校验规避问题，否则可能把越界映射写入 3MF，并把错误延后到加载、切片或 G-code 阶段。

## 8. 备注

### 历史备注摘要

- BambuStudio 02.06.00.51 在打印机模型变化后将全局映射模式恢复为自动模式，实际映射在后续切片阶段按照新喷嘴拓扑重新计算。
- BambuStudio 的 3MF 项目配置保存没有 C3 当前的映射严格校验，因此允许映射在切片时再收敛。
- C3 必须支持“切换老机型后不切片直接保存”，所以需要把映射整理提前到打印机切换完成时，同时保留导出校验作为防御。

## 2. 问题现象

- 用户反馈：导入旧 3MF 后，打印机下拉框仍显示 `Creality F039 0.4 nozzle(叠色小船.3mf)`，当前机型已更名为 K3。
- 实际结果：旧配置成为独立的“项目预设”，下方另有 `Creality K3` 系统预设，旧工程未关联到对应的新系统预设。
- 期望结果：旧 F039 系统预设及其继承关系正确关联 K3，保留用户修改过的参数；用户自行命名的内嵌预设保留其名称。没有用户差异的打印机配置可直接选择 K3，有差异的配置按已有修改态机制显示。

## 3. 复现步骤

### 前置条件

- 当前版本已安装 K3 系统预设。
- 使用上述旧工程，包含四个 `0.4 mm` 喷嘴、四个耗材槽和小船模型。
- 工程中的打印机、工艺和耗材仍使用 F039 历史名称。

### 操作步骤

1. 将 `叠色小船.3mf` 作为工程导入，加载其参数。
2. 打开左侧打印机下拉框。
3. 检查选中名称、项目预设和系统预设分组。

### 复现结果

- 截图显示项目预设 `Creality F039 0.4 nozzle(叠色小船.3mf)`，系统预设中另有 `Creality K3`。

## 4. 根因分析

### 触发条件与样本证据

`Metadata/project_settings.config` 实际保存：

| 字段                        | 样本中的值                                   |
| --------------------------- | -------------------------------------------- |
| `printer_model`             | `Creality F039`                              |
| `printer_settings_id`       | `Creality F039 0.4 nozzle`                   |
| `print_settings_id`         | `0.20mm Standard @Creality F039 0.4 nozzle`  |
| `filament_settings_id`      | 四项 `Hyper PLA @Creality F039 0.4 nozzle`   |
| `print_compatible_printers` | `Creality F039 0.4 nozzle`                   |
| `inherits_group`            | 工艺和耗材引用旧 F039 系统预设；打印机项为空 |

工程还包含一个继承旧 Hyper PLA 预设的自定义耗材配置。项目差异记录包含工艺加加速度、预热等修改，以及耗材温度、回抽等修改；打印机差异项为空。

旧项目没有保存新版 `nozzle_variant_ids` 和 `support_filament_nozzle_mapping`，也没有打印机、工艺、耗材的新式喷嘴参数表身份字段。

### 代码链路与问题原因

1. `PresetBundle::load_config_file_config()` 拆分工艺、打印机、耗材配置，调用 `PresetCollection::load_external_preset()`。
2. `load_external_preset()` 按原预设名称查找，失败后查询 `renamed_from` 映射；仍未找到时生成“原预设名(工程文件名)”并标记为项目预设。
3. K3 系统预设加载后没有建立对应的 F039 历史名称映射。最终方案在代码中集中注册运行时别名，不依赖 JSON 的 `renamed_from` 字段，也不修改 JSON 元数据解析路径。
4. 即使名称匹配成功，旧 `inherits`、兼容打印机引用和 `printer_model` 仍需要归一化；多耗材导入还会检查继承名称中 `@` 后面的机型，旧名称及空格可使继承关系被清空。
5. 新 K3 使用完整的喷嘴变体参数表。旧项目只有默认单行身份或缺少身份字段，直接套用新表恢复逻辑可能只匹配 E1，或者因为行数不一致回退系统值，不能完整保留旧项目修改。

### 当前 ID 与名称的关系

- `printer_settings_id` 实际保存预设名称，不是与显示名称独立的永久 ID。
- 当前机型文件有 `model_id = Creality_K3`，但样本项目配置没有保存对应的独立机型 ID；上述预设导入匹配也没有按这个字段统一寻址。
- 因而本次更名需要显式兼容旧身份引用，不能只替换下拉框文字。

### 补充问题：自定义打印机名称在重新导入后丢失

首次分析时，用户提供的 `222叠色小船.3mf` 保存 `printer_settings_id = my-重新保存的Creality K3`，机型和打印机父项均为 `Creality K3`，打印机参数差异记录为空，压缩包中没有独立的 `Metadata/printer_settings_*.config`。

实施补充修复时再次读取同一路径，文件内容已更新：`printer_settings_id = 222Creality K3 - 拷贝(1)`，打印机差异记录为 `nozzle_diameter`，父项仍为 K3，仍无独立内嵌打印机配置。两次样本分别覆盖“仅改名称”和“自定义名称加参数修改”，不可将早期样本内容当成当前文件值。

原导入路径在找不到自定义名称时尝试父预设；`profile_print_params_same()` 忽略名称和继承字段，导致仅改名称的配置直接复用父预设 K3。原保存路径仅收集已标记为项目内嵌的预设，选中的普通用户打印机预设不会自动作为内嵌预设写入工程。

## 5. 修复方案

### 修复思路

在现有预设体系内，由代码集中维护明确的历史名称规则：系统预设加载后，在 `update_map_system_profile_renamed()` 中注册运行时别名，复用既有匹配机制。统一导入时的机型关联，并按旧 0.4 喷嘴配置的语义恢复用户差异。

最终交付不修改打印机、工艺、耗材 JSON，也不修改预设生成脚本或 JSON 解析器。本次此前加入的 64 份 JSON 历史名称字段、生成脚本辅助函数和配套 JSON 读取改动均已撤回。

### 具体兼容流程：认曾用名 → 接好关联 → 恢复参数

#### 第一步：从旧工程读取预设引用

3MF 是压缩包，项目配置保存在 `Metadata/project_settings.config`。旧 F039 工程中的典型引用为：

```text
printer_model       = Creality F039
printer_settings_id = Creality F039 0.4 nozzle
print_settings_id   = 0.20mm Standard @Creality F039 0.4 nozzle
filament_settings_id 中的耗材名称 = Hyper PLA @Creality F039 0.4 nozzle
```

这里的 `printer_settings_id` 保存的是打印机预设名称，不是机型文件的 `model_id`。界面最终显示的是导入后选中的打印机预设名称，并非直接照搬 JSON 字符串。因此，选中了哪个预设决定了用户最终看到哪个名称。

#### 第二步：通过“曾用名”找到当前系统预设

代码识别已加载的 Creality 厂商、打印机类型、系统预设 `Creality K3`，在内存中的 `Preset::renamed_from` 注册以下历史名称；这些值不写入配置文件：

```text
Creality F039 0.4 nozzle
Creality F039
Creality K3 0.4 nozzle
```

工艺、耗材仅对 Creality 系统预设且名称以 ` @Creality K3` 结尾的项生成对应别名，保留前面的工艺或材料名称。规则只有一处，不需要修改每份配置。例如：

| 旧系统预设引用                              | 对应当前系统预设               |
| ------------------------------------------- | ------------------------------ |
| `Creality F039 0.4 nozzle`                  | `Creality K3`                  |
| `0.20mm Standard @Creality F039 0.4 nozzle` | `0.20mm Standard @Creality K3` |
| `Hyper PLA @Creality F039 0.4 nozzle`       | `Hyper PLA @Creality K3`       |

程序先查实际同名预设；不存在时再查明确的历史名称映射。它不是删除字符串里的 F039 再随便拼上 K3，也不是根据 3MF 文件名猜机型。没有明确对应项时，保留原有项目配置处理方式。

#### 第三步：把内部关联一起接到 K3

找到新预设后，还需要更新内部关联，不能只修改下拉框文字：

| 旧工程里的关联                       | 导入后关联到                 |
| ------------------------------------ | ---------------------------- |
| 机型 `printer_model = Creality F039` | `Creality K3`                |
| 打印机父预设指向旧 F039 系统预设     | 对应的 K3 打印机系统预设     |
| 工艺、耗材继承旧 F039 预设           | 对应的 K3 工艺、耗材系统预设 |
| 兼容打印机列表引用旧 F039 系统预设   | 对应的 K3 打印机系统预设     |
| 默认工艺、默认耗材引用旧系统名称     | 对应的当前系统预设名称       |

这样，工艺和耗材才能继续关联当前选中的 K3。`inherits_group` 在项目配置中汇总各类预设的父项，拆分导入后分别处理其 `inherits`；这些关联字段与用户自定义的显示名称是不同的信息。

#### 第四步：恢复工程参数，不直接整套覆盖成 K3 默认值

- 工程差异记录明确标记为用户修改的参数：恢复这些修改。
- 没有标记为修改的参数：沿用现有导入规则，采用当前系统预设值。
- 旧 0.4 喷嘴参数：恢复到新版参数表中对应的 `0.4 / Standard` 行；工艺共享值、打印机 E1–E4 数组和拆分后的耗材值分别按其语义处理，详见下文“参数保留规则”。

兼容的目标是正确关联并恢复旧工程。系统默认值和切片实现可能随版本变化，因此不保证新旧版本的切片结果完全一致。缺失差异记录、异常数组或手动改变喷嘴拓扑的文件仍需单独验证。

#### 第五步：保留自定义打印机名称，再保存时带上身份信息

旧系统名字需要迁移，用户自己起的名字需要保留：

| 导入情况                                                          | 预期显示和处理                           |
| ----------------------------------------------------------------- | ---------------------------------------- |
| 旧系统名称 `Creality F039 0.4 nozzle`，且没有同名实际预设优先命中 | 根据历史映射关联 `Creality K3`           |
| 用户名称 `222Creality K3 - 拷贝(1)`                               | 保留该名称，机型与父项仍关联 K3          |
| 用户名称“我的 F039 调试配置”                                      | 保留用户文字，仅迁移内部明确的旧系统关联 |
| 未提供预设名称                                                    | 按父项或既有项目预设机制处理             |
| 本地已有同名且参数相同的用户预设                                  | 复用该预设                               |
| 本地已有同名但参数不同的用户预设                                  | 区分工程版本的名称，保留本地参数         |

当前补充样本 `222叠色小船.3mf` 的名称位置是：

```text
Metadata/project_settings.config
  printer_settings_id = 222Creality K3 - 拷贝(1)
  printer_model       = Creality K3
  inherits_group 最后一项 = Creality K3
```

导入后应恢复这个自定义打印机预设，不能仅因为参数与父项相同就显示默认 K3。保存工程时，将选中的自定义打印机作为内嵌预设写入 `Metadata/printer_settings_*.config`，保存名称、继承关系和参数差异；没有业务参数差异也保留身份。项目汇总配置继续通过 `printer_settings_id` 引用它。

**记忆规则：旧系统认曾用名，自定义保原名，内部关系接 K3，工程修改按记录恢复。** 上述为已实现的处理规则及预期行为，实际 GUI 导入、切片和保存重开验证状态见第 6 节。

注册规则：

- 只有 `is_system` 且厂商 ID 为 `Creality` 的预设可以获得这些兼容别名。
- 打印机必须精确名为 `Creality K3`；工艺和耗材必须以 ` @Creality K3` 结尾。
- 已有历史别名保留，重复重建索引不重复添加。
- 未加载对应 K3 系统预设时，不创建虚构目标。
- 实际同名预设优先于历史别名，用户自定义名称不做模糊替换。
- 别名保存在内存预设对象及现有名称索引中；配置文件和生成脚本无需维护这些字段。

### 参数保留规则

- 明确的旧 F039/K3 0.4 预设关联到新 K3 系统来源后，沿用现有项目差异机制：未修改项使用当前系统值，用户修改项保留。
- 旧工艺的共享单值恢复到四个物理喷嘴各自的 `0.4 / Standard` 参数行。
- 旧打印机的四项数组按 E1–E4 顺序恢复到对应的 0.4 参数行；旧共享值按行展开。
- 拆分后的单个旧耗材值恢复到该耗材的 0.4 参数行，其他口径继续使用新系统值。
- 已有多行或非默认变体身份的配置继续使用既有身份匹配逻辑。
- 自定义内嵌预设保留原名称，只迁移其父预设与必要的关联引用。
- 未安装对应新系统预设、没有明确历史映射或名称不匹配时，不做模糊字符串替换。

### 补充修复：自定义打印机身份保留

- 项目导入先识别当前系统名称及明确的历史别名，继续执行 F039 → K3 迁移。
- 对有独立名称的用户打印机配置，即使参数与父预设相同，也不回退选择父预设。没有同名预设时，直接以用户名称建立项目预设，不额外添加工程文件名。
- 本地同名且参数一致时复用；参数不同时创建 `用户名称 (工程文件名)`，必要时追加编号，保留本地预设的参数。
- 保存工程时，`get_project_embedded_presets()` 同时收集当前选中的非系统、非默认打印机预设，使用其当前编辑状态生成快照，明确保存 `printer_settings_id` 和 `inherits`。没有业务参数差异也保留名称和父项，不改变本地预设的来源标志。
- 仅改变打印机预设的身份恢复规则；工艺和耗材仍沿用现有导入复用规则。用户起的名字如“我的 F039 调试配置”不做字符串替换，内部明确的旧系统关联仍迁移到 K3。

### 多口径导入星号与喷嘴显示不一致：原因及修复

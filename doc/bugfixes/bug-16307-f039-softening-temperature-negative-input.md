## 2. 现象与复现
- 复现场景：进入耗材参数中的“喷嘴预热”分组，编辑“软化温度”输入框。
- 实际结果：键盘直接输入 `-` 号无效，导致无法手动输入 `-6` 等负值；但在其他输入框中输入负数后复制粘贴到该输入框可以生效。
- 期望结果：当参数允许负范围时，输入框应允许直接输入负号，并能正常输入负值。

## 4. 根因分析
- 触发条件：`SpinInput` 控件被用于允许负值的整数参数，并且控件实例来自对象池复用或创建后再调用 `SetRange()` 更新范围。
- 代码链路：`Field::SpinCtrl::BUILD()` 根据参数定义计算 `min_val`，随后调用 `SpinInput::SetRange(min_val, max_val)` 设置控件范围。
- 为什么会出现该现象：`SpinInput` 创建 `TextCtrl` 时默认使用 `wxTextValidator(wxFILTER_DIGITS)`，该 validator 只允许数字输入，会拦截键盘输入的 `-`。当后续 `SetRange()` 把控件范围更新为负数范围时，原 validator 没有同步更新，因此键盘负号仍被过滤。复制粘贴负数可以生效，说明参数解析和保存链路本身可以接受负值，问题集中在输入框的字符过滤层。

## 5. 修复方案
- 修复思路：不针对“软化温度”单独写特殊逻辑，而是在通用 `SpinInput` 控件中，让输入过滤规则跟随 `SetRange()` 的最新范围动态更新。
- 修改点：在 `SpinInput::SetRange()` 中调用 `updateTextValidator()`；当 `min < 0` 时使用 `wxFILTER_INCLUDE_CHAR_LIST` 并允许 `-0123456789`，否则保持原来的 `wxFILTER_DIGITS`。
- 为什么这样改：`SetRange()` 是控件最终获得有效范围的统一入口，放在这里可以覆盖对象池复用、默认构造后再设范围等场景，避免只在构造阶段设置 validator 导致状态过期。

## 6. 影响范围与风险
- 正向影响：允许负范围的 `SpinInput` 参数可以直接键盘输入负号，软化温度可正常输入负值。
- 可能风险：所有复用 `SpinInput` 且 `min < 0` 的整数输入框都会允许输入负号；`min >= 0` 的输入框仍保持只允许数字。
- 是否改变旧行为：改变了允许负范围参数的键盘输入行为；不改变非负参数的输入限制和已有粘贴/解析逻辑。

## 7. 回归建议
- 必测场景：软化温度输入框中直接键盘输入 `-6`，失焦或回车后值保持为 `-6`。
- 边界场景：输入单独 `-` 后失焦，应按现有无效输入处理逻辑回退；输入 `0`、正整数、复制粘贴负数均应正常。
- 反向场景：选择 `min >= 0` 的普通整数输入框，确认仍不能输入 `-`，避免放开所有数字框限制。

# 物理喷嘴组合属性写入 G-code 说明

## 1. 背景与目标

F039/K3 多喷嘴切片已经具备耗材分组、`filament_map` 和多口径参数。固件还需要知道每个物理喷嘴的完整属性，才能自行判断哪些喷嘴可以互换。

本次不输出“4 个喷嘴是否全部相同”的总开关，而是按物理喷嘴顺序保存“口径 + 流量类型”组合。这样任意两个或多个属性相同的喷嘴都能形成独立的可互换组，互不影响其他喷嘴。

## 2. G-code 字段

字段位于 G-code 的配置块中：

```gcode
; physical_nozzle_properties = 0.4-standard,0.4-standard,0.6-standard,0.4-high_flow
```

字段规则：

- 逗号分隔的第 1、2、3、4 项依次对应物理喷嘴 P1、P2、P3、P4。
- 单项格式为 `<口径毫米值>-<流量类型名称>`。
- 口径直接使用毫米值，例如 `0.4`、`0.6`，便于固件日志和人工检查。
- 流量类型使用固定名称：`standard`、`high_flow`、`hybrid`、`tpu_high_flow`。

## 3. 分组判断示例

### 3.1 只有两个喷嘴相同

```gcode
; physical_nozzle_properties = 0.4-standard,0.4-standard,0.6-standard,0.4-high_flow
```

- P1、P2 都是 `0.4-标准`，固件可将这两个喷嘴任意映射。
- P3 是 `0.6-标准`，P4 是 `0.4-高流量`，不能加入 P1/P2 的组。
- 不需要 4 个喷嘴全部相同。

### 3.2 存在两个独立组

```gcode
; physical_nozzle_properties = 0.4-standard,0.6-high_flow,0.4-standard,0.6-high_flow
```

- P1、P3 是一组。
- P2、P4 是另一组。
- 固件可分别在两个组内处理映射。

## 4. 数据来源与生成链路

字段不新增可编辑的预设参数，也不单独持久化到 3MF，避免产生重复状态。它由切片时已经物化完成的两个参数派生：

1. `nozzle_diameter[]`：各物理喷嘴口径。
2. `nozzle_volume_type[]`：各物理喷嘴流量类型。
3. `GCode::append_full_config()`：导出配置块时组合为 `physical_nozzle_properties`。

因此字段反映的是本次切片实际使用的物理喷嘴属性，而不是 UI 中尚未物化的候选值。

## 5. 输出条件与异常处理

仅在以下条件同时满足时输出字段：

- 机型开启 `support_filament_nozzle_mapping`。
- 物理喷嘴数量大于 1。
- 口径和流量类型源数据存在且有效。

任何口径小于等于 0，或流量类型超出协议范围时，整行不输出，避免固件依据错误数据放宽映射。

## 6. 固件处理边界

切片端只负责提供按位置排列的属性组合，不预先生成组号，也不改变 `filament_map`。固件可按自身策略比较完整 token：token 完全相同的物理喷嘴具有相同属性，可以组成可互换集合；不同 token 不应视为同组。

本次不修改发送页、上传协议或设备侧逻辑。固件直接读取生成的 G-code 字段即可。

## 7. 代码修改

- `src/libslic3r/GCode.cpp`：生成并按条件写入组合属性字段。
- `src/libslic3r/GCode.hpp`：声明组合属性序列化接口。
- `tests/fff_print/test_gcode.cpp`：覆盖局部分组和非法源数据两个场景。
